第三章：类型系统与模式匹配

Rust 的类型系统是其最强大的特性之一。它结合了静态类型的编译期检查和动态类型的灵活性，通过 Trait 系统实现了类型类（type classes）的效果，同时保持了零运行时开销。本章将深入探讨枚举、Trait、模式匹配和零成本抽象的底层机制。

3.1 枚举（Enum）的深度应用

Rust 的枚举不仅仅是 C 风格的命名整数常量。它们是带标签的联合类型（tagged unions），每个变体可以携带不同类型的数据。这种设计被称为 ADT（Algebraic Data Types）。

3.1.1 枚举变体携带数据

enum Message {
    Quit,                                    // 无数据
    Move { x: i32, y: i32 },                 // 结构体变体
    Write(String),                            // 元组变体
    ChangeColor(u8, u8, u8),                  // 多个原始类型
}

impl Message {
    fn execute(&self) {
        match self {
            Message::Quit => println!("Exiting..."),
            Message::Move { x, y } => {
                println!("Moving to ({}, {})", x, y);
            }
            Message::Write(text) => println!("Text: {}", text),
            Message::ChangeColor(r, g, b) => {
                println!("RGB({}, {}, {})", r, g, b);
            }
        }
    }
}

// 枚举可以关联方法
enum Result<T, E> {
    Ok(T),
    Err(E),
}

3.1.2 Option 和 Result 作为枚举

Option<T> 和 Result<T, E> 本质上是枚举，但它们在标准库中被特殊对待：

// Option 的定义（简化版）
enum Option<T> {
    Some(T),
    None,
}

// Result 的定义（简化版）
enum Result<T, E> {
    Ok(T),
    Err(E),
}

// 使用模式匹配处理 Option
fn first_letter(name: &str) -> Option<char> {
    name.chars().next()
}

fn greet(name: &str) -> String {
    match first_letter(name) {
        Some(first) => format!("Hello, {}!", first.to_uppercase()),
        None => "Hello, anonymous!".to_string(),
    }
}

// 使用 Result 处理错误
fn parse_port(s: &str) -> Result<u16, std::num::ParseIntError> {
    s.parse::<u16>()
}

3.1.3 枚举的内存布局

枚举的内存表示

enum Status {
    Ready,                    // 0 字节变体
    Busy(u32),                // 4 字节数据
    Error(String),            // 24 字节（String 的栈上元数据）
}

内存布局（简化）：
┌──────────────────────────────────┐
│ discriminant (4 bytes)           │ ← 哪个变体被激活
│ + data (variable size)           │
│                                  │
│ Ready:     discriminant=0        │
│ Busy:      discriminant=1, u32   │
│ Error:     discriminant=2, ptr   │
└──────────────────────────────────┘

总大小 = discriminant + 最大变体的大小 + 对齐填充
       = 4 + 24 + 4 = 32 字节（对齐到 8 字节）

Rust 使用discriminant（判别值）来标识当前哪个变体处于活动状态。编译器会尽可能优化内存布局，例如使用 [repr(C)] 或与 C 枚举兼容的布局。

3.2 Trait 系统

Trait 是 Rust 的核心抽象机制，类似于其他语言的接口（interface），但功能更加强大。它支持两种多态形式：

特性 泛型（Monomorphization） Trait Object（VTable）
语法 fn foo<T: Trait>(x: &T) fn foo(x: &dyn Trait)
代码膨胀 每种类型生成一份副本 单一函数，无膨胀
运行时开销 零（内联调用） 间接调用（vtable 查找）
大小已知 编译期确定 需要装箱（&T 或 Box<T>）
适用场景 性能敏感、类型确定 动态分发、异构集合

3.2.1 Trait 作为接口

trait Shape {
    fn area(&self) -> f64;
    fn perimeter(&self) -> f64;
}

struct Circle {
    radius: f64,
}

struct Rectangle {
    width: f64,
    height: f64,
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.radius * self.radius
    }
    fn perimeter(&self) -> f64 {
        2.0 * std::f64::consts::PI * self.radius
    }
}

impl Shape for Rectangle {
    fn area(&self) -> f64 {
        self.width * self.height
    }
    fn perimeter(&self) -> f64 {
        2.0 * (self.width + self.height)
    }
}

// 泛型使用：编译期 monomorphization
fn print_shape_info<S: Shape>(shape: &S) {
    println!("Area: {:.2}, Perimeter: {:.2}", shape.area(), shape.perimeter());
}

// Trait object 使用：运行时分发
fn draw_shapes(shapes: &[&dyn Shape]) {
    for shape in shapes {
        println!("Drawing shape with area {:.2}", shape.area());
    }
}

3.2.2 Trait Bound 语法

// 传统语法
fn process<T: Clone + Debug>(value: &T) {
    let cloned = value.clone();
    println!("{:?}", cloned);
}

// '+' 语法糖
fn process2<T>(value: &T)
where
    T: Clone + Debug,
{
    let cloned = value.clone();
    println!("{:?}", cloned);
}

// impl Trait 语法（仅限参数）
fn process3(value: &impl Clone + Debug) {
    let cloned = value.clone();
    println!("{:?}", cloned);
}

// impl Trait 也可用于返回类型（OLEG）
fn create_iterator() -> impl Iterator<Item = i32> {
    (0..10).filter(|x| x % 2 == 0)
}

3.2.3 关联类型 vs 泛型参数

// 使用泛型参数：每种组合都需要实现
trait ContainerGeneric<T> {
    fn add(&mut self, item: T);
    fn get(&self, index: usize) -> Option<&T>;
}

// 使用关联类型：每个实现只有一个类型
trait ContainerAssoc {
    type Item;
    fn add(&mut self, item: Self::Item);
    fn get(&self, index: usize) -> Option<&Self::Item>;
}

struct IntContainer {
    items: Vec<i32>,
}

impl ContainerAssoc for IntContainer {
    type Item = i32;  // 明确指定关联类型
    fn add(&mut self, item: i32) {
        self.items.push(item);
    }
    fn get(&self, index: usize) -> Option<&i32> {
        self.items.get(index)
    }
}
什么时候用关联类型，什么时候用泛型参数？

如果你需要一个类型实现 trait 多次（每次用不同的类型参数），使用泛型参数。如果每个实现只对应一个类型，使用关联类型。标准库中 Iterator::Item、Hash::Hasher 都是关联类型。

3.3 模式匹配（Pattern Matching）

Rust 的模式匹配是其表达能力的核心。它不仅仅用于 match 语句，还贯穿了整个语言。

3.3.1 Match Ergonomics（匹配自适应性）

从 Rust 1.26 开始，match 会自动解引用引用。这使得模式匹配更加直观：

struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let point = Point { x: 3, y: 4 };
    let ref_point = &point;

    // 新版本自动解引用
    match ref_point {
        Point { x, y } => {
            // x = 3, y = 4 （自动解引用为 &i32）
            println!("Point at ({}, {})", x, y);
        }
    }

    // 如果需要绑定为引用
    match ref_point {
        Point { x: ref px, y: ref py } => {
            println!("Coordinates: ({}, {})", px, py);
        }
    }
}

3.3.2 解构（Destructuring）

// 解构元组
let tuple = (1, "hello", true);
let (num, _, flag) = tuple;

// 解构嵌套结构
enum NetworkMessage {
    Tcp { src: u16, dst: u16, payload: Vec<u8> },
    Udp { src: u16, dst: u16 },
    Icmp { code: u8, data: [u8; 4] },
}

fn process_message(msg: &NetworkMessage) {
    match msg {
        NetworkMessage::Tcp { dst, payload, .. } => {
            println!("TCP to port {}, {} bytes", dst, payload.len());
        }
        NetworkMessage::Udp { src, dst } => {
            println!("UDP from {} to {}", src, dst);
        }
        NetworkMessage::Icmp { code, data } => {
            println!("ICMP code {}, data: {:?}", code, data);
        }
    }
}

// 解构函数返回值
fn get_user() -> (String, u32, Option<String>) {
    ("Alice".to_string(), 30, Some("alice@example.com".to_string()))
}

let (name, age, Some(email)) = get_user();

3.3.3 If Let 和 While Let

// 替代简单的 match
fn find_first_even(numbers: &[i32]) -> Option<i32> {
    for n in numbers {
        if let Some(even) = n.checked_mul(2) {
            if even % 2 == 0 {
                return Some(even);
            }
        }
    }
    None
}

// while let 用于迭代 Option/Result
fn consume_option(opt: Option<Vec<i32>>) {
    let mut remaining = opt;
    while let Some(mut vec) = remaining {
        if let Some(last) = vec.pop() {
            println!("Popped: {}", last);
        } else {
            break;
        }
        remaining = if vec.is_empty() { None } else { Some(vec) };
    }
}

3.4 零成本抽象的底层机制

3.4.1 Monomorphization（单态化）

当使用泛型代码时，编译器为每种具体类型生成一份独立的函数/类型副本。这是 C++ 模板和 Rust 泛型的共同策略：

// 泛型定义
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list.iter() {
        if item > largest {
            largest = item;
        }
    }
    largest
}

// 编译器生成的代码（伪代码）
fn largest_i32(list: &[i32]) -> &i32 { /* ... */ }
fn largest_char(list: &[char]) -> &char { /* ... */ }

fn main() {
    let numbers = vec![34, 50, 25, 100, 65];
    let largest_num = largest(&numbers);  // 实例化为 largest_i32

    let chars = vec!['y', 'm', 'a', 'q'];
    let largest_char = largest(&chars);   // 实例化为 largest_char
}

性能影响：单态化消除了所有间接调用开销。在基准测试中，泛型版本的 Vec::get 与手写的索引访问性能完全相同（在 -O2 优化下）。

3.4.2 VTable vs Inline 调用的性能对比

trait Processor {
    fn process(&self, data: &[u8]) -> u64;
}

// 泛型版本：单态化，内联调用
fn process_all_generic<P: Processor>(processor: &P, data: &[u8]) -> u64 {
    processor.process(data)  // 编译期内联，无间接调用
}

// Trait 对象版本：vtable 间接调用
fn process_all_object(processor: &dyn Processor, data: &[u8]) -> u64 {
    processor.process(data)  // 运行时通过 vtable 查找
}

// 性能对比（Release 模式，10^9 次调用）：
// Generic:   ~0.5ns  per call（完全内联）
// Dyn:       ~2.0ns  per call（一次间接跳转）
// 差距：~4x，但在整体程序中通常可忽略

3.5 Newtype 模式：类型级安全

Newtype 是一种将现有类型包裹在新类型中的模式，用于在编译期提供额外的语义保证：

// 金额类型：区分不同货币
struct Dollars(f64);
struct Euros(f64);

// 编译器确保不会混淆货币
fn convert_dollars_to_euros(d: Dollars) -> Euros {
    Euros(d.0 * 0.85)  // 汇率固定为 0.85
}

// 密码类型：标记已验证的字符串
struct Password(String);

impl Password {
    fn new(raw: &str) -> Self {
        assert!(raw.len() >= 8, "Password too short");
        Password(raw.to_string())
    }

    fn verify(&self, input: &str) -> bool {
        self.0 == input
    }
}

// 不使用 Password 类型的代码无法传入普通字符串
fn authenticate(user: &str, pwd: &Password) -> bool {
    pwd.verify(user)
}

3.5.1 Newtype 的内存布局

Newtype 的零开销保证

原始类型                    Newtype 包装
┌──────────┐              ┌──────────┐
│ f64      │  8 字节      │ Dollars  │  8 字节
│ 0.0001%  │  运行时开销   │ (f64)    │  0% 运行时开销
└──────────┘              └──────────┘

编译器在 monomorphization 阶段会直接替换
Dollars → f64，生成的机器码完全相同。

3.6 Trait 的继承与扩展

// Trait 继承
trait Draw: std::fmt::Display {
    fn draw(&self) -> String;
}

// 实现 Draw 必须同时实现 Display
struct Widget {
    label: String,
}

impl std::fmt::Display for Widget {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{}", self.label)
    }
}

impl Draw for Widget {
    fn draw(&self) -> String {
        format!("[{}] {}", self.label, self)
    }
}

// 扩展 Trait：为所有实现特定 trait 的类型添加方法
trait VectorExt: std::ops::Mul<Output = Self> + Sized {
    fn dot_product(self, other: Self) -> f64 {
        (self * other).into_iter().map(|v| v * v).sum()
    }
}

3.7 本章小结

关键要点
  • 枚举：Rust 的枚举是带标签的联合类型，可以携带任意数据，内存布局紧凑
  • Trait 两种多态：泛型（编译期单态化，零开销）vs Trait 对象（运行期分发，vtable 查找）
  • 关联类型 vs 泛型参数：一对一用关联类型，一对多用泛型参数
  • 模式匹配：Match ergonomics 让匹配引用更加自然，guard 子句提供条件过滤
  • Newtype：编译期类型安全，零运行时开销
