第 12 章　敌人 AI 与战斗管线

本章拆解敌人的组织方式：一个敌人由哪些组件构成，骨钉命中后 HealthManager 如何在格挡、扣血、死亡之间分流，以及 Walker、Recoil 这些 C# 行为组件如何与 FSM 协作。

12.1 敌人的组件构成

和主角一样，敌人也是"C# 管理器 + 行为组件 + PlayMaker FSM"的组合，但核心是 HealthManager：

flowchart TB E["敌人 GameObject"] --> HM["HealthManager
生命值/受击/死亡的总入口"] E --> BEHAVIOR["行为组件
Walker（巡逻）/ Recoil（受击）
各种移动/攻击脚本"] E --> FSM["PlayMaker FSM
具体 AI 状态编排（chaser 等）"] E --> COLL["Collider2D / Rigidbody2D
物理与触发"] HM -->|"事件字符串"| FSM

HealthManager 不直接决定敌人怎么移动、怎么攻击，它只管"被打时如何响应"，并通过事件通知 FSM；具体 AI 行为由 FSM 和行为组件承担。这是职责分离。

12.2 HitInstance：一次攻击的数据包

命中信息不是零散参数，而是一个 [Serializable] 结构体：

[Serializable]
public struct HitInstance
{
    public GameObject Source;
    public AttackTypes AttackType;
    public int DamageDealt;
    public float Direction;
    public bool CircleDirection;
    public float Multiplier;
    public float MagnitudeMultiplier;
    public bool IgnoreInvulnerable;
    // ...

    public float GetActualDirection(Transform target)
    {
        if (CircleDirection)
        {
            Vector2 offset = (Vector2)target.position - (Vector2)Source.transform.position;
            return Mathf.Atan2(offset.y, offset.x) * 57.29578f;  // 环形方向按相对位置算
        }
        return Direction;
    }
}

固定方向与环形方向：普通攻击 Direction 是固定角度；CircleDirection 为真时，方向根据攻击来源和目标的相对位置动态计算，法术等范围攻击用它让击退方向总是"从命中点向外"。57.29578 是弧度转角度的常数。

12.3 Hit 入口：三道前置门控

public void Hit(HitInstance hitInstance)
{
    if (!isDead && !(evasionByHitRemaining > 0f) && hitInstance.DamageDealt > 0)
    {
        FSMUtility.SendEventToGameObject(hitInstance.Source, "DEALT DAMAGE");
        int cardinal = DirectionUtils.GetCardinalDirection(
            hitInstance.GetActualDirection(transform));
        if (IsBlockingByDirection(cardinal, hitInstance.AttackType))
            Invincible(hitInstance);     // 格挡
        else
            TakeDamage(hitInstance);     // 受击
    }
}
  • isDead——已死亡的敌人不再响应
  • evasionByHitRemaining——受击后的短暂闪避窗口，防止同一帧多段攻击重复命中
  • 伤害必须大于 0

通过门控后，按攻击方向是否被格挡分流到 Invincible 或 TakeDamage。

12.4 格挡分支：Invincible

当敌人持盾或该方向有护甲（IsBlockingByDirection），攻击不扣血，而是触发完整的格挡反馈：

FSMUtility.SendEventToGameObject(gameObject, "BLOCKED HIT");
FSMUtility.SendEventToGameObject(hitInstance.Source, "HIT LANDED");
if (hitInstance.AttackType == AttackTypes.Nail)
{
    if (cardinal == 0) HeroController.instance.RecoilLeft();   // 玩家被反震
    if (cardinal == 2) HeroController.instance.RecoilRight();
}
GameManager.instance.FreezeMoment(1);                          // 顿帧
GameCameras.instance.cameraShakeFSM.SendEvent("EnemyKillShake");
GameObject blockFx = blockHitPrefab.Spawn();                  // 格挡火花，位置/朝向随方向

格挡反馈为什么要做全套？

玩家需要立刻知道"这一击被挡住了"。于是同时给：玩家骨钉反震、全局顿帧、相机震动、按方向定位的格挡火花和音效。这些信号叠加让"砍在盾上"和"砍中肉体"有明确可感的区别。结尾设 evasionByHitRemaining=0.15 进入短暂冷却。

按攻击类型播放命中特效

骨钉、法术、暗影冲刺各有不同的命中特效，骨钉还会让主角获得灵魂：

        HeroController.instance.SoulGain();       // 砍中回魂
    strikeNailPrefab.Spawn(hitPos, Quaternion.identity);
    // 火花朝向随命中方向随机旋转

case AttackTypes.Spell:

扣血与死活分流

int finalDamage = Mathf.RoundToInt(hitInstance.DamageDealt * hitInstance.Multiplier);
if (damageOverride) finalDamage = 1;
hp = Mathf.Max(hp - finalDamage, -50);
if (hp > 0)
    NonFatalHit(hitInstance.IgnoreInvulnerable);   // 没死：硬直/闪避动画
else
    Die(hitInstance.GetActualDirection(transform),
        hitInstance.AttackType, hitInstance.IgnoreInvulnerable);  // 死亡

注意 hp 下限是 -50 而非 0，允许伤害溢出（某些机制需要知道超额伤害）。NonFatalHit 会设 0.2 秒闪避窗口或播放受击动画。

战斗场景计数

PlayMakerFSM battle = FSMUtility.LocateFSM(battleScene, "Battle Control");
FsmInt enemies = battle.FsmVariables.GetFsmInt("Battle Enemies");
enemies.Value--;
notifiedBattleScene = true;

这是 Boss 房间判断"小怪是否清完"的机制：每个敌人死亡时给战斗控制 FSM 的计数减一，归零触发开门等后续。

不同攻击类型走不同结局：Splatter 直接生成碎尸并销毁；普通攻击抛洒吉欧并播放死亡特效；特殊死亡（hasSpecialDeath）不销毁物体，完全交给 FSM 处理（如某些 Boss 阶段）。

12.7 C# 行为组件：Walker 与 Recoil

Walker：数据驱动的巡逻

Walker 是纯 C# 写的巡逻组件，自带状态枚举（NotReady/WaitingForConditions/Stopped/Walking/Turning），含视线检测、警戒范围、伏击标记：

private enum States { NotReady, WaitingForConditions, Stopped, Walking, Turning }
[SerializeField] private LineOfSightDetector lineOfSightDetector;
[SerializeField] private AlertRange alertRange;
[SerializeField] private bool ambush;
private const float CameraDistanceForActivation = 60f;

它用相机距离（60）做激活门控，离屏敌人不跑逻辑以省性能；停顿、转向、缩放朝向都由序列化字段配置，同一个组件能支撑大量步行敌人。

Recoil：受击冻结与击退

private enum States { Ready, Frozen, Recoiling }
[SerializeField] public bool freezeInPlace;
[SerializeField] private float recoilSpeedBase;
[SerializeField] private float recoilDuration;

Recoil 提供两种受击响应：冻结在原地（Frozen）或按方向击退（Recoiling），RecoilByDirection 被 HealthManager 调用。带 Sweep 检测防止击退时穿墙。

12.8 EnemySpawner：概率生成

public float spawnChance = 0.75f;
private void Start()
{
    if (Random.Range(0f, 1f) <= spawnChance)
    {
        iTween.MoveBy(gameObject, hashtable);   // 从地下移动 + 颜色渐变
    }
    else
    {
        gameObject.SetActive(false);            // 概率不生成
    }
}
// 动画结束后激活敌人，并给其 chaser FSM 发 Start Alert

生成器用 iTween 做"钻出地面"的位移和颜色渐变，按概率决定是否真的生成，激活时设置敌人 FSM 的警报变量。这让同一处敌人每次开局不一定出现，增加变化。

12.9 打击感的三个来源

把战斗"手感"拆开，它由三个可在代码中定位的机制共同构成：

  • 顿帧 FreezeMoment：命中瞬间时间短暂冻结，强化命中重量感
  • 相机震动：cameraShakeFSM 按事件发不同强度震动
  • 击退/硬直：敌人 Recoil + 玩家反震，双向受力反馈
