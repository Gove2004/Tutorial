第 9 章：部署与运行模式

代码写完了，功能跑通了——但现在你面对一个全新的问题：怎么让别人连进来玩？ 从 Editor 里的 Host 模式到生产环境中的专用服务器，部署涉及到编译、配置、网络、运维多个层面。 本章覆盖从本地测试到云端部署的完整链路。

9.1 三种运行模式

Mirror 支持三种运行模式，每种适用于不同场景：

模式角色适用场景部署复杂度
Client Only仅客户端玩家正常进入游戏低
Host客户端 + 服务器开发测试、P2P 主机游戏中
Dedicated Server仅服务器生产环境、正式服高

9.2 编译专用服务器

专用服务器（Dedicated Server）是无头进程——没有图形渲染，只有服务器逻辑。

9.2.1 Unity 构建设置

Build Settings 配置：
• Build Target: Standalone Server (Windows/Linux/macOS)
• Architecture: x86_64
• Development Build: 关闭（发布时）/ 开启（调试时）
• Compression Method: LZ4（减小体积）

9.2.2 命令行启动参数

# Windows
YourGame.exe -batchmode -nographics -dedicated -port 7777

# Linux
./YourGame.x86_64 -batchmode -nographics -dedicated -port 7777

# macOS
./YourGame.app/Contents/MacOS/YourGame -batchmode -nographics -dedicated -port 7777

参数说明：

参数作用必需？
-batchmode无 UI 模式，不等待用户输入✅ 必须
-nographics不初始化 Graphics 模块，节省内存和 CPU✅ 必须
-dedicated自定义参数，在你的代码中判断是否专用服务器模式推荐
-port 7777自定义端口可选
-logFile /tmp/game.log指定日志文件路径可选

9.2.3 在代码中处理专用服务器模式

public class GameBootstrapper : MonoBehaviour
{
    void Start()
    {
        // 检测是否以专用服务器模式启动
        bool isDedicated = System.ArgumentList.Contains("-dedicated");

        if (isDedicated)
        {
            StartDedicatedServer();
        }
        else
        {
            StartClientOrHost();
        }
    }

    void StartDedicatedServer()
    {
        // 获取端口
        int port = 7777;
        var portArg = System.ArgumentList.Get("-port");
        if (int.TryParse(portArg, out int parsed))
            port = parsed;

        // 启动服务器
        NetworkServer.Listen(port);

        Debug.Log($"[Server] 专用服务器已启动，端口 {port}");

        // 加载游戏场景
        SceneManager.LoadScene("GameScene");
    }

    void StartClientOrHost()
    {
        // 客户端/Host 模式的启动逻辑
        NetworkClient.Connect("localhost");
    }
}
内存优化：使用 -nographics 后，Unity 不会初始化 GPU 驱动， 服务器进程的内存占用可以从 ~500MB 降到 ~100MB。这对云服务器成本影响很大—— 一台 2GB 内存的机器可以跑 20 个服务器实例，而不是 4 个。

9.3 本地测试流程

9.3.1 Editor 内测试

步骤 1: 打开 Unity Editor → 点击 "Host"（服务器 + 本地客户端）
步骤 2: 再打开一个 Editor → 点击 "Client Only"（连接到 Host）
步骤 3: 验证 Player 对象生成、移动同步、RPC 调用

9.3.2 独立客户端测试

步骤 1: 构建服务器 → YourGame.exe -dedicated -port 7777
步骤 2: 打开另一个 Unity Editor → Client Only → 连接 localhost:7777
步骤 3: 或者构建独立客户端 → YourGameClient.exe → 连接 localhost:7777

9.3.3 多客户端测试

步骤 1: 启动专用服务器
步骤 2: 同时打开 4 个 Editor/客户端实例
步骤 3: 依次连接，验证多人同步
为什么不在 Editor 的 Host 模式下测试多客户端？
Host 模式只包含一个服务器实例和一个客户端实例。 要测试"多个玩家"，至少需要两个客户端连接同一个服务器。 最方便的方式是：一个构建的服务器 + 多个 Editor 客户端。

9.4 使用 Unity Relay 进行 NAT 穿透

当服务器和客户端不在同一局域网时，NAT（网络地址转换）会阻止直连。 Relay 服务作为中间代理转发数据。

// Unity Relay (之前叫 Netcode Relay)
// 通过 Unity Gaming Services (UGS) 提供

using Unity.Netcode.Relay;

// 服务器端：创建 Relay 房间
var relay = new Relay();
var joinCode = await relay.CreateRoom(maxClients: 10);
// joinCode 是一个字符串，类似 "ABC12345"

// 客户端：用 JoinCode 加入
await relay.JoinRoom(joinCode);

// 获取 Relay 信息并配置 Transport
var serverConnectionData = relay.GetServerConnectionData();
var clientConnectionData = relay.GetClientConnectionData();

9.4.1 Relay vs 直连的权衡

维度直连（专用服务器）Relay
延迟低（直连）较高（多一跳转发）
带宽成本服务器承担Relay 服务商承担
NAT 穿透需要端口转发或公网 IP自动处理
部署复杂度需要 VPS / 云服务器零服务器管理
适用规模任意规模中小规模（<500 并发）
成本模型固定（服务器费用）按流量付费
推荐方案：开发阶段用直连（本地服务器），发布初期用 Relay（快速上线）， 用户量增长后用专用服务器 + CDN 加速。三者可以共存——你的游戏应该支持多种连接方式。

9.5 CI/CD 中的自动化服务器测试

在持续集成管道中运行服务器测试，确保每次提交都不会破坏联网功能：

# Jenkins / GitLab CI 脚本示例
#!/bin/bash

# 1. 构建服务器
unity -batchmode -quit -executeMethod BuildServer.Build \
    -projectPath ./MyGame \
    -buildTarget StandaloneLinux64

# 2. 启动服务器
./Builds/linux-server/MyGameServer -batchmode -nographics -dedicated -port 7777 &
SERVER_PID=$!

# 3. 等待服务器就绪
sleep 5

# 4. 运行自动化测试（Headless 客户端）
./Builds/linux-client/MyGameClient \
    -batchmode -nographics \
    -testServer localhost:7777

# 5. 清理
kill $SERVER_PID
// 自动化测试脚本
public class ServerTests : MonoBehaviour
{
    IEnumerator TestPlayerSpawn()
    {
        NetworkClient.Connect("localhost", 7777);
        yield return new WaitUntil(() => NetworkClient.isConnected);

        // 等待 Player 对象生成

9.6 云服务器部署

9.6.1 推荐的云服务商

平台特点适合场景
AWS EC2功能最全，生态完善大规模生产
GCP Compute Engine全球网络好，价格透明国际服
阿里云 ECS国内延迟低，合规方便中国大陆
DigitalOcean简单易用，按小时计费中小项目
Google Cloud Run容器化部署，自动扩缩弹性需求

9.6.2 Docker 容器化部署

# Dockerfile for Unity Mirror Server
FROM ubuntu:22.04

# 安装 Unity 运行时依赖
RUN apt-get update && apt-get install -y \
    libgl1-mesa-glx \
    libssl1.1 \
    libstdc++6 \
    zlib1g \
    && rm -rf /var/lib/apt/lists/*

# 复制服务器二进制
COPY MyGameServer /game/
COPY GameData /game/Data/

WORKDIR /game

# 启动命令
ENTRYPOINT ["./MyGameServer", "-batchmode", "-nographics", "-dedicated"]
CMD ["--port", "7777"]
# 构建和运行
docker build -t mygame-server .
docker run -d -p 7777:7777 --name mygame-1 mygame-server

# 多实例部署
docker run -d -p 7778:7777 mygame-server
docker run -d -p 7779:7777 mygame-server

9.6.3 服务器扩缩策略

静态部署（简单但浪费）：
  始终运行 N 个服务器实例
  适合：日活稳定、峰值可预估

动态扩缩（推荐）：
  监控在线人数 → 低于阈值时缩减 → 高于阈值时扩展
  适合：日活波动大、成本控制严格

混合模式（最佳）：
  基础 N 个实例常驻 + 高峰期自动扩展 M 个实例
  适合：大多数商业游戏

9.7 监控与运维

9.7.1 服务器健康检查

public class ServerMonitor : MonoBehaviour
{
    void Update()
    {
        // 监控关键指标
        int connectedClients = NetworkServer.connections.Count;
        float cpuUsage = GetCPUUsage();
        float memoryUsage = GetMemoryUsage();
        long bytesReceived = GetBytesReceived();
        long bytesSent = GetBytesSent();

        // 异常检测
        if (connectedClients == 0 && Time.time > 300)
        {
            Debug.LogWarning("服务器运行 5 分钟但无客户端连接");
        }

        if (memoryUsage > 200 * 1024 * 1024)  // 200MB
        {
            Debug.LogError("内存占用过高！可能存在内存泄漏");
        }

        // 定期输出性能报告
        if (Time.frameCount % 300 == 0)  // 每 5 秒
        {
            Debug.Log($"[Perf] 客户端:{connectedClients} CPU:{cpuUsage:F1}% Mem:{memoryUsage / 1024 / 1024:F0}MB");
        }
    }
}

// 结构化日志输出（方便 ELK/Grafana 等工具采集）
public class StructuredLogger
{
    public static void LogEvent(string eventType, Dictionary<string, string> data)
    {
        // JSON 格式输出，便于解析
        string json = JsonConvert.SerializeObject(new
        {
            timestamp = DateTime.UtcNow.ToString("O"),
            type = eventType,
            data = data
        });

        Debug.Log(json);
    }
}

9.8.2 防 DDoS 基础措施

  • 速率限制：每个连接每秒最多 N 条消息
  • 连接限制：单个 IP 最多 M 个并发连接
  • 消息大小限制：拒绝超过 MTU × 2 的消息
  • Cloudflare / AWS Shield：在服务器前加 CDN 做 L3/L4 防护

9.9 本章小结

  • 专用服务器是生产环境的标配——无头进程、命令行参数、Docker 容器化
  • Unity Relay可以快速上线，但适合中小规模
  • CI/CD 自动化测试确保每次代码变更都不会破坏联网功能
  • 监控和日志是运维的基础——不知道服务器出了什么问题，就无法修复
