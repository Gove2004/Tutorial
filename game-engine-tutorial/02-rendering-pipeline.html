第二章：渲染管线——从顶点到像素

学习目标：理解图形从 CPU 内存到 GPU 屏幕的完整旅程。掌握渲染管线的每个阶段、Draw Call 的性能影响、批渲染和实例化等核心技术。这些是渲染子系统的基础。

渲染管线概述

渲染管线（Rendering Pipeline）是图形 API（OpenGL / Vulkan / DirectX）定义的一套固定流程，描述了顶点数据如何一步步变成屏幕上的像素。理解这个流程是编写高效渲染器的第一步。

每一帧，GPU 都要为场景中的每个物体执行这套流程。如果场景中有 1000 个物体，就需要执行 1000 次。这就是为什么减少 Draw Call（绘制调用）是渲染优化的第一要务。

固定功能管线 vs 可编程管线

在 OpenGL 2.x 时代，渲染管线是「固定功能」的——顶点变换、光照计算、纹理采样都由 GPU 内部硬编码的模块完成。开发者只能通过设置参数（如光源位置、材质颜色）来影响结果，无法改变计算逻辑。

从 OpenGL 3.0+（以及 DirectX 10+）开始，管线全面转向可编程。固定的顶点变换和光照被 Vertex Shader 和 Fragment Shader 取代。开发者用 GLSL 编写着色器代码，完全控制每个顶点和每个片段的计算过程。

特性 固定功能管线（OpenGL 2.x） 可编程管线（OpenGL 3.0+）
灵活性 低——只能调参数 极高——完全自定义计算

视觉效果 有限（Blinn-Phong 为主） 无限（PBR、体积光、后处理）
现代地位 已废弃 行业标准

着色器：渲染管线的灵魂

顶点着色器（Vertex Shader）

顶点着色器是渲染管线的第一个可编程阶段。它的职责是将顶点从模型空间变换到裁剪空间，并传递数据给后续阶段。

#version 460 core

layout(location = 0) in vec3 aPosition;   // 顶点位置
layout(location = 1) in vec3 aNormal;     // 顶点法线
layout(location = 2) in vec2 aTexCoord;   // 纹理坐标

uniform mat4 uModel;       // 模型矩阵
uniform mat4 uView;        // 视图矩阵
uniform mat4 uProjection;  // 投影矩阵

out vec3 vNormal;
out vec2 vTexCoord;
out vec3 vWorldPos;

void main()
{
    // 1. 将顶点变换到世界空间
    vec4 worldPos = uModel * vec4(aPosition, 1.0);
    vWorldPos = worldPos.xyz;

    // 2. 变换法线（使用逆转置矩阵确保正确性）
    vNormal = mat3(uModel) * aNormal;

    // 3. 传递纹理坐标
    vTexCoord = aTexCoord;

    // 4. 变换到裁剪空间（GPU 自动执行透视除法）
    gl_Position = uProjection * uView * worldPos;
}

顶点着色器的输入是顶点数据（位置、法线、纹理坐标等），输出是传递给片段着色器的插值数据。每个顶点执行一次，如果模型有 10 万个顶点，就执行 10 万次。

片段着色器（Fragment Shader）

片段着色器决定屏幕上每个像素的颜色。它接收顶点着色器输出的插值数据，进行光照计算、纹理采样等操作。

#version 460 core

in vec3 vNormal;
in vec2 vTexCoord;
in vec3 vWorldPos;

uniform sampler2D uTexture;
uniform vec3 uLightDir;
uniform vec3 uCameraPos;
uniform vec3 uBaseColor;

out vec4 fragColor;

void main()
{
    // 1. 纹理采样
    vec3 texColor = texture(uTexture, vTexCoord).rgb;

    // 2. 标准化光照方向和观察方向
    vec3 normal = normalize(vNormal);
    vec3 lightDir = normalize(uLightDir);
    vec3 viewDir = normalize(uCameraPos - vWorldPos);

    // 3. 漫反射光照（Lambert 模型）
    float diff = max(dot(normal, lightDir), 0.0);
    vec3 diffuse = diff * texColor;

    // 4. 镜面高光（Blinn-Phong）
    vec3 halfDir = normalize(lightDir + viewDir);
    float spec = pow(max(dot(normal, halfDir), 0.0), 32.0);
    vec3 specular = spec * vec3(0.3);

    // 5. 环境光（全局光照的简化近似）
    vec3 ambient = texColor * 0.1;

    // 6. 组合
    vec3 result = ambient + diffuse + specular;
    fragColor = vec4(result, 1.0);
}
为什么片段着色器叫「片段」不叫「像素」？：因为光栅化阶段生成的片段数量远多于屏幕像素。一个三角形可能覆盖 1000 个片段，但屏幕只有 200 万像素。片段经过深度测试、模板测试后，失败的才会被丢弃，剩下的才成为真正的像素写入帧缓冲区。

Draw Call 的概念与性能影响

Draw Call（绘制调用）是 CPU 向 GPU 发送的一次「画这个物体」的命令。每次 Draw Call 都需要：

  1. CPU 准备顶点数据和状态（绑定纹理、设置着色器）
  2. 通过 PCIe 总线将命令发送到 GPU
  3. GPU 切换状态、验证参数、执行渲染
  4. CPU 等待 GPU 完成（或异步排队）

这个过程虽然单次只需要几微秒，但累积起来是巨大的性能瓶颈。典型的性能数据：

Draw Call 数量 CPU 耗时/帧 GPU 耗时/帧 预估帧率
1000.1 ms2.0 ms~450 FPS
1,0000.8 ms2.5 ms~300 FPS
5,0003.5 ms4.0 ms~130 FPS
10,0007.0 ms6.0 ms~75 FPS
50,00035 ms15 ms~20 FPS
100,00070 ms25 ms~10 FPS

可以看到，当 Draw Call 超过 10,000 时，CPU 已经成为瓶颈（7ms 占了一帧 16.7ms 的 42%）。这就是为什么 减少 Draw Call 是渲染优化的第一优先级。

批渲染（Batch Rendering）

批渲染的核心思想是：把多个物体的绘制合并成一次 Draw Call。方法是把多个物体的顶点数据拼接到一个大的顶点缓冲区中，然后一次性提交。

// 批渲染的核心逻辑
class RenderBatcher {
public:
    void addMesh(const Mesh& mesh, const Mat4& transform, Texture* tex)
    {
        // 如果当前批次使用了不同的纹理，先 flush 再开新批次
        if (m_currentTexture && m_currentTexture != tex) {
            flush();
        }

        // 计算变换后的顶点
        const auto& vertices = mesh.getVertices();
        for (const auto& v : vertices) {
            Vertex batchVertex;
            batchVertex.position = transform * v.position;
            batchVertex.normal = (mat3(transform) * v.normal).normalized();
            batchVertex.texCoord = v.texCoord;
            batchVertex.color = v.color;
            m_batchVertices.push_back(batchVertex);
        }

        // 记录索引偏移
        m_batchIndices.reserve(m_batchIndices.size() + mesh.getIndexCount());
        uint32_t offset = static_cast(m_vertexOffset);
        for (uint32_t i = 0; i < mesh.getIndexCount(); ++i) {
            m_batchIndices.push_back(mesh.getIndices()[i] + offset);
        }

        m_vertexOffset += vertices.size();
        m_currentTexture = tex;
    }

    void flush()
    {
        if (m_batchVertices.empty()) return;

        // 一次性上传所有顶点数据到 GPU
        m_vbo.bind();
        m_vbo.setData(m_batchVertices.data(), m_batchVertices.size() * sizeof(Vertex));
        m_ibo.bind();
        m_ibo.setData(m_batchIndices.data(), m_batchIndices.size() * sizeof(uint32_t));

        // 绑定纹理（同一批次内纹理不变）
        if (m_currentTexture) {
            m_currentTexture->bind();
        }

        // 一次 Draw Call 渲染所有合并的物体
        glDrawElements(GL_TRIANGLES, m_batchIndices.size(), GL_UNSIGNED_INT, nullptr);

        // 清空批次
        m_batchVertices.clear();
        m_batchIndices.clear();
        m_vertexOffset = 0;
        m_currentTexture = nullptr;
    }

private:
    std::vector<Vertex> m_batchVertices;
    std::vector<uint32_t> m_batchIndices;
    uint32_t m_vertexOffset = 0;
    Texture* m_currentTexture = nullptr;
    BufferObject m_vbo;
    BufferObject m_ibo;
};

批渲染的限制：同一批次内的物体必须使用相同的着色器和纹理。如果场景中有很多不同材质的物体，批渲染的效果会打折扣。这时候需要考虑 Instancing（实例化）或其他优化技术。

实例化渲染（Instancing）

Instancing 是批渲染的进阶版——它不仅合并顶点数据，还在一次 Draw Call 中渲染多个相同网格的不同实例。每个实例可以有独立的位置、旋转、缩放、颜色。

// 顶点着色器支持 instanced arrays
#version 460 core

layout(location = 0) in vec3 aPosition;
layout(location = 1) in vec3 aNormal;
layout(location = 2) in vec2 aTexCoord;

// 实例属性：每个实例一个矩阵
layout(location = 3) in mat4 aInstanceMatrix;

uniform mat4 uView;
uniform mat4 uProjection;

out vec3 vNormal;
out vec2 vTexCoord;
out vec3 vWorldPos;

void main()
{
    // 每个实例的顶点 = 实例矩阵 × 网格顶点
    vec4 worldPos = aInstanceMatrix * vec4(aPosition, 1.0);
    vWorldPos = worldPos.xyz;
    vNormal = mat3(aInstanceMatrix) * aNormal;
    vTexCoord = aTexCoord;
    gl_Position = uProjection * uView * worldPos;
}
// 实例化渲染的 CPU 端代码
void renderInstanced(const Mesh& mesh,
                     const std::vector<Mat4>& transforms,
                     Texture* texture)
{
    // 1. 上传实例矩阵数组到 GPU
    GLuint instanceBuffer;
    glGenBuffers(1, &instanceBuffer);
    glBindBuffer(GL_ARRAY_BUFFER, instanceBuffer);
    glBufferData(GL_ARRAY_BUFFER,
                 transforms.size() * sizeof(Mat4),
                 transforms.data(),
                 GL_STATIC_DRAW);

    // 2. 绑定实例属性（location 3）
    glEnableVertexAttribArray(3);
    glVertexAttribPointer(3, 4, GL_FLOAT, GL_FALSE,
                          sizeof(Mat4), (void*)0);
    // 关键：告诉 GPU 每个实例前进 1 个属性，而不是 1 个顶点
    glVertexAttribDivisor(3, 1);

    // 3. 一次 Draw Call 渲染 N 个实例
    glBindTexture(GL_TEXTURE_2D, texture->id());
    glDrawElementsInstanced(
        GL_TRIANGLES,
        mesh.getIndexCount(),
        GL_UNSIGNED_INT,
        nullptr,
        transforms.size()  // 实例数量
    );

    // 4. 清理
    glVertexAttribDivisor(3, 0);
    glDeleteBuffers(1, &instanceBuffer);
}

使用 glDrawElementsInstanced 替代 glDrawElements，只需增加一行 glVertexAttribDivisor(3, 1) 就可以告诉 GPU：属性数组是按实例而不是按顶点推进的。

2D 渲染的特殊优化

2D 引擎的渲染模式与 3D 有显著不同，主要体现在两个方面：Sprite Batching 和 Texture Atlas。

Sprite Batching

2D 游戏中最常见的优化技术。将所有 Sprite 的矩形顶点合并到一个批次中，一次性渲染。由于 2D Sprite 通常是正对摄像机的四边形的，变换矩阵非常简单（只需要平移和缩放）。

class SpriteBatcher {
public:
    void begin() {
        m_vertices.clear();
        m_indices.clear();
        m_currentTexture = nullptr;
        m_quadCount = 0;
    }

    void draw(Texture* tex, const Rect& quad) {
        // 纹理切换时 flush
        if (m_currentTexture && m_currentTexture != tex) {
            flush();
        }

        // 添加四边形（2 个三角形 = 6 个顶点）
        float x = quad.x, y = quad.y;
        float w = quad.w, h = quad.h;
        float u = quad.u, v = quad.v;  // 纹理坐标
        float uw = quad.uw, vh = quad.vh;

        // 顶点布局：位置(2) + 纹理坐标(2) + 颜色(4) = 16 字节/顶点
        m_vertices.push_back({x,     y,     u,          v,           1,1,1,1});
        m_vertices.push_back({x+w,   y,     u+uw,       v,           1,1,1,1});
        m_vertices.push_back({x+w,   y+h,   u+uw,       v+vh,        1,1,1,1});
        m_vertices.push_back({x,     y+h,   u,          v+vh,        1,1,1,1});

        // 索引：两个三角形
        uint32_t baseIndex = m_quadCount * 4;
        m_indices.push_back(baseIndex + 0);
        m_indices.push_back(baseIndex + 1);
        m_indices.push_back(baseIndex + 2);
        m_indices.push_back(baseIndex + 0);
        m_indices.push_back(baseIndex + 2);
        m_indices.push_back(baseIndex + 3);

        m_quadCount++;
        m_currentTexture = tex;
    }

    void flush() {
        if (m_vertices.empty()) return;

        // 上传到 GPU 并绘制
        m_vbo.bind();
        m_vbo.setData(m_vertices.data(), m_vertices.size() * sizeof(SpriteVertex));
        m_ibo.bind();
        m_ibo.setData(m_indices.data(), m_indices.size() * sizeof(uint32_t));

        glDrawElements(GL_TRIANGLES, m_indices.size(), GL_UNSIGNED_INT, nullptr);

        // 重置
        m_vertices.clear();
        m_indices.clear();
        m_quadCount = 0;
        m_currentTexture = nullptr;
    }

    // 性能：10000 个 Sprite
    // 传统方式：10000 Draw Calls
    // SpriteBatcher：1-4 Draw Calls（取决于纹理切换次数）
    // CPU 耗时：~50ms → ~0.3ms（167x 提升）
};

Texture Atlas（纹理图集）

将多个小纹理拼成一张大图，Sprite 通过不同的 UV 坐标引用大图的子区域。这样即使 Sprite 来自不同的源文件，也可以共用同一个纹理，从而合并到一个批次中。

方案 独立纹理（100 个 Sprite） Texture Atlas（1 张图集）
Draw Calls1001
纹理切换次数1000
显存占用100 × 64KB = 6.25 MB1 × 4MB = 4 MB
GPU 缓存命中率低（频繁切换）高（连续访问）

Texture Atlas 的缺点是会浪费一些空间（Atlas 中无法完美填充的空白区域），以及纹理边界处的 纹理 bleeding（相邻纹理的颜色渗透到边界）。解决方法是在 Atlas 生成时给每个子纹理加 1px 的 padding，并在采样时使用 clamp-to-edge 模式。

OpenGL 基础渲染循环

让我们把所有概念整合到一个完整的渲染循环中，展示从场景准备到屏幕输出的全过程。

// 完整的 OpenGL 渲染循环
void Renderer::render(const Scene& scene, float deltaTime)
{
    // 1. 清除缓冲区
    glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);

    // 2. 设置渲染状态
    glEnable(GL_DEPTH_TEST);
    glEnable(GL_BLEND);
    glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);

    // 3. 更新 Uniform（每帧变化的数据）
    m_shader.use();
    m_shader.setMat4("uView", scene.getCamera().getViewMatrix());
    m_shader.setMat4("uProjection", scene.getCamera().getProjectionMatrix());
    m_shader.setVec3("uLightDir", scene.getLightDirection());
    m_shader.setFloat("uTime", deltaTime * scene.getTotalTime());

    // 4. 渲染所有可见物体（按材质分组以实现批渲染）
    auto groupedObjects = groupByMaterial(scene.getVisibleObjects());

    for (auto& [material, objects] : groupedObjects) {
        // 绑定材质对应的纹理
        material->bindTextures();

        // 绑定着色器
        material->getShader().use();

        // 渲染该组所有物体
        for (auto& obj : objects) {
            // 计算实例矩阵
            Mat4 transform = obj.getWorldTransform();

            // 设置 Uniform（每物体唯一的数据）
            material->getShader().setMat4("uModel", transform);

            // 绘制
            obj.getMesh().draw();
        }
    }

    // 5. UI 层（叠加在场景之上）
    renderUI(scene.getUIElements());

    // 6. 后处理效果（可选）
    if (m_postProcessEnabled) {
        applyPostProcessing();
    }

    // 7. 交换缓冲区
    glfwSwapBuffers(m_window);
}

// groupByMaterial 的实现——批渲染的关键
std::map<Material*, std::vector<GameObject*>>
groupByMaterial(const std::vector<GameObject*>& objects)
{
    std::map<Material*, std::vector<GameObject*>> groups;
    for (auto* obj : objects) {
        groups[obj->getMaterial()].push_back(obj);
    }
    return groups;
}

渲染循环的执行顺序

1

清屏

清除颜色缓冲区和深度缓冲区。每帧开始时，屏幕上是上一帧的内容，必须先清除。

2

设置渲染状态

启用深度测试（3D 遮挡）、混合（透明物体）、抗锯齿等。

3

更新 Uniform

将每帧变化的数据（视图矩阵、时间等）上传到 GPU Uniform。

4

按材质分组渲染

将物体按材质分组，同组物体共用相同的着色器和纹理，减少状态切换。

5

渲染 UI

UI 通常使用正交投影，叠加在 3D 场景之上。

6

后处理

对整帧图像应用泛光、色调映射、景深等效果（可选）。

7

交换缓冲区

将渲染好的后台缓冲区交换到前台显示。

本章小结

本章核心知识点回顾：
  1. 渲染管线：顶点 → 几何 → 光栅化 → 片段 → 帧缓冲。理解每个阶段的职责。
  2. 可编程管线：Vertex Shader 负责坐标变换，Fragment Shader 负责颜色计算。
  3. Draw Call：CPU 到 GPU 的桥梁，也是性能瓶颈的主要来源。
  4. 批渲染：合并顶点数据，减少状态切换，可将 10000 个物体的 Draw Call 从 10000 降到 1-4。
  5. Instancing：一次 Draw Call 渲染 N 个相同网格的不同实例，适合大量重复物体。
  6. 2D 优化：Sprite Batching + Texture Atlas 是 2D 引擎渲染的核心技术。
