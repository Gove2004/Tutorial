第八章：事件循环与异步执行

JavaScript 是单线程语言——它只有一个调用栈、一个事件循环。但我们的网页需要同时处理用户交互、网络请求、动画更新等多种异步任务。事件循环（Event Loop）就是连接同步代码与异步世界的桥梁，它决定了任务的执行顺序和时机。本章将彻底拆解事件循环的工作机制。

核心概念：事件循环是什么？

事件循环是一个无限循环，它不断地检查调用栈是否为空、任务队列是否有待处理的任务。当调用栈为空时，事件循环从任务队列中取出一个任务放入调用栈执行。这个过程重复进行，构成了 JavaScript 异步执行的基础模型。

8.1 Event Loop 宏观模型

事件循环的核心由三个组件构成：调用栈（Call Stack）、任务队列（Task Queue）和微任务队列（Microtask Queue）。

8.2 宏任务 vs 微任务

JavaScript 将异步任务分为两大类：宏任务（Macrotask）和微任务（Microtask）。它们的执行顺序遵循严格的规则。

特性宏任务 (Macrotask)微任务 (Microtask)
来源外部事件JS 引擎内部
执行时机每轮 Event Loop 执行一个每轮宏任务后全部执行
优先级较低较高
典型任务setTimeout, setInterval, I/O, UI 渲染Promise.then/catch/finally, queueMicrotask, MutationObserver
队列数量多个（每个来源一个队列）一个（全局微任务队列）

8.2.1 经典执行顺序

// 事件循环的经典面试题
console.log('1. 同步代码');

setTimeout(() => {
    console.log('2. setTimeout 回调');  // 宏任务
}, 0);

Promise.resolve().then(() => {
    console.log('3. Promise.then #1');  // 微任务
}).then(() => {
    console.log('4. Promise.then #2');  // 微任务
});

queueMicrotask(() => {
    console.log('5. queueMicrotask');   // 微任务
});

console.log('6. 同步代码结束');

// 输出顺序: 1, 6, 3, 5, 4, 2
//
// 执行过程:
// ┌─────────────────────────────────────────────────┐
// │ 第一轮 Event Loop                               │
// │                                                 │
// │ Call Stack:                                     │
// │   [同步代码 1] → 打印 "1"                       │
// │   [同步代码 6] → 打印 "6"                       │
// │   (栈空)                                        │
// │                                                 │
// │ → 清空微任务队列:                               │
// │   [Promise.then #1] → 打印 "3"                  │
// │     → 产生新的微任务 [Promise.then #2]           │
// │   [queueMicrotask] → 打印 "5"                    │
// │   [Promise.then #2] → 打印 "4"                  │
// │   (微任务队列空)                                │
// │                                                 │
// │ → 渲染帧                                        │
// │                                                 │
// │ → 执行宏任务:                                   │
// │   [setTimeout] → 打印 "2"                       │
// └─────────────────────────────────────────────────┘

8.2.2 微任务优先于 UI 渲染

微任务在每轮 Event Loop 的宏任务之前执行，并且在 UI 渲染之前执行。这意味着大量的微任务会推迟页面渲染：

// ❌ 大量微任务阻塞 UI 渲染
function processLargeDataset(data) {
    data.forEach(item => {
        Promise.resolve().then(() => {
            renderItem(item);  // 每个 item 一个微任务
        });
    });
    // 如果有 10000 个 item，就有 10000 个微任务
    // 浏览器必须全部执行完才能渲染下一帧
    // 导致页面卡顿数秒
}

// ✅ 分批处理，让出渲染机会
function processLargeDataset(data) {
    let index = 0;
    function processBatch() {
        const batch = data.slice(index, index + 50);
        batch.forEach(item => {
            renderItem(item);
        });
        index += 50;
        if (index < data.length) {
            // 使用 setTimeout 让出控制权，允许浏览器渲染
            setTimeout(processBatch, 0);
        }
    }
    processBatch();
}

8.3 Promise 的微任务调度

Promise 是 JavaScript 中最常用的异步抽象。理解 Promise 如何在事件循环中被调度，对编写正确的异步代码至关重要。

8.3.1 Promise.then 的调度机制

// Promise.then 总是以微任务方式调度
Promise.resolve().then(() => {
    console.log('A');
});
// 等价于:
queueMicrotask(() => {
    console.log('A');
});

// 链式调用: 每个 .then() 返回一个新的 Promise
// 每个 .then 的回调都是独立的微任务
Promise.resolve()
    .then(() => console.log('1'))  // 微任务 #1
    .then(() => console.log('2'))  // 微任务 #2 (在 #1 之后)
    .then(() => console.log('3')); // 微任务 #3 (在 #2 之后)
// 输出: 1, 2, 3

// 在 .then 回调中返回 Promise 会等待它 resolved
Promise.resolve()
    .then(async () => {
        await delay(100);  // async 函数隐式返回 Promise
        console.log('100ms 后');
    })
    .then(() => {
        console.log('上面完成后立即执行');
    });

8.3.2 async/await 的本质

async/await 只是 Promise 的语法糖——await 本质上就是 .then() 的另一种写法：

// async/await 写法
async function example() {
    console.log('A');
    await Promise.resolve();  // 等价于 .then()
    console.log('B');
}

// 完全等价的 Promise 写法
function example() {
    console.log('A');
    Promise.resolve().then(() => {
        console.log('B');
    });
}

// 关键洞察: await 后面的代码总是在当前宏任务
// 的所有同步代码执行完毕后，作为微任务执行
async function demo() {
    console.log('1');
    await delay(1000);  // 暂停 1 秒
    console.log('2');
}
console.log('3');
demo();
console.log('4');
// 输出: 3, 4, (等待 1 秒), 2
// 注意: "2" 在 1 秒后作为微任务执行，不是宏任务

8.4 requestAnimationFrame vs setInterval

动画是 Web 开发中的常见需求。选择正确的定时机制对流畅度至关重要。

特性requestAnimationFramesetIntervalsetTimeout
执行时机浏览器渲染前固定间隔最小延迟后
与刷新率同步是 (通常 60fps)否否
后台标签页暂停执行继续 (节流至 1s)继续 (节流至 1s)
与渲染管线协同在 Layout + Paint 之后不协同不协同
回调合并同一帧内的多次 rAF 合并不合并不合并
适用场景动画、滚动效果定期轮询延迟执行
 
// ✅ 正确用法：rAF 动画
function animate(timestamp) {
    // timestamp 是浏览器传入的精确时间戳
    // 格式: performance.now()
    const elapsed = timestamp - startTime;

    // 更新状态
    const progress = (elapsed % 2000) / 2000;  // 2 秒循环
    elem.style.transform = `translateX(${progress * 100}px)`;

    // 请求下一帧
    requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

// ❌ 错误用法：setInterval 做动画
setInterval(() => {
    const elapsed = Date.now() - startTime;
    const progress = (elapsed % 2000) / 2000;
    elem.style.transform = `translateX(${progress * 100}px)`;
}, 16);  // 16ms ≈ 60fps，但与浏览器刷新率不同步！
// 问题：
// 1. 可能与屏幕刷新率不同步 → 撕裂/卡顿
// 2. 后台标签页仍执行 → 浪费 CPU
// 3. 多次回调可能在同一帧内执行 → 多余计算

// 📊 性能数据：
// rAF 动画在 60fps 显示器上：每帧 ~0.1-0.3ms
// setInterval 动画：每帧 ~0.1-0.5ms（但不同步导致视觉抖动）
// 两者 CPU 开销相近，但 rAF 视觉流畅度高 3-5 倍

8.5 Web Worker：多线程编程

JavaScript 单线程模型的限制意味着长时间运行的计算会阻塞 UI。Web Worker 提供了在后台线程执行 JavaScript 的能力，而不阻塞主线程。

8.5.1 Worker 类型对比

类型生命周期通信方式适用场景
Classic Worker与创建它的页面绑定postMessage数据计算、图像处理
SharedWorker跨多个同源页面共享port.postMessage跨标签页通信、共享缓存
ServiceWorker独立于页面，代理网络请求postMessage离线缓存、推送通知、网络拦截
Dedicated Worker与单个 JS 上下文绑定postMessageWebGL 渲染、音频处理
 
// === Classic Worker 示例 ===

// worker.js (后台线程)
self.onmessage = function(e) {
    const { type, data } = e.data;
    if (type === 'compute') {
        // 耗时计算在后台线程执行
        const result = heavyComputation(data);
        self.postMessage({ type: 'result', data: result });
    }
};

// main.js (主线程)
const worker = new Worker('worker.js');
worker.onmessage = function(e) {
    if (e.data.type === 'result') {
        updateUI(e.data.data);  // 更新 UI
    }
};
worker.postMessage({ type: 'compute', data: largeDataset });

// === SharedWorker 示例 ===
// 多个标签页共享同一个 Worker 实例
// shared-worker.js
let port;
self.onconnect = function(e) {
    port = e.ports[0];
    port.onmessage = function(e) {
        // 处理来自任意标签页的消息
        broadcastToAll(e.data);
    };
};

// === ServiceWorker 示例 ===
// service-worker.js
self.addEventListener('fetch', function(event) {
    event.respondWith(
        caches.match(event.request)
            .then(function(response) {
                return response || fetch(event.request);
            })
    );
});

8.5.2 Worker 的性能收益

// 主线程执行大数据处理
function processDataSync(data) {
    const start = performance.now();
    let result = 0;
    for (let i = 0; i < data.length; i++) {
        result += Math.sqrt(data[i]);  // 耗时计算
    }
    console.log(`主线程耗时: ${performance.now() - start}ms`);
    // 结果: ~2000ms (2 秒)，期间 UI 完全冻结
}

// Worker 线程执行相同计算
function processDataAsync(data) {
    return new Promise(resolve => {
        const worker = new Worker('compute.js');
        worker.onmessage = (e) => {
            console.log(`Worker 耗时: ${e.data}ms`);
            // 结果: ~2000ms (计算时间相同)
            // 但主线程 UI 保持响应！
            resolve(e.data);
        };
        worker.postMessage(data);
    });
}
📊 性能数据：Worker 不加速计算本身（计算量相同），但它将计算从主线程卸载，使 UI 保持响应。实测中，在大数据处理场景下，使用 Worker 可以将用户体验评分从 "差"提升到"良好"——因为 LCP 和 INP 指标不再被计算阻塞。

8.6 事件循环时序图

让我们用一个完整的时序图来理解事件循环的完整工作流程：

// 完整的事件循环时序
console.log('A');  // 同步

setTimeout(() => console.log('B'), 0);  // 宏任务 #1
Promise.resolve().then(() => console.log('C'));  // 微任务

console.log('D');  // 同步

// 第一轮 Event Loop:
// ┌──────────────────────────────────────┐
// │ Call Stack: [A] → 打印 "A"           │
// │          [D] → 打印 "D"              │
// │ (栈空)                               │
// │                                      │
// │ Microtask Queue: [C] → 打印 "C"      │
// │ (微任务队列空)                        │
// │                                      │
// │ Render Frame                         │
// │                                      │
// │ Macrotask Queue: [B] → 打印 "B"      │
// └──────────────────────────────────────┘

// 输出: A, D, C, B
//
// 关键点:
// 1. 同步代码优先执行
// 2. 微任务在宏任务之前全部清空
// 3. 微任务中产生的新微任务也会在同一轮执行
// 4. 只有在微任务队列完全清空后，才执行下一个宏任务
// 5. 每个宏任务执行后，都会先清空微任务队列

8.6.1 微任务嵌套的陷阱

// 微任务中可以产生新的微任务 → 持续执行
let count = 0;
function microLoop() {
    count++;
    console.log('微任务 #' + count);
    if (count < 5) {
        Promise.resolve().then(microLoop);  // 继续产生微任务
    }
}
Promise.resolve().then(microLoop);

// 输出: 微任务 #1, #2, #3, #4, #5
// 注意: setTimeout 在微任务循环期间永远不会执行!
setTimeout(() => console.log('永远不会先执行'), 0);
// 因为微任务一直在产生新的微任务，宏任务队列被永久推迟
🚨 无限微任务循环：如果在微任务中不断产生新的微任务（没有终止条件），宏任务将被永久推迟。这不仅会导致 UI 无法响应，还可能被浏览器检测为无响应页面而终止脚本。确保微任务链有明确的终止条件。

8.7 实战：正确使用异步机制

8.7.1 防抖与节流的事件循环实现

// 防抖 (Debounce)：使用微任务
function debounce(fn, delay = 300) {
    let timer = null;
    return function(...args) {
        if (timer) clearTimeout(timer);
        timer = setTimeout(() => {
            fn.apply(this, args);
            timer = null;
        }, delay);
    };
}

// 节流 (Throttle)：使用 rAF
function throttle(fn, interval = 16) {
    let lastTime = 0;
    return function(...args) {
        const now = Date.now();
        if (now - lastTime >= interval) {
            fn.apply(this, args);
            lastTime = now;
        }
    };
}

// 使用 rAF 实现真正的节流（与屏幕刷新率同步）
function rafThrottle(fn) {
    let ticking = false;
    return function(...args) {
        if (!ticking) {
            requestAnimationFrame(() => {
                fn.apply(this, args);
                ticking = false;
            });
            ticking = true;
        }
    };
}

8.7.2 异步迭代器

// 异步迭代器：结合 Event Loop 和 Generator
async function* fetchPages(baseURL) {
    let url = baseURL;
    while (url) {
        const response = await fetch(url);  // 微任务调度
        const data = await response.json();
        url = data.nextPage;
        yield data.items;
    }
}

// 使用：每次迭代等待网络请求完成
(async () => {
    for await (const items of fetchPages('https://api.example.com')) {
        renderItems(items);  // 渲染一批数据后让出控制权
        await new Promise(r => setTimeout(r, 100));  // 短暂暂停
    }
})();

8.8 本章小结

本章全面解析了 JavaScript 的事件循环模型：

  • 事件循环：无限循环，协调调用栈、微任务队列和宏任务队列的执行。
  • 微任务优先：每轮宏任务执行前清空微任务队列，包括 Promise.then、queueMicrotask、MutationObserver。
  • 宏任务间隔：每次只执行一个宏任务，然后检查微任务，形成 "宏任务 → 微任务 → 渲染 → 宏任务" 的循环。
  • rAF vs setInterval：动画应使用 requestAnimationFrame，它与屏幕刷新率同步且不阻塞后台标签页。
  • Web Worker：将计算密集型任务卸载到后台线程，保持 UI 响应。
