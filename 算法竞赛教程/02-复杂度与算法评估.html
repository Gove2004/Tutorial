第 2 章 复杂度与算法评估

拿到一道题，职业选手的第一个动作不是写代码，而是看数据范围。范围决定算法，算法决定能不能过。 这一章讲的就是这个判断链条：资源有多少、算法算不算“算法”、复杂度怎么估、以及为什么同一个问题有两种写法会差一百倍。

学完本章，你应该能做到

  • 看到 n ≤ 105 就排除 O(n2)，看到 n ≤ 20 就想到状压或指数搜索；
  • 用“1 秒约 108 次基本运算”把复杂度换算成可行性；
  • 解释为什么 O(n/2) 要写成 O(n)，常数因子在什么情况下必须考虑；
  • 区分“理论上更优”和“比赛里更划算”，知道什么时候可以用低效但好写的算法。

2.1 计算的资源：时间与空间

程序运行需要两种资源：计算时间和存储空间。资源是有限的，一个算法对这两种资源的使用程度，就是衡量它优劣的标准。 对应地，OJ 的题面通常会给出两个限制： 

Time Limit     : 2000 / 1000 ms (Java / Others)
Memory Limit   : 65536 / 65536 KB (Java / Others)

这两行是硬约束。程序必须在限定时间内结束，必须在限定内存内运行——超出任何一项，答案再对也拿不到分。 现场赛有时会故意不写这两个参数，需要选手自己判断，这时数据范围就成了唯一的线索。

1 秒有多快？一个经验值：C++ 在 1 秒内大约能完成 108 次简单运算（加法、比较、数组访问）。 所以 n = 105 时，O(n2) 是 1010 次，必然超时；n = 106 时，O(n log n) 约 2×107 次，安全。 这个数字会随常数、编译器、机器变化，但作为数量级判断足够用。

2.1.1 由数据范围倒推算法：一张对照表

n 的量级可以接受的复杂度典型算法

这张表是“反推”的工具，不是死记硬背的规矩。它的用法是：先看题目给的最大范围，估出允许的复杂度， 再看哪个算法落在这个区间里。如果你想到的算法比这个区间高一档，说明思路大概率错了，或者需要优化。

2.2 算法的定义：五个特征

“程序 = 算法 + 数据结构”。算法是解决问题的逻辑、方法和过程，数据结构是数据在计算机中的存储和访问方式， 两者紧密结合。严格地说，一个算法是指令的有限序列，必须满足五条：

1
输入：有零个或多个输入。程序可以没有输入（比如一个闹钟程序），但它的行为必须确定。
2
输出：有一个或多个输出。没有输出的算法没有意义。
3
有穷性：必须在执行有穷步之后结束，且每一步都在有穷时间内完成。死循环不是算法。
4
确定性：每条指令必须有确切的含义，相同输入只能得到相同输出。用了随机数的算法必须保证结果仍然确定（比如固定种子或多次取样）。
5
可行性：每一步操作都能通过已实现的基本操作执行有限次来完成。
第 5 条最容易被忽略。原书举了一个很妙的例子：珠排序（Bead Sort）用重力在 O(1) 或 O(√n) 时间里完成排序， 效率高得惊人，但它依赖物理过程，无法编程实现。在竞赛里，不能写成代码的算法等于不存在。

用冒泡排序对照这五条：输入是 n 个数的序列；输出是升序排列；有穷性体现为最多执行 O(n2) 次比较交换； 每一步是“比较相邻两个数，若逆序则交换”，确定且可实现。五条全部满足。

2.3 复杂度：怎么估，估到什么程度

竞赛里谈“复杂度”，默认指时间复杂度。原因是空间复杂度通常容易分析（数组开多大一目了然）， 而时间复杂度直接关联算法的根本逻辑，更能说明程序优劣。

复杂度的三条使用规则：
① 它是估计，不需要精确计算。在 n 个数里找某个数，可能第一个就找到（O(1)），也可能最后一个才找到（O(n)）， 但一律记为 O(n)，不写 O(n/2)。
② 常数系数被忽略。冒泡排序约 n2/2 次比较，仍记作 O(n2)。
③ OJ 判的是整程序运行时间，不是理论时间。同一个算法，不同人写出来可能差好几倍——这和第 1 章讲的 I/O、容器选择有关。

2.3.2 一个案例：同一个问题，三种复杂度

原书用一道题把所有东西串起来了：给出 n 个各不相同的整数，按从大到小的顺序输出其中前 m 大的数。 输入 0 < n, m < 1000000，数值范围 [-500000, 500000]，时限 1 秒，内存 32MB。

先看最直白的做法：

// 解法一：冒泡排序，O(n^2)
#include <bits/stdc++.h>
using namespace std;
int a[1000001];
int n, m;

void bubble_sort() {
    for (int i = 1; i <= n - 1; i++)
        for (int j = 1; j <= n - i; j++)
            if (a[j] > a[j + 1]) swap(a[j], a[j + 1]);
}

int main() {
    while (~scanf("%d%d", &n, &m)) {
        for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
        bubble_sort();
        for (int i = n; i >= n - m + 1; i--) {   // 从后往前打印前 m 大
            if (i == n - m + 1) printf("%d\n", a[i]);
            else printf("%d ", a[i]);
        }
    }
    return 0;
}

n 最大 106，冒泡是 1012 级，实际跑起来要几十分钟。这个解法在 OJ 上必然是 TLE， 但它的价值是帮你确认题意——用小数据跑通，再去想更快的写法。 

// 解法二：sort，O(n log n)
#include <bits/stdc++.h>
using namespace std;
int a[1000001];

int main() {
    int n, m;
    while (~scanf("%d%d", &n, &m)) {
        for (int i = 0; i < n; i++) scanf("%d", &a[i]);
        sort(a, a + n);
        for (int i = n - 1; i >= n - m; i--) {
            printf("%d", a[i]);
            printf(i == n - m ? "\n" : " ");
        }
    }
    return 0;
}

sort 是内省排序（快排 + 堆排 + 插入排序的组合），n = 106 时约 2×107 次比较， 1 秒内能过。这是绝大多数人的第一选择。 

// 解法三：哈希计数，O(n)
// 数值范围只有 [-500000, 500000]，把数直接映射到下标
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 1000001;
int a[MAXN];

int main() {
    int n, m, t;
    while (~scanf("%d%d", &n, &m)) {
        memset(a, 0, sizeof(a));
        for (int i = 0; i < n; i++) {
            scanf("%d", &t);
            a[500000 + t] = 1;        // 标记存在，不做显式排序
        }
        for (int i = MAXN - 1; m > 0; i--) {
            if (a[i]) {
                if (m > 1) printf("%d ", i - 500000);
                else       printf("%d\n", i - 500000);
                m--;
            }
        }
    }
    return 0;
}

这个解法完全没有排序：插入是 O(1)，输出是 O(值域)。总复杂度 O(n + 值域)，在 HDU 上实测约 500ms。 它成立的前提是值域有限且可映射——这正是“哈希思想”的本质：用空间换时间，把比较换成定位。

但它有两个前提，缺一不可： ① 值域必须是常数级（这里 106）；② 元素必须能作为下标（这里是整数）。 如果数值是 1018 或者浮点数，这个解法直接作废，必须回到排序或离散化。
解法复杂度1 秒内能否过 n = 106适用条件
冒泡排序O(n2)不能，差 4 个数量级只适合 n ≤ 5000
sortO(n log n)能，约 0.5–1s通用
哈希计数O(n + V)能，约 0.5s值域小、可作下标

2.3.3 算法选择：不只看复杂度

原书在这里给了一个诚实的判断：并不是只有高效算法才“合理”。竞赛比的是在限定条件内完成更多题。 如果一道题时限 1 秒，低效算法刚好 1 秒能过、代码 20 行 10 分钟写完，而高效算法要 40 分钟， 那在赛场上就应该写低效的那个。

但这个判断成立的条件很窄：数据规模小、属于签到题、且你有把握低效算法真的能过。 对绝大多数题目，“能不能过”只有高效算法一个答案。

一个训练建议：每道题 AC 之后，在代码顶部用一行注释写下“本题复杂度 + 数据范围 + 为什么这个复杂度能过”。 三十道题之后，你会发现自己看数据范围的速度和直觉都会明显变快。

自测清单

问题参考答案要点
1 秒大约对应多少次基本运算？C++ 约 108 次，用于数量级判断
n ≤ 20 时通常对应什么复杂度？O(2n)，子集枚举或状压 DP
为什么 O(n/2) 写作 O(n)？大 O 忽略常数系数，只看增长阶
珠排序为什么不能算竞赛意义上的算法？不满足“可行性”：无法用基本操作编程实现
哈希解法在什么情况下会失效？值域过大、元素不能作为数组下标（如浮点、大整数、字符串）

练习题

  1. 把本章“输出前 m 大的数”三种解法各写一遍，用 time 命令测出 n = 105、106 时的真实耗时，记录在你的模板里。
  2. 给定 n ≤ 1000 和 n ≤ 105 两组限制，分别说出你会选 O(n2) 还是 O(n log n)，并解释理由。
  3. 构造一组数据，让 sort 在 n = 106 时明显变慢（提示：大量重复元素），并说明为什么。
  4. 找一个值域是 109 的计数类问题，说明为什么不能直接开数组，替代方案是什么（提示：离散化或 map）。
