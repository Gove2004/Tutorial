第九章：实时渲染

实时渲染的核心矛盾是：如何在 16.67ms（60fps）内计算出看起来像离线渲染质量的画面。离线渲染可以花几小时计算一帧光线追踪，而实时渲染必须在毫秒级完成。本章探讨现代实时渲染管线中的关键技术——从屏幕空间反射到虚拟几何体，从延迟着色到软件光线追踪。

核心思想：实时渲染的本质是"聪明的近似"。每一个实时渲染技术都是在精度、性能和视觉质量之间做出权衡。理解这些权衡，才能选择正确的技术方案。

一、Screen Space Reflections（SSR）

SSR 是一种基于屏幕空间的反射技术，它利用已有的 G-Buffer（深度、法线、颜色）在屏幕空间中追踪反射光线，产生逼真的环境反射效果。与传统的 Cube Map 反射相比，SSR 的优势在于无需预烘焙任何数据，所有反射都是实时计算的。

1.1 SSR 算法流程

SSR 渲染管线

G-Buffer: Depth + Normal + Albedo + Roughness
↓
For each pixel: reflect view direction using normal
↓
Ray march in screen space (step size ∝ roughness)
↓
At each step: transform to NDC, sample depth buffer
↓
If ray depth < stored depth → intersection found!
↓
Bilinear sample color buffer at hit position
↓
Blend reflection color with base color (Fresnel + roughness)

1.2 SSR 实现

#version 460
// Fragment shader: Screen Space Reflections

layout(binding = 0) uniform sampler2D depthTex;
layout(binding = 1) uniform sampler2D normalTex;
layout(binding = 2) uniform sampler2D colorTex;
layout(binding = 3) uniform sampler2D roughnessTex;

uniform mat4 projMatrix;
uniform mat4 invProjMatrix;
uniform vec2 screenSize;

const int MAX_STEPS = 64;
const float STEP_SCALE = 1.5;
const float EPSILON = 0.001;

vec3 traceReflection(vec2 uv, vec3 worldPos, vec3 worldNormal, float roughness) {
    // 1. 计算反射方向
    vec3 viewDir = normalize(cameraPosition - worldPos);
    vec3 reflectDir = reflect(-viewDir, worldNormal);

    // 2. 将反射方向投影到屏幕空间
    vec4 clipPos = projMatrix * vec4(worldPos, 1.0);
    vec3 ndcDir = reflectDir;

    float distance = 0.0;
    float stepSize = roughness * 0.05 + 0.001;
    vec2 currentUv = uv;

    // 3. Ray marching in screen space
    for (int i = 0; i < MAX_STEPS; i++) {
        distance += stepSize;
        stepSize *= STEP_SCALE;

        // 投影到 NDC 空间
        vec4 projected = projMatrix * vec4(worldPos + reflectDir * distance, 1.0);
        vec2 currentNdc = projected.xy / projected.w;
        currentUv = currentNdc * 0.5 + 0.5;

        // 超出屏幕范围则停止
        if (currentUv.x < 0.0 || currentUv.x > 1.0 ||
            currentUv.y < 0.0 || currentUv.y > 1.0) {
            break;
        }

        // 4. 比较射线深度与表面深度
        float rayDepth = (projected.z / projected.w) * 0.5 + 0.5;
        float surfaceDepth = texture(depthTex, currentUv).r;

        if (rayDepth < surfaceDepth - EPSILON) {
            // 找到交点！
            vec3 hitWorldPos = worldPos + reflectDir * distance;
            vec2 hitUv = currentUv;

            // 5. 双线性采样反射颜色
            return texture(colorTex, hitUv).rgb;
        }

        // 6. 容差检查：射线足够接近表面
        if (abs(rayDepth - surfaceDepth) < stepSize * 0.1) {
            return texture(colorTex, currentUv).rgb;
        }
    }

    // 未找到反射 → 返回环境色或 skybox
    return vec3(0.15);
}

1.3 SSR 的局限性

  • 屏幕空间限制：只能反射屏幕上已有的像素，无法反射屏幕外的物体
  • 深度缓冲区精度：远距离物体的深度精度不足导致反射抖动
  • 无反射表面：没有几何体的区域（如虚空）无法产生反射
  • 性能开销：每像素最多 64 次 ray march，对移动端不友好
混合策略：工业实践中通常将 SSR 与 Cube Map 反射混合：SSR 处理近距离精确反射，Cube Map 处理屏幕外反射。混合权重由 Fresnel 项和 roughness 共同决定。

二、Voxel-based GI（VXGI）

2.1 传统 GI 方法的困境

实时全局光照的传统方案有两种：光照贴图（Lightmaps）和实时光栅化 GI。光照贴图质量高但无法响应动态物体；实时光栅化 GI（如 Screen Space GI）质量有限且依赖屏幕空间信息。VXGI 提供了第三种选择：将场景体素化，在体素空间中计算间接光照。

2.2 VXGI 架构

VXGI 渲染管线

Step 1: Voxelize (Geometry → Voxel Tracts)
GPU 加速体素化（GS/Compute Shader）
↓
Step 2: Voxel Cone Tracing
从每个像素发射锥形射线扫描体素
↓
Step 3: Irradiance Accumulation
累积锥体内的光照能量
↓
Step 4: Indirect Lighting Pass
混合直接光照 + 间接光照

体素锥追踪（Voxel Cone Tracing, VCT）是 VXGI 的核心算法。每个像素从表面点沿法线方向发射一个圆锥体，圆锥的宽度随距离增大。在体素纹理中沿圆锥扫描，累积遇到的光照信息。

#version 460
// Voxel Cone Tracing fragment shader

layout(binding = 0) uniform texture3D voxelColor;
layout(binding = 1) uniform texture3D voxelShadows;

const int MAX_CONE_STEPS = 16;
const float CONE_EXPANSION = 1.5;

vec3 traceCone(vec3 voxelPos, vec3 coneDir, float coneWidth) {
    vec3 indirectLight = vec3(0.0);
    float accumulatedShadow = 0.0;

    for (int i = 0; i < MAX_CONE_STEPS; i++) {
        // 在当前锥体位置采样
        vec4 color = texture(voxelColor, voxelPos);

        // 如果体素为空，扩大锥体继续搜索
        if (color.a < 0.01) {
            coneWidth *= CONE_EXPANSION;
            voxelPos += coneDir * coneWidth;
            continue;
        }

        // 体素有内容：累积光照
        indirectLight += color.rgb * color.a;
        accumulatedShadow += color.a;

        // 扩大锥体，沿方向前进
        coneWidth *= CONE_EXPANSION;
        voxelPos += coneDir * coneWidth;

        // 超出体素范围则停止
        if (any(greaterThan(voxelPos, vec3(1.0))) ||
            any(lessThan(voxelPos, vec3(0.0)))) {
            break;
        }
    }

    return indirectLight;
}

三、Deferred Shading vs Forward+

3.1 传统 Deferred Shading

延迟着色（Deferred Shading）将几何_pass 和光照 pass 分离：第一遍将所有几何体的属性写入 G-Buffer（位置、法线、颜色、粗糙度等），第二遍对每个光源独立计算光照并累加到屏幕空间。

3.2 Forward+ 渲染

Forward+ 是 AMD 提出的创新渲染架构，结合了前向渲染和延迟渲染的优点。它将屏幕划分为 tiles（通常 16×16 像素），对每个 tile 计算受影响的灯光列表，然后在 tile 内对每个像素只处理相关灯光。

#version 460
// Forward+ lighting shader

uniform ivec3 tileLightLists[GRID_DIM_X][GRID_DIM_Y]; // 每 tile 最多 128 盏灯
uniform Light lights[MAX_LIGHTS];
uniform vec2 screenSize;
uniform ivec2 gridDim;

void main() {
    vec2 uv = gl_FragCoord.xy / screenSize;
    ivec2 tileId = ivec2(gl_FragCoord.xy) / ivec2(16);

    // 获取当前 tile 的灯光列表
    ivec3* lightList = tileLightLists[tileId.y][tileId.x];
    vec3 color = vec3(0.0);

    // 只处理影响当前 tile 的灯光
    for (int i = 0; lightList[i].x != -1; i++) {
        uint lightIdx = uint(lightList[i].x);
        Light light = lights[lightIdx];

        // 逐像素计算光照
        vec3 toLight = light.position - fragWorldPos;
        float dist = length(toLight);
        float attenuation = light.intensity / (dist * dist + 0.1);

        // 简单点光源衰减
        color += attenuation * light.color *
                 max(0.0, dot(normal, normalize(-toLight)));
    }

    // 环境光 + 直接光
    color += ambient;
    FragColor = vec4(color, 1.0);
}

Forward+ 的关键优势：每像素处理的灯光数量是恒定的（等于 tile 大小 16×16 = 256 像素共享同一份灯光列表），无论场景中有多少盏灯。这使得性能与灯光数量完全解耦。

四、Nanite——虚拟几何体系统

Nanite 是 Epic Games 为 Unreal Engine 5 开发的虚拟几何体系统，它彻底改变了 3D 资产的加载和管理方式。核心创新是：将高精度网格（数亿面）切割成微集群（micro-clusters），在渲染时根据屏幕空间误差动态选择 LOD。

4.1 Nanite 架构

Nanite 虚拟化管线

原始网格 (100M 面) → 离线处理
↓
构建 LOD 金字塔 (8 级 LOD)
↓
每个 LOD 切分为 ~200 三角面的微集群
↓
微集群打包到 Virtual Textured Mesh (VTM)
↓
运行时：按屏幕空间误差裁剪集群
↓
仅渲染可见集群 → 恒定 ~5M 三角面

4.2 Cluster-based LOD 选择

Nanite 不使用传统的基于距离的 LOD，而是基于屏幕空间误差（Screen-Space Error）。每个微集群预计算其在不同 LOD 级别下的几何误差，渲染时根据集群在屏幕上的像素覆盖率动态选择最精细且误差可接受的 LOD。

// 屏幕空间误差计算
float screenSpaceError(Cluster cluster, Camera camera) {
    // 1. 集群包围球在屏幕上的像素直径
    vec4 clipPos = camera.projMatrix * camera.viewMatrix * cluster.center;
    float screenRadius = cluster.radius * camera.viewportWidth / (2.0 * clipPos.w);

    // 2. 几何误差（预烘焙）
    float geometricError = cluster.maxLODerror;

    // 3. 归一化屏幕空间误差
    float sse = geometricError * camera.viewportWidth / screenRadius;

    // 4. 选择满足 SSE < threshold 的最精细 LOD
    for (int lod = cluster.lodCount - 1; lod >= 0; lod--) {
        if (cluster.lodErrors[lod] < screenErrorThreshold) {
            return lod;
        }
    }
    return 0;
}
关键数字：一个典型的 Nanite 场景可以有数十亿面的源资产，但渲染时只处理约 500 万-1000 万个三角面。这意味着无论场景多么复杂，GPU 的几何处理负载几乎恒定。

五、Lumen——软件路径追踪全局光照

Lumen 是 UE5 的全局光照和反射系统，它使用软件路径追踪（Software Ray Tracing）而非光线追踪硬件来实现实时 GI。核心思路是：利用已经存在的 G-Buffer 和 Scene Texture（包含世界空间位置），在屏幕空间和层次化网格索引（HMI, Hierarchical Mesh Indices）上进行光线追踪。

5.1 Lumen 架构

Lumen 软件路径追踪管线

G-Buffer + Scene Texture (World Space Pos)
↓
Level Strategy: Screen-space traces first
快速路径：屏幕空间光线追踪
↓
If screen-space miss → Hierarchical Ray Tracing
HMI 加速结构：预构建的网格层次树
↓
Cascade: 多级 HMI 从粗到细追踪
粗 HMI 快速找到大致碰撞，细 HMI 精确定位
↓
Indirect Lighting = Direct + Bounced Light
混合直接光照和反弹光照

5.2 HMI（Hierarchical Mesh Indices）

HMI 是 Lumen 的核心加速结构。它将场景网格组织成多级层次结构，每一级都是前一级的简化版本。光线追踪时从最粗糙的级别开始，快速排除大量无关区域，逐步细化到精确碰撞检测。

struct HmiLevel {
    std::vector<AABB> bounds;      // 包围盒
    std::vector<int>  childRefs;    // 子节点引用
    std::vector<int>  triangleRefs; // 叶子节点的三角形引用
    int parentLevel;               // 父级别索引（-1 表示根）
};

class HierarchicalMeshIndices {
    std::vector<HmiLevel> levels;

public:
    // 从粗到细的光线追踪
    HitRecord rayTrace(Ray ray, int startLevel = MAX_LEVELS - 1) {
        HitRecord closest;
        closest.t = INFINITY;

        for (int level = startLevel; level >= 0; level--) {
            const HmiLevel& hmi = levels[level];

            for (int i = 0; i < hmi.bounds.size(); i++) {
                if (!intersectAABB(ray, hmi.bounds[i])) continue;

                if (hmi.triangleRefs[i] >= 0) {
                    // 叶子节点：精确三角形相交
                    HitRecord hit = intersectTriangles(ray, hmi.triangleRefs);
                    if (hit.t < closest.t) closest = hit;
                } else {
                    // 内部节点：继续向下追踪
                    // （实际实现中使用栈避免递归）
                }
            }
        }
        return closest;
    }
};

七、本章小结

本章涵盖了现代实时渲染的核心技术：

  • SSR 利用屏幕空间信息产生精确的环境反射，但受限于屏幕边界和深度精度
  • VXGI/VCT 通过体素化和锥追踪实现动态全局光照，弥补光照贴图的不足
  • Forward+ 用 tile-based 策略实现灯光数量的完全解耦，是移动端和主机端的理想选择
  • Nanite 将虚拟几何体和 cluster-based LOD 结合，实现十亿面资产的实时渲染
  • Lumen 用软件路径追踪和 HMI 加速结构，在不依赖 RT Core 的情况下提供高质量的动态 GI

实时渲染的未来趋势是：混合方法——将多种技术的优点结合起来。例如 UE5 同时使用 Nanite（几何）、Lumen（光照）和 MetaHuman（角色），每种技术解决一个特定问题，组合起来才是完整的解决方案。
