04 - Alan Wake 2 — GPU 虚拟化与 Northlight Engine

Remedy Entertainment 的 Alan Wake 2 代表了独立游戏工作室在渲染技术上的巅峰之一。Northlight Engine 3.0 引入了 GPU Driven Rendering Pipeline 和 Virtual Shadow Maps，在中等硬件上实现了电影级画质。本章深入解析这些技术的实现细节。

前置知识：DX12/Vulkan 基础、Shadow Map 原理、Compute Shader、PBR 渲染

一、Northlight Engine 核心架构

Northlight Engine 是 Remedy 自研的跨平台游戏引擎，从《Control》（2019）开始使用，到《Alan Wake 2》（2023）已经发展到 3.0 版本。Engine 3.0 的核心设计理念是"GPU 驱动一切"——将尽可能多的渲染决策从 CPU 转移到 GPU。

┌─────────────────────────────────────────────────────────────┐ │ Northlight Engine 3.0 架构 │ │ │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ GPU Driven Rendering Pipeline │ │ │ │ │ │ │ │ CPU: 场景图遍历 → 可见性判断 → 命令生成 │ │ │ │ ↓ │ │ │ │ GPU Compute: 剔除 → 排序 → 批处理 → 命令编码 │ │ │ │ ↓ │ │ │ │ GPU: 顶点着色 → 光栅化 → 像素着色 → 后处理 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────┐ │ │ │ Virtual │ │ Lumen │ │ Chaos │ │ Northlight │ │ │ │ Shadow │ │ GI │ │ Physics │ │ Post-Proc │ │ │ │ Maps │ │ │ │ │ │ │ │ │ └──────────┘ └──────────┘ └──────────┘ └──────────────┘ │ └─────────────────────────────────────────────────────────────┘

从 CPU 驱动到 GPU 驱动的转变

传统渲染管线中，CPU 负责决定"画什么"和"怎么画"——遍历场景图、判断可见性、排序物体、生成 Draw Call。这种方式在物体数量多时成为瓶颈。

GPU Driven Rendering 的核心思想是：让 GPU 来计算哪些物体可见、如何排序、如何批处理。具体流程：

  1. Scene Build（CPU）：构建场景图，生成 Object Table（物体列表，包含世界矩阵、包围盒、材质 ID）
  2. Visibility Culling（GPU Compute）：将 Object Table 传入 GPU，使用 Frustum Culling + Occlusion Culling 判断可见性
  3. Tiling & Batching（GPU Compute）：将可见物体按材质/纹理分组，生成 Tile 和 Batch 信息
  4. Command Encoding（GPU Compute）：根据 Batch 信息直接生成 DX12/Vulkan 的 Command List
  5. Render（GPU）：执行 Command List 完成渲染

二、GPU Driven Rendering Pipeline 详解

这是 Northlight Engine 3.0 最重要的架构变革。让我们逐层拆解。

Object Table 结构

// ObjectTable.h - GPU 驱动渲染的物体描述符
struct ObjectDescriptor
{
    uint32  InstanceID;       // 物体实例 ID
    uint32  MaterialID;       // 材质索引
    uint32  TextureSetID;     // 纹理集索引
    uint32  LODIndex;         // LOD 级别
    uint32  Padding0;

    float4  WorldTransform[4]; // 世界矩阵（4x4）
    float4  BoundingBoxMin;    // 包围盒最小值
    float4  BoundingBoxMax;    // 包围盒最大值
    float4  CameraSpaceCenter; // 相机空间中心（用于排序）
    float   DistanceSq;        // 到相机的距离平方
    uint32  SortKey;           // 排序键（按距离 + 材质分组）
};

// CPU 端构建 Object Table
void BuildObjectTable(const Scene& scene)
{
    ObjectTable.Reset();
    for (auto& actor : scene.Actors)
    {
        if (!actor.IsVisible()) continue;

        ObjectDescriptor desc;
        desc.InstanceID  = actor.ID;
        desc.MaterialID  = actor.Material.Index;
        desc.TextureSetID = actor.TextureSet.Index;
        desc.LODIndex    = actor.GetLODIndex();
        desc.WorldTransform = actor.WorldMatrix;
        desc.BoundingBoxMin = actor.BoundingBox.Min;
        desc.BoundingBoxMax = actor.BoundingBox.Max;

        // 计算相机空间中的位置和距离
        desc.CameraSpaceCenter = TransformPoint(actor.WorldMatrix.GetTranslation(), ViewMatrix);
        desc.DistanceSq = desc.CameraSpaceCenter.LengthSquared();
        desc.SortKey = GenerateSortKey(desc.MaterialID, desc.DistanceSq);

        ObjectTable.Add(desc);
    }

    // 将 Object Table 上传到 GPU
    UploadToGPU(ObjectTable, GPUBuffer);
}

GPU 端可见性判定

// VisibilityCulling.compute - GPU 端遮挡剔除
RWStructuredBuffer<ObjectDescriptor> InputObjects;
RWStructuredBuffer<ObjectDescriptor> OutputObjects;
Buffer<uint>                         OutputCount;
cbuffer ViewConstants : register(b0)
{
    float4   FrustumPlanes[6];  // 视锥平面（法线, 距离）
    float3   CameraPosition;
    float    FarClipDistance;
};

[numthreads(256, 1, 1)]
void Main(uint3 tid : SV_DispatchThreadID)
{
    uint idx = tid.x;
    if (idx >= InputObjects.Length) return;

    ObjectDescriptor obj = InputObjects[idx];

    // 1. 视锥剔除
    if (!IsInsideFrustum(obj.BoundingBoxMin, obj.BoundingBoxMax))
    {
        OutputObjects[idx] = obj;
        OutputObjects[idx].SortKey = 0xFFFFFFFF; // 标记为不可见
        return;
    }

    // 2. 距离裁剪（超出 Far Clip 的物体不渲染）
    float dist = length(obj.CameraSpaceCenter.xyz);
    if (dist > FarClipDistance)
    {
        OutputObjects[idx].SortKey = 0xFFFFFFFF;
        return;
    }

    // 3. 复制有效物体
    uint outIdx = InterlockedAdd(OutputCount, 1);
    OutputObjects[outIdx] = obj;
}

bool IsInsideFrustum(float3 min, float3 max)
{
    // 检查包围盒的 8 个顶点是否都在视锥内
    for (int p = 0; p < 6; p++)
    {
        bool allOutside = true;
        for (int x = 0; x <= 1; x++)
        for (int y = 0; y <= 1; y++)
        for (int z = 0; z <= 1; z++)
        {
            float3 corner = float3(
                min.x + x * (max.x - min.x),
                min.y + y * (max.y - min.y),
                min.z + z * (max.z - min.z)
            );
            if (dot(FrustumPlanes[p].xyz, corner) + FrustumPlanes[p].w >= 0)
                allOutside = false;
        }
        if (allOutside) return false; // 整个包围盒在平面外
    }
    return true;
}

三、Virtual Shadow Maps（VSM）

VSM 是 Alan Wake 2 最具标志性的技术特征之一。它解决了传统阴影贴图（Shadow Map）的几个根本性限制。

传统阴影贴图的局限

问题原因影响
锯齿边缘离散采样 + 有限分辨率阴影边缘出现阶梯状锯齿
分辨率受限纹理大小固定（通常 2K-4K）远处阴影模糊或近处锯齿明显
视差问题阴影贴图与摄像机视角绑定远距离物体阴影精度低
存储限制每光源需要独立的 Shadow Map多光源场景难以处理

VSM 的工作原理

Virtual Shadow Map 核心概念

VSM 不预先生成完整的阴影贴图，而是在渲染时按需计算阴影。它将场景中的阴影信息存储在层级 Mipmap 纹理中，不同分辨率的 Mipmap 对应不同距离的阴影精度。渲染时根据像素到光源的距离，自动选择合适分辨率的 Mipmap 采样阴影。

VSM 的生成流程：

1

阴影体积烘焙

对场景中所有不透明物体，沿光源方向生成阴影体积（Shadow Volume）。将阴影体积的深度信息烘焙到层级 Mipmap 纹理中。第一层 Mipmap 分辨率最高（如 4096x4096），后续每层减半。

2

PCF 滤波

对阴影贴图进行 Percentage-Closer Filtering（PCF），消除锯齿。VSM 使用 4x4 或 8x8 PCF，在质量和性能之间取得平衡。

3

运行时采样

渲染时，根据每个像素到光源的距离选择 Mipmap Level，然后在该分辨率下采样阴影值。远距离使用低分辨率 Mipmap，近距离使用高分辨率 Mipmap。

// VirtualShadowMap.hlsl - VSM 运行时着色器
struct VSMInput
{
    float4 Position : POSITION;
    float2 UV : TEXCOORD0;
    float Depth : DEPTH;
};

Texture2D<float> VSMTexture;          // 层级阴影贴图
SamplerState VSSampler;                // 采样器

float4 MainVS(VSMInput input) : POSITION
{
    return input.Position;
}

float MainPS(VSMInput input) : SV_TARGET
{
    // 计算像素到光源的距离
    float3 LightDir = input.Position.xyz - LightPosition;
    float Dist = length(LightDir);

    // 根据距离选择 Mipmap Level
    // 近距离 = 高分辨率 (Level 0)，远距离 = 低分辨率 (Level N)
    float MipLevel = Log2(Dist / NearDistance);
    MipLevel = clamp(MipLevel, 0.0, MaxMipLevels - 1.0);

    // 采样阴影值
    float Shadow = VSMTexture.SampleGrad(VSSampler, input.UV,
        ddx(input.UV) * MipLevelScale,
        ddy(input.UV) * MipLevelScale);

    // PCF 滤波
    Shadow = PCFShadow(Shadow, input.UV, MipLevel);

    return Shadow;
}

Alan Wake 2 充分利用了 DX12 和 Vulkan 的异步计算能力，将图形管线和计算管线并行执行。

关键 Compute Shader 在渲染管线中的应用：

  • Visibility Culling：GPU 端可见性判定（见上文）
  • LOD Selection：根据屏幕空间误差自动选择最优 LOD
  • Terrain Tessellation：地形细分在 Compute Shader 中完成
  • Particle Simulation：Niagara 风格的粒子模拟
  • Post-Processing：Tonemapping、Bloom、DOF 等后处理

五、路径追踪预览

Remedy 在 GDC 讲座中展示了 Northlight Engine 的路径追踪原型。虽然 AW2 正式发售时未使用全路径追踪，但技术储备已经就绪。

路径追踪核心算法

// PathTracer.cpp - 简化版路径追踪实现
struct PathTraceResult
{
    float3 Radiance;      // 累积辐射度
    float  Throughput;    // 传输率（权重）
    int    Bounces;       // 反弹次数
    bool   bTerminated;   // 是否已终止
};

PathTraceResult TracePath(float2 ScreenUV, uint Seed)
{
    PathTraceResult Result = { float3(0,0,0), 1.0f, 0, false };

    // 初始化射线：从相机出发
    Ray CurrentRay = GenerateCameraRay(ScreenUV, Seed);

    for (int bounce = 0; bounce < MaxBounces; bounce++)
    {
        // 1. 射线-场景求交
        HitRecord Hit;
        if (!TraceRay(CurrentRay, Hit))
        {
            // 命中天空盒，添加天空颜色
            Result.Radiance += Result.Throughput * SampleSky(Hit.Normal);
            break;
        }

        // 2. 评估 BRDF
        float3 Albedo = Hit.Material.Albedo;
        float3 Specular = Hit.Material.Specular;

        // 3. 重要性采样下一方向
        float2 SampleUV = SampleHS(Seed++);
        Ray NextRay = ImportanceSampleBRDF(Hit, SampleUV);

        // 4. 计算 Russian Roulette 终止概率
        float TerminationProb = max(Result.Throughput.r,
                                     max(Result.Throughput.g,
                                         Result.Throughput.b));
        TerminationProb = min(TerminationProb, 0.95f);

        if (Rand(Seed) < TerminationProb)
        {
            Result.bTerminated = true;
            break;
        }

        // 5. 更新传输率和辐射度
        float3 Li = EvaluateLightSampling(Hit, SampleUV);
        Result.Radiance += Result.Throughput * Li;

        // 6. 更新 throughpu（BRDF 估值 / 采样概率）
        Result.Throughput *= BRDFRatio(Hit, NextRay) / (1.0f - TerminationProb);

        CurrentRay = NextRay;
    }

    return Result;
}

六、内存管理

GPU 内存池

Northlight Engine 3.0 使用分层的 GPU 内存管理策略：

内存层次

持久层：引擎核心资源（材质、Shader、字体），常驻显存。
场景层：关卡几何体、纹理、灯光数据，随关卡加载。
临时层：渲染中间缓冲区（G-Buffer、Shadow Map、VSM），每帧分配和释放。

纹理压缩

AW2 使用 BC7（DXTC）和 ASTC（移动端）压缩格式，纹理数据压缩比约为 4:1-8:1。对于 VSM 等特殊纹理，使用专门的浮点压缩格式。

本章小结

Alan Wake 2 的技术突破在于将 GPU 从"渲染执行者"转变为"渲染决策者"。GPU Driven Rendering Pipeline 让渲染系统能够处理远超传统方法的物体数量，Virtual Shadow Maps 解决了阴影分辨率和性能的根本矛盾。这些技术正在成为下一代游戏引擎的标准配置。

核心经验总结：

  1. GPU Driven：将可见性判定、排序、批处理移到 GPU 端，释放 CPU 算力
  2. VSM：层级 Mipmap 阴影贴图 + 按需采样，用一次性生成成本换取运行时灵活性
  3. 异步计算：DX12 多队列并行执行，Compute Shader 参与渲染管线
  4. 内存分层：持久/场景/临时三层管理策略，配合纹理压缩最大化显存利用率
