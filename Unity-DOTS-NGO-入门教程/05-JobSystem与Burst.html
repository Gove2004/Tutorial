05　Job System 与 Burst：让数据跑满多核

第四章的 SystemAPI.Query 仍然在主线程串行执行。这一章把数据搬进 Worker 线程，并交给 Burst 编译成原生机器码。这是 DOTS 性能的两个放大器：Job System 解决“用满多核”，Burst 解决“每个核都算得更快”。

5.1 Job 的基本形态

Job 是一个实现特定接口的 struct，包含需要处理的数据字段和一个 Execute 方法。它不是对象、不能捕获外部变量——所有输入都通过字段显式传入，这是它能被安全复制到其他线程的前提。

最基础的 IJob 只有一个 Execute，适合做一件独立的事：

using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;

[BurstCompile]
public struct SumJob : IJob
{
    public NativeArray<float> Values;
    public NativeArray<float> Result;

    public void Execute()
    {
        float sum = 0f;
        for (int i = 0; i < Values.Length; i++)
            sum += Values[i];
        Result[0] = sum;
    }
}

5.2 IJobEntity：按实体并行的主力

游戏逻辑里最常见的需求是“对查询出的每个实体执行同样操作”，这正是 IJobEntity 的用途。它把第四章的查询循环封装成可调度的 Job：

using Unity.Burst;
using Unity.Entities;
using Unity.Transforms;

[BurstCompile]
public partial struct RotationJob : IJobEntity
{
    public float DeltaTime;

    // in = 只读，ref = 读写，由源生成器自动匹配拥有这些组件的实体
    void Execute(ref LocalTransform transform, in RotationSpeed speed)
    {
        transform = transform.RotateY(speed.RadiansPerSecond * DeltaTime);
    }
}

public partial struct RotationJobSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var job = new RotationJob
        {
            DeltaTime = SystemAPI.Time.DeltaTime
        };

        // 调度到多个 Worker 线程，按 Chunk 并行
        state.Dependency = job.ScheduleParallel(state.Dependency);
    }
}

几个关键约定：

  • IJobEntity 必须是 partial struct，同样依赖源生成器。
  • Execute 的参数用 in（只读）和 ref（读写）标注，语义和 RefRO/RefRW 一致。
  • 需要过滤但不取值的组件，在 struct 上用特性标注：[WithAll(typeof(AliveTag))]、[WithNone(typeof(StunnedTag))]。
  • Job 不能捕获变量，DeltaTime 这类外部值通过字段传入。

5.4 JobHandle 与依赖链

调度 Job 是异步的，返回一个 JobHandle 作为这次工作的凭据。引擎用它做两件事：管理依赖顺序、决定何时等待完成。

在 ISystem 里，state.Dependency 是当前系统的依赖句柄。你把它传给 Schedule，再把返回的句柄赋回去，引擎就自动串起了依赖链：

// 前一个 Job 的句柄作为输入，保证读写同一数据的 Job 不重叠
state.Dependency = job.ScheduleParallel(state.Dependency);

当主线程需要用到 Job 正在写入的数据（比如要做结构变更），调用 handle 的 Complete() 阻塞等待，引擎会在安全点自动完成大部分等待，你通常不需要手动 Complete，但要知道这个机制存在。依赖关系由安全系统根据你访问的 NativeContainer 和组件自动推导，写错访问意图会直接报冲突错误，而不是产生静默的数据竞争。

5.5 Burst 编译器：不只是“变快”

Burst 是基于 LLVM 的编译器，专门处理 DOTS 中的高性能代码。它做的事包括：

  • 把 IL 翻译成目标机器的原生码，消除托管运行时开销；
  • 自动向量化：识别可并行的数值循环，生成 SIMD 指令（一条指令同时处理多个 float）；
  • 针对 Unity.Mathematics 的 math 类型做内联和代数优化；
  • 在编译期对非法用法直接报错，把多线程和原生环境的危险操作挡在运行前。
数学运算一律用 Unity.Mathematics：float3、quaternion、math.mul 等。它们是 struct、有明确的精度契约，Burst 能深度优化。不要在 Burst 代码里用 Vector3、Quaternion 等 UnityEngine 数学类型。

精度与性能的开关

[BurstCompile] 可加在 Job、System 的方法或普通方法上。需要调整浮点行为时可设置精度模式（如 FloatPrecision、FloatMode），默认配置对绝大多数游戏逻辑已经足够，不要为了“可能更快”随手放宽精度，先测量再决定。

5.6 Burst 不允许什么

这是新手报错最集中的地方。Burst 运行在原生、无托管运行时的环境，以下写法会被拒绝或无法正常工作：

禁止/受限用法替代方案
访问 class 对象、string、托管数组struct、FixedString、NativeArray
调用未被 Burst 编译的托管方法、虚方法把逻辑放进 Burst 方法；必要时用函数指针
在 Job 里直接做结构变更EntityCommandBuffer.ParallelWriter（第七章）
随意读写静态可变状态System 字段、NativeContainer、SharedStatic（进阶）
读报错的方式：Burst 的错误信息通常会指出具体的非法构造和触发位置。不要看到一大段编译输出就慌，先找到指向你代码文件名和行号的那一行，它一般会明确说明“这里用了托管对象/不支持的调用”。

5.7 NativeContainer：Job 之间的数据通道

Job 里用到的容器来自 Unity.Collections：NativeArray、NativeList、NativeHashMap 等。它们分配在原生内存、不经过 GC，并带有安全检查：

  • 创建时指定分配器：Allocator.Temp（帧内，最快）、Allocator.TempJob（跨帧、Job 用）、Allocator.Persistent（长期）；
  • 用完必须 Dispose()，通常在 System 的 OnDestroy 或 Job 完成后；
  • 安全系统会跟踪容器的读写归属，两个 Job 同时写同一容器会被直接拦截。
// 典型的生命周期：OnCreate 分配，OnDestroy 释放
[BurstCompile]
public void OnCreate(ref SystemState state)
{
    m_Buffer = new NativeList<float>(64, Allocator.Persistent);
}

[BurstCompile]
public void OnDestroy(ref SystemState state)
{
    if (m_Buffer.IsCreated) m_Buffer.Dispose();
}

5.8 一个完整的并行示例：带标签的批量推进

using Unity.Burst;
using Unity.Entities;
using Unity.Mathematics;
using Unity.Transforms;

[WithAll(typeof(AliveTag))]
[WithNone(typeof(StunnedTag))]
[BurstCompile]
public partial struct MoveForwardJob : IJobEntity
{
    public float DeltaTime;

    void Execute(ref LocalTransform transform, in MovementSpeed speed)
    {
        transform.Position += transform.Forward() * speed.Value * DeltaTime;
    }
}

public partial struct MoveForwardSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        state.Dependency = new MoveForwardJob
        {
            DeltaTime = SystemAPI.Time.DeltaTime
        }.ScheduleParallel(state.Dependency);
    }
}

  2. 分别用 Run 和 ScheduleParallel 调度同一个 Job，在 Profiler 里观察主线程耗时和 Worker 线程活动。
  3. 故意在 Burst Job 里访问一个 string 字段，记录编译器给出的错误信息，定位它指向的代码行。
  4. 解释为什么 Job 不能用 Lambda 捕获外部变量，字段传参解决了什么安全问题。

本章小结

  • Job 是携带数据字段与 Execute 的 struct，IJobEntity 是按实体批量处理的主力，配合 ScheduleParallel 按 Chunk 并行。
  • JobHandle 与 state.Dependency 自动管理依赖链，安全系统把读写冲突挡在运行前。
  • Burst 把 IL 编译为原生 SIMD 机器码，配合 Unity.Mathematics 做深度优化；托管对象、虚调用等在 Burst 中被禁止。
  • NativeContainer 是原生内存数据通道，按分配器创建、必须手动 Dispose。
  • 读 Burst 报错先找指向你代码行号的那一条。
