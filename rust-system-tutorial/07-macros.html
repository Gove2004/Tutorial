第七章：宏系统

宏系统是 Rust 最具表达力的特性之一。它允许你在编译期进行代码生成，用极少的代码描述通用的模式，同时保持零运行时开销。Rust 的宏分为两类：声明宏（macro_rules!）和过程宏（procedural macros）。本章将深入两者的工作原理和使用场景。

为什么 Rust 的宏比 C/C++ 的宏更安全？

C 语言的 #define 宏是纯文本替换，不做任何语法检查。C++ 模板元编程虽然强大但极其复杂。Rust 的宏工作在语法树（AST）层面，编译器确保生成的代码是合法的，并且有完善的 hygiene（命名卫生）机制防止变量名冲突。

7.1 声明宏（macro_rules!）：模式匹配的代码生成

声明宏是 Rust 最常用、最强大的宏形式。它通过模式匹配来匹配输入，然后将匹配的部分插入到模板中生成代码。

7.1.1 基本语法：重复匹配

// $()* 语法：零次或多次重复
// 匹配逗号分隔的表达式列表
macro_rules! sum {
    // 基准情形：只有一个元素
    ($first:expr) => {
        $first
    };
    // 递归情形：第一个元素 + 剩余部分的求和
    ($first:expr, $($rest:expr),+) => {
        $first + sum!($($rest),+)
    };
}

fn main() {
    println!("{}", sum!(1));          // 1
    println!("{}", sum!(1, 2));       // 3
    println!("{}", sum!(1, 2, 3));    // 6
    println!("{}", sum!(1, 2, 3, 4)); // 10
}

7.1.2 片段说明符（Fragment Specifiers）

macro_rules! 支持多种片段类型，每种对应语法树的不同部分：

说明符 匹配内容 示例 限制
expr 表达式 1 + 2, x.max(y) 无
stmt 语句 let x = 1; 需要 ; 结尾
pat 模式 Some(x), [a, ..] 无
ty 类型 i32, Vec<String> 无
ident 标识符 foo, x 无
path 路径 std::vec::Vec 无
tt token tree 任意单个 token 树 无
block 代码块 { let x = 1; } 需要 {}
item 顶层项 fn foo() {} 需要完整定义 
// 组合使用多个片段说明符
macro_rules! define_struct {
    // 匹配: define_struct!(MyStruct { field: Type, ... })
    ($name:ident { $($field:ident: $ty:ty),* $(,)? }) => {
        pub struct $name {
            $(pub $field: $ty),*
        }

        impl $name {
            // 自动生成 getter
            $(
                pub fn $field(&self) -> &$ty {
                    &self.$field
                }
            )*
        }
    };
}

define_struct!(Person {
    name: String,
    age: u32,
    email: String,
});

fn main() {
    let p = Person {
        name: "Alice".to_string(),
        age: 30,
        email: "alice@example.com".to_string(),
    };
    println!("{} is {} years old", p.name(), p.age());
}

7.1.3 TT Muncher：处理嵌套语法

TT Muncher 是一种递归处理 token tree 的技术，常用于解析复杂的嵌套语法：

// 一个简单的 JSON 字面量宏
macro_rules! json {
    // 对象
    ({ $($key:literal : $val:expr),* $(,)? }) => {{
        let mut map = std::collections::HashMap::new();
        $(
            map.insert($key.to_string(), $val);
        )*
        map
    }};
    // 数组
    ([ $($elem:expr),* $(,)? ]) => {{
        vec![$($elem),*]
    }};
    // 字面量
    ($lit:literal) => { $lit };
    // 标识符
    ($id:ident) => { $id };
}

7.1.4 宏的 Hygiene（命名卫生）

宏的 hygiene 机制确保宏内部引入的标识符不会与外部代码冲突：

macro_rules! example {
    () => {
        let x = 42;
        println!("x = {}", x);
    };
}

fn main() {
    let x = 100;  // 外部的 x
    example!();    // 宏内部的 x 不会影响外部
    println!("x = {}", x);  // 仍然输出 100
    // 输出:
    // x = 42
    // x = 100
}

// $crate: 引用定义宏的 crate，防止名称冲突
// $call_site: 使用调用点的可见性（而非定义点的可见性）
// 默认行为：宏内引入的标识符具有定义点的可见性
注意：宏的 hygiene 也意味着你不能在宏中访问调用点的局部变量。如果需要引用外部变量，必须通过参数显式传入。

7.2 过程宏（Procedural Macros）

过程宏接受 Rust 代码作为输入，生成 Rust 代码作为输出。它们运行在编译期，比声明宏更灵活，但也更复杂。

7.2.1 三种过程宏

类型 属性 输入 输出 典型用途
Derive #[derive(MyTrait)] 结构体/枚举定义 附加 trait 实现 serde::Serialize
Function-like my_macro!(...) 或 #[my_macro(...)] 任意 token 流 新 token 流 sqlx::sql!
Attribute #[my_attr] 带属性的项 修改后的项 actix_web::get

7.2.2 Derive Macro 示例

// 手动实现 Debug trait（冗长）
impl std::fmt::Debug for Point {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.debug_struct("Point")
            .field("x", &self.x)
            .field("y", &self.y)
            .finish()
    }
}

// 使用 derive macro（一行搞定）
#[derive(Debug)]
struct Point {
    x: f32,
    y: f32,
}

serde 是最著名的 derive macro 示例：

use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Debug)]
struct Config {
    host: String,
    port: u16,
    debug: bool,
}

// serde 的 derive macro 自动生成：
// - Serialize::serialize() — 将结构体编码为 JSON
// - Deserialize::deserialize() — 从 JSON 解码为结构体
// 性能：序列化 1KB 结构体约 2μs，零拷贝优化后可达 0.5μs

7.3 cargo-expand：查看宏展开

cargo-expand 是调试宏的最重要工具。它将宏展开为普通的 Rust 代码：

$ cargo install cargo-expand
$ cargo expand

// 展开后的 #[derive(Debug)] 示例：
impl ::core::fmt::Debug for Point {
    fn fmt(&self, f: &mut ::core::fmt::Formatter<'_>) -> ::core::fmt::Result {
        f.debug_struct("Point")
            .field("x", &self.x)
            .field("y", &self.y)
            .finish()
    }
}

// 展开后的 macro_rules! 示例：
// sum!(1, 2, 3) 展开为：
1 + (2 + (3))
调试技巧：cargo-expand 的输出可能很长。使用 cargo expand --lib 只看库代码，cargo expand --bin mybin 只看特定二进制文件的代码。

7.4 编写自己的 derive macro crate

创建一个 derive macro 需要两个 crate：一个是 proc-macro crate（存放宏代码），另一个是使用宏的普通 crate。

7.4.1 项目结构

my-macros/
├── Cargo.toml           # proc-macro crate
├── src/
│   └── lib.rs           # 宏的实现
├── examples/
│   └── demo.rs          # 使用宏的示例
└── tests/
    └── compile-fail.rs   # 编译失败测试

7.4.2 Cargo.toml 配置

# my-macros/Cargo.toml
[package]
name = "my-macros"
version = "0.1.0"
edition = "2021"

[lib]
proc-macro = true  # 必须是 proc-macro crate

[dependencies]
syn = { version = "2", features = ["full"] }
quote = "1"
proc-macro2 = "1"

7.4.3 实现一个 derive macro

// my-macros/src/lib.rs
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput, Data, Fields};

/// 自动为结构体生成 Display trait 的 derive macro
#[proc_macro_derive(DisplayEx)]
pub fn derive_display_ex(input: TokenStream) -> TokenStream {
    // 1. 解析输入
    let input = parse_macro_input!(input as DeriveInput);

    // 2. 提取结构体名和字段
    let name = &input.ident;
    let fields = match &input.data {
        Data::Struct(s) => match &s.fields {
            Fields::Named(f) => &f.named,
            Fields::Unnamed(f) => &f.unnamed,
            Fields::Unit => return TokenStream::new(),
        },
        _ => panic!("只能用于结构体"),
    };

    // 3. 生成代码
    let field_formats: Vec<_> = fields.iter().map(|f| {
        let field_name = &f.ident;
        quote! {
            .field(#field_name, &self.#field_name)
        }
    }).collect();

    let expanded = quote! {
        impl std::fmt::Display for #name {
            fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
                f.debug_struct(stringify!(#name))
                    #(.field_formats)*
                    .finish()
            }
        }
    };

    TokenStream::from(expanded)
}

7.4.4 使用 syn 和 quote 的核心概念

// syn: 将 TokenStream 解析为 AST
// quote: 将 AST 转回 TokenStream

// 核心类型：
// TokenStream  — 编译器输入的原始 token 流
// DeriveInput  — 被 derive 修饰的类型
// Ident       — 标识符（如 "MyStruct"）
// Fields      — 结构体的字段（Named/Unnamed/Unit）
// Generics    — 泛型参数

// quote! 宏的插值语法：
// $variable  — 插入 Rust 表达式
// #ident    — 插入单个标识符
// #( ... )*  — 重复插入（每个元素用空格分隔）
// #(, ...)*  — 重复插入（每个元素用逗号分隔）

// 性能提示：
// - quote! 在编译期运行，不影响运行时性能
// - 大型宏展开可能增加编译时间 10-50ms
// - 使用 cargo-expand 验证生成的代码是否正确

7.5 Attribute Macro 实战

Attribute macro 可以修改带属性的函数、结构体或其他项：

// 一个简单的 logging attribute macro
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, ItemFn, LitStr};

#[proc_macro_attribute]
pub fn log_call(args: TokenStream, input: TokenStream) -> TokenStream {
    let args_str = parse_macro_input!(args as LitStr);
    let log_msg = args_str.value();

    let input_fn = parse_macro_input!(input as ItemFn);
    let fn_name = &input_fn.sig.ident;
    let fn_inputs = &input_fn.sig.inputs;
    let fn_output = &input_fn.sig.output;
    let fn_body = &input_fn.block;

    let expanded = quote! {
        fn #fn_name(#fn_inputs) #fn_output {
            tracing::info!("Entering {}: {}", stringify!(#fn_name), #log_msg);
            let _span = tracing::info_span!("#fn_name").entered();
            #fn_body
        }
    };

    TokenStream::from(expanded)
}

// 使用：
#[log_call("processes user input")]
fn process_input(data: &str) -> String {
    data.to_uppercase()
}

// 展开后等价于：
fn process_input(data: &str) -> String {
    tracing::info!("Entering process_input: processes user input");
    let _span = tracing::info_span!("process_input").entered();
    data.to_uppercase()
}

7.6 宏的性能考量

// 声明宏 vs 函数的性能对比（10^9 次调用）：
// macro_rules! 内联展开: ~0.3ns（零开销，直接内联）
// 函数调用:              ~0.5ns（可能有内联，但不保证）
// 结论：宏不会带来运行时开销，因为它在编译期就展开了

// 编译期性能：
// macro_rules! 展开:  ~1-5ms（简单宏）
// derive macro:      ~10-50ms（中等复杂度）
// 复杂 attribute macro: ~50-200ms
// 结论：宏会增加编译时间，但不影响运行时性能

// 大型项目的宏展开时间占比：
// 小型项目 (<10 个宏):  编译时间增加 <5%
// 中型项目 (10-100 个宏): 编译时间增加 5-15%
// 大型项目 (>100 个宏):  编译时间增加 15-30%

7.7 本章小结

关键要点
  • macro_rules!：通过模式匹配生成代码，支持 $()* 重复、hygiene 隔离、片段说明符
  • 片段说明符：expr、stmt、pat、ty、ident、path、tt、block、item，各有不同的匹配范围
  • TT Muncher：递归处理 token tree 的技术，用于解析复杂嵌套语法
  • Hygiene：宏内引入的标识符与外部隔离，不会发生命名冲突
  • Derive macro：为结构体/枚举自动生成 trait 实现，最广泛使用的过程宏类型
  • Attribute macro：修改带属性的函数/结构体，功能最强大
  • syn + quote：编写过程宏的标准工具链
  • cargo-expand：调试宏的最重要工具，查看宏展开结果
  • 性能：宏零运行时开销，但增加编译时间
