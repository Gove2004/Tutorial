实战三：GPU 加速算法

本章将实现三个经典并行算法：Parallel Reduce（并行归约）、Prefix Sum（扫描）和 Radix Sort（基数排序）。这些不是"炫技"算法——它们是 GPU 加速库（如 CUB、Thrust）的核心构件，也是理解 GPU 并行思维的试金石。

算法思维转换：从串行到并行

串行算法的思维方式是："一步一步做"。并行算法的思维方式是："每一步都让 N 个人一起做"。这个思维转换是学习 GPU 算法最大的挑战。

核心范式：Work Reduction（工作归约）

串行算法的复杂度通常用操作次数衡量。并行算法用两个维度衡量：
  • Work（总工作量）：所有线程执行的操作总数
  • Depth（并行步数）：最长的依赖链长度
一个好的并行算法应该是：Work 接近最优（不浪费太多资源）+ Depth 对数级（并行度够高）。

Parallel Reduce：求数组之和

Reduce 是所有并行算法的基础。目标：给定数组 [a, b, c, d, e, f, g, h]，求 a+b+c+d+e+f+g+h。

串行版本（对比基准）

// 串行 Reduce：N-1 次加法
// Work = N-1, Depth = N-1

result = 0;
for (i = 0; i < N; i++)
    result += arr[i];

树形 Reduce（并行版本）

// 并行 Reduce：log2(N) 步
// Work = N-1, Depth = log2(N)

// Step 1: 间距 1 的配对相加
[ a+b, c+d, e+f, g+h ]      // 4 个线程并行

// Step 2: 间距 2 的配对相加
[ a+b+c+d, e+f+g+h ]        // 2 个线程并行

// Step 3: 间距 4 的配对相加
[ a+b+c+d+e+f+g+h ]         // 1 个线程

// 总共 3 步 = log2(8) 步

HLSL 实现

// Shared Memory 中的 Tree-Based Reduce
// 计算 Shared Memory 中所有元素的和
SharedMemory float sharedData[256];
uint threadId = threadIdx.x;

// Step 1: 每个线程将自己的数据放入 Shared Memory
// （数据已在前面加载完毕）

// Step 2: Tree Reduction
for (uint stride = 1; stride < blockDim.x; stride *= 2)
{
    GroupMemoryBarrierWithGroupSync();

    if (threadId % (stride * 2) == 0)
    {
        sharedData[threadId] += sharedData[threadId + stride];
    }
}

// Step 3: 线程 0 持有最终结果
if (threadId == 0)
{
    output[groupIdx] = sharedData[0];
}

这个实现的细节很重要：

  1. stride 从 1 开始递增：第一步间距 1（相邻元素相加），第二步间距 2，以此类推
  2. Barrier 在每个循环迭代前：确保上一个迭代的写入已完成
  3. 条件 threadId % (stride * 2) == 0：确保每对元素只有一个线程做加法，避免竞争
  4. 最后只有 thread 0 有结果：如果需要每个 Group 的输出，写到一个全局 UAV
Bank Conflict 陷阱：在 stride = 1 时，线程 i 和线程 i+1 访问相邻的 Shared Memory 地址——如果它们在同一个 Bank，会产生冲突。但在 32-Warp 的 GPU 上，thread 0 和 thread 1 在不同 Bank，thread 32 和 thread 33 又在同一 Bank。所以 stride=1 时有一半的加法会有 Bank Conflict。

缓解方法：给 Shared Memory 加 padding，或者接受这个小的损失（tree reduction 的总 Bank Conflict 比例是 50% → 25% → 12.5% → ...，很快收敛）。

Prefix Sum（扫描算法）

Prefix Sum（也叫 Scan）是 Reduce 的推广。给定输入 [a, b, c, d]，输出 [0, a, a+b, a+b+c]（Exclusive Scan）或 [a, a+b, a+b+c, a+b+c+d]（Inclusive Scan）。

为什么 Prefix Sum 重要？因为它可以做：

  • Stream Compaction：过滤数组中满足条件的元素
  • Parallel Sort：Radix Sort 的核心构件
  • Blob Counting：图像中连通分量计数
  • Work Distribution：根据任务长度计算每个线程的起始偏移

Blelloch Scan（工作最优的 Parallel Scan）

最经典的并行 Scan 算法，由 Blelloch 于 1990 年提出。分两步：

Up-Sweep (Reduction Phase):
  从叶子节点向根节点累加，形成一棵求和树
  [1, 3, 2, 7, 4, 6, 3]
      →
  [1, 3, 2, 11, 4, 6, 19]    (根节点 = 总和)

Down-Sweep (Scan Phase):
  从根节点向叶子节点传播前缀和
  [0, 1, 4, 2, 11, 4, 10]    (结果)

HLSL 实现（组内 Exclusive Scan）：

// 组内 Blelloch Scan（假设 256 线程）
SharedMemory float sharedData[256];
SharedMemory float sharedTemp[256];

uint threadId = threadIdx.x;

// 加载数据
sharedData[threadId] = input[threadId];

// ---- Up-Sweep ----
for (uint stride = 1; stride < blockDim.x; stride *= 2)
{
    GroupMemoryBarrierWithGroupSync();

    if (threadId % (stride * 2) == 0)
    {
        uint left = threadId;
        uint right = threadId + stride;
        sharedData[right] += sharedData[left];
    }
}

// ---- Down-Sweep ----
if (threadId == 0)
    sharedData[0] = 0;  // 第一个元素清零（Exclusive Scan）

GroupMemoryBarrierWithGroupSync();

for (uint stride = blockDim.x / 2; stride > 0; stride /= 2)
{
    GroupMemoryBarrierWithGroupSync();

    if (threadId % (stride * 2) == 0)
    {
        uint left = threadId;
        uint right = threadId + stride;
        float temp = sharedData[left];
        sharedData[left] = sharedData[right];
        sharedData[right] += temp;
    }
}

GroupMemoryBarrierWithGroupSync();

if (threadId < N)
    output[threadId] = sharedData[threadId];

跨 Group 的 Prefix Sum

上面的实现只在一个 Group 内有效。要处理大规模数组（比如 100 万个元素），需要跨 Group：

数组: [1, 3, 2, 7, 4, 6, 3, ...]  (100 万个元素)
每组处理 256 个元素 → 需要 3907 个 Group

Pass 1: 每组内做 Scan，得到组内前缀和
Pass 2: 每组输出最后一个元素（组总和），对这 3907 个总和做 Scan
Pass 3: 每个 Group 将自己组内的所有值加上前一组的总和（偏移量）

Radix Sort

Radix Sort 是 GPU 上最快的通用排序算法。它不基于比较（O(N log N)），而是基于位（O(N × bits_per_digit)）。

算法原理

基数排序（LSD - Least Significant Digit）:
输入: [329, 457, 657, 839, 436, 720, 355]

第 1 轮：按个位排序
  个位: 9, 7, 7, 9, 6, 0, 5
  结果: [720, 436, 355, 457, 657, 329, 839]

第 2 轮：按十位排序
  十位: 2, 3, 5, 5, 5, 2, 3
  结果: [720, 329, 436, 839, 355, 457, 657]

第 3 轮：按百位排序
  百位: 7, 3, 4, 8, 3, 4, 6
  结果: [329, 355, 436, 457, 657, 720, 839] ✓

GPU 实现：Binary Radix Sort（1-bit 基数）

对于 32-bit 整数，做 32 轮排序。每轮用 Prefix Sum 确定每个元素的输出位置：

// 单轮 Binary Radix Sort（按第 bit 位排序）
// 使用 Stable Sort：0 位放前面，1 位放后面

[numthreads(256, 1, 1)]
void RadixSortBitPass(uint3 tid : SV_DispatchThreadID)
{
    uint index = tid.x;
    if (index >= n) return;

    // 1. 检查当前 bit
    uint bitValue = (keys[index] >> bit) & 1;

    // 2. 局部计数（Shared Memory）
    SharedMemory uint sharedCount[2];  // sharedCount[0] = 0 的个数
                                       // sharedCount[1] = 1 的个数
    sharedCount[bitValue]++;

    GroupMemoryBarrierWithGroupSync();

    // 3. 组内 Prefix Sum 确定输出位置
    // ... (调用前面的 Scan 代码)

    // 4. 写入临时缓冲区
    if (bitValue == 0)
    {
        outputKeys[localRank0] = keys[index];
        outputValues[localRank0] = values[index];
    }
    else
    {
        outputKeys[groupSum - localRank1] = keys[index];
        outputValues[groupSum - localRank1] = values[index];
    }
}

完整实现 32 轮需要：

  1. 两个缓冲区交替使用（Ping-Pong）
  2. 每轮 Dispatch 一次（32 次 Dispatch = 32 轮 × 1-bit）
  3. 或者用 DispatchIndirect 实现 Indirect Dispatch 减少 CPU 开销
优化：16-bit 基数：每轮排 1 bit 太慢了（32 轮）。可以用 16-bit 基数（每轮排 16 个值 = 2 轮），但需要预计算 65536 大小的 Histogram。实际中，16-bit 基数排序通常比 1-bit 快 1.5-2x。

算法组合：从构件到完整系统

这些算法不是孤立的。它们可以组合成强大的系统：

Radix Sort = Prefix Sum + Scatter
Prefix Sum = Reduce + Scan
Particle Sorting = Radix Sort (按深度排序用于 Transparency)
Stream Compaction = Prefix Sum + Scatter (只保留满足条件的元素)
Histogram = Reduce (分组累加)

本章小结

  • Reduce 是树形并行：log₂(N) 步完成 N 个元素的求和
  • Prefix Sum（Scan）是 Reduce 的逆向——从总和到分布
  • Blelloch Scan 是工作最优的并行扫描算法
  • Radix Sort 不基于比较，在 GPU 上远超比较排序
  • 这些算法是更大系统的构件：Histogram、Stream Compaction、Sorting
