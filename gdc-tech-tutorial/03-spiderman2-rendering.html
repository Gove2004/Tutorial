03 - 蜘蛛侠2 — 开放世界渲染架构

Insomniac Games 为《漫威蜘蛛侠2》开发了专属的 Spidey Engine，在 PS5 有限的硬件资源下实现了完整的纽约市开放世界。本章深入解析其渲染架构、光影管理、角色渲染和粒子系统。

前置知识：PBR 渲染流程、开放世界架构、粒子系统基础、PS5 RDNA2 架构

一、Spidey Engine 渲染架构

Insomniac Games 从《漫威蜘蛛侠》（2018）开始就使用自研引擎，到《蜘蛛侠2》时引擎已经历了三轮重大重构。Spidey Engine 的设计哲学是"为特定类型的内容高度优化"——它不是通用引擎，而是专门为超级英雄开放世界游戏打造的专用引擎。

引擎设计原则

  1. 内容优先：引擎API直接映射到美术工作流，减少中间转换
  2. PS5 原生开发：没有跨平台抽象层带来的开销，充分利用 RDNA2 特性
  3. 数据驱动：所有渲染参数通过数据资产配置，便于迭代和调整
  4. 渐进式复杂度：根据硬件能力自动降级，保持目标帧率

二、开放世界光影管理

纽约市开放世界的最大挑战是：如何在保持画面质量的同时，管理数百个光源、动态昼夜循环和大量建筑物的阴影计算。

光照分区系统（Light Partitioning）

Insomniac 将 NYC 地图划分为多个光照分区（Light Zones），每个分区独立管理其光源集合：

光照分区原理

将世界划分为规则的 Grid（默认 256x256 单位），每个 Grid Cell 维护一份局部光源列表。渲染时只处理摄像机周围 N 个 Cell 内的光源，远处的光源被完全忽略。

// LightZoneManager.cpp - 光照分区管理
class LightZoneManager
{
    static constexpr int ZoneGridSize = 256;  // 每个 Cell 256 单位
    static constexpr int ActiveZoneRadius = 5; // 摄像机周围 5x5 个 Cell

    struct LightZone
    {
        int GridX, GridY;
        TArray<DynamicLight> DynamicLights;
        TArray<StaticLight>  StaticLights;
        FBox2D BoundingBox;
        uint32 Version; // 变更版本号，用于增量更新
    };

    void UpdateVisibleZones(const FVector& CameraPos)
    {
        int CenterX = CameraPos.X / ZoneGridSize;
        int CenterY = CameraPos.Z / ZoneGridSize;

        // 清除上一帧的光照缓存
        CurrentLights.Reset();

        // 只处理可见范围内的 Zone
        for (int dy = -ActiveZoneRadius; dy <= ActiveZoneRadius; ++dy)
        {
            for (int dx = -ActiveZoneRadius; dx <= ActiveZoneRadius; ++dx)
            {
                int ZoneX = CenterX + dx;
                int ZoneY = CenterY + dy;

                auto* Zone = GetOrCreateZone(ZoneX, ZoneY);
                if (!Zone || !IsZoneVisible(Zone->BoundingBox))
                    continue;

                // 合并该 Zone 的光源到全局列表
                CurrentLights.Append(Zone->DynamicLights);
                CurrentLights.Append(Zone->StaticLights);
            }
        }
    }
};

动态昼夜循环

蜘蛛侠的游戏世界中，时间会真实流逝——白天、黄昏、夜晚各有不同的光照参数。Insomniac 实现了以下系统：

  • 太阳角度系统：根据游戏内时间计算太阳方位角和高度角，实时调整主光源方向和强度
  • 天空盒渐变：天空颜色随太阳角度平滑过渡，使用多层天空球实现渐变
  • 城市灯光响应：建筑物窗户灯光在黄昏时自动亮起，黎明时自动熄灭
  • 动态阴影调整：低角度阳光产生更长的阴影，夜间主要依赖人造光源照明

实时 GI 方案

《蜘蛛侠2》没有使用 Lumen（因为是自研引擎），而是实现了一套定制的实时 GI 系统：

方案用途性能开销
光照探针（Light Probes）静态间接光照零运行时开销（预计算）
屏幕空间 GI（SSGI）动态物体间接光照~2ms/帧
辐射度缓存（Irradiance Cache）加速光照探针插值~0.5ms/帧

三、角色次表面散射（SSS）

蜘蛛侠面具下的角色面部需要有真实的皮肤质感，这需要次表面散射（Subsurface Scattering）技术。SSS 模拟光线穿透半透明材质（如皮肤）并在内部散射的效果。

SSS 参数化系统

Insomniac 为每个角色建立了完整的 SSS 参数集：

// SubsurfaceScattering.h - SSS 材质参数
struct SSSProfile
{
    // 散射半径：光线在材质内传播的平均距离
    // 不同组织类型有不同的值
    struct TissueType
    {
        FString Name;
        float  Radius;      // 散射半径 (mm)
        float3 Color;       // 散射颜色
        float  Scale;       // 散射强度
        float  Falloff;     // 衰减指数
    };

    TArray<TissueType> Tissues;

    // 预设的皮肤类型
    static SSSProfile Skin_WarmThin()    // 薄皮肤（耳朵、手指）
    {
        return {
            { "epidermis",  0.3f, float3(0.95f, 0.75f, 0.65f), 1.0f, 3.0f },
            { "dermis",     1.5f, float3(0.90f, 0.60f, 0.50f), 0.8f, 2.0f },
            { "blood",      3.0f, float3(0.80f, 0.15f, 0.10f), 0.5f, 1.5f }
        };
    }

    static SSSProfile Skin_Thick()       // 厚皮肤（手掌、脚底）
    {
        return {
            { "epidermis",  0.1f, float3(0.90f, 0.85f, 0.75f), 1.0f, 4.0f },
            { "dermis",     0.8f, float3(0.85f, 0.70f, 0.60f), 0.6f, 2.5f },
        };
    }

    static SSSProfile Mask_Material()    // 蜘蛛侠面罩（不透光）
    {
        return { /* SSS 关闭，纯 PBR 渲染 */ };
    }
};

实现方式

PS5 上的 SSS 实现采用了屏幕空间 + 几何近似的混合方案：

  1. 屏幕空间 SSS（近距角色）：对角色屏幕空间像素进行多通道模糊，模拟光线散射效果。开销约 3ms/角色
  2. 几何近似 SSS（远距角色）：使用简化的顶点着色器计算，将 SSS 效果烘焙到法线贴图的方向偏移中。开销约 0.2ms/角色
  3. 混合过渡：在两个方案之间使用平滑过渡，避免切换时的视觉跳变

四、大规模粒子系统

蜘蛛侠系列的核心玩法涉及大量的粒子效果：蛛丝、爆炸、火焰、雨水、城市尘埃。Insomniac 实现了高性能的粒子系统来支撑这些效果。

蛛丝物理模拟

蛛丝是游戏中最复杂的粒子系统之一——它既是视觉特效，也是物理交互对象：

蛛丝的两种形态

发射态：从蜘蛛侠手部射出的蛛丝，使用粒子系统 + 绳索物理模拟。
连接态：粘附到建筑物上的蛛丝，使用绳索关节（Skeletal Constraint）维持张力。

// WebSwingPhysics.cpp - 蛛丝摆荡物理
class WebSwingController
{
    struct WebLine
    {
        FVector AnchorPoint;     // 锚点（建筑物上的附着点）
        FVector PlayerPos;       // 玩家位置
        float   LineLength;      // 当前线长
        float   LineVelocity;    // 线的伸缩速度
        float   Tension;         // 张力
        float   Angle;           // 与垂直方向的夹角
    };

    void UpdateSwingPhysics(WebLine& Web, float DeltaTime)
    {
        // 单摆运动方程（简化版）
        float GravityTorque = -GRAVITY * sin(Web.Angle);

        // 线的伸缩效应（收线/放线）
        float AngularMomentum = Web.LineLength * Web.LineVelocity;
        float ConservationTorque = AngularMomentum / (Web.LineLength * Web.LineLength);

        // 空气阻力
        float DragTorque = -AIR_RESISTANCE * Web.LineVelocity;

        // 合力矩
        float TotalTorque = GravityTorque + ConservationTorque + DragTorque;

        // 更新角度和线长
        Web.LineVelocity += TotalTorque * DeltaTime;
        Web.Angle += Web.LineVelocity * DeltaTime;

        // 计算玩家新位置
        Web.PlayerPos = Web.AnchorPoint +
            FVector(sin(Web.Angle) * Web.LineLength,
                    -cos(Web.Angle) * Web.LineLength, 0);
    }
};

五、角色动画融合系统

蜘蛛侠的移动方式多样——攀爬、摆荡、飞行（滑翔）、奔跑、战斗。每种移动方式都有独立的动画，系统需要在它们之间无缝切换。

动画状态机架构

// AnimationStateMachine.cpp - 蜘蛛侠动画状态机
class SpiderAnimationController
{
    enum class MovementMode
    {
        Ground,       // 地面移动（跑、走、蹲）
        Climbing,     // 攀爬（墙面行走、天花板悬挂）
        WebSwing,     // 摆荡
        Glide,        // 滑翔
        WebGlide,     // 蛛丝滑翔（高速）
        Combat,       // 战斗
        Special       // 特殊动作（翻滚、跳跃、终结技）
    };

    struct BlendState
    {
        MovementMode CurrentMode;
        MovementMode TargetMode;
        float BlendWeight;    // 当前动画混合比例
        float BlendDuration;  // 混合持续时间
        float BlendStartTime;
    };

    void UpdateAnimation(float DeltaTime)
    {
        // 1. 确定目标移动模式
        MovementMode NewMode = DetermineMovementMode();

        // 2. 检查是否可以切换
        if (CanTransition(CurrentMode, NewMode))
        {
            // 3. 开始混合
            BlendState.TargetMode = NewMode;
            BlendState.BlendTime = GetBlendDuration(CurrentMode, NewMode);
            BlendState.BlendStartTime = CurrentTime;
        }

        // 4. 计算混合权重
        float Elapsed = CurrentTime - BlendState.BlendStartTime;
        BlendState.BlendWeight = FMath::Clamp(Elapsed / BlendState.BlendTime, 0.f, 1.f);

        // 5. 混合两组动画
        MixedPose = FMath::Lerp(CurrentPose, TargetPose, BlendState.BlendWeight);
    }
};

六、渲染优化策略

GPU Instancing 全面应用

PS5 上 NYC 的建筑物、车辆、路灯、行人全部使用 GPU Instancing 渲染：

建筑物~20002000~45

行人~300300~5

通过 Instancing，场景物体的 Draw Call 从 5100 降到了 ~90，降幅超过 98%。

遮挡剔除（Occlusion Culling）

NYC 的建筑密度极高，大量物体被其他建筑遮挡。Insomniac 使用了多层遮挡剔除：

  1. Hierarchical Z-Buffer（HZB）：GPU 端的层级 Z 缓冲，通过多级渐远纹理（Mipmap Chain）快速判断物体是否在屏幕空间中可见
  2. Portal-based Culling：对于室内场景，使用门洞/窗口作为 Portal，递归判断后方区域的可见性
  3. Spatial Hash Culling：将场景划分为空间哈希格子，只检测相邻格子的遮挡关系

Draw Call 控制

PS5 上《蜘蛛侠2》的目标 Draw Call 为：开放区域 < 1500，室内场景 < 800，战斗特写 < 2000。

七、60fps 实现方案

PS5 上《蜘蛛侠2》的性能模式目标是稳定 60fps。实现方式包括：

1

分辨率缩放

使用动态分辨率渲染，基础分辨率 1440p，根据 GPU 负载在 1440p-2160p 之间动态调整。配合 FSR 2.2 的上采样技术，视觉上几乎看不出分辨率波动。

2

LOD 距离调整

当 GPU 负载接近阈值时，自动缩短 LOD 切换距离，减少远处物体的多边形数和细节级别。

3

特效降级

粒子系统的粒子数量、SSS 质量、阴影分辨率等可以在运行时动态降级，确保帧率稳定。

4

多线程渲染

充分利用 PS5 的 8 核 CPU，将渲染命令录制分配到多个线程，避免单线程瓶颈。

本章小结

《蜘蛛侠2》的渲染技术核心在于：为特定玩法量身定制的引擎架构。Spidey Engine 不是通用引擎，而是专门为"超级英雄开放世界"这一类型优化的专用引擎。其光照分区、SSS 参数化、GPU Instancing 和动画状态机的设计都值得深入学习。

核心经验总结：

  1. 光照分区：将世界划分为 Grid Cell，每格独立管理光源，大幅减少每帧的光照计算量
  2. SSS 参数化：为不同身体部位定义不同的 SSS 配置文件，实现真实的皮肤质感
  3. GPU Instancing：场景物体的 DC 降低 98% 以上，是开放世界渲染的必选项
  4. 动画混合：多模式的动画状态机 + 平滑混合是无缝切换移动方式的关键
