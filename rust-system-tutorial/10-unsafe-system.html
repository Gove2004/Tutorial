第十章：Unsafe Rust 与系统编程

这是本教程的最后一章。我们将探索 Rust 最强大的特性——unsafe 代码。虽然 99% 的日常编程不需要 unsafe，但理解它是掌握系统编程的关键。本章将展示如何使用 unsafe 编写内核模块、自定义分配器和操作系统级工具。

为什么 Rust 需要 unsafe？

Rust 的目标是在保持零成本抽象的同时提供内存安全保证。但有些操作（如直接与硬件交互、实现底层数据结构）天然需要绕过安全检查。unsafe 关键字是 Rust 的"逃生舱"——它不会破坏安全保证，而是将责任从编译器转移到程序员身上，并提供一个明确的审计边界。

10.1 六大 Unsafe Superpowers

Rust 的 unsafe 关键字允许六种在 safe Rust 中不被允许的操作。理解每一种能力的精确语义是安全使用 unsafe 的前提：

能力 描述 安全替代 风险等级
解引用裸指针 读取/写入 *const T / *mut T &T / &mut T 高
调用 unsafe 函数 标记为 unsafe 的外部函数 safe wrapper 中
读写 static mut 可变静态变量 std::sync::atomic 极高
实现不安全的 trait 标记类型满足未检查的不变量 安全 trait 高
访问 union 字段 读取/修改 union 的字段 避免使用 union 中
调用 extern "C" fn 调用不同 ABI 的代码 safe FFI wrapper 中

10.1.1 解引用裸指针

// 安全引用：编译器保证有效性
let x = 42;
let r: &i32 = &x;
println!("{}", *r);  // ✅ 编译器保证 r 不为 null 且有效

// 裸指针：编译器不做任何保证
let x = 42;
let raw: *const i32 = &x as *const i32;
unsafe {
    println!("{}", *raw);  // ⚠️ 编译器信任你不会犯错
}

// 裸指针的特点：
// - 可以为 null
// - 可以悬空（指向已释放的内存）
// - 可以同时存在多个 &mut 指针
// - 不受借用检查器保护
// - 线程安全（不自动实现 Send/Sync）

// 何时使用裸指针：
// 1. FFI 交互（C 函数返回 *mut T）
// 2. 实现底层数据结构（链表、树）
// 3. 内存映射文件
// 4. 自定义分配器

10.1.2 实现不安全的 trait

use std::sync::Mutex;

// Sync 是不安全 trait —— 手动实现需要自己保证线程安全
struct SharedState {
    value: Mutex<i32>,
}

// SharedState: Sync 已由编译器自动派生（因为 Mutex<i32>: Sync）
// 但如果我们包装了一个裸指针：
struct RawWrapper {
    ptr: *mut i32,
}

// 手动实现 Send/Sync 需要证明线程安全
unsafe impl Send for RawWrapper {}
unsafe impl Sync for RawWrapper {}

// 这意味着：
// - Send: 可以将 RawWrapper 的所有权转移到其他线程
// - Sync: 可以在多个线程间共享 &RawWrapper 引用
// 前提是 ptr 指向的内存有适当的同步机制保护

10.1.3 Union 字段访问

// union 允许同一块内存存储不同类型的数据
#[repr(C)]
union MyUnion {
    i: i32,
    f: f32,
    bytes: [u8; 4],
}

fn main() {
    let mut u = MyUnion { i: 42 };

    // 读取 i 字段
    unsafe {
        println!("i = {}", u.i);  // 42
    }

    // 切换到 f 字段（覆盖内存）
    unsafe {
        u.f = 3.14;
        println!("f = {}", u.f);  // 3.14
        // 此时 u.i 的值是未定义的！
    }

    // 使用 Tagged Union（安全替代方案）
    enum TaggedValue {
        Int(i32),
        Float(f32),
        Bytes([u8; 4]),
    }
    // 推荐使用 enum 而非 union，除非你有明确的内存布局需求
}

10.2 裸指针 vs 引用：深入理解别名规则

Rust 的别名规则（aliasing rules）是 unsafe 编程中最容易出错的概念：

// 引用的别名规则：
// - &T（不可变引用）：可以有任意多个，但不能与 &mut T 共存
// - &mut T（可变引用）：必须有且仅有一个，不能与其他任何引用共存

// 裸指针的别名规则：
// - *const T：可以有任意多个 &const 指针，互相不干扰
// - *mut T：可以有任意多个 &mut 指针，互相不干扰
// - 编译器不会检查 *const 和 *mut 之间的别名冲突

// 因此，裸指针的别名检查完全由程序员负责

// 安全地使用裸指针：
fn swap_using_raw(a: *mut i32, b: *mut i32) {
    unsafe {
        // 必须保证 a 和 b 不重叠（否则行为未定义）
        let temp = ptr::read(a);  // 先读，不释放
        ptr::write(a, ptr::read(b));
        ptr::write(b, temp);
    }
}

// 使用 std::ptr::swap 更安全（内部处理了重叠情况）
fn swap_using_std(a: *mut i32, b: *mut i32) {
    unsafe {
        std::ptr::swap(a, b);
    }
}

10.2.1 指针有效性（Validity）

解引用裸指针前，必须确保指针指向的内存是有效的：

use std::ptr;

fn main() {
    let x = 42;
    let raw = &x as *const i32;

    unsafe {
        // 1. 指针不为 null ✅
        // 2. 指针指向的内存已初始化 ✅
        // 3. 指针指向的内存未被释放 ✅
        // 4. 指针已正确对齐 ✅
        println!("{}", *raw);
    }

    // 悬空指针的危险：
    let raw2;
    {
        let y = 100;
        raw2 = &y as *const i32;
    }
    // y 已离开作用域，raw2 现在是悬空指针
    // unsafe { println!("{}", *raw2); }  // 💀 UB！
}

10.3 ManuallyDrop 和 Drop::drop 手动管理

use std::mem::ManuallyDrop;

fn main() {
    // ManuallyDrop：阻止自动 drop
    let mut value = ManuallyDrop::new(String::from("hello"));
    // value 离开作用域时不会自动释放

    // 手动读取
    println!("{}", &**value);

    // 手动释放
    unsafe {
        ManuallyDrop::drop(&mut value);
    }
    // 现在 value 已被释放，不能再使用

    // 应用场景：在释放前修改值
    let mut s = String::from("hello");
    let ptr = s.as_mut_ptr();
    let len = s.len();
    let cap = s.capacity();
    // 手动重建 String
    let rebuilt = unsafe { String::from_raw_parts(ptr, len, cap) };

    // 性能意义：ManuallyDrop 避免了不必要的 clone
    // 传统做法：
    let cloned = s.clone();       // 分配 + 拷贝
    drop(s);                       // 释放原内存
    // ManuallyDrop 做法：
    let moved = ManuallyDrop::new(s);  // 零拷贝
    let ptr = moved.as_mut_ptr();      // 直接获取指针
    // moved 不会自动 drop
}

10.3.1 forget 和 leak

use std::mem;

fn main() {
    let s = String::from("hello");

    // forget: 阻止 drop，但内存泄漏
    mem::forget(s);
    // s 的内存永远不会被释放 —— 适合交给 C 管理的场景

    // leak: 返回 &'static mut T，但不释放
    let leaked: &'static mut str = s.leak();
    // 内存直到进程退出才会释放

    // 性能对比：
    // drop(s):   释放内存 + 调用 Drop trait（~50ns）
    // forget(s): 不释放（内存泄漏，但避免了 drop 开销）
    // leak(s):   不释放，但返回引用（适合 'static 生命周期）
}

10.4 对齐与指针算术

use std::alloc::{alloc, dealloc, Layout};
use std::ptr;

fn main() {
    // 查询对齐要求
    println!("align_of<i32>: {}", std::mem::align_of::<i32>());      // 4
    println!("align_of<u64>: {}", std::mem::align_of::<u64>());      // 8
    println!("align_of<u128>: {}", std::mem::align_of::<u128>());    // 16
    println!("align_of<[T; N]>: {}", std::mem::align_of::<[u8; 16]>()); // 1

    // 手动分配内存
    let layout = Layout::from_size_align(1024, 16).unwrap();
    let ptr = unsafe { alloc(layout) };

    if ptr.is_null() {
        std::alloc::handle_alloc_error(layout);
    }

    // 指针算术：按元素偏移（不是按字节）
    unsafe {
        // 写入数据
        ptr::write(ptr, 0x41);  // 写入 'A'
        ptr::write(ptr.add(1), 0x42);  // 写入 'B'（偏移 1 个 u8）

        // 读取数据
        let a = ptr::read(ptr);
        let b = ptr::read(ptr.add(1));

        // 释放内存
        dealloc(ptr, layout);
    }

    // 对齐分配：64 字节对齐
    let layout = Layout::from_size_align(100, 64).unwrap();
    let aligned_ptr = unsafe { alloc(layout) };
    assert!(aligned_ptr as usize % 64 == 0);  // 64 字节对齐
}

10.4.1 offset 和 with_exposed_provenance

use std::ptr;

fn main() {
    let data = [10, 20, 30, 40, 50];
    let ptr = data.as_ptr();

    // offset: 按元素数量偏移（自动乘以 size_of<T>）
    unsafe {
        let third = ptr.offset(2);  // 指向 data[2]
        println!("{}", *third);     // 30

        // 负偏移
        let first = third.offset(-2);
        println!("{}", *first);     // 10
    }

    // with_exposed_provenance: 将 usize 转回指针
    // 需要 nightly Rust（Rust 1.80+ 已稳定）
    let addr = ptr as usize;
    let recovered = usize::with_exposed_provenance(addr);
    unsafe {
        assert_eq!(*recovered, 10);  // 恢复原始指针
    }

    // from_exposed_provenance: 从不透明的 usize 恢复指针
    let recovered2 = usize::from_exposed_provenance(addr);
    unsafe {
        assert_eq!(*recovered2, 10);
    }

10.5 自定义分配器

Rust 的分配器接口（Allocator trait）允许你替换默认的 global allocator，实现针对特定场景优化的内存管理：

use std::alloc::{Allocator, Global, Layout, alloc, dealloc};
use std::ptr;

/// 一个简单的 bump allocator
/// 分配 O(1)，但不支持单个释放
struct BumpAllocator {
    buffer: *mut u8,
    capacity: usize,
    offset: usize,
}

unsafe impl Allocator for BumpAllocator {
    fn allocate(&self, layout: Layout) -> Result<ptr::NonNull<u8>, AllocError> {
        // 对齐偏移
        let aligned_offset = (self.offset + layout.align() - 1) & !(layout.align() - 1);
        let new_offset = aligned_offset + layout.size();

        if new_offset > self.capacity {
            return Err(AllocError);
        }

        let ptr = unsafe { self.buffer.add(aligned_offset) };
        unsafe { ptr::write(ptr, 0); }  // 清零内存

        Ok(unsafe { ptr::NonNull::new_unchecked(ptr) })
    }

    unsafe fn deallocate(&self, _ptr: ptr::NonNull<u8>, _layout: Layout) {
        // bump allocator 不支持单个释放
        // 只在 reset 时一次性释放
    }
}

impl BumpAllocator {
    fn new(buffer: *mut u8, capacity: usize) -> Self {
        BumpAllocator { buffer, capacity, offset: 0 }
    }

    fn reset(&mut self) {
        self.offset = 0;
    }
}

// 使用自定义分配器
fn main() {
    let layout = Layout::from_size_align(1024 * 1024, 64).unwrap();
    let buffer = unsafe { alloc(layout) };

    let mut allocator = BumpAllocator::new(buffer, 1024 * 1024);

    // 快速分配（无需遍历 freed list）
    let a = allocator.allocate(Layout::new<u32>()).unwrap();
    let b = allocator.allocate(Layout::new<u64>()).unwrap();

    // 重置（一次性释放所有分配）
    allocator.reset();

    unsafe {
        dealloc(buffer, layout);
    }
}

10.6 OS 级编程

10.6.1 系统调用

通过 syscall 接口直接调用操作系统内核：

#[cfg(target_os = "linux")]
mod linux_syscalls {
    use std::os::raw::c_int;

    // Linux x86_64 系统调用号
    // open: 2, read: 0, write: 1, close: 3, mmap: 9, munmap: 11

    extern "C" {
        fn syscall(num: c_int, ...) -> c_int;
    }

    pub fn open(path: &[u8], flags: c_int, mode: c_int) -> c_int {
        let ptr = path.as_ptr();
        unsafe { syscall(2, ptr as *const c_int, flags, mode) as c_int }
    }

    pub fn read(fd: c_int, buf: &mut [u8]) -> c_int {
        unsafe { syscall(0, fd, buf.as_mut_ptr() as *const c_int, buf.len()) as c_int }
    }

    pub fn write(fd: c_int, buf: &[u8]) -> c_int {
        unsafe { syscall(1, fd, buf.as_ptr() as *const c_int, buf.len()) as c_int }
    }

    pub fn close(fd: c_int) -> c_int {
        unsafe { syscall(3, fd) as c_int }
    }

    pub fn mmap(addr: *mut u8, len: usize, prot: c_int, flags: c_int, fd: c_int, offset: i64) -> *mut u8 {
        unsafe { syscall(9, addr as *const c_int, len, prot, flags, fd, offset as *const c_int) as *mut u8 }
    }

    pub fn munmap(addr: *mut u8, len: usize) -> c_int {
        unsafe { syscall(11, addr as *const c_int, len) as c_int }
    }
}

10.6.2 内存映射（mmap）

内存映射将文件直接映射到进程的虚拟地址空间，实现零拷贝访问：

use memmap2::MmapMut;

fn main() -> std::io::Result<()> {
    // 内存映射文件：将文件直接映射到进程的虚拟地址空间
    // 操作系统负责按需加载页面，零拷贝

    let mut file = std::fs::OpenOptions::new()
        .read(true)
        .write(true)
        .create(true)
        .open("mmap_test.bin")?;

    // 设置文件大小
    use std::io::Write;
    file.write_all(&[0u8; 4096])?;

    // 创建可变的内存映射
    let mut mmap = unsafe { MmapMut::map_mut(&file)? };

    // 直接写入内存（操作系统处理页缓存）
    mmap[..10].copy_from_slice(b"HelloMMap");
    mmap.flush()?;

    // 读取
    println!("First 10 bytes: {:?}", &mmap[..10]);

    // 内存映射的性能优势：
    // 1. 零拷贝：内核直接映射文件到用户空间
    // 2. 按需加载：只加载访问的页面
    // 3. 自动缓存：操作系统管理页缓存
    // 4. 多进程共享：多个进程可以映射同一文件

    // 性能对比（读取 1GB 文件）：
    // read():     ~200ms（两次拷贝：磁盘→内核→用户）
    // mmap():     ~50ms（零拷贝，OS 页缓存）
    // 加速：4x
}

10.6.3 /proc 文件系统访问

// Linux 的 /proc 文件系统提供了内核与用户空间的接口
// 通过 FFI 或直接读取 /proc 文件，可以进行系统级编程

use std::fs;
use std::path::Path;

// 读取 /proc/stat 获取系统信息
fn get_cpu_count() -> std::io::Result<usize> {
    let content = fs::read_to_string("/proc/stat")?;
    content.lines()
        .find(|l| l.starts_with("cpu "))
        .map(|l| l.split_whitespace().count() - 1)
        .ok_or_else(|| std::io::Error::new(std::io::ErrorKind::Other, "no cpu line"))
}

// 读取 /proc/meminfo 获取内存信息
fn get_total_memory_kb() -> std::io::Result<u64> {
    let content = fs::read_to_string("/proc/meminfo")?;
    content.lines()
        .find(|l| l.starts_with("MemTotal:"))
        .and_then(|l| l.split_whitespace().nth(1).map(|s| s.parse::<u64>().unwrap()))
        .ok_or_else(|| std::io::Error::new(std::io::ErrorKind::Other, "no MemTotal"))
}

// 读取 /proc/[pid]/status 获取进程信息
fn get_process_status(pid: i32) -> std::io::Result<String> {
    let path = format!("/proc/{}/status", pid);
    fs::read_to_string(Path::new(&path))
}

10.7 Unsafe 编程的黄金法则

⚠️ 必须遵守的规则
  1. 永远不要信任外部输入：FFI 返回的指针可能是 null 或悬空的
  2. 保持不变量：如果类型有内部不变量，unsafe 代码必须维护它们
  3. 最小化 unsafe 块：每个 unsafe 块都应该有明确的注释说明为什么它是安全的
  4. 用 safe wrapper 封装：unsafe 代码应该被 safe API 包围
  5. 线程安全需要显式证明：手动实现 Send/Sync 需要严谨的论证
  6. 测试！测试！测试！：使用 Miri 检测未定义行为
