05 - Cyberpunk 2077 — 路径追踪与优化历程

CD Projekt Red 的《赛博朋克 2077》经历了从 2020 年首发到 2025 年完全重制的漫长优化历程。其中最具革命性的变化是从传统的光栅化 + 屏幕空间 GI 转向全路径追踪渲染。本章将详细拆解这一技术转型的每一步。

前置知识：路径追踪基础、Ray Tracing API、DLSS 原理、PBR 渲染

一、REDengine 5 的路径追踪改造

《赛博朋克 2077》最初使用 REDengine 4，在 2020 年以传统光栅化渲染为主。2022 年的 Phantom Liberty 资料片引入了初步的光线追踪支持，而 2025 年的"路径追踪完全重制版"则将整个渲染管线迁移到了路径追踪架构上。

二、全路径追踪渲染器

路径追踪（Path Tracing）是一种基于蒙特卡洛积分的全局光照算法。与传统的光栅化渲染不同，路径追踪通过模拟光线的物理传播来计算最终图像。

单向路径追踪算法

CP2077 使用的是单向路径追踪（Unidirectional Path Tracing），从相机出发追踪每条光线：

// PathTracer.cpp - REDengine 5 路径追踪核心
struct PathTracePayload
{
    float3 Radiance;          // 累积的光辐射度
    float3 Throughput;        // 光线传输率（权重衰减）
    uint   BounceCount;       // 当前反弹次数
    bool   bTerminated;       // 是否已终止
    Ray    CurrentRay;        // 当前追踪射线
};

float3 PathTracePixel(float2 ScreenUV, uint PixelSeed)
{
    PathTracePayload Payload;
    Payload.Radiance = float3(0, 0, 0);
    Payload.Throughput = float3(1, 1, 1);
    Payload.BounceCount = 0;
    Payload.bTerminated = false;

    // 初始相机射线
    Payload.CurrentRay = GenerateCameraRay(ScreenUV, PixelSeed);

    // 主路径追踪循环
    while (Payload.BounceCount < MaxPathLength && !Payload.bTerminated)
    {
        // 1. 射线-几何体求交
        HitRecord Hit;
        bool HitSomething = TraceScene(Payload.CurrentRay, Hit);

        if (!HitSomething)
        {
            // 命中背景（天空盒）
            Payload.Radiance += Payload.Throughput * EvaluateBackground(Payload.CurrentRay.Direction);
            break;
        }

        // 2. 直接光照采样
        float3 DirectLight = SampleDirectLight(Hit, PixelSeed);
        Payload.Radiance += Payload.Throughput * DirectLight;

        // 3. 间接光照采样（BRDF 重要性采样）
        float2 BRDFSample = SampleUniform2D(PixelSeed);
        Ray NextRay = SampleBRDF(Hit, BRDFSample);

        // 4. 计算俄罗斯轮盘赌终止概率
        float ContinueProb = max(Payload.Throughput.r,
                                  max(Payload.Throughput.g,
                                      Payload.Throughput.b));
        ContinueProb = min(ContinueProb, 0.9f); // 最大 90% 继续

        if (RandFloat(PixelSeed) > ContinueProb)
        {
            Payload.bTerminated = true;
        }
        else
        {
            // 5. 更新传输率
            float3 BRDFValue = EvaluateBRDF(Hit, Payload.CurrentRay.Direction, NextRay.Direction);
            float PDF = EvaluatePDF(Hit, Payload.CurrentRay.Direction, NextRay.Direction);

            if (PDF > 0.001f)
            {
                Payload.Throughput *= BRDFValue / PDF;
                Payload.CurrentRay = NextRay;
                Payload.BounceCount++;
            }
            else
            {
                Payload.bTerminated = true;
            }
        }
    }

    return Payload.Radiance;
}

从屏幕空间到全局光照

2020 年原版 CP2077 的 GI 方案：

技术覆盖范围局限性
预烘焙 GI（Lightmaps）静态物体无法响应动态物体
SSGI（屏幕空间 GI）屏幕内可见表面屏幕外 GI 丢失、反射/折射物体不准确
Light Probes稀疏采样点插值质量差，密集场景不准确

2025 年路径追踪版的 GI 方案：

技术覆盖范围优势
路径追踪 GI全局（所有光线反弹）物理准确，支持动态物体
Ray Reconstruction降噪后恢复完整 GI低采样数下仍可获得高质量结果

三、Ray Reconstruction：DLSS 3.5 的核心

路径追踪的最大问题是噪声——因为使用蒙特卡洛采样，每个像素的采样数有限，导致结果充满噪点。DLSS 3.5 的 Ray Reconstruction 技术使用 AI 模型来去除路径追踪产生的噪声。

传统降噪 vs Ray Reconstruction

去噪质量容易模糊细节保留高频细节
闪烁问题运动时容易出现显著减少

GPU 耗时~3-5ms（空间滤波）~2-3ms（DLSS 推理）

Ray Reconstruction 输入特征

模型接收以下特征图作为输入：
L - 低采样路径追踪辐射度图
V - 运动向量（Optical Flow）
D - 深度图
N - 法线图（G-Buffer）
A - альbedo/反照率图
H - 历史帧（Temporal Accumulation）

// RayReconstruction.h - 降噪模型接口
class RayReconstructionModel
{
public:
    // 降噪推理
    float3 Denoise(const Texture2D& LowSampleRadiance,
                   const Texture2D& MotionVectors,
                   const Texture2D& Depth,
                   const Texture2D& Normals,
                   const Texture2D& Albedo,
                   const Texture2D& HistoryFrame)
    {
        // 1. 特征提取（卷积层）
        auto Features = ExtractFeatures(LowSampleRadiance,
                                        MotionVectors,
                                        Depth, Normals, Albedo);

        // 2. 时空聚合（Temporal Accumulation）
        auto TemporalAgg = AlignWithHistory(Features, HistoryFrame, MotionVectors);

        // 3. CNN 推理（类似 UNet 的编码器-解码器结构）
        auto Denoised = CNNInference(TemporalAgg);

        // 4. 后处理（色调映射 + 限制）
        return ApplyTonemapAndClamp(Denoised);
    }

private:
    // 特征提取：将多通道输入合并为统一特征表示

数学模型

Ray Reconstruction 本质上是一个条件去噪问题：

f_noisy(u) = (1/N) * Σ [ (f_li · pdf(ω_i)) / pdf_sample(ω_i) ] + ε

其中：
  f_noisy  - 低采样数的路径追踪结果（含噪声）
  f_li     - 第 i 条路径的直接/间接光照贡献
  N        - 每个像素的采样数（通常 1-4）
  pdf      - 概率密度函数
  ε        - 蒙特卡洛估计误差（噪声来源）

目标：学习映射 g(f_noisy, context) → f_clean
其中 context = {V, D, N, A, History}

四、DLSS 3.5 Frame Generation

除了 Ray Reconstruction 降噪，DLSS 3.5 还包含了帧生成（Frame Generation）技术，通过 AI 生成的中间帧来提升帧率。

光学流加速器（OFA）

帧生成的核心是 Optical Flow Estimation——准确计算相邻帧之间的像素运动：

// OpticalFlowEstimator.cpp - OFA 核心逻辑
struct OpticalFlowField
{
    float2 Velocity;  // 每个像素的运动向量 (dx, dy)
    float  Confidence; // 运动估计的可信度 (0.0 ~ 1.0)
};

OpticalFlowField EstimateFlow(Frame PrevFrame, Frame CurrFrame)
{
    // 1. 特征提取
    auto PrevFeatures = ExtractFeatures(PrevFrame.Depth, PrevFrame.Normals);
    auto CurrFeatures = ExtractFeatures(CurrFrame.Depth, CurrFrame.Normals);

    // 2. 代价体积（Cost Volume）构建
    // 对 PrevFrame 的每个像素，在 CurrFrame 的邻域内计算匹配代价
    auto CostVolume = BuildCostVolume(PrevFeatures, CurrFeatures, SearchRadius);

    // 3. 最小化代价，找到最优匹配
    auto Disparities = MinimizeCostVolume(CostVolume);

    // 4. 后处理：一致性校验 + 置信度评估
    return PostProcessDisparities(Disparities, PrevFrame, CurrFrame);
}

帧生成管线

1

渲染原始帧

路径追踪渲染器生成一帧低采样数的图像（1-4 samples/pixel）

2

运动向量计算

使用几何信息（顶点位移）计算每像素的运动向量

3

AI 帧生成

光学流模型估计前后帧之间的像素运动，AI 模型生成中间帧

4

合成输出

将原始帧和 AI 生成的帧合成，输出最终图像

RTX 4070 的妥协方案

RTX 4070（12GB VRAM）在路径追踪模式下需要做出一些妥协：

  • 降低路径追踪距离：从 150m 降至 80m，远处使用传统 GI 混合
  • 减少采样数：从 4 samples 降至 2 samples，依赖更强的降噪
  • 关闭部分后处理：DOF（景深）和 Volumetric Fog（体积雾）降级
  • DLSS 模式：必须使用"性能"或"平衡"模式，不能使用"质量"

本章小结

《赛博朋克 2077》的路径追踪改造是游戏行业从光栅化转向全局光照的里程碑。其核心技术组合——路径追踪 + Ray Reconstruction 降噪 + DLSS 3.5 帧生成——代表了当前实时渲染的最高水平。这个方案的关键启示是：纯路径追踪在当前硬件下不够高效，但路径追踪 + AI 辅助是当前最佳实践。

核心经验总结：

  1. 路径追踪是未来：物理准确的全局光照是光栅化无法企及的
  2. AI 降噪是关键使能技术：没有 Ray Reconstruction，路径追踪在实时应用中不可行
  3. 渐进式迁移：从光栅化到混合 RT 再到全路径追踪，每一步都有明确的收益
  4. 硬件门槛：目前路径追踪仍然需要 RTX 40 系列以上的硬件
