第四章：DOM 树构建

浏览器通过网络层接收到 HTML 文档后，第一步要做的事情就是把它变成一棵树——DOM 树（Document Object Model Tree）。这棵树不仅是页面结构的表示，更是浏览器与 JavaScript 交互的桥梁。本章将深入 HTML 解析器的内部，理解 DOM 是如何诞生的。

4.1 HTML 解析器的工作原理

HTML 解析器是一个流式处理器——它在接收到 HTML 数据的瞬间就开始工作，而不是等到整个文档下载完毕。这种设计允许"边下载边解析"，显著提升了首屏渲染速度。

4.1.1 词法分析（Tokenization）

解析的第一步是将 HTML 字符流转换为 Token 序列。HTML 解析器遵循一套复杂的规则来处理各种边界情况：

// 词法分析示例：HTML 字符流 → Token 序列
// 输入: "<p>Hello <b>World</b>!</p>"

// 输出的 Token 序列:
[
  { type: 'START_TAG',   name: 'p',    attrs: [] },
  { type: 'TEXT',        chars: 'Hello ' },
  { type: 'START_TAG',   name: 'b',    attrs: [] },
  { type: 'TEXT',        chars: 'World' },
  { type: 'END_TAG',     name: 'b' },
  { type: 'TEXT',        chars: '!' },
  { type: 'END_TAG',     name: 'p' },
]

词法分析器需要处理很多特殊情况：

HTML 特殊字符处理

  1. 注释—— 以 <!-- 开头，--> 结尾。注释内容不参与 DOM 树构建。
  2. 实体编码——&amp;、&lt;、&nbsp; 等特殊字符会被解码为对应的 Unicode 字符。
  3. CDATA——<![CDATA[...]]> 原始内容块，不进行任何解析。
  4. DOCTYPE——<!DOCTYPE html> 声明，触发标准模式解析。
  5. 不可见标签——<script> 和 <style> 的内容会被特殊处理（暂停解析去下载和执行）。

4.1.2 树构建（Tree Construction）

树构建器（又称"渲染引擎的 DOM 构建器"）接收 Token 流，根据 HTML 规范中的插入模式（Insertion Mode）规则，将节点插入到 DOM 树中。


树构建的核心逻辑
─────────────────

for each token in token_stream:
    current_node = getActiveFormattingElement()

    switch (insertion_mode):
        case 'in_body':
            if token is START_TAG_html:
                append token to document
            elif token is TEXT:
                create text node, append to current
            elif token is START_TAG:
                create element node, push to stack
                set insertion_mode based on element
            elif token is END_TAG:
                pop from stack if name matches
            elif token is COMMENT:
                create comment node, append to current

        case 'in_table':
            # 表格有特殊的解析规则
            # 例如: 隐式创建 tbody

        case 'in_cell':
            # 单元格内的特殊处理
            # 例如: 遇到新单元格则闭合当前单元格
            ...

树构建器维护着一个打开的元素栈（Stack of Open Elements）。每当遇到开始标签，就将对应元素压入栈顶；遇到结束标签时，从栈顶向下查找匹配的元素并弹出。这个栈也决定了元素的嵌套关系。

4.1.3 错误恢复（Error Recovery）

现实世界中的 HTML 经常是不规范的——缺少闭合标签、标签嵌套错误、属性值未加引号等。HTML 解析器有一套完善的容错机制：

<!-- 不规范但能被正确解析的 HTML -->
<div class="container">
  <p>第一段
  <p>第二段</p>    ← 缺少闭合标签
  <span>文字</div>  ← 标签不匹配
</div>
💡 为什么 HTML 解析如此宽容？

Web 的兼容性要求解析器必须能够处理几十年来积累的不规范 HTML。一个现代浏览器如果拒绝解析有轻微错误的页面，会导致大量现有网站无法正常工作。这种"宽容解析"是 Web 平台向后兼容的代价。

4.2 DOM 节点模型

DOM 树中的每个节点都是一个对象，不同类型的节点有不同的属性和方法。理解节点模型对于编写高效的 DOM 操作代码至关重要。

// DOM 节点类型常量
Node.ELEMENT_NODE         // 1  - 元素节点 (div, p, span...)
Node.ATTRIBUTE_NODE       // 2  - 属性节点 (class, id...)
Node.TEXT_NODE            // 3  - 文本节点
Node.COMMENT_NODE         // 8  - 注释节点
Node.DOCUMENT_NODE        // 9  - 文档节点
Node.DOCUMENT_TYPE_NODE   // 10 - DOCTYPE 节点
Node.DOCUMENT_FRAGMENT_NODE // 11 - 文档片段

// 节点之间的关系
const div = document.querySelector('.container');

div.childNodes        // 所有子节点（包括文本和注释）
div.children          // 只有元素子节点（推荐用这个）
div.firstChild        // 第一个子节点
div.lastChild         // 最后一个子节点
div.parentNode        // 父节点
div.parentElement     // 父元素节点（null 如果无父元素）
div.previousSibling   // 前一个兄弟节点
div.nextSibling       // 后一个兄弟节点
div.ownerDocument     // 所属文档

4.2.1 Element 节点

Element 是最常用的 DOM 节点类型，代表 HTML 标签。它继承了 HTMLElement，拥有大量的属性和方法：

// Element 常用 API
const el = document.getElementById('myDiv');

// 属性操作
el.tagName          // "DIV"
el.className        // "container active"
el.id               // "myDiv"
el.getAttribute('data-id')  // 自定义属性
el.dataset.id       // 等价于上面的写法（更简洁）

// 内容操作
el.innerHTML        // HTML 字符串（会触发解析）
el.outerHTML        // 包含自身标签的 HTML 字符串
el.textContent      // 纯文本（不含标签，性能更好）
el.innerText        // 可见文本（考虑 CSS 样式，如 display:none 的文本不包含）

// 样式操作
el.style.color      // "red"（只读，返回 computed style）
el.classList.add('active')
el.classList.remove('hidden')
el.classList.toggle('expanded')
el.matches(':hover')  // 是否匹配选择器

// 查询子元素
el.querySelector('p')       // 第一个匹配的子孙元素
el.querySelectorAll('.item') // 所有匹配的子孙元素（NodeList）

// 创建和插入
const newEl = document.createElement('div');
el.appendChild(newEl);           // 追加到最后
el.insertBefore(newEl, child);   // 在指定子节点前插入
el.prepend(newEl);               // ES2017: 追加到最前
el.append(child1, child2);       // ES2017: 追加多个节点
el.replaceWith(newEl);           // 替换当前节点
el.remove();                     // 删除当前节点

4.2.2 属性节点与自定义属性

HTML 属性存储在元素的属性列表中。每个属性都有一个名称和一个值：

<div id="main" class="container" data-user-id="42" custom-attr="value">
🚀 为什么推荐用 data-* 属性？

自定义属性必须以 data- 开头，这样浏览器会自动将它们暴露为 element.dataset 对象。这是 HTML5 规范推荐的在 HTML 和 JavaScript 之间传递数据的方式，语义清晰且不会与未来新增的标准属性冲突。

4.3 Shadow DOM：封装的力量

Shadow DOM 是 Web Components 的核心技术之一。它允许你在 DOM 树中创建一个"隔离的子树"，这个子树的样式和结构与外部 DOM 完全隔离。


普通 DOM 树 vs Shadow DOM
──────────────────────────

普通 DOM:
<div class="card">
  <h2>标题</h2>
  <p>内容</p>
  <style>
    h2 { color: red; }  ← 影响全局
  </style>
</div>

Shadow DOM:
<div class="card">
  #shadow-root (open)          ← 隔离边界
  ┌─────────────────────────┐
  │ <style>                │
  │   h2 { color: blue; }   │  ← 样式只影响 shadow 内部
  │ </style>               │
  │ <h2>标题</h2>          │
  │ <slot name="content"></slot>  ← 插槽：外部内容注入点
  └─────────────────────────┘
  <p slot="content">外部传入</p>  ← 通过 slot 注入
</div>
// 创建 Shadow DOM
const card = document.createElement('div');
document.body.appendChild(card);

// 附加 shadow root（open 模式下可以从外部访问）
const shadow = card.attachShadow({ mode: 'open' });

// 在 shadow 内部定义结构和样式
shadow.innerHTML = `
  <style>
    :host {
      display: block;
      border: 1px solid #ccc;
      border-radius: 8px;
      padding: 16px;
    }
    h2 {
      color: #333;
      margin: 0 0 8px 0;
    }
    ::slotted(p) {
      color: #666;
    }
  </style>
  <h2>卡片标题</h2>
  <slot></slot>  
`;

// 外部可以通过 slot 注入内容
const paragraph = document.createElement('p');
paragraph.textContent = '这是通过 slot 注入的内容';
card.appendChild(paragraph);

// mode: 'closed' 时，shadow root 从外部完全不可见
// 但内部仍然正常工作

4.3.1 Slot 和 Slotfill

Shadow DOM 通过 <slot> 元素实现内容分发。外部传入的子节点被称为"slotfill"，它们被插入到 shadow 树中对应的 slot 位置：

概念 说明 示例
Named Slot 具名插槽，通过 name 属性区分 <slot name="header"></slot>
Fallback Content 插槽的默认内容，当外部没有提供时显示 <slot>默认文本</slot>
Slotfill 外部传入并填充到插槽的内容 <p slot="header">标题</p>
:host 伪类 选择 shadow host 元素本身 :host { display: block; }
::slotted() 选择通过 slot 插入的元素 ::slotted(p) { color: red; }

4.4 DOM 操作的坑与优化

4.4.1 重排（Reflow）与重绘（Repaint）

修改 DOM 会触发两种昂贵的操作：

重排 (Reflow) 重绘 (Repaint)
触发条件 改变布局（尺寸、位置） 改变外观（颜色、背景）
成本 高（需要重新计算所有相关布局） 中（只需要填充像素）
常见操作 修改 width/height、添加/删除节点、改变字体、滚动页面 修改 color/background-color/border
优化技巧 批量修改、使用 transform（触发合成而非重排） 通常无法避免，但成本较低 
// ❌ 糟糕的做法：每次修改都触发重排
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  ul.appendChild(li);  // 1000 次重排！
}

// ✅ 好做法：使用 DocumentFragment 批量插入
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);  // 不触发重排
}
ul.appendChild(fragment);      // 只触发 1 次重排

// ✅ 更好的做法：使用 innerHTML 一次性设置
ul.innerHTML = Array.from({ length: 1000 }, (_, i) =>
  `
  • Item ${i}
    • `
).join('');

// ✅ 极致优化：先 detach，再操作，最后 reattach
const parent = ul.parentNode;
parent.removeChild(ul);
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  ul.appendChild(li);  // detached 操作不触发重排
}
parent.appendChild(ul);  // 最后才放回文档

    4.4.2 避免强制同步布局

    当你交替读写 DOM 属性时，浏览器被迫在每个写操作后立即执行重排，而不是批量处理：

    // ❌ 强制同步布局：每次循环都触发重排
boxes.forEach(box => {
  box.style.width = '100px';
  const w = box.offsetWidth;  // 强制浏览器立即计算布局
});

// ✅ 分离读写操作：先批量写，再批量读
boxes.forEach(box => {
  box.style.width = '100px';
});
boxes.forEach(box => {
  const w = box.offsetWidth;  // 此时浏览器可以批量计算
});

    4.5 性能数据：DOM 节点数量与渲染时间的关系

    DOM 节点数 首次渲染时间 内存占用 推荐场景
    < 1,000 < 100ms < 10MB 绝大多数页面
    1,000 - 5,000 100-300ms 10-30MB 中等复杂度页面
    5,000 - 15,000 300-800ms 30-80MB 数据密集型应用（需虚拟列表）
    > 15,000 > 800ms > 80MB ⚠️ 需要架构优化

    Google 的工程团队曾发现，Chrome 设置页面的 DOM 节点数超过 15,000 时，页面交互明显变慢。他们通过将页面拆分为多个独立的 Web Component（每个组件有 Shadow DOM 隔离），将每个组件的 DOM 节点数控制在 1,000 以内，显著改善了性能。

    ⚠️ 1500 节点警告

    Chrome DevTools 的 Elements 面板在节点数超过 1500 时会发出警告。这不是硬性限制，但意味着你的页面可能需要优化。对于数据表格、列表等场景，使用虚拟滚动（Virtual Scrolling）技术只渲染可视区域内的节点。

    4.6 本章小结

    • HTML 解析器分三步工作：词法分析（Tokenization）→ 树构建（Tree Construction）→ 错误恢复（Error Recovery）。
    • DOM 节点有多种类型，Element 是最核心的类型，提供了丰富的属性和方法。
    • Shadow DOM 通过封装和插槽机制，实现了样式和结构的隔离，是 Web Components 的基石。
    • 频繁的 DOM 操作会触发重排和重绘，应使用 DocumentFragment、批量操作、离线操作等技巧优化。
    • DOM 节点数量直接影响渲染性能，建议将单页面节点数控制在 1500 以内。
