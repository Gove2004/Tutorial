第 2 章：三大基石 — NetworkIdentity / NetworkServer / NetworkClient

如果说 Mirror 是一座建筑，那么这三者就是它的承重墙。 不理解它们的精确含义和行为边界，后续所有代码都会埋下隐患。 本章将逐一拆解，并给出真实项目中会遇到的陷阱。

Mirror 96 API 更新
本章已全面适配 Mirror 96.x（v96.11.1+）。主要变化包括： hasAuthority 已更名为 isOwned； NetworkIdentity 的 isServer/isClient/netId 均为只读属性； connectionToServer/connectionToClient 移至 NetworkBehaviour； NetworkManager 回调方法名调整（OnStartServer 而非 StartServer）； NetworkClient.Connect 签名简化为字符串地址。

2.1 NetworkIdentity：网络对象的身份证

NetworkIdentity 是附加在 GameObject 上的组件。 它的作用只有一个：告诉 Mirror"这个对象是网络对象"。

Mirror 通过它来区分：
• 这个对象需要通过网络同步吗？→ 有 NetworkIdentity → 需要
• 这个对象只是本地表现吗？→ 没有 NetworkIdentity → 不需要

2.1.1 关键属性（全部只读）

在 Mirror 96 中，NetworkIdentity 的所有网络状态属性都是只读的。 它们由 Mirror 内部自动管理，你无法也不应在代码中手动赋值：

// NetworkIdentity 上的只读属性
NetworkIdentity identity = GetComponent<NetworkIdentity>();

identity.netId        // uint，由服务器在 Spawn 时分配，全局唯一
identity.isServer     // bool，当前实例是否运行在服务器端
identity.isClient     // bool，当前实例是否运行在客户端
identity.server       // NetworkServer 引用（服务器端有效）

// 注意：以下属性不在 NetworkIdentity 上，而在 NetworkBehaviour 上
// hasAuthority → 已更名为 isOwned（详见 2.2 节）
常见错误：旧版教程或 UNet 迁移代码中可能出现这样的写法： 
// ❌ 错误：这些属性是只读的，不能赋值
identity.isServer = true;
identity.isClient = true;
identity.netId = 12345;
这在 Mirror 96 中会直接编译报错。网络状态由 Mirror 在 Spawn / 连接时自动设置。

NetID（网络 ID）是什么？

每个被 Spawn 到场景中的网络对象都有一个唯一的 netId。 它是一个 uint 类型，由服务器分配，全局唯一。 你通过 netId 可以引用任何已 Spawn 的对象——无论它在哪个客户端上。

NetId 的生命周期：
• Spawn 时分配 → • 对象销毁时回收 → • 不会重复使用（在同一局游戏中）

2.1.2 组件同步机制（替代旧版 Observed 概念）

如果你从 UNet 或旧版 Mirror 迁移，可能会记得 NetworkIdentity 上有一个 Observed Components 列表，需要手动添加同步组件。 在 Mirror 96 中，这个概念已被移除。

Mirror 96 的做法更简洁：

  • GameObject 上只要有 NetworkIdentity，它就是网络对象
  • 同对象上所有继承 NetworkBehaviour 的组件自动参与同步——无需手动注册
  • 同步内容包括：SyncVar 字段、SyncList 集合、RPC 方法、NetworkTransform 等
// 一个典型的网络 Player 对象
[RequireComponent(typeof(NetworkIdentity))]
public class PlayerSetup : NetworkBehaviour
{
    // SyncVar 自动同步 —— 无需在 NetworkIdentity 上注册
    [SyncVar] public string playerName;
    [SyncVar] public int score;

    // RPC 方法自动注册 —— 无需手动添加到任何列表
    [Command]
    void CmdUpdateScore(int newScore) { score = newScore; }

    [ClientRpc]
    void RpcShowScorePopup(int score) { /* UI 更新 */ }
}

你只需确保同步组件继承自 NetworkBehaviour，Mirror 会在运行时自动发现并管理它们。

2.1.3 Prefab 注册：客户端如何找到正确的模板

当服务器 Spawn 一个对象时，客户端需要知道用哪个 Prefab 来实例化。 Mirror 通过 Prefab hash（基于 Prefab 名称或自定义 hash）来匹配。

注册方式有两种：

// 方式 1：在 NetworkManager 的 Inspector 中配置
// NetworkManager → Spawnable Prefabs → Prefab 列表拖入

// 方式 2：代码注册（通常在 OnStartServer / Awake 中）
public class MyNetworkManager : NetworkManager
{
    public GameObject[] additionalPrefabs;

    public override void OnStartServer()
    {
        base.OnStartServer();
        // Mirror 96 使用 NetworkClient.RegisterPrefab 注册
        foreach (var prefab in additionalPrefabs)
        {
            NetworkClient.RegisterPrefab(prefab);
        }
    }
}
常见错误：在运行时用 Instantiate(prefab) 创建对象， 但没有通过 NetworkServer.Spawn() 注册。结果就是这个对象对所有客户端不可见—— 因为你创建了 GameObject，但没有告诉 Mirror 它是网络对象。

2.2 NetworkBehaviour：所有网络脚本的基类

在 Mirror 中，你不能直接把普通的 MonoBehaviour 放在网络对象上。 必须继承 NetworkBehaviour：

// ❌ 错误：普通 MonoBehaviour 不能放在网络对象上
public class PlayerController : MonoBehaviour { ... }

// ✅ 正确：继承 NetworkBehaviour
public class PlayerController : NetworkBehaviour { ... }

NetworkBehaviour 提供了几个关键属性，你在每个网络脚本中都会用到：

public class PlayerController : NetworkBehaviour
{
    void Update()
    {
        // 这些属性决定代码在当前实例上是否应该执行
        if (isServer)
        {
            // 这段代码只在服务器实例上运行
            ValidatePlayerInput();
        }

        if (isClient)
        {
            // 这段代码只在客户端实例上运行（Host 模式下也执行）
            UpdateVisuals();
        }

        if (isLocalPlayer)
        {
            // 这段代码只对"本地玩家的 Player 对象"运行
            HandleLocalInput();
        }

        // isOwned（Mirror 96 中替代了旧版的 hasAuthority）
        // 表示"当前本地客户端是否拥有此对象的控制权"
        if (isOwned)
        {
            // 只有对象的拥有者才能操控它
            // 对于 Player 对象，拥有者通常是绑定它的客户端
            MovePlayer();
        }
    }
}
Mirror 96 命名变化
NetworkBehaviour.hasAuthority 已更名为 isOwned。 旧代码中所有 hasAuthority 引用需要替换为 isOwned。 语义不变：表示当前本地客户端拥有此对象的所有权（authority）。 如果你看到 hasAuthority，说明代码基于旧版 Mirror，需要更新。
关键区别：isLocalPlayer vs isOwned
• isLocalPlayer：这个对象是"我的玩家角色"（即 NetworkClient.localPlayer 指向的对象）。
• isOwned：我有权控制这个对象。

对于 Player 对象，两者通常都为 true。但对于非 Player 的网络对象（如队友的角色、共享道具、被分配了 authority 的 NPC）， 可能有 isOwned 为 true 但 isLocalPlayer 为 false 的情况。 例如：服务器把一个 NPC 的 authority 分配给某个客户端，该客户端的 isOwned 为 true， 但 isLocalPlayer 为 false（因为它不是 Player 对象）。

2.2.1 NetworkBehaviour 上的连接属性

在 Mirror 96 中，connectionToServer 和 connectionToClient 已从 NetworkIdentity 移至 NetworkBehaviour 上。 这两个属性用于获取当前对象的网络连接引用：

public class WeaponSystem : NetworkBehaviour
{
    [Command]
    void CmdFireWeapon(int weaponId, Vector3 target)
    {
        // 在 Command 内部，Mirror 96 可通过可选参数自动获取发送方
        // connectionToClient 指向"拥有此对象的客户端连接"
        // 这在服务器端有效
        Debug.Log($"玩家 {connectionToClient} 发射了武器 {weaponId}");
    }

    void OnStartClient()
    {
        // 在客户端端，connectionToServer 指向"此客户端到服务器的连接"
        // 这在客户端端有效
        if (connectionToServer != null)
            Debug.Log("已连接到服务器");
    }
}

2.2.2 NetworkBehaviour 的生命周期回调

每个 NetworkBehaviour 都有一组生命周期回调，在对象 Spawn / 销毁时被调用：

回调方法调用端调用时机
OnStartServer()服务器对象在服务器上 Spawn 后
OnStartClient()客户端对象在客户端上 Spawn 后
OnStartAuthority()拥有者客户端客户端获得对象控制权时
OnStopAuthority()拥有者客户端客户端失去对象控制权时
OnStartLocalPlayer()本地客户端此对象被设为本地玩家的 Player 对象时
OnStopServer()服务器对象在服务器上销毁前
OnStopClient()客户端对象在客户端上销毁前
 
public class PlayerSetup : NetworkBehaviour
{
    [SyncVar] public string playerName;

    // 服务器端初始化
    public override void OnStartServer()
    {
        base.OnStartServer();
        // 此时 isServer == true，可以安全使用
        playerName = $"Player_{netId}";
    }

    // 客户端端初始化
    public override void OnStartClient()
    {
        base.OnStartClient();
        // 此时 isClient == true，SyncVar 已同步
        UpdateNameDisplay();
    }

    // 获得控制权时（客户端）
    public override void OnStartAuthority()
    {
        base.OnStartAuthority();
        // 此时 isOwned == true
        EnableLocalCamera();
    }

    // 被设为本地玩家时（客户端）
    public override void OnStartLocalPlayer()
    {
        base.OnStartLocalPlayer();
        // 此时 isLocalPlayer == true
        // 适合做：启用输入控制、绑定摄像机、初始化 UI
        HUDManager.Instance.BindPlayer(this);
    }
}

2.3 NetworkServer：服务器端的静态管理器

NetworkServer 是一个静态类（不是 MonoBehaviour 组件）， 它掌控着服务器上的一切网络状态：

// 核心属性
NetworkServer.active           // bool，服务器是否正在运行
NetworkServer.connections      // Dictionary<int, NetworkConnectionToClient>，所有已连接的客户端
NetworkServer.localConnection  // 本地连接（Host 模式下使用）

// 核心方法
NetworkServer.Spawn(GameObject obj);              // 生成网络对象
NetworkServer.Destroy(GameObject obj);            // 从服务器上销毁对象
NetworkServer.Disconnect();                       // 断开所有客户端连接并关闭服务器
NetworkServer.AddPlayerForConnection(conn, player); // 为连接绑定 Player 对象
NetworkServer.RemovePlayerForConnection(conn, player, true); // 移除连接上的 Player 对象

// 注册消息处理器
NetworkServer.RegisterHandler<MyMessage>(OnMyMessage);
注意：NetworkServer 不是组件
NetworkServer 是静态类，不需要也不应该挂载到 GameObject 上。 它的初始化由 NetworkManager 自动完成。 你通常只通过它调用 Spawn()、Destroy() 和注册消息处理器。

2.3.1 服务器上的对象管理

当一个对象通过 NetworkServer.Spawn() 生成后，Mirror 会在服务器内部维护一个字典： netId → NetworkIdentity。这个映射贯穿整个游戏生命周期。

// 在服务器端生成一个敌人
GameObject enemyPrefab = Resources.Load<GameObject>("Enemies/Boss");

// 先设置位置/旋转，再 Spawn
GameObject enemyInstance = Instantiate(enemyPrefab, spawnPosition, spawnRotation);

// 关键：用 NetworkServer.Spawn 而不是单纯的 Instantiate
NetworkServer.Spawn(enemyInstance);

// Spawn 后可以继续修改（会自动同步给客户端）
// 例如通过 SyncVar 或 RPC 更新状态
致命错误：以下代码在服务器上是无效的 Spawn： 
// ❌ 错误：只用 Instantiate，没调用 NetworkServer.Spawn
GameObject enemy = Instantiate(enemyPrefab, position, rotation);
这个对象存在于服务器的 GameObject 层级中，但 Mirror 不知道它的存在。 客户端永远不会收到它的 Spawn 消息，服务器上也无法对它调用 RPC。

2.3.2 注册消息处理器

Mirror 96 的消息处理器签名：

// 定义消息结构体
public struct MyCustomMessage : NetworkMessage
{
    public int playerId;
    public string action;
}

// 服务器端注册处理器
// 注意：Mirror 96 中，handler 的第一个参数是 NetworkConnectionToClient
NetworkServer.RegisterHandler<MyCustomMessage>(OnMyCustomMessage);

void OnMyCustomMessage(NetworkConnectionToClient conn, MyCustomMessage msg)
{
    Debug.Log($"服务器收到来自 {conn} 的消息: playerId={msg.playerId}, action={msg.action}");
}

你也可以在注册时指定是否需要认证：

// requiresAuthentication: false 表示未认证的客户端也能发送此消息
// 适合用于登录认证消息本身
NetworkServer.RegisterHandler<LoginMessage>(OnLogin, requireAuthentication: false);

2.4 NetworkClient：客户端的静态管理器

NetworkClient 同样是一个静态类， 负责客户端的网络连接和消息处理：

// 核心属性
NetworkClient.active          // bool，客户端是否活跃
NetworkClient.isConnected     // bool，是否已连接到服务器
NetworkClient.connection      // NetworkConnection，当前连接对象
NetworkClient.localPlayer     // NetworkIdentity，本地玩家的 Player 对象

// 核心方法
NetworkClient.Connect(address);      // 连接到服务器（address 是字符串，如 "localhost" 或 "192.168.1.100"）
NetworkClient.Disconnect();          // 断开连接
NetworkClient.RegisterPrefab(prefab); // 注册可 Spawn 的 Prefab
NetworkClient.RegisterHandler<T>(handler); // 注册消息处理器
Mirror 96 连接方式变化
NetworkClient.Connect() 在 Mirror 96 中只接受一个字符串地址参数 （或 Uri）。端口不再在此处指定——它配置在 Transport 组件上。

旧写法（已过时）： 
// ❌ Mirror 96 中不支持这种写法
NetworkClient.Connect(new ConnectMessage {
    host = "192.168.1.100",
    port = 7777
});
正确写法： 
// ✅ Mirror 96 正确写法
NetworkClient.Connect("192.168.1.100");
// 端口由 Transport 组件决定，如 KCP Transport 的 Port 字段

2.4.1 客户端的消息处理

客户端注册消息处理器的签名与服务器端略有不同——不需要 NetworkConnection 参数：

// 客户端注册处理器（注意：只需要消息参数，不需要连接参数）
NetworkClient.RegisterHandler<ScoreUpdateMessage>(OnScoreUpdate);

void OnScoreUpdate(ScoreUpdateMessage msg)
{
    // 客户端收到服务器发来的分数更新
    scoreUI.text = $"分数: {msg.score}";
}

2.4.2 客户端的对象接收

当服务器 Spawn 一个对象时，客户端并不会"手动创建"它。 流程是这样的：

1

服务器发送 Spawn 消息

服务器向所有客户端广播一条消息，包含：
• Prefab hash（Prefab 标识）
• netId（对象唯一 ID）
• 初始状态数据（序列化后的 SyncVar 值）
• 所有权信息（如果分配了 authority）

2

客户端查找 Prefab

客户端收到消息后，根据 Prefab hash 在已注册的 Prefab 池中查找对应模板。 如果找不到，会输出警告日志，对象将无法在客户端生成。

3

客户端 Instantiate

用找到的 Prefab 模板实例化对象，设置 netId，反序列化 SyncVar 初始值。

4

客户端回调

触发 OnStartClient() 等生命周期方法。如果是拥有者， 还会触发 OnStartAuthority() 和 OnStartLocalPlayer()。

这意味着：客户端的 Spawn 对象必须是已注册的 Prefab。 你不能用 Resources.Load 动态加载一个从未注册过的 Prefab 然后 Spawn—— 客户端找不到 hash 对应的模板。

2.5 NetworkManager：开箱即用的胶水

NetworkManager 是 Mirror 提供的最高层抽象。 它把连接流程、场景管理、Player Spawn、对象重置等琐碎工作都封装好了。

public class MyNetworkManager : NetworkManager
{
    [Header("Spawn 点")]
    public Transform[] spawnPoints;

    // 服务器启动回调（注意：不是 StartServer()）
    public override void OnStartServer()
    {
        base.OnStartServer();
        // playerPrefab 已在 NetworkManager 的 Inspector 中设置
        // Mirror 会自动处理 Player Prefab 注册，无需手动调用
        Debug.Log("服务器已启动");
    }

    // 新客户端连接时的回调
    public override void OnServerAddPlayer(NetworkConnection conn)
    {
        base.OnServerAddPlayer(conn);
        // base 方法会自动用 playerPrefab 实例化并绑定到连接
        // 如果你需要自定义 Spawn 逻辑，可以不调用 base，自行处理：
        //
        // GameObject player = Instantiate(playerPrefab, GetSpawnPosition(), Quaternion.identity);
        // NetworkServer.AddPlayerForConnection(conn, player);
    }

    Vector3 GetSpawnPosition()
    {
        if (spawnPoints.Length == 0) return Vector3.zero;
        return spawnPoints[Random.Range(0, spawnPoints.Length)].position;
    }
}
Mirror 96 方法名修正
旧版代码中常见的 StartServer() 已更新为 OnStartServer()。 这是因为 StartServer() 是 NetworkManager 的公共方法（用于启动服务器）， 而 OnStartServer() 是虚方法回调（在服务器启动后被调用）。 混淆两者会导致回调不执行或编译错误。

同理： StartClient() → 公共方法（启动客户端）
OnStartClient() → 虚方法回调（客户端启动后调用）
StopServer() → 公共方法（停止服务器）
OnStopServer() → 虚方法回调

2.5.1 NetworkManager 的生命周期钩子

钩子方法运行环境典型用途
OnStartServer()服务器服务器启动后的初始化（注册 Prefab、加载配置等）
OnStopServer()服务器服务器关闭时的清理
OnServerConnect(NetworkConnection conn)服务器新客户端连接时
OnServerDisconnect(NetworkConnection conn)服务器客户端断开时的清理
OnServerAddPlayer(NetworkConnection conn)服务器为新客户端生成 Player 对象
OnServerRemovePlayer(NetworkConnection conn, NetworkIdentity player)服务器移除玩家的 Player 对象
OnStartClient()客户端客户端启动后的初始化
OnStopClient()客户端客户端停止时的清理
OnClientConnect()客户端连接成功后的回调
OnClientDisconnect()客户端断线后的回调
OnServerChangeScene(string newSceneName)服务器服务器端场景切换前
OnServerSceneChanged(string sceneName)服务器服务器端场景切换后
OnClientChangeScene(string newSceneName, SceneOperation sceneOperation)客户端客户端端场景切换前
OnClientSceneChanged()客户端客户端端场景切换后

2.5.2 playerPrefab 的配置

在 Mirror 96 中，playerPrefab 是 NetworkManager 上的一个公共字段， 在 Inspector 中直接设置即可。Mirror 会在内部自动注册它，无需手动调用任何注册方法：

// 在 Inspector 中设置 NetworkManager.playerPrefab = yourPlayerPrefab
// 或者代码设置（不常用，通常在 Inspector 拖拽即可）
// networkManager.playerPrefab = playerPrefab;

// 当客户端连接时，Mirror 自动调用 OnServerAddPlayer
// base.OnServerAddPlayer 的默认实现会：
// 1. 用 playerPrefab 实例化对象
// 2. 调用 NetworkServer.AddPlayerForConnection(conn, player)
// 3. 客户端收到 Spawn 消息并实例化

2.6 实战：从零搭建最小可运行联网项目

让我们把所有概念串起来，搭建一个最简单的可运行项目。

步骤 1：创建 Player Prefab

// PlayerController.cs
using UnityEngine;
using Mirror;

public class PlayerController : NetworkBehaviour
{
    [SerializeField] float moveSpeed = 5f;

    void Update()
    {
        // 只有本地玩家才能控制这个角色
        if (!isLocalPlayer) return;

        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");

        Vector3 movement = new Vector3(h, 0, v) * moveSpeed * Time.deltaTime;

        // 通过 Command 将移动请求发送到服务器
        // 服务器验证并执行，然后通过 SyncVar / NetworkTransform 同步
        CmdMovePlayer(movement);
    }

    // [Command] 方法前缀 Cmd 在 Mirror 96 中是可选的
    // 但保留前缀是良好的命名约定，便于区分
    [Command]
    void CmdMovePlayer(Vector3 movement)
    {
        // 服务器端验证：防止超速移动
        if (movement.sqrMagnitude > moveSpeed * moveSpeed * Time.deltaTime * Time.deltaTime)
            movement = movement.normalized * moveSpeed * Time.deltaTime;

        // 服务器端执行移动
        transform.position += movement;
        // 位置同步由 NetworkTransform 组件自动处理
    }
}
简化方案：使用 NetworkTransform
上面的手动 Command 移动方案是为了演示概念。在实际项目中，你通常会在 Player 对象上添加 NetworkTransform 组件，它会自动处理位置/旋转的同步。 客户端只需在本地移动（isOwned 为 true 时），NetworkTransform 会自动把位置同步给服务器和其他客户端。

步骤 2：配置 NetworkManager

在场景中创建一个空的 GameObject，添加 NetworkManager 组件， 然后在 Inspector 中设置：

  1. Player Prefab：拖入你的 Player Prefab（需带有 NetworkIdentity + NetworkTransform）
  2. Offline Scene / Online Scene：设置离线和联机场景（可选）
  3. Transport：在同一个 GameObject 上添加 Transport 组件（见步骤 3）

步骤 3：配置 Transport

在 NetworkManager 所在的 GameObject 上添加 Transport 组件。 Mirror 96 的 Transport 是一个抽象类，你需要选择具体实现：

Transport 选择建议：

• KCP Transport（Mirror 内置默认）
  → 可靠 UDP，快速重传，适合大多数游戏
  → 配置 Port（默认 7777）

• UnityTransport（基于 Unity Transport Package / UTP）
  → 官方维护，适合需要 Unity 生态集成的项目
  → 配置 Address + Port

• Simple Web Transport（SWT）
  → 基于 WebSocket，用于浏览器端客户端
  → 配置 Url

• Telepathy Transport（已弃用）
  → 旧版默认，不推荐新项目使用

选择 Transport 后，在 Inspector 中设置端口号（KCP 默认 7777）。 Mirror 会自动发现并使用 GameObject 上的 Transport 组件。

2.7 常见陷阱与调试技巧

陷阱 1：在客户端修改了服务器上的数据

// ❌ 危险：没有环境检查，任何端都能修改
public void TakeDamage(int amount)
{
    health -= amount;  // 客户端也能调用并修改！
}

// ✅ 正确：确保只有服务器能修改权威数据
public void TakeDamage(int amount)
{
    if (!isServer) return;  // 客户端调用直接返回
    health -= amount;
    // 如果 health 是 SyncVar，Mirror 会自动同步给所有客户端
    // 不需要手动调用 RPC
SyncVar 自动同步
在 Mirror 96 中，如果 health 是 [SyncVar]， 你只需要在服务器端修改它，Mirror 会自动将新值同步给所有客户端。 不再需要手动调用 RpcUpdateHealth(health)——那是旧版 UNet 的做法。

陷阱 2：Spawn 顺序错误

// ❌ 错误：先 Spawn 父对象，子对象尚未准备好
GameObject parent = Instantiate(parentPrefab);
NetworkServer.Spawn(parent);  // 子对象的 NetworkIdentity 可能还没初始化

// ✅ 正确：确保所有子对象的 NetworkIdentity 已配置
// NetworkManager 的 playerPrefab 和 Spawnable Prefabs 列表已注册
// 然后正常 Spawn
GameObject parent = Instantiate(parentPrefab);
NetworkServer.Spawn(parent);
// 如果子对象也在 Prefab 中且带有 NetworkIdentity，Mirror 会自动处理父子关系

陷阱 3：isServer / isClient 在 Awake 时为 false

void Awake()
{
    // ❌ 这些在这里都是 false！
    Debug.Log(isServer);   // false
    Debug.Log(isClient);   // false
    Debug.Log(isOwned);    // false
}

void OnStartServer()
{
    // ✅ 服务器端初始化放这里
    Debug.Log(isServer);   // true
}

void OnStartClient()
{
    // ✅ 客户端端初始化放这里
    Debug.Log(isClient);   // true
}

void OnStartAuthority()
{
    // ✅ 获得控制权后的初始化放这里
    Debug.Log(isOwned);   // true
}
为什么 Awake 时是 false？ 因为 NetworkIdentity 的网络状态是在 Spawn 流程中才设置的。 Awake 执行时，网络模块可能还没有初始化完成。 Mirror 专门设计了 OnStartServer / OnStartClient / OnStartAuthority 等生命周期钩子， 保证在这些方法被调用时，网络状态已经就绪。

陷阱 4：混淆 isServer 和 isOwned

// ❌ 错误：用 isServer 判断"是否是我的对象"
void Update()
{
    if (isServer) // 这在 Host 模式下对所有人的对象都为 true！
    {
        HandleInput(); // 会控制所有玩家的角色
    }
}

// ✅ 正确：用 isOwned 或 isLocalPlayer 判断控制权
void Update()
{
    if (isLocalPlayer) // 或者 isOwned
    {
        HandleInput(); // 只控制自己的角色
    }
}

调试技巧：使用 Mirror 日志

Mirror 在 Console 中输出详细的网络日志。你可以通过 Mirror 的日志级别来控制输出量：

// Mirror 96 使用 LogFilter 控制日志级别
using Mirror;

// 开启调试日志（最详细）
LogFilter.Debug = true;   // 输出 Spawn、序列化、消息收发等细节
LogFilter.Info = true;    // 输出连接、断开等基本信息

// 关闭不需要的日志（生产环境）
LogFilter.Debug = false;  // 关闭调试日志减少噪音
LogFilter.Info = false;   // 关闭信息日志

你还可以注册消息处理器来追踪特定类型的数据流：

// 服务器端：追踪所有 Spawn 消息
NetworkServer.RegisterHandler<SpawnMessage>((conn, msg) =>
{
    Debug.Log($"[Server] Spawn 通知: netId={msg.netId}, assetHash={msg.assetHash}");
});

// 客户端：追踪连接状态
NetworkClient.RegisterHandler<ConnectMessage>(msg =>
{
    Debug.Log("[Client] 连接到服务器成功");
});

2.8 本章小结

本章我们建立了 Mirror 的核心认知模型：

组件/类类型核心职责
NetworkIdentity 组件 标记 GameObject 为网络对象；持有只读的 netId / isServer / isClient
NetworkBehaviour 基类 所有网络脚本的基类；提供 isServer / isClient / isLocalPlayer / isOwned / connectionToServer / connectionToClient；定义生命周期回调
NetworkServer 静态类 服务器端管理：Spawn / Destroy / 连接管理 / 消息注册
NetworkClient 静态类 客户端端管理：Connect / Disconnect / Prefab 注册 / 消息注册
NetworkManager MonoBehaviour 胶水层：封装连接流程、场景管理、Player Spawn；提供丰富的虚方法回调
Transport 抽象类 传输层抽象：KCP / UnityTransport / WebSocket 等，配置端口和地址

下一章，我们将深入通信机制：RPC 和 SyncVar——这是你和服务器、客户端之间对话的语言。

自测题

点击展开自测题
  1. 代码分析：以下代码有什么问题？如何修复？ 
    public class HealthSystem : NetworkBehaviour
{
    public int health = 100;

    public void Damage(int amount)
    {
        health -= amount;
        if (health <= 0)
            Die();
    }
}
  2. 场景推理：服务器 Spawn 了一个对象 A，然后销毁了它。 此时客户端收到了 Destroy 消息但延迟了 500ms。在这 500ms 内， 客户端还能对对象 A 调用 RPC 吗？为什么？
  3. 设计题：你需要在一个网络对象上存储一个玩家的名字字符串。 这个名字在对象 Spawn 时由服务器设定，之后所有客户端都需要看到相同的值。 你会用 SyncVar 还是其他方式？为什么？
  4. Mirror 96 变化：如果一段旧代码写了 if (hasAuthority)，在 Mirror 96 中会怎样？应该怎么改？
参考答案：
1) Damage 方法没有 isServer 检查，客户端可以直接调用并修改服务器状态。 修复：改为 [Command] 方法，或在方法开头加 if (!isServer) return;。 如果 health 是 [SyncVar]，服务器修改后会自动同步，无需手动 RPC。

2) 不能。客户端收到 Destroy 消息后，对象已从客户端的 Spawn 列表中移除， 调用 RPC 时会报 "unknown netId" 错误。

3) 用 [SyncVar]。名字是"状态数据"，不是"动作指令"——它需要在服务器修改后自动同步到所有客户端。 SyncVar 正是为此设计的，服务器修改后自动同步，零样板代码。

4) hasAuthority 在 Mirror 96 中已被 isOwned 替代， 代码会编译报错（属性不存在）。应将 hasAuthority 替换为 isOwned。
