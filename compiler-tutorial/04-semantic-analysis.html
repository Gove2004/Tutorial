语义分析：类型检查、作用域与符号表

语法分析确保你的代码"句子结构正确"，语义分析确保你的代码"意思合理"。本章深入类型系统、符号表设计、作用域解析和类型推断算法，这些是编译器中最复杂也最有价值的部分。

语义分析的任务

语义分析在 AST 之上附加语义信息（主要是类型），并检查语义约束。核心任务包括：类型检查（类型兼容性）、作用域解析（变量名绑定到声明）、常量折叠（编译期求值）、以及重载决议（选择正确的函数/运算符版本）。

1. 符号表：编译器的"字典"

符号表（Symbol Table）是编译器中最重要的数据结构之一。它记录了程序中所有"名字"（标识符）的信息：变量名、函数名、类型名、常量名等。

1.1 符号表条目

struct Symbol {
    std::string name;
    enum class Kind { VARIABLE, FUNCTION, TYPE, LABEL } kind;
    Type* type;
    int scopeLevel;      // 所属作用域层级
    int offset;          // 栈帧偏移（变量）或参数索引（函数）
    bool isConstant;
    bool isDeclared;     // 是否已定义（vs 仅声明）
    SourceLocation loc;  // 源代码位置（用于错误消息）
};

1.2 符号表的三种实现方式

实现 插入 查找 删除 适用场景
Hash Table O(1) O(1) 平均 O(1) 单层作用域，快速查找
平衡二叉树 O(log n) O(log n) O(log n) 需要有序遍历（如列出所有变量）
Stack of Hash Tables O(1) O(k)，k=作用域层数 O(1) pop 嵌套作用域（最常用）
最佳实践：工业级编译器几乎总是使用"栈 + Hash Table"的组合。每个作用域（函数体、块、循环体）对应栈上的一个 Hash Table。查找时从栈顶往下找，找到第一个匹配的即可。这样天然支持变量的遮蔽（shadowing）——内层作用域的 x 会遮蔽外层作用域的 x。

1.3 符号表的 C++ 实现

class SymbolTable {
    struct Scope {
        std::unordered_map<std::string, Symbol> symbols;
        Scope* parent = nullptr;
    };

    std::unique_ptr<Scope> root;
    Scope* current = nullptr;

public:
    SymbolTable() {
        root = std::make_unique<Scope>();
        current = root.get();
    }

    void enterScope() {
        auto* newScope = new Scope{ {}, current };
        current = newScope;
    }

    void exitScope() {
        Scope* old = current;
        current = current->parent;
        delete old;
    }

    bool insert(const std::string& name, Symbol sym) {
        if (current->symbols.count(name))
            return false; // 重复声明
        sym.scopeLevel = scopeDepth();
        current->symbols[name] = std::move(sym);
        return true;
    }

    Symbol* lookup(const std::string& name) {
        Scope* s = current;
        while (s) {
            auto it = s->symbols.find(name);
            if (it != s->symbols.end())
                return &(it->second);
            s = s->parent;
        }
        return nullptr; // 未找到
    }

    int scopeDepth() const {
        int depth = 0;
        Scope* s = current;
        while (s) { depth++; s = s->parent; }
        return depth;
    }
};

2. 类型系统

类型系统是语义分析的核心。它决定了编译器如何判断一个程序"是否合理"。

2.1 类型系统的分类

维度 选项 说明
检查时机 静态类型 编译时检查（C, Java, Rust, Haskell）
动态类型 运行时检查（Python, JavaScript, Ruby）
严格程度 强类型 不允许隐式类型转换（Python, Haskell）
弱类型 允许隐式类型转换（C, JavaScript）
关键区别：强类型 ≠ 静态类型。Python 是动态 + 强类型（不允许 "5" + 3）。C 是静态 + 弱类型（允许 int* → void* 隐式转换）。Rust 是静态 + 强类型。理解这些正交维度有助于选择合适的类型系统设计。

2.2 类型表示

enum class TypeKind {
    VOID, INT, FLOAT, BOOL, CHAR,
    POINTER, ARRAY, FUNCTION,
    STRUCT, UNION, ENUM,
    GENERIC, VOID_PTR
};

struct Type {
    TypeKind kind;
    size_t size;        // 字节
    size_t alignment;   // 对齐要求

    // 复合类型的附加信息
    std::vector<Type*> elementTypes;  // 数组元素类型 / 函数参数类型
    Type* elementType;                 // 指针指向的类型
    std::string structName;            // 结构体名称

    bool isCompatibleWith(const Type* other) const;
    size_t bitWidth() const;
};

// 类型等价性检查
bool Type::isCompatibleWith(const Type* other) const {
    if (this == other) return true;
    if (kind != other->kind) return false;

    switch (kind) {
        case TypeKind::ARRAY:
            return elementType->isCompatibleWith(other->elementType);
        case TypeKind::FUNCTION:
            if (elementTypes.size() != other->elementTypes.size())
                return false;
            for (size_t i = 0; i < elementTypes.size(); i++) {
                if (!elementTypes[i]->isCompatibleWith(other->elementTypes[i]))
                    return false;
            }
            return true;
        default:
            return true;
    }
}

3. 类型检查算法

类型检查的本质是对 AST 进行遍历，为每个节点赋予类型，并验证类型约束。

3.1 基于 Visitor 的类型检查器

class TypeChecker : public ASTVisitor {
    SymbolTable& symbols;
    std::map<ASTNode*, Type*> typeMap;

    void checkBinaryOp(BinOpNode* node) {
        Type* left = getType(node->left);
        Type* right = getType(node->right);

        if (left->kind != TypeKind::INT || right->kind != TypeKind::INT) {
            reportError(node->line,
                "Binary operator requires integer operands");
            node->type = builtinTypes.intType;
            return;
        }
        node->type = builtinTypes.intType;
    }

    void checkCall(CallNode* node) {
        Symbol* sym = symbols.lookup(node->funcName);
        if (!sym || sym->kind != Symbol::Kind::FUNCTION) {
            reportError(node->line,
                "Undefined function: " + node->funcName);
            return;
        }

        Type* funcType = sym->type;
        // 检查参数数量和类型
        if (node->args.size() != funcType->elementTypes.size() - 1) {
            reportError(node->line, "Argument count mismatch");
        }

        for (size_t i = 0; i < node->args.size(); i++) {
            Type* argType = getType(node->args[i]);
            Type* paramType = funcType->elementTypes[i + 1]; // +1 skip return type
            if (!argType->isCompatibleWith(paramType)) {
                reportError(node->args[i]->line,
                    "Type mismatch: expected " + paramType->name() +
                    ", got " + argType->name());
            }
        }
        node->type = funcType->elementTypes[0]; // return type
    }

    Type* getType(ASTNode* node) {
        auto it = typeMap.find(node);
        if (it != typeMap.end()) return it->second;
        node->accept(*this);
        return typeMap[node];
    }

public:
    TypeChecker(SymbolTable& sym) : symbols(sym) {}

    void visit(IntLiteralNode* node) override {
        node->type = builtinTypes.intType;
        typeMap[node] = builtinTypes.intType;
    }

    void visit(BinOpNode* node) override {
        checkBinaryOp(node);
    }

    void visit(CallNode* node) override {
        checkCall(node);
    }

    void visit(AssignNode* node) override {
        Symbol* sym = symbols.lookup(node->varName);
        if (!sym) {
            reportError(node->line, "Undefined variable: " + node->varName);
            return;
        }
        Type* varType = sym->type;
        Type* exprType = getType(node->expr.get());
        if (!exprType->isCompatibleWith(varType)) {
            reportError(node->line,
                "Cannot assign " + exprType->name() +
                " to " + varType->name());
        }
        node->type = varType;
    }
};

3.3 Hindley-Milner 类型推断简介

Hindley-Milner（HM）算法用于静态类型推断，代表语言包括 Haskell、ML 和 Rust。它的核心思想是：不需要显式标注类型，编译器从使用上下文中自动推断出最通用的类型。

点击查看 HM 算法的详细步骤 
// HM 类型推断的核心概念:
// 1. 类型变量: 'a, 'b, 'c ... (未知类型)
// 2. 类型约束: 'a = 'b (两个类型必须相同)
// 3. 替换: {'a := int} (将类型变量替换为具体类型)

// 伪代码:
function infer(expr):
    // 第一步: 生成约束
    constraints = generateConstraints(expr)
    // 例如: f(x) → ['a = 'b -> 'c, 'b = int]

    // 第二步: 求解约束
    substitution = solveConstraints(constraints)
    // 例如: {'a := int -> bool, 'b := int, 'c := bool}

    // 第三步: 应用替换
    return apply(substitution, inferredType)
    // 结果: int -> bool

// 通用性最大化:
// let id x = x
// 推断: ∀'a. 'a -> 'a  (多态恒等函数)
// 而不是: int -> int  (太具体)

4. 作用域解析

作用域决定了标识符的可见性和生命周期。理解作用域解析是正确实现变量绑定的前提。

4.1 词法作用域 vs 动态作用域

特性 词法作用域（静态） 动态作用域
变量查找 代码书写时的嵌套结构 函数调用时的嵌套结构
确定性 编译时确定 运行时确定
典型语言 C, Java, Python, Rust 旧版 Bash, Emacs Lisp
闭包支持 天然支持 不支持

4.2 作用域链的实现

源代码:
    int x = 10;          // 全局 x
    void foo() {
        int x = 20;      // 局部 x (遮蔽全局)
        int y = x;       // y = 20 (取局部 x)

        {
            int x = 30;  // 块级 x (遮蔽局部)
            int z = x;   // z = 30
        }

        int w = ::x;     // w = 10 (显式访问全局)
    }

符号表查找过程:
    查找 "x" in foo():
    ├─ 当前作用域 (foo 局部): 找到 x=20 ✓
    └─ (不会继续向上查找)

    查找 "::x" in foo():
    └─ 全局作用域: 找到 x=10 ✓

块级作用域:
    Scope 0 (全局):  {x: 10}
    Scope 1 (foo):   {x: 20, y: ?, w: ?}
    Scope 2 (block): {x: 30, z: ?}

5. 重载决议

当一个名字对应多个函数/运算符时，编译器需要决定使用哪一个。这就是重载决议（Overload Resolution）。

5.1 C++ 重载决议规则

C++ 使用一个复杂的排名系统来确定最佳匹配：

等级 匹配类型 示例
1 (最优) 精确匹配 void f(int) 调用 f(42)
2 提升转换 char → int, float → double
3 标准转换 int → double, Derived* → Base*
4 用户定义转换 构造函数或转换运算符
5 (最差) 省略号匹配 ... 参数

5.2 重载决议算法

// 简化版重载决议
struct OverloadCandidate {
    Function* func;
    std::vector<ConversionRank> ranks; // 每个参数的转换等级
    int score; // 总评分
};

OverloadCandidate* findBestMatch(
    const std::string& name,
    const std::vector<Type*> argTypes) {

    // 1. 收集所有同名候选函数
    auto candidates = symbolTable.lookupOverloads(name);

    // 2. 过滤掉参数数量不匹配的
    candidates.erase_if([&](auto& c) {
        return c->params.size() != argTypes.size();
    });

    // 3. 为每个候选计算转换等级
    for (auto& c : candidates) {
        c->score = 0;
        for (size_t i = 0; i < argTypes.size(); i++) {
            c->score += rankConversion(
                c->params[i], argTypes[i]);
        }
    }

    // 4. 选择得分最低的（越优匹配得分越低）
    auto best = *std::min_element(
        candidates.begin(), candidates.end(),
        [](auto& a, auto& b) { return a.score < b.score; });

    // 5. 检查是否有并列
    auto secondBest = candidates[0];
    for (auto& c : candidates) {
        if (c.score == best.score && &c != &best) {
            throw AmbiguousError(name);
        }
    }

    return &best;
}

6. 性能数据：符号表查找的复杂度分析

符号表是编译器中使用最频繁的数据结构之一，它的性能直接影响整体编译速度。

操作 Hash Table (单次查找) Stack of Hash Tables 平衡 BST
插入新符号 O(1) O(1) O(log n)
查找（k 层作用域） O(1) O(k) O(log n)
删除作用域 O(n) O(1) pop O(n)
遍历所有符号 O(n) O(n) O(n) 有序
实际性能：对于一个典型的 C++ 源文件，符号表的大小通常在几百到几千个条目。作用域深度一般不超过 10 层。因此即使是 O(k) 的查找也完全可以忽略不计。但在大型项目中（如 Chromium），符号表可能包含数十万个条目，此时 Hash Table 的 O(1) 优势就变得重要了。

7. 常量折叠与编译期求值

语义分析阶段还可以做一件事：常量折叠（Constant Folding）。如果表达式的所有操作数都是编译期常量，编译器可以直接计算出结果。

// 常量折叠示例
// 源代码:
int x = 2 + 3 * 4;        // 编译期求值为: int x = 14;
int y = sizeof(int) + 1;  // 编译期求值为: int y = 5;
int z = (1 << 10) - 1;    // 编译期求值为: int z = 1023;

// 实现:
Expr* foldConstants(Expr* expr) {
    if (auto* binop = dynamic_cast<BinOpNode*>(expr)) {
        binop->left = foldConstants(binop->left);
        binop->right = foldConstants(binop->right);

        if (auto* lhs = dynCast<IntLitNode>(binop->left)) {
            if (auto* rhs = dynCast<IntLitNode>(binop->right)) {
                int result = evaluate(binop->op, lhs->value, rhs->value);
                return new IntLitNode(result);
            }
        }
    }
    return expr;
}

8. 本章小结

本章我们深入语义分析的核心组件：

  • 符号表：栈 + Hash Table 是实现嵌套作用域的标准方案，支持变量遮蔽。
  • 类型系统：静态/动态、强/弱是正交的维度，选择取决于语言设计目标。
  • 类型检查：基于 Visitor 的遍历是类型检查的标准模式，HM 算法解决了类型推断问题。
  • 作用域解析：词法作用域是绝大多数现代语言的选择，动态作用域仅存在于少数语言中。
  • 重载决议：通过转换等级排名系统选择最佳匹配函数。
  • 常量折叠：编译期求值是语义分析阶段的额外收益。
