第 2 章　程序集与工程结构

本章建立全书的"物理地图"：2600 多个文件分布在哪些工程和目录里，每块代码的职责是什么，以及它们之间的依赖方向。读完之后，你应该能在听到某个机制时立刻知道该去哪个目录找它。

2.1 五个工程的职责划分

Solution.sln 包含五个工程，对应游戏编译后的五个 DLL。Unity 的编译规则是：Plugins 等目录下的代码先编译成 Assembly-CSharp-firstpass，普通目录下的代码后编译成 Assembly-CSharp，后者可以引用前者。

工程cs 文件数职责
Assembly-CSharp2678游戏全部自有逻辑 + 随主工程一起编译的第三方库，是本教程的绝对主体
Assembly-CSharp-firstpass51先编译的第三方代码：GOG 平台对接、PolyAndCode 循环滚动列表、Unity 官方图像特效（Bloom/景深/抗锯齿等）
TeamCherry.Localization14本地化运行时，多语言文本的加载与查找（Language.Get(...)）
TeamCherry.Cinematics10过场视频系统，与 CinematicPlayer 配合
TeamCherry.BuildBot4构建/打包辅助工具，不参与游戏运行时逻辑

注意一个反编译现象：像 System.Security.Cryptography 这种 .NET 基础库代码出现在游戏工程里，通常是因为游戏用了某个 Mono 版本中缺失、需要随游戏一起补编的类型。这不是 Team Cherry 自己实现了加密算法，而是 BCL（基础类库）的兼容性回填。

2.3 关键第三方依赖清单

从 csproj 的引用和源码目录可以还原出游戏的技术选型：

依赖类型在游戏中的用途

2.4 GlobalEnums：32 个枚举速查

枚举是理解游戏语义的捷径——它们列出了某个维度上全部合法的取值。重点枚举先记住这几个：

枚举表达的维度
ActorStates主角的 9 个粗粒度主状态（grounded/idle/running/airborne/no_input 等）
MapZone地图区域（遗忘十字路、苍绿之径、深邃巢穴……），驱动地图与音乐切换
SceneType场景类型（游戏场景/菜单/过场），GameManager 用它决定加载与暂停策略
HazardType危险类型：普通伤害、尖刺、酸液、深坑，决定死亡演出方式
GatePosition门口的位置（左/右/上/下门），决定主角入场朝向与落点
PhysLayers物理层编号，射线检测与碰撞过滤的依据
DamageMode / CollisionSide / AttackDirection伤害模式、碰撞方向、攻击方向，战斗管线的基础词汇

读任何一个类之前，先扫一眼它 using 了哪些 GlobalEnums、字段里出现了哪些枚举类型——这能在 30 秒内告诉你这个类处理的是哪个维度的问题。

2.5 一个实用的目录定位口诀

  • 找"机制与管理器" → 根目录，按 XxxManager / XxxController 检索
  • 找"某个 FSM 里能调的动作" → HutongGames.PlayMaker.Actions，按 ActionCategory 语义检索
  • 找"合法取值/状态分类" → GlobalEnums
  • 找"手柄按键/设备适配" → InControl 三个目录
  • 找"屏幕视觉特效" → firstpass 的 ImageEffects
  • 找"多语言文本" → TeamCherry.Localization 工程

思考与练习

  1. 不看教程，尝试在根目录定位负责以下功能的类并说出依据：骨钉攻击判定、场景物件状态、相机震动、吉欧计数器。
  2. 解释为什么 Assembly-CSharp 可以引用 firstpass，而 firstpass 不能反向引用（结合 Unity 的编译顺序）。
  3. 打开 GlobalEnums/MapZone.cs，数一下共有多少个地图区域，并思考 PlayerData 为什么还要同时保存 mapZone 字段而不是直接从场景读取。
  4. 在 PlayMaker.Actions 目录里分别找出 2 个官方通用 Action 和 2 个 Team Cherry 自定义 Action，总结你辨别二者的方法。
