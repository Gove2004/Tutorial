实战二：百万级粒子系统

粒子系统是 Compute Shader 最经典的应用场景之一。CPU 端的粒子模拟通常在 10 万粒子后就遇到瓶颈，而 GPU 可以轻松处理百万甚至千万级粒子。本章将实现一个完整的粒子系统，包括物理模拟和渲染。

粒子系统的核心架构

一个 GPU 粒子系统由两个部分组成：

┌─────────────────────────────────────────────────────┐
│  Compute Shader (模拟)                               │
│  ─────────────────                                  │
│  输入：粒子位置、速度、加速度、时间                    │
│  输出：新位置、新速度、粒子生死状态                    │
│  每个线程处理一个粒子                                 │
└─────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────┐
│  Render (GPU Instancing)                             │
│  ─────────────────                                  │
│  从 Structured Buffer 读取粒子位置                    │
│  用 DrawInstanced 一次性绘制所有粒子                  │
│  1 draw call = N 个粒子（N 可以是 100 万）            │
└─────────────────────────────────────────────────────┘

数据结构：SoA vs AoS

粒子数据有两种组织方式，在 GPU 上差别巨大：

AoS (Array of Structures)SoA (Structure of Arrays)
布局struct Particle { float3 pos; float3 vel; float life; }; Particle[N];float3 pos[N]; float3 vel[N]; float life[N];
缓存命中率差——读 pos 时把 vel 也载入缓存优——只加载需要的字段
SIMT 友好度低——线程可能需要不同字段高——所有线程处理同种数据
推荐❌ CPU 端使用✅ GPU 端使用

Compute Shader 中：

// SoA 布局（GPU 最佳）
StructuredBuffer<float3> positions : register(t0);
StructuredBuffer<float3> velocities : register(t1);
StructuredBuffer<float> lifetimes : register(t2);
StructuredBuffer<float3> accelerations : register(t3);

RWStructuredBuffer<float3> newPositions : register(u0);
RWStructuredBuffer<float3> newVelocities : register(u1);
RWStructuredBuffer<float> newLifetimes : register(u2);

Velocity Verlet 积分器

粒子物理模拟需要一个数值积分器。Velocity Verlet 是游戏和模拟中最常用的积分器之一——它比欧拉法稳定，比 Runge-Kutta 快：

// Velocity Verlet 积分公式：
// x(t+dt) = x(t) + v(t)*dt + 0.5*a(t)*dt^2
// v(t+dt) = v(t) + 0.5*(a(t) + a(t+dt))*dt

[numthreads(256, 1, 1)]
void ParticleSimulation(uint3 tid : SV_DispatchThreadID)
{
    uint index = tid.x;
    if (index >= particleCount)
        return;

    float3 pos = positions[index];
    float3 vel = velocities[index];
    float3 accel = accelerations[index];
    float life = lifetimes[index];

    // 1. 计算新位置
    float3 newPos = pos + vel * dt + 0.5f * accel * dt * dt;

    // 2. 计算新加速度（取决于新位置）
    float3 newAccel = ComputeGravity(newPos);  // 或其他力场

    // 3. 更新速度
    float3 newVel = vel + 0.5f * (accel + newAccel) * dt;

    // 4. 更新生命周期
    float newLife = life - dt;

    // 5. 粒子死亡检测与重生
    if (newLife <= 0.0f)
    {
        newPos = emitPoint[index % emitPointCount];
        newVel = float3(0, 5, 0);
        newAccel = float3(0, -9.81, 0);
        newLife = lifetimeRange.x +
                  frac(sin(index * 127.1f) * 43758.5453f) *
                  (lifetimeRange.y - lifetimeRange.x);
    }

    // 6. 写入
    newPositions[index] = newPos;
    newVelocities[index] = newVel;
    newLifetimes[index] = newLife;
}

力的类型

现实中的粒子系统需要多种力的组合：

float3 ComputeForces(float3 pos, float3 vel, uint index)
{
    float3 force = float3(0, 0, 0);

    // 1. 重力
    force += float3(0, -9.81f, 0) * mass[index];

    // 2. 空气阻力 (F = -0.5 * Cd * rho * A * |v| * v)
    float dragCoeff = 0.47;  // 球体
    force -= dragCoeff * vel * length(vel);

    // 3. 风力（可加噪声）
    float3 wind = float3(sin(time * 0.5), 0, cos(time * 0.3)) * windStrength;
    force += wind;

    // 4. 粒子间排斥力（简化版：只考虑组内相邻粒子）
    // 注意：这需要 Shared Memory 或原子操作
    // 对于大规模粒子系统，通常用 Spatial Hash 优化

    return force;
}

GPU Instancing 渲染

模拟完成后，需要将百万粒子渲染出来。用 CPU 绘制 100 万个球体需要 100 万次 Draw Call——GPU 会直接卡死。解决方案是 GPU Instancing：

1 Draw Call = 渲染 N 个实例（每个实例可以有不同位置）

Vertex Shader:
  每个实例读取一个粒子位置
  用位置偏移顶点坐标
  → 一个球体出现在粒子位置

Fragment Shader:
  根据粒子生命周期设置颜色/透明度
// DX12 中设置 Instancing
commandList->IASetVertexBuffers(0, 1, &sphereVBView);  // 球体顶点缓冲
commandList->DrawInstanced(sphereVertexCount, particleCount, 0, 0);
// sphereVertexCount = 一个球体的顶点数（如 422）
// particleCount = 粒子数（如 1,000,000）
// 总绘制顶点 = 422 × 1,000,000 = 4.22 亿个顶点

Vertex Shader 中获取实例位置：

StructuredBuffer<float3> particlePositions : register(t0);

struct VSInput
{
    float3 position : POSITION;
    uint instanceId : INSTANCEID;
};

struct VSOutput
{
    float4 position : SV_POSITION;
    float life : LIFE;
};

VSOutput VSMain(VSInput input)
{
    VSOutput output;
    float3 pos = particlePositions[input.instanceId];

    // 将球体顶点平移到粒子位置
    output.position = float4(pos + input.position * particleSize, 1.0);
    output.life = particleLifetimes[input.instanceId];

    return output;
}

AppendBuffer 和 ConsumeBuffer

当粒子数量动态变化时（比如粒子碰撞后产生碎片），固定大小的缓冲区不够用。这时需要：

类型操作原子性用途
AppendBuffer只追加，不读✓粒子生成、结果收集
ConsumeBuffer只消费，不追加✓工作队列、任务分发
 
// AppendStructuredBuffer：原子追加
AppendStructuredBuffer<float3> newParticles : register(u1);

[numthreads(256, 1, 1)]
void ParticleCollision(uint3 tid : SV_DispatchThreadID)
{
    // 如果检测到碰撞，生成碎片粒子
    if (isColliding[tid.x])
    {
        // 原子追加——不会和其他线程冲突
        newParticles.Append(float3(1, 0, 0));
        newParticles.Append(float3(-1, 0, 0));
        newParticles.Append(float3(0, 1, 0));
    }
}

// 读取当前追加了多少个粒子
RWStructuredBuffer<uint> appendCounter : register(u2);
uint count = appendCounter[0];

粒子系统的完整循环

// 每帧执行
void UpdateParticles(float dt)
{
    // 1. Barrier：确保上一帧的写入完成
    commandList->ResourceBarrier(Transition(outputBuffer, UNORDERED_ACCESS, COPY_SOURCE));

    // 2. 绑定 UAV/SRV
    commandList->SetPipelineState(particlePSO.Get());
    commandList->SetDescriptorHeaps(1, &descriptorHeap);
    commandList->GSSetShaderBuffers(0, positionsBuffer, velocityBuffer, lifetimeBuffer);
    commandList->GSSetShaderBuffers(0, newPositionsBuffer, newVelocitiesBuffer, newLifetimeBuffer);

    // 3. Dispatch 粒子模拟
    UINT groupCount = (particleCount + 255) / 256;
    commandList->Dispatch(groupCount, 1, 1);

    // 4. Barrier：模拟完成，切换到渲染状态
    commandList->ResourceBarrier(Transition(newPositionsBuffer, COPY_SOURCE, NON_PIXEL_SHADER_RESOURCE));

    // 5. 绑定 Instancing 渲染
    commandList->IASetVertexBuffers(0, 1, &sphereVBView);
    commandList->DrawInstanced(sphereVertexCount, particleCount, 0, 0);

    // 6. 关闭并提交
    commandList->Close();
    commandQueue->ExecuteCommandLists(1, &commandList);

    // 7. 等待完成
    WaitForGPU();

    // 8. Swap ping-pong buffers
    std::swap(positionsBuffer, newPositionsBuffer);
    std::swap(velocitiesBuffer, newVelocitiesBuffer);
    std::swap(lifetimesBuffer, newLifetimesBuffer);
}

性能优化：减少 Instancing 的顶点传输

用球体渲染 100 万个粒子，每帧要传输 4.22 亿个顶点（422 顶点 × 100 万粒子）。优化方案：

  1. 低多边形球体：用 24 面体代替 422 面球体，减少 17x 顶点传输
  2. Billboard（始终面向相机的四边形）：只用 4 个顶点 + 2 个三角形
  3. 点精灵（Point Sprites）：GPU 自动将点渲染为圆形，0 顶点传输

Point Sprites 实现：

// DX12 Point List 拓扑
commandList->IASetPrimitiveTopology(D3D12_PRIMITIVE_TOPOLOGY_POINTLIST);
commandList->DrawInstanced(particleCount, 1, 0, 0);
// 只需要一个顶点缓冲：粒子位置
// Vertex Shader：只输出位置
struct VSInput
{
    float3 position : POSITION;
    uint instanceId : INSTANCEID;
};

struct PSOutput
{
    float4 position : SV_POSITION;
    float pointSize : PSIZE;  // 点精灵大小
    float life : LIFE;
};

PSOutput VSMain(VSInput input)
{
    PSOutput output;
    output.position = float4(input.position, 1.0);
    output.pointSize = particleSize * 50.0f;  // 屏幕空间大小
    output.life = input.life;
    return output;
}

// Pixel Shader：将方形点精灵变为圆形
float4 PSMain(PSOutput input) : SV_TARGET
{
    // 点精灵默认是方形 UV [0,1]x[0,1]
    float2 uv = input.position.xy;  // 需要转为 [-1,1] 范围
    float dist = length(uv);
    if (dist > 0.5) discard;  // 丢弃方形角落

    float alpha = input.life;  // 生命周期控制透明度
    return float4(1, 0.5, 0.2, alpha);
}

粒子系统的可视化效果

让粒子系统看起来真实的技巧：

  • 粒子颜色随生命周期渐变：出生时亮色 → 中年时饱和 → 死亡时暗淡/透明
  • Size 衰减：粒子从小到大再消失（模拟火花/烟雾）
  • 噪声扰动：用 Simplex Noise 或 Perlin Noise 给风力加随机性
  • 粒子拖尾：用 Ping-Pong 纹理记录历史位置，在 Fragment Shader 中画线

练习与思考

1

动手练习

实现一个喷泉粒子系统：10 万个粒子从原点向上喷射，受重力下落。用 Point Sprites 渲染。验证：粒子轨迹应该是抛物线。

2

扩展练习

加入粒子间排斥力。提示：用 Shared Memory 做组内碰撞检测——每个 Group 处理一块粒子，组内线程共享空间分区数据。复杂度 O(N) 而非 O(N²)。

3

性能分析

本章小结

  • 粒子系统用 SoA 布局而非 AoS，缓存友好度高得多
  • Velocity Verlet 是稳定性与性能的平衡选择
  • GPU Instancing 让 1 次 Draw Call 渲染 N 个粒子成为可能
  • Append/Consume Buffer 支持动态粒子数量
  • Point Sprites 是最轻量级的粒子渲染方案
  • Ping-Pong Buffer 是两帧间交换数据的标准模式
