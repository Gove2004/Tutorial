第 8 章　场景状态与持久化

第 7 章看到 SaveGameData 里有两个对象：PlayerData 和 SceneData。PlayerData 管跨场景的全局进度，本章讲另一半——SceneData 如何记录"这个场景里的门开了没有、宝箱拿了没有、岩石还剩几下"，以及场景物体怎样把自己的状态接进存档管线。

8.1 两层数据的分工

PlayerDataSceneData
作用域全局，跨整个游戏单个场景内的物体
组织方式1500 多个平铺字段三个 List，按 (场景名, id) 存取
典型内容能力、护符、吉欧、统计开关门、宝箱、可破坏岩石的状态

为什么场景物体不直接塞进 PlayerData？因为场景物体数量庞大且每个场景独立，若都做成 PlayerData 字段会让本已臃肿的类彻底失控。SceneData 用列表按场景隔离，是一种按需增长的稀疏存储。

8.2 SceneData 的三个列表

[Serializable]
public class SceneData
{
    public List geoRocks;
    public List persistentBoolItems;
    public List persistentIntItems;
}

三个数据类各自承载一种状态，结构都很简单：

数据类字段用途
PersistentBoolDataid、sceneName、activated、semiPersistent最常用：物体的布尔开关（门、宝箱、机关）
PersistentIntDataid、sceneName、value（默认 -1）、semiPersistent需要记数值的物体
GeoRockDataid、sceneName、hitsLeft专用于吉欧岩石：还剩几下没敲

8.3 复合键与线性查找

SceneData 不用字典，而是用 (sceneName, id) 两个字段做键，通过线性遍历查找：

private int FindPersistentBoolItemInList(PersistentBoolData pbd)
{
    for (int i = 0; i < persistentBoolItems.Count; i++)
    {
        if (string.Compare(persistentBoolItems[i].sceneName, pbd.sceneName,
                           ignoreCase: true) == 0
            && persistentBoolItems[i].id == pbd.id)
        {
            return i;
        }
    }
    return -1;
}

存取走统一的 SaveMyState/FindMyState 模式：找不到（-1）就 Add，找到了就替换。这是典型的 upsert 逻辑。

两个要注意的点：场景名比较用 ignoreCase: true 忽略大小写，但 id 比较是区分大小写的；另外线性查找的复杂度是 O(n)，好在单个场景的持久化物体数量有限，且只在保存/加载时执行，不在高频路径上。

8.4 三个 MonoBehaviour 桥接器

数据类本身不挂在场景里，真正在场景物体上的是三个 MonoBehaviour 组件，它们实现同一个接口 IPersistentItem：

public interface IPersistentItem
{
    string GetId();
    string GetSceneName();
    string GetValueTypeName();
    bool GetIsSemiPersistent();
}
组件持有数据对接的 FSM 变量
PersistentBoolItemPersistentBoolDataFSM 布尔变量 "Activated"
PersistentIntItemPersistentIntDataFSM 整数变量 "Value"
GeoRockGeoRockDataFSM 整数变量 "Hits"

统一的双向同步模式

三个组件的工作方式几乎一模一样，本质是在 PlayMaker FSM 变量和 SceneData 之间做双向同步：

flowchart TB subgraph 场景加载 S["Start / LevelActivated"] -->|"FindMyState 查 SceneData"| Q{"存档里有记录?"} Q -->|"有"| W["把保存值写回 FSM 变量
Activated / Value / Hits"] Q -->|"无"| E["从 FSM 当前值初始化"] end subgraph 保存 SV["SaveState（由 SavePersistentObjects 触发）"] -->|"从 FSM 变量读当前值"| SM["SaveMyState 写入 SceneData"] end 
// 加载时：存档值 → FSM
myFSM.FsmVariables.FindFsmBool("Activated").Value = saved.activated;

// 保存时：FSM → SceneData
persistentBoolData.activated = myFSM.FsmVariables.FindFsmBool("Activated").Value;
SceneData.instance.SaveMyState(persistentBoolData);

这解释了为什么重进场景后，开过的门不会重新关上：物体的 FSM 启动时会被存档值"校正"，而不是按场景默认状态运行。

8.5 委托订阅：接入存档管线的方式

桥接器不主动轮询，也不被 GameManager 逐个查找，而是在 OnEnable 里把自己的方法挂到 GameManager 的委托上：

private void OnEnable()
{
    gm = GameManager.instance;
    gm.SavePersistentObjects += SaveState;        // 保存时被调用
    if (semiPersistent)
        gm.ResetSemiPersistentObjects += ResetState;  // 重置时被调用
}
private void OnDisable()
{
    gm.SavePersistentObjects -= SaveState;
    gm.ResetSemiPersistentObjects -= ResetState;
}

回忆第 7 章：SaveGame 第一步调用 SaveLevelState，它执行的正是 SavePersistentObjects 委托。场景里所有桥接器的 SaveState 会被依次调用，各自把状态写进同一个 SceneData。这是观察者模式的典型应用——GameManager 不需要知道场景里有哪些持久化物体，物体自己登记、自己退出。

OnDisable 里必须取消订阅，否则物体销毁后委托仍持有它的引用，下次保存会调用到已销毁对象而报错。这种"订阅必配退订"是 C# 事件使用的基本纪律。

8.6 半持久化：semiPersistent 的语义

数据类里的 semiPersistent 标记决定了状态的存活边界：

  • 普通持久化（false）：状态永久保留，直到玩家开新档
  • 半持久化（true）：在某些情况下（主角死亡、休息等触发 ResetSemiPersistentItems）被重置回初始值
public void ResetSemiPersistentItems()
{
    for (int i = 0; i < persistentBoolItems.Count; i++)
        if (persistentBoolItems[i].semiPersistent)
            persistentBoolItems[i].activated = false;
    // int 项重置为哨兵 -1
}

组件的 ResetState 还会向 FSM 发送 "RESET" 事件，让状态机本身也回到初始状态，保证数据和表现一致。这个机制用于那些"临时变化、死亡后应恢复"的场景物体。

8.7 不依赖 FSM 的扩展点与只读模式

PersistentBoolItem 除了对接 PlayMaker，还提供两个事件允许纯 C# 代码参与：

public event BoolEvent OnSetSaveState;     // 加载存档时回调，通知代码新状态
public event BoolRefEvent OnGetSaveState;  // 保存时回调，让代码提供当前状态

若挂载的物体没有合适的 FSM，可以订阅这两个事件用代码读写状态，组件会优先走事件而非 FSM。另外 dontSave 字段标记"只读"物体：它会从存档读取状态，但 SaveState 时不写回，用于只需要根据存档决定表现、自身不产生新状态的物体。

8.8 id 的默认约定与冲突风险

private void SetMyID()
{
    if (string.IsNullOrEmpty(persistentBoolData.id))
        persistentBoolData.id = base.name;   // 默认用物体名
    if (string.IsNullOrEmpty(persistentBoolData.sceneName))
        persistentBoolData.sceneName =
            GameManager.GetBaseSceneName(gameObject.scene.name);  // 基础场景名
}

陷阱：id 默认取物体名，而同场景内同名物体会互相覆盖。因为键是 (sceneName, id)，如果两个物体都没显式指定 id 且恰好同名，它们会写到同一条记录上，一个的状态会覆盖另一个。实践中要么保证物体名唯一，要么显式设置 id。场景名用 GetBaseSceneName 剥离后缀，保证拆分场景的状态能归并到一起。
