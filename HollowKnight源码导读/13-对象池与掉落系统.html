第 13 章　对象池与掉落系统

游戏里大量特效、吉欧、命中火花需要频繁创建和消失。反复 Instantiate/Destroy 会产生托管垃圾、触发 GC 卡顿。对象池用"回收复用"解决这个问题。本章拆解全局对象池、局部对象池、自动回收和掉落抛洒机制。

13.1 为什么需要对象池

直接 Instantiate/Destroy对象池
每次创建有开销，销毁产生托管垃圾实例预先创建，取出/归还几乎无分配
频繁触发 GC，可能造成帧卡顿显著减少 GC 压力，运行更平稳
数量不可控，峰值可能爆量实例可复用，内存占用可预测

动作游戏的特效、命中火花、吉欧都是"短生命周期、高频"对象，正是对象池的典型适用对象。

13.2 全局 ObjectPool 的数据结构

ObjectPool 是一个单例 MonoBehaviour，核心是两个字典：

// 预制体 → 该预制体当前空闲的实例列表
private Dictionary> pooledObjects;
// 已取出的实例 → 它对应的预制体（回收时据此找回归属）
private Dictionary spawnedObjects;

为什么需要两个字典？

pooledObjects 解决"取出时从哪拿"：按预制体找到空闲实例；spawnedObjects 解决"回收时往哪还"：给定一个实例，要知道它是哪个预制体的，才能放回对应列表。两个方向的查找都需要 O(1)，所以各用一个字典。

13.3 Spawn：取出与自动扩容

public static GameObject Spawn(GameObject prefab, Transform parent,
                               Vector3 position, Quaternion rotation)
{
    if (instance.pooledObjects.TryGetValue(prefab, out var list) && list.Count > 0)
    {
        GameObject obj = null;
        while (obj == null && list.Count > 0)   // 跳过已被外部销毁的空引用
        {
            obj = list[0];
            list.RemoveAt(0);
        }
        obj.transform.SetParent(parent);
        obj.transform.localPosition = position;
        obj.transform.localRotation = rotation;
        if (hasActiveRecycler)
            FSMUtility.SendEventToGameObject(obj, "A SPAWN");  // 不 SetActive，发事件
        else
            obj.SetActive(true);
        instance.spawnedObjects.Add(obj, prefab);
        return obj;
    }
    // 池里没有空闲实例：直接 Instantiate，池自动扩容
    GameObject created = Instantiate(prefab);
    // ...
    return created;
}

两个细节：取出时用 while 跳过 null——如果某个池内对象被意外销毁，列表里会留空引用，需要清理；池耗尽不报错中断，而是 Instantiate 新实例并打一条警告，池容量因此能自动增长，但这也意味着初始容量估算不足时仍会有创建开销。

13.4 Recycle：归还与兜底销毁

public static void Recycle(GameObject obj)
{
    if (instance.spawnedObjects.TryGetValue(obj, out var prefab))
        Recycle(obj, prefab);
    else
        Destroy(obj);   // 不是池创建的对象，直接销毁
}

private static void Recycle(GameObject obj, GameObject prefab)
{
    instance.pooledObjects[prefab].Add(obj);
    instance.spawnedObjects.Remove(obj);
    obj.transform.SetParent(instance.transform);
    if (obj.GetComponent() != null)
    {
        obj.transform.position = activeStashLocation;   // 移到 (-20,-20)
        FSMUtility.SendEventToGameObject(obj, "A RECYCLE");
    }
    else
    {
        obj.SetActive(false);
    }
}

普通对象回收即 SetActive(false) 并挂到池物体下；带 ActiveRecycler 标记的对象不关闭，而是移到屏幕外的 (-20,-20) 并发送 "A RECYCLE" 事件，让 FSM 自行处理——用于那些不能直接 SetActive(false) 的特殊对象（如持续运行的状态机）。

13.5 启动池与扩展方法

StartupPool：预创建

ObjectPool 配置了 StartupPool 数组，启动时 CreateStartupPools 按指定 size 预实例化常用对象，让游戏运行中第一次 Spawn 就有现成实例，避免首次使用时的创建卡顿。

ObjectPoolExtensions：让语法更简洁

静态扩展方法把调用转发给 ObjectPool，于是代码里可以直接写：

// 扩展方法定义
public static GameObject Spawn(this GameObject prefab, Vector3 position)
{
    return ObjectPool.Spawn(prefab, null, position, Quaternion.identity);
}

// 实际调用（前面章节大量出现的 .Spawn()）
GameObject fx = strikeNailPrefab.Spawn(position);
gameObject.Recycle();

ActiveRecycler 本身只是一个空的标记类，靠 GetComponent 识别，不承载逻辑，是典型的标记组件（Marker）。

13.6 PersonalObjectPool：局部对象池

除了全局 ObjectPool，还有挂在单个物体上的局部池，实现 IInitialisable 接口：

public class PersonalObjectPool : MonoBehaviour, IInitialisable
{
    public List startupPool;
    private void RegisterDestroy()
    {
        gm = GameManager.instance;
        gm.DestroyPersonalPools += DestroyMyPooledObjects;
    }
}

全局池与局部池的区别：全局池跨场景存在、服务所有系统；局部池归属某个物体（如一个频繁生成特定特效的敌人），场景卸载或物体销毁时通过订阅 DestroyPersonalPools 统一清理，避免局部池的对象残留。IInitialisable 提供 OnAwake/OnStart 的标准化初始化契约。

13.7 AutoRecycleSelf：自动回收的三种触发

对象不需要外部记得回收，可挂 AutoRecycleSelf 按条件自动归还：

private void OnEnable()
{
    if (afterEvent == AfterEvent.TIME)
        StartCoroutine(StartTimer(timeToWait));              // 定时回收
    else if (afterEvent == AfterEvent.LEVEL_UNLOAD)
        GameManager.instance.DestroyPersonalPools += RecycleSelf;  // 场景卸载回收
    else if (afterEvent == AfterEvent.AUDIO_CLIP_END)
        audioSource = GetComponent();          // 音效播完回收
}

private void Update20()
{
    if (validAudioSource && !audioSource.isPlaying)
        RecycleSelf();   // 每 20 帧检测一次音效是否结束
}
触发方式适用对象
TIME定时消失的特效，支持真实时间/游戏时间
LEVEL_UNLOAD只在当前场景需要的对象
AUDIO_CLIP_END音效型对象，声音停即回收

13.8 FlingUtils：配置化的掉落抛洒

敌人死亡时吉欧如何飞散，由 FlingUtils 按一个 Config 结构驱动：

[Serializable]
public struct Config
{
    public GameObject Prefab;
    public float SpeedMin, SpeedMax;
    public float AngleMin, AngleMax;
    public float OriginVariationX, OriginVariationY;
    public int AmountMin, AmountMax;
}

public static GameObject[] SpawnAndFling(Config config, Transform point, Vector3 offset)
{
    int amount = Random.Range(config.AmountMin, config.AmountMax + 1);
    for (int i = 0; i < amount; i++)
    {
        Vector3 pos = origin + new Vector3(
            Random.Range(-config.OriginVariationX, config.OriginVariationX),
            Random.Range(-config.OriginVariationY, config.OriginVariationY), 0f);
        GameObject drop = config.Prefab.Spawn(pos);          // 从对象池取
        float speed = Random.Range(config.SpeedMin, config.SpeedMax);
        float angle = Random.Range(config.AngleMin, config.AngleMax);
        drop.GetComponent().linearVelocity =
            new Vector2(Mathf.Cos(angle * Mathf.PI / 180f),
                        Mathf.Sin(angle * Mathf.PI / 180f)) * speed;
    }
}

所有随机性（数量、初始位置、速度、角度）都在 Config 范围内，同一个工具能服务小/中/大吉欧、碎片等各种抛洒。FlingChildren 则用于抛洒已存在的子物体而非新 Spawn。掉落物本身也来自对象池，整条链路无额外分配。

13.9 审计与权衡

ObjectPoolAuditor 记录每次池创建、Spawn、Recycle（含是否真的 Instantiate），用于在开发期分析池的使用情况、容量是否合理。这是为性能优化埋的观测点。

收益代价与陷阱
大幅减少 GC 与运行时卡顿；复用对象；内存占用可预测 池内对象状态可能残留（取出时需手动重置）；初始容量占内存；自动扩容会退化为 Instantiate；同名/空引用需清理

最常见的池陷阱：状态残留。对象回收时不会自动重置字段，若 Spawn 时不显式初始化，新使用者会看到上一次留下的血量、计时器、碰撞标记。从池取对象后必须把它当作"可能带旧状态"处理，显式重置再使用。
