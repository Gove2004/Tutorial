T2 魔法森林：网格 DP 与 LCG 数据生成

题目描述

A 级 · 17noi #1720 原题 第二届区域赛 100 分（推定）

有一片 n 行 m 列的魔法森林，每个格子有一个法力值 w。 你从左下角 (n, 1) 出发，要走到右上角 (1, m)。 每一步只能向右或向上移动一格，经过的格子（包括起点和终点）的法力值会累加。 求能获得的最大法力值总和。

输入描述

一行三个整数 n、m、seed，分别表示行数、列数和随机种子。

输出描述

一个整数，表示最大路径和。

数据生成方式

矩阵不直接输入，而是用线性同余生成器（LCG）生成：

kMod = 1000000001
kMul = 1103515245
kInc = 13331
seed = (kMul * seed + kInc) % kMod

先更新 seed，再取更新后的值作为当前格子的 w； 按 i = 1..n、j = 1..m 的行优先顺序依次填充。

样例

输入：
3 2 114514

输出：
2739225543

生成的矩阵为：

944652894  719943493
269595497  625362356
805033659  556277872

最优路径是 (3,1) → (2,1) → (1,1) → (1,2)，和为 805033659 + 269595497 + 944652894 + 719943493 = 2739225543。

数据范围：30% 的数据 n, m ≤ 10；100% 的数据 1 ≤ n, m ≤ 2000，0 ≤ w ≤ 109，0 ≤ seed ≤ 109。

先自己想一想（建议 10 分钟）
  • 从 (n,1) 到 (1,m)，只能向右/向上，总共走多少步？
  • 每个格子的答案依赖哪两个格子？遍历顺序应该是什么？
  • 如果边 DP 边生成矩阵，会发生什么？

DP 定义

设 dp[i][j] 表示「从起点 (n,1) 走到 (i,j) 的最大路径和」。那么：

dp[i][j] = w[i][j] + max(dp[i+1][j], dp[i][j−1])

解释：走到 (i,j) 的最后一步，只可能从下方 (i+1,j) 上来，或从左侧 (i,j−1) 过来。 两者取最大，再加上当前格子的值。

遍历顺序必须是 i 从 n 递减到 1，j 从 1 递增到 m——先算下面一行，再算上面一行；同一行从左往右。 这样 dp[i+1][j] 和 dp[i][j−1] 都已经算好。

边界

  • 起点 dp[n][1] = w[n][1]，没有前驱。
  • 最下面一行 dp[n][j]（j > 1）只能从左边来。
  • 最左一列 dp[i][1]（i < n）只能从下边来。

两个坑，都在「看起来没问题」的地方

坑一：先生成矩阵，再 DP

LCG 要求按行优先（i 从 1 到 n，j 从 1 到 m）顺序生成。 而 DP 的遍历顺序是从下往上。如果你在 DP 的两层循环里边走边生成， 拿到的 w 与题目给的顺序完全不同，样例都过不了。 

// 错误：边 DP 边生成
for (int i = n - 1; i >= 0; --i)
    for (int j = 0; j < m; ++j) {
        seed = (MUL * seed + INC) % MOD;   // 这里是「从下往上」的顺序
        dp[i][j] = seed + ...;
    }

正确做法是先跑一遍行优先生成，把矩阵存下来，再做 DP。

坑二：起点没有显式初始化

如果所有 dp 初始化为 0，然后对每个格子都写 max(下方, 左方)， 起点会变成 w[n][1] + max(0,0) = w[n][1]，看起来是对的。 但一旦你把不可达方向的初值改成 -INF（这是好习惯），起点就会变成 -INF + w， 一个负的巨大数——后面所有格子都被污染。

正确写法是显式设置起点并继续：起点单独赋 w[n][1]，然后 continue， 不参与 max。

这个坑在赛场上很常见

本地样例如果是正数矩阵、且用 0 初始化，你根本发现不了。等到了有负数或大数据才炸。 养成「起点/终点显式初始化」的习惯，比事后调试便宜得多。

完整代码

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const ll MOD = 1000000001LL;
const ll MUL = 1103515245LL;
const ll INC = 13331LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    ll seed;
    cin >> n >> m >> seed;

    // 1. 行优先生成矩阵
    vector<vector<ll>> w(n, vector<ll>(m));
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < m; ++j) {
            seed = (MUL * seed + INC) % MOD;
            w[i][j] = seed;
        }
    }

    // 2. 从下往上、从左往右 DP，滚动数组省内存
    vector<ll> dp(m);
    for (int i = n - 1; i >= 0; --i) {
        for (int j = 0; j < m; ++j) {
            if (i == n - 1 && j == 0) {
                dp[j] = w[i][j];              // 起点显式初始化
                continue;
            }
            ll best = LLONG_MIN;
            if (i + 1 < n) best = max(best, dp[j]);        // 从下方来
            if (j - 1 >= 0) best = max(best, dp[j - 1]);   // 从左侧来
            dp[j] = w[i][j] + best;
        }
    }

    cout << dp[m - 1] << '\n';
    return 0;
}

滚动数组为什么安全

dp[j] 在更新前存的是「下一行同列」的值（即 dp[i+1][j]）； 更新后存的是「当前行」的值，供下一轮 i−1 使用。 dp[j−1] 在同一行内已经被更新过，正好是「当前行左侧」的值。 两个依赖都不会被覆盖错。

空间从 O(nm) 降到 O(m)。如果连矩阵也不想存，可以重跑一次 LCG，但没必要——2000×2000 的 long long 是 32 MB，在 256 MB 限制内。

样例验证

用 Python 跑一遍，矩阵与题面完全一致，DP 结果为 2739225543：

MOD, MUL, INC = 1000000001, 1103515245, 13331

n, m, seed = 3, 2, 114514
w = [[0] * m for _ in range(n)]
for i in range(n):
    for j in range(m):
        seed = (MUL * seed + INC) % MOD
        w[i][j] = seed

print(w)
# [[944652894, 719943493], [269595497, 625362356], [805033659, 556277872]]

dp = [0] * m
for i in range(n - 1, -1, -1):
    for j in range(m):
        if i == n - 1 and j == 0:
            dp[j] = w[i][j]
            continue
        best = -10**30
        if i + 1 < n: best = max(best, dp[j])
        if j - 1 >= 0: best = max(best, dp[j - 1])
        dp[j] = w[i][j] + best

print(dp[m - 1])   # 2739225543

注意 i 用的是 0-indexed，与题面的 1-indexed 差一位，但生成顺序和 DP 依赖都一致。

复杂度

  • 生成矩阵：O(nm) = 4×106 次乘加，long long 运算，几十毫秒。
  • DP：O(nm) = 4×106 次比较加法。
  • 空间：矩阵 32 MB + 滚动数组 16 KB。

n, m 都是 2000 时总计 8×106 级别操作，1 s 内轻松通过。 如果 n, m 都到 105，这套 O(nm) 就不行了，需要换思路（本题没有这个范围）。

易错点清单

  • 在 DP 循环里生成矩阵，顺序与题面要求的行优先不一致。
  • 先取 seed 再更新（得到的是 114514 开头的矩阵，样例对不上）。
  • 用 int 做 kMul * seed：1103515245 × 109 ≈ 1.1×1018，int 直接溢出。
  • 起点没显式初始化，配合 -INF 初值导致答案变成负的巨大数。
  • 遍历顺序写成「从上往下」，用到还没算的 dp[i+1][j]。
  • 把「只能向右/向上」写成四方向，路径和偏大。
  • 答案用 int 输出：最长路径 4000 格 × 109 = 4×1012，必须 long long。

延伸练习

1

改成求最小路径和

把 max 换成 min。注意此时 -INF 要换成 INF，起点初始化逻辑不变。

2

输出路径

额外记录每个格子的前驱方向，最后从终点回溯。滚动数组存不下路径，需要完整 dp 表或反向重算。

3

换一种 LCG

把 kMul、kInc、kMod 换成别的常数，验证你的生成顺序仍然正确。这类题的数据生成规则经常变，但「先更新再取值 + 行优先」的结构不变。

本章小结

  • 网格 DP 的遍历顺序由依赖方向决定：从下往上、从左往右。
  • 数据生成类题目，生成顺序本身就是题面的一部分，不能想当然。
  • 起点/终点显式初始化，是避免 -INF 污染的标准做法。
  • 滚动数组能把空间从 O(nm) 降到 O(m)，但要想清楚「更新前/更新后」各代表什么。
