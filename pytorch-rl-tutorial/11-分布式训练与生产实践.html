第 11 章：分布式训练与生产实践

11.1 为什么需要分布式 RL

强化学习训练的瓶颈通常在采样而非计算。一个 Agent 在单卡上每天可能只能采集几万到几十万步，而复杂任务需要数十亿步。分布式 RL 通过并行采样来解决这个瓶颈：

  • 数据并行：多个 worker 并行采集数据，汇总后统一更新
  • 模型并行：将大模型拆到多个 GPU 上（RL 中较少使用）
  • 分布式推理：多个 GPU 并行推理加速采样

11.2 RLlib：Ray 的强化学习框架

RLlib 是 Ray 生态中的分布式 RL 框架，支持 PPO、DQN、A2C 等主流算法，自动处理分布式采样和同步。

11.3 检查点管理与恢复

"""
生产环境中，训练往往需要长时间运行并支持中断恢复
"""
import os
import json
import torch

class CheckpointManager:
    def __init__(self, agent, env, save_dir="./checkpoints"):
        self.agent = agent
        self.env = env
        self.save_dir = save_dir
        os.makedirs(save_dir, exist_ok=True)
        self.best_reward = -float('inf')
        self.episode = 0

    def save(self, episode, reward, is_best=False):
        checkpoint = {
            'episode': episode,
            'agent_state': self.agent.policy.state_dict(),
            'optimizer_state': self.agent.optimizer.state_dict(),
            'reward': reward,
            'epsilon': self.agent.epsilon,
            'memory_size': len(self.agent.memory)
        }
        path = os.path.join(self.save_dir, f"checkpoint_ep{episode}.pt")
        torch.save(checkpoint, path)

        if is_best or reward > self.best_reward:
            self.best_reward = reward
            best_path = os.path.join(self.save_dir, "best.pth")
            torch.save(checkpoint, best_path)
            print(f"保存最佳模型: 奖励={reward:.1f}")

    def load(self, path="best.pth"):
        path = os.path.join(self.save_dir, path)
        if os.path.exists(path):
            checkpoint = torch.load(path, map_location='cpu')
            self.agent.policy.load_state_dict(checkpoint['agent_state'])
            self.agent.optimizer.load_state_dict(checkpoint['optimizer_state'])
            self.episode = checkpoint['episode']
            self.agent.epsilon = checkpoint['epsilon']
            print(f"从检查点恢复: episode={self.episode}")
            return True
        return False

    def list_checkpoints(self):
        files = sorted(os.listdir(self.save_dir),
                      key=lambda x: int(x.split('ep')[1].split('.')[0])
                      if 'ep' in x else 0)
        return [f for f in files if f.endswith('.pt')]

11.4 训练稳定性保障

"""
训练监控与自动调整
"""
import numpy as np
from collections import deque

class TrainingMonitor:
    def __init__(self, window=50):
        self.window = window
        self.rewards = deque(maxlen=window)
        self.losses = deque(maxlen=window)
        self.entropies = deque(maxlen=window)
        self.stalls = 0
        self.max_stalls = 5

    def record(self, reward, loss=None, entropy=None):
        self.rewards.append(reward)
        if loss is not None:
            self.losses.append(loss)
        if entropy is not None:
            self.entropies.append(entropy)

    def check_stall(self, min_improvement=0.95):
        """检测训练是否停滞"""
        if len(self.rewards) < self.window:
            return False
        recent = np.mean(list(self.rewards)[-10:])
        earlier = np.mean(list(self.rewards)[:10])
        if recent < earlier * min_improvement:
            self.stalls += 1
            return self.stalls >= self.max_stalls
        self.stalls = 0
        return False

    def check_divergence(self, max_loss=100.0):
        """检测训练发散"""
        if self.losses and self.losses[-1] > max_loss:
            return True
        return False

    def get_stats(self):
        return {
            'avg_reward': np.mean(self.rewards) if self.rewards else 0,
            'max_reward': max(self.rewards) if self.rewards else 0,
            'avg_loss': np.mean(self.losses) if self.losses else 0,
            'avg_entropy': np.mean(self.entropies) if self.entropies else 0,
            'stalls': self.stalls
        }

常见的性能优化方向：

  • GPU 利用率低：检查 batch_size 是否太小，或是否在 CPU 上做了大量数据处理
  • 采样成为瓶颈：增加并行环境数，或使用向量化的环境（如 gym.vector）
  • 内存泄漏：定期检查 tensor 数量，使用 torch.cuda.empty_cache()
  • 数据加载慢：使用 torch.utils.data.DataLoader 的 num_workers 并行加载

11.6 生产部署要点

方面要点
模型版本每个检查点打标签，记录训练配置和超参数
A/B 测试新模型先在仿真环境中与旧模型对比，再上线
回滚机制保留历史模型，出问题可以快速回退
监控告警训练中断、奖励骤降、熵崩溃时自动通知
资源成本使用 spot instances、自动关停空闲 GPU
