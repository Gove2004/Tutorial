第 8 章：延迟补偿与客户端预测

这是单机开发者转联机时遇到的最大体验鸿沟。 在 50ms 延迟下你可能感觉不到问题，但一旦达到 150ms+（跨区匹配、海外服务器）， "射击打不中"、"移动卡顿"、"操作跟手性差"这些问题就会集中爆发。 本章从零搭建一套可工作的预测+插值系统。

📌 Mirror 96 API 更新要点（本章涉及）：
• hasAuthority → isOwned：NetworkBehaviour 属性更名
• isLocalPlayer 已隐含 isOwned，无需双重检查
• NetworkClient.RegisterHandler<T> 不再有 replace 参数
• 自定义消息必须为 struct : INetworkMessage（非 class : MessageBase）
• Command 中可通过 NetworkConnectionToClient sender = null 获取发送方
• connectionToClient.rtt 可直接获取往返延迟
• [Command] / [ClientRpc] 方法前缀（Cmd/Rpc）从必需变为可选（推荐保留）

8.1 问题的本质：延迟为什么影响体验？

假设你和服务器的 RTT（往返延迟）是 200ms：

t=0ms    客户端: 按下 W 键，发送移动请求
t=100ms  服务器: 收到移动请求，执行移动，广播新位置
t=200ms  客户端: 收到新位置更新

问题：从按下 W 到看到角色移动，经过了 200ms！
玩家感受："操作有延迟"、"角色不听使唤"

更严重的是其他玩家的视角：

玩家 A（本地，RTT=20ms）   玩家 B（远程，RTT=200ms）
     |                            |
     |-- 移动请求 -------------->|
     |<-- 位置更新 --------------|
     |                            |
     |<--- 位置更新（经过转发） --->|
     |                          |
     感觉流畅                    感觉卡顿 100ms+

关键指标

RTT（Round Trip Time）：数据包从客户端到服务器再返回的时间。在 Mirror 96 中可通过 connectionToClient.rtt 获取。
服务端 Tick Rate：服务器每秒更新游戏的次数。常见值：20Hz（50ms）、30Hz（33ms）、60Hz（16ms）。
Input Lag：从玩家按下按键到看到效果的时间。

8.2 客户端预测（Client-side Prediction）

核心思想：不等服务器确认，客户端先自己移动。 如果服务器的反馈和客户端的预测不一致，再修正回来。

using Mirror;
using System.Collections.Generic;
using UnityEngine;

public class ClientPrediction : NetworkBehaviour
{
    public float moveSpeed = 5f;

    // 输入缓存：存储尚未被服务器确认的输入
    readonly List<PlayerInput> pendingInputs = new List<PlayerInput>();
    int serverConfirmedSeq = 0;
    int inputSequence = 0;
    float lastSendTime = 0f;

    // 服务器确认的移动速度（可能和客户端略有不同）
    public float serverMoveSpeed = 5f;

    void Update()
    {
        // Mirror 96: isLocalPlayer 已隐含 isOwned，无需额外检查 hasAuthority
        if (!isLocalPlayer) return;

        PlayerInput? newInput = null;

        // ===== 第 1 步：收集输入 =====
        Vector2 input = new Vector2(Input.GetAxis("Horizontal"), Input.GetAxis("Vertical"));
        if (input.sqrMagnitude > 0.01f)
        {
            newInput = new PlayerInput
            {
                sequence = ++inputSequence,
                timestamp = Time.time,
                direction = input
            };
            pendingInputs.Add(newInput.Value);

            // ===== 第 2 步：预测性执行（本地立即应用）====
            PredictMove(input * moveSpeed * Time.deltaTime);
        }

        // ===== 第 3 步：发送输入给服务器 =====
        if (newInput.HasValue && Time.time - lastSendTime > 1f / 30f)  // 30Hz 发送频率
        {
            CmdSendInput(newInput.Value);
            lastSendTime = Time.time;
        }
    }

    void PredictMove(Vector3 delta)
    {
        transform.position += delta;
    }

    // Mirror 96: Cmd 前缀可选但推荐保留作为约定
    [Command]
    void CmdSendInput(PlayerInput input)
    {
        // 服务器执行输入并广播
        ServerProcessInput(input);
        RpcBroadcastInput(input);
    }

    void ServerProcessInput(PlayerInput input)
    {
        // 服务器端执行移动逻辑...
        transform.position += (Vector3)(input.direction * serverMoveSpeed * Time.deltaTime);
    }

    // Mirror 96: Rpc 前缀可选但推荐保留作为约定
    [ClientRpc]
    void RpcBroadcastInput(PlayerInput input)
    {
        // 所有客户端收到后更新对应玩家的位置
        UpdatePlayerPosition(input);
    }

    void UpdatePlayerPosition(PlayerInput input)
    {
        if (!isLocalPlayer)  // 远程玩家才需要更新
        {
            // 应用位置更新...
        }
    }

    // 服务器回传确认状态
    public void ApplyServerCorrection(Vector3 serverPos, int confirmedSeq)
    {
        serverConfirmedSeq = confirmedSeq;

        // ===== 第 4 步：校正 —— 这是最关键的一步 =====
        // 如果服务器位置和预测位置差异太大，需要平滑校正
        float diff = Vector3.Distance(transform.position, serverPos);
        if (diff > 5f)
        {
            // 差距过大，可能是网络抖动或作弊检测，直接瞬移
            transform.position = serverPos;
            pendingInputs.Clear();  // 清空未确认输入
        }
        else if (diff > 0.1f)
        {
            // 小差距，平滑过渡
            transform.position = Vector3.Lerp(transform.position, serverPos, 0.3f);
        }
        // 差距很小，忽略——避免微小抖动
    }
}

[System.Serializable]
public struct PlayerInput
{
    public int sequence;
    public float timestamp;
    public Vector2 direction;
}
Mirror 96 变化：
  • hasAuthority 已更名为 isOwned。对于 Player 对象，isLocalPlayer 为 true 时 isOwned 也必为 true，因此 isLocalPlayer && hasAuthority 可简化为 isLocalPlayer。
  • [Command] 和 [ClientRpc] 的 Cmd/Rpc 前缀从必需变为可选，但社区约定仍推荐保留前缀以提高可读性。
  • 如需在 Command 中获取发送方连接，可添加 NetworkConnectionToClient sender = null 可选参数，Mirror 会自动填充。

8.2.1 预测的核心难点：校正（Reconciliation）

最棘手的部分不是"预测移动"，而是"预测错了怎么办"。

时间线：

客户端预测：  A → B → C → D → E（当前位置）
服务器确认：  A ---------→ C'（只确认到 C'）

问题：D 和 E 是基于错误的 C 预测的，而服务器认为正确的中间点是 C'。
      C 和 C' 的差异会导致 D 和 E 也不准确。

解决方案 1：暴力回滚
  删除 C 之后的所有输入，从 C' 重新开始预测。
  优点：简单正确。缺点：位置跳变，视觉不流畅。

解决方案 2：平滑校正（推荐）
  不删除pending输入，而是在每一帧将预测位置向服务器位置靠拢。
  优点：视觉平滑。缺点：需要调参（校正速度不能太快也不能太慢）。
using UnityEngine;

// 平滑校正组件（不需要网络功能，挂载在客户端预测对象上）
public class SmoothCorrection : MonoBehaviour
{
    public float correctionSpeed = 5f;
    Vector3 targetPosition;
    bool awaitingCorrection = false;

    void Update()
    {
        if (awaitingCorrection)
        {
            transform.position = Vector3.MoveTowards(
                transform.position,
                targetPosition,
                correctionSpeed * Time.deltaTime
            );

            if (Vector3.Distance(transform.position, targetPosition) < 0.01f)
            {
                awaitingCorrection = false;
            }
        }
    }

    public void RequestCorrection(Vector3 serverPos)
    {
        targetPosition = serverPos;
        awaitingCorrection = true;
    }
}

8.3 状态插值（State Interpolation）

预测解决的是"本地玩家"的体验。插值解决的是"看别人"的体验。

问题：服务器每 33ms（30Hz）发送一次位置更新。
      如果客户端收到就立即渲染，其他玩家会看到"一帧一帧跳动"的效果。

解决方案：永远渲染"过去"的状态，在两个更新之间做插值。

时间线：
t=0ms    收到位置 A（t=0时的位置）
t=33ms   收到位置 B（t=33时的位置）→ 但渲染时用 A 和 B 之间的插值
t=66ms   收到位置 C（t=66时的位置）→ 渲染时用 B 和 C 之间的插值

关键：引入 bufferTime（缓冲时间），让渲染永远落后服务器一小段时间。
      这样即使网络抖动导致数据包迟到，也有余量补偿。
using Mirror;
using System.Collections.Generic;
using UnityEngine;

// Mirror 96: 自定义消息必须是 struct : INetworkMessage
public struct PositionUpdateMessage : INetworkMessage
{
    public float timestamp;
    public Vector3 position;
    public Quaternion rotation;

    public void Serialize(NetworkWriter writer)
    {
        writer.WriteSingle(timestamp);
        writer.WriteVector3(position);
        writer.WriteQuaternion(rotation);
    }

    public void Deserialize(NetworkReader reader)
    {
        timestamp = reader.ReadSingle();
        position = reader.ReadVector3();
        rotation = reader.ReadQuaternion();
    }
}

public class StateInterpolation : NetworkBehaviour
{
    // 存储最近的状态历史
    struct StateRecord
    {
        public float serverTime;
        public Vector3 position;
        public Quaternion rotation;
    }

    readonly Queue<StateRecord> stateBuffer = new Queue<StateRecord>();

    public float interpolationFactor = 0.1f;  // 插值系数（越小越平滑，但延迟越大）
    public int maxBufferSize = 10;             // 最大缓冲状态数

    // Mirror 96: OnStartClient() 是 NetworkBehaviour 的虚方法
    public override void OnStartClient()
    {
        // Mirror 96: RegisterHandler 不再有 replace 参数
        // 消息处理器签名：void Handler(T msg) — 无连接参数
        NetworkClient.RegisterHandler<PositionUpdateMessage>(OnPositionUpdate);
    }

    void OnPositionUpdate(PositionUpdateMessage msg)
    {
        // 注意：客户端消息处理器签名是 void Handler(T msg)
        // 不含 NetworkConnection 参数（与服务器端处理器不同）
        StateRecord record = new StateRecord
        {
            serverTime = msg.timestamp,
            position = msg.position,
            rotation = msg.rotation
        };

        stateBuffer.Enqueue(record);

        // 限制缓冲区大小
        while (stateBuffer.Count > maxBufferSize)
        {
            stateBuffer.Dequeue();
        }
    }

    void Update()
    {
        // 只对远程玩家做插值（本地玩家用预测）
        if (!isLocalPlayer && stateBuffer.Count >= 2)
        {
            StateRecord[] records = stateBuffer.ToArray();
            StateRecord older = records[0];
            StateRecord newer = records[1];

            // 计算插值因子
            float timeSpan = newer.serverTime - older.serverTime;
            if (timeSpan > 0.001f)
            {
                float t = (Time.time - older.serverTime) / timeSpan;
                t = Mathf.Clamp01(t);

                // 线性插值位置
                transform.position = Vector3.Lerp(older.position, newer.position, t);
                transform.rotation = Quaternion.Slerp(older.rotation, newer.rotation, t);
            }
        }
    }
}
Mirror 96 变化：
  • NetworkClient.RegisterHandler<T>(handler) 不再有 replace 参数。如需替换已有处理器，直接再次注册即可。
  • 自定义消息从 class XXXMessage : MessageBase 改为 struct XXXMessage : INetworkMessage，需实现 Serialize() 和 Deserialize() 方法。
  • 客户端消息处理器签名为 void Handler(T msg)（无连接参数）；服务器端为 void Handler(NetworkConnectionToClient conn, T msg)。
  • OnStartClient() 需使用 override 关键字，因为它是 NetworkBehaviour 的虚方法。

8.3.1 插值的延迟权衡

插值延迟视觉效果适用场景
0ms（无插值）抖动、跳动不适用
50ms轻微平滑，基本实时快节奏竞技游戏
100ms明显平滑大多数多人游戏（推荐）
200ms+非常平滑但有可见延迟回合制、策略游戏
经验法则：对于大多数动作类游戏，使用 1-2 个服务器的 tick 作为插值延迟。 如果服务器是 30Hz（33ms/tick），那么插值延迟约 33-66ms。 这个延迟玩家几乎感知不到，但能大幅减少抖动。

8.4 延迟补偿（Server-Side Lag Compensation）

预测和插值解决的是"视觉流畅度"问题。延迟补偿解决的是"命中判定"问题。

场景：你用 200ms 延迟射击一个快速移动的敌人。 当你看到他在某个位置时，实际上他已经移动了 100ms。 如果你朝"看到的位置"射击，大概率打不中——因为那已经是"过去"了。

using Mirror;
using System.Collections.Generic;
using UnityEngine;

// Mirror 96: 使用 NetworkBehaviour（需要 [Command] 和 connectionToClient）
public class LagCompensation : NetworkBehaviour
{
    [SerializeField] Rigidbody rb;  // Mirror 96: 使用 SerializeField 而非废弃的 rigidbody 属性

    // 服务器端：回放敌人的历史位置
    struct PositionHistory
    {
        public float timestamp;
        public Vector3 position;
        public Vector3 velocity;
    }

    readonly Queue<PositionHistory> positionHistory = new Queue<PositionHistory>();
    const int HistoryLengthSeconds = 2;  // 保留最近 2 秒的历史

    void RecordPosition()
    {
        PositionHistory record = new PositionHistory
        {
            timestamp = Time.time,
            position = transform.position,
            velocity = rb != null ? rb.velocity : Vector3.zero
        };

        positionHistory.Enqueue(record);

        while (positionHistory.Count > HistoryLengthSeconds * 60)  // 假设 60fps
        {
            positionHistory.Dequeue();
        }
    }

    // 服务器根据客户端的射击时间，回溯敌人当时的位置
    Vector3 GetPositionAtTime(float shotTimestamp, float rtt)
    {
        float targetTime = shotTimestamp + rtt / 2f;  // 估算敌人在射击时刻的位置

        foreach (var record in positionHistory)
        {
            if (Mathf.Abs(record.timestamp - targetTime) < 0.01f)
            {
                return record.position;
            }
        }

        // 没找到精确匹配，用最近的
        if (positionHistory.Count > 0)
        {
            // 遍历找最接近的
            Vector3 closest = transform.position;
            float minDiff = float.MaxValue;
            foreach (var record in positionHistory)
            {
                float diff = Mathf.Abs(record.timestamp - targetTime);
                if (diff < minDiff)
                {
                    minDiff = diff;
                    closest = record.position;
                }
            }
            return closest;
        }

        return transform.position;
    }

    // 射击时
    // Mirror 96: requiresAuthority = false 允许无权限对象也调用此 Command
    // NetworkConnectionToClient sender = null 自动填充发送方连接
    [Command(requiresAuthority = false)]
    void CmdShoot(Vector3 shootDirection, float shotTime, Vector3 shootOrigin,
                  NetworkConnectionToClient sender = null)
    {
        // Mirror 96: 通过 sender 参数获取 RTT（也可用 connectionToClient.rtt）
        float rtt = sender != null ? sender.rtt : connectionToClient.rtt;

        // 获取敌人在射击时刻的位置（而不是现在的位置）
        Vector3 enemyPosAtShotTime = GetPositionAtTime(shotTime, rtt);

        // 用回溯后的位置做射线检测
        RaycastHit hit;
        if (Physics.Raycast(shootOrigin, shootDirection, out hit, 100f))
        {
            var healthSystem = hit.collider.GetComponent<HealthSystem>();
            if (healthSystem != null)
            {
                healthSystem.TakeDamage(25);
            }
        }
    }
}
Mirror 96 变化：
  • 需要在 Command 中获取发送方连接时，添加 NetworkConnectionToClient sender = null 可选参数，Mirror 自动填充。也可直接使用 connectionToClient.rtt。
  • [Command(requiresAuthority = false)]：当非拥有权限的对象需要调用 Command 时使用（如非 Player 对象上的射击逻辑）。
  • Unity 的 rigidbody 快捷属性已废弃，应使用 [SerializeField] Rigidbody rb; 在 Inspector 中引用。

8.5 完整整合：预测 + 插值 + 延迟补偿

一个完整的联网运动系统应该同时包含这三个组件：

using Mirror;
using System.Collections.Generic;
using UnityEngine;

public class CompleteNetworkedMovement : NetworkBehaviour
{
    // ===== 客户端预测相关 =====
    readonly List<MovementCommand> clientCommands = new List<MovementCommand>();
    int nextCommandSeq = 0;
    Vector3 predictedPosition;
    float lastSendTime = 0f;
    public float sendRate = 30f;

    // ===== 服务器插值相关 =====
    // 使用可空类型（struct 不能直接与 null 比较）
    struct ServerState
    {
        public float timestamp;
        public Vector3 position;
        public Quaternion rotation;
    }

    readonly Queue<ServerState> serverStateBuffer = new Queue<ServerState>();
    ServerState? prevState = null;
    ServerState? nextState = null;

    // ===== 配置 =====
    public float interpolationDelay = 0.1f;  // 100ms 插值延迟
    public float correctionSpeed = 5f;
    public float moveSpeed = 5f;

    void Update()
    {
        // Mirror 96: isLocalPlayer 已隐含 isOwned，无需检查 hasAuthority
        if (isLocalPlayer)
        {
            UpdatePrediction();
        }
        else if (!isLocalPlayer)
        {
            UpdateInterpolation();
        }
    }

    // ---------- 客户端预测部分 ----------
    void UpdatePrediction()
    {
        // 收集输入
        Vector2 input = new Vector2(Input.GetAxisRaw("Horizontal"), Input.GetAxisRaw("Vertical"));

        if (input.sqrMagnitude > 0.1f)
        {
            MovementCommand cmd = new MovementCommand
            {
                seq = nextCommandSeq++,
                timestamp = Time.time,
                input = input
            };
            clientCommands.Add(cmd);

            // 预测执行
            predictedPosition += (Vector3)(input * moveSpeed * Time.deltaTime);
            transform.position = predictedPosition;
        }

        // 发送输入
        if (clientCommands.Count > 0 && Time.time - lastSendTime > 1f / sendRate)
        {
            // Mirror 96: List<T> 作为 RPC 参数需要 Reader/Writer 支持
            // 更推荐使用数组：MovementCommand[] 
            CmdSendMovementCommand(clientCommands.ToArray());
            clientCommands.Clear();
            lastSendTime = Time.time;
        }
    }

    // ---------- 服务器处理部分 ----------
    [Command]
    void CmdSendMovementCommand(MovementCommand[] commands)
    {
        foreach (var cmd in commands)
        {
            ProcessMovementCommand(cmd);
        }

        // 广播服务器计算的位置
        BroadcastServerState();
    }

    void ProcessMovementCommand(MovementCommand cmd)
    {
        Vector3 move = (Vector3)(cmd.input * moveSpeed * Time.deltaTime);
        transform.position += move;
        RecordServerState();
    }

    void RecordServerState()
    {
        ServerState state = new ServerState
        {
            timestamp = Time.time,
            position = transform.position,
            rotation = transform.rotation
        };
        RpcReceiveServerState(state);
    }

    void BroadcastServerState()
    {
        // 服务器处理时 RecordServerState 已调用 RpcReceiveServerState
    }

    // ---------- 客户端插值部分 ----------
    void UpdateInterpolation()
    {
        // 获取最新的服务器状态
        if (serverStateBuffer.Count > 0)
        {
            ServerState latest = serverStateBuffer.Peek();

            if (!nextState.HasValue || latest.timestamp > nextState.Value.timestamp)
            {
                prevState = nextState ?? latest;
                nextState = latest;
                serverStateBuffer.Dequeue();
            }
        }

        if (prevState.HasValue && nextState.HasValue)
        {
            float elapsed = Time.time - prevState.Value.timestamp;
            float duration = nextState.Value.timestamp - prevState.Value.timestamp;
            float t = duration > 0 ? elapsed / duration : 0;
            t = Mathf.Clamp01(t);

            transform.position = Vector3.Lerp(prevState.Value.position, nextState.Value.position, t);
            transform.rotation = Quaternion.Slerp(prevState.Value.rotation, nextState.Value.rotation, t);
        }
    }

    [ClientRpc]
    void RpcReceiveServerState(ServerState state)
    {
        serverStateBuffer.Enqueue(state);

        // 限制缓冲区
        while (serverStateBuffer.Count > 20)
            serverStateBuffer.Dequeue();
    }
}

[System.Serializable]
public struct MovementCommand
{
    public int seq;
    public float timestamp;
    public Vector2 input;
}
Mirror 96 注意事项：
  • ServerState 是 struct，不能与 null 比较。使用 ServerState?（Nullable<ServerState>）或布尔标志位来判断是否已赋值。
  • RPC 参数推荐使用数组（T[]）而非 List<T>，因为数组是 Mirror 原生支持的序列化类型，性能更好且无需额外 Reader/Writer。
  • 自定义 struct（如 MovementCommand、ServerState）作为 RPC 参数时，需要添加 [System.Serializable] 特性，Mirror 会自动生成序列化代码。

8.6 调试与可视化

预测和插值的问题往往很难通过日志发现。可视化是关键：

using Mirror;
using UnityEngine;

// Mirror 96: 使用 NetworkBehaviour（需要 isClient 属性）
public class NetworkDebugVisualizer : NetworkBehaviour
{
    [SerializeField] Vector3 predictedPosition;
    [SerializeField] Vector3 serverPosition;

    void OnDrawGizmos()
    {
        // isClient 是 NetworkBehaviour 的只读属性
        if (!isClient) return;

        // 绘制预测位置（绿色球）
        Gizmos.color = Color.green;
        Gizmos.DrawWireSphere(predictedPosition, 0.3f);

        // 绘制服务器位置（红色球）
        Gizmos.color = Color.red;
        Gizmos.DrawWireSphere(serverPosition, 0.3f);

        // 绘制当前渲染位置（蓝色球）
        Gizmos.color = Color.blue;
        Gizmos.DrawWireSphere(transform.position, 0.3f);

        // 绘制连线
        Gizmos.DrawLine(predictedPosition, serverPosition);

        // 如果预测和服务器位置差距过大，画一个警告圈
        float diff = Vector3.Distance(predictedPosition, serverPosition);
        if (diff > 2f)
        {
            Gizmos.color = Color.yellow;
            Gizmos.DrawWireSphere(transform.position, diff);
        }
    }
}
调试技巧：当预测校正导致位置跳变时，观察绿色球（预测）和红色球（服务器） 之间的距离。如果经常超过 1-2 米，说明你的预测模型和服务器模型不一致—— 最可能的原因是两边的移动速度参数不同，或者服务器做了额外的验证/限制。

8.7 性能考量

优化项建议原因
发送频率30Hz（每 33ms）高于 30Hz 收益递减，低于 20Hz 有明显卡顿
插值缓冲2-3 个状态太少容易断档，太多增加延迟
校正阈值1-2 米超过这个值说明模型不一致，需要调查根因
历史长度2-3 秒覆盖最大可能的 RTT + 抖动
RPC 参数类型数组优于 ListMirror 原生支持数组序列化，无需额外 Reader/Writer
RTT 获取方式connectionToClient.rtt 或 sender.rtt直接读取，无需额外消息往返

8.8 本章小结

技术解决的问题Mirror 96 API 要点
客户端预测 自己的操作有延迟 → 不等服务器确认就执行 isLocalPlayer 隐含 isOwned；[Command] 前缀可选
状态插值 看别人一卡一卡 → 在两个状态间平滑过渡 RegisterHandler<T> 无 replace 参数；消息为 INetworkMessage
延迟补偿 明明瞄准了却打不中 → 回溯目标在射击时刻的位置 sender.rtt 获取延迟；[Command(requiresAuthority = false)]

三者结合，才能在 200ms+ 延迟下获得可玩的体验。 这些技术是所有商业级联网游戏的标配。实现它们不需要高深数学， 只需要理解延迟的来源和每一方看到的"时间线"。

自测题

点击展开自测题
  1. 场景推理：如果 RTT 是 0ms（局域网），还需要预测和插值吗？为什么？
  2. 设计题：预测校正时，如果客户端和服务器对物理模拟的结果不一致（比如一个撞墙了，另一个穿过去了），应该如何处理？
  3. 数值题：服务器 60Hz，RTT 100ms。插值延迟应该设多少？缓冲队列应该保持多少个状态？
  4. Mirror 96 变化题：在 Mirror 96 中，如果要在一个非 Player 对象上实现延迟补偿射击逻辑，[Command] 需要添加什么参数？如何获取发送方的 RTT？
  5. Mirror 96 变化题：自定义消息 PositionUpdateMessage 在 Mirror 96 中应该如何定义？客户端消息处理器的签名是什么？
参考答案：
1) 理论上 RTT=0 时不需要预测。但实际上"零延迟"几乎不存在（即使是局域网也有 1-5ms）。 而且插值不是为了 RTT，而是为了平滑服务器 tick 之间的抖动。所以插值始终需要。

2) 这是最常见的预测问题根源。解决方案：确保客户端和服务器的物理参数完全一致（重力、摩擦力、碰撞体）。 如果仍然不一致，应该以服务器为准进行强制校正，而不是尝试让两边一致。

3) 插值延迟建议 60-100ms（1-2 个 tick）。缓冲队列保持 3-5 个状态。 60Hz 下 100ms ≈ 6 个 tick，所以缓冲 5-6 个状态足够覆盖大多数抖动。

4) 需要 [Command(requiresAuthority = false)]，因为非 Player 对象没有客户端权限。 获取 RTT 两种方式：① 添加 NetworkConnectionToClient sender = null 参数，用 sender.rtt； ② 直接使用 connectionToClient.rtt（NetworkBehaviour 属性）。

5) 定义为 public struct PositionUpdateMessage : INetworkMessage，实现 Serialize(NetworkWriter) 和 Deserialize(NetworkReader) 方法。 客户端消息处理器签名为 void OnPositionUpdate(PositionUpdateMessage msg)（无连接参数）。 使用 NetworkClient.RegisterHandler<PositionUpdateMessage>(OnPositionUpdate) 注册（无 replace 参数）。
