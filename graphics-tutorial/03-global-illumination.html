03 - 全局光照：从辐射传输方程到路径追踪

全局光照（Global Illumination）是计算机图形学中最核心的问题之一：光线如何在场景中多次反弹？为什么阴影不是纯黑色的？为什么白墙会让房间变暖？本章从辐射传输方程出发，推导各种全局光照算法，并给出可工作的路径追踪器实现。

3.1 辐射传输方程（RTE）

辐射传输方程是描述光在介质中传播的积分-微分方程。它是所有全局光照算法的数学基础。

辐射传输方程（RTE）

在位置 x 沿方向 ω 的辐射亮度变化率为：

dL(x, ω) / ds = -σ_t · L(x, ω) + σ_s · ∫ f_r(ω', ω) · L(x, ω') dω' + Q(x, ω)

其中：

  • σ_t = 消光系数（吸收 + 散射）
  • σ_s = 散射系数
  • f_r = 相函数（散射方向分布）
  • Q = 自发辐射（光源项）

在真空/空气中 σ_t ≈ 0（无介质散射），方程简化为著名的渲染方程（Rendering Equation）：

Lₒ(x, ωₒ) = Lₑ(x, ωₒ) + ∫Ω fᵣ(ωᵢ, ωₒ) · Lᵢ(x, ωᵢ) · max(cos θᵢ, 0) dωᵢ

这个方程的含义极其深刻：一个点发出的光 = 自身发光 + 从所有方向入射的光 × 材质的反射概率。这是一个递归定义——Lᵢ 本身又是另一个点的 Lₒ。求解这个方程就是全局光照的本质。

为什么渲染方程这么难解？：因为它是一个积分方程，而且 Lᵢ 又依赖于其他点的 Lₒ，形成无限递归。解析解几乎不存在（除了最简单的场景）。我们必须用数值方法——这就是蒙特卡洛路径追踪的由来。

3.2 BRDF 模型详解

BRDF（双向反射分布函数）是渲染方程中的 fᵣ。选择合适的 BRDF 模型直接决定渲染的视觉效果。

3.2.1 Lambertian（理想漫反射）

最简单的 BRDF 模型，假设表面在所有方向均匀反射：

// Lambertian BRDF
// f_r = albedo / pi
// 为什么除以 pi？因为积分 ∫ max(cosθ, 0) dω over hemisphere = pi
float lambertianBRDF(float albedo) {
    return albedo / PI;
}

// 能量守恒检查：
// ∫ f_r * cos(theta) domega = (albedo/pi) * pi = albedo <= 1 ✓

3.2.2 Phong 模型（经验模型）

Phong 不是物理正确的，但因其简单而被广泛使用：

// Phong 着色模型（片段着色器实现）
vec3 phongBRDF(vec3 N, vec3 V, vec3 L, vec3 albedo, vec3 specColor, float shininess) {
    vec3 H = normalize(V + L);

    // 漫反射
    float NdotL = max(dot(N, L), 0.0);
    vec3 diffuse = albedo * NdotL;

    // 镜面反射
    float NdotH = max(dot(N, H), 0.0);
    vec3 specular = specColor * pow(NdotH, shininess);

    return diffuse + specular;
}

3.2.3 GGX + Cook-Torrance（PBR 标准）

现代实时渲染的标准 BRDF 基于 Cook-Torrance 模型，使用 GGX 法线分布函数（NDF）、Smith 遮蔽-阴影函数和 Fresnel 方程：

// GGX NDF（Trowbridge-Reitz 分布）
float D_GGX(float NdotH, float alpha) {
    float a2 = alpha * alpha;
    float d = (NdotH * NdotH * (a2 - 1.0f) + 1.0f);
    return a2 / (PI * d * d);
}

// Smith 遮蔽函数（GGX 近似）
float G_Smith(float NdotV, float NdotL, float alpha) {
    float ggxV = NdotL * sqrt((-NdotV * alpha + NdotV) * NdotV);
    float ggxL = NdotV * sqrt((-NdotL * alpha + NdotL) * NdotL);
    return 0.5f / (ggxV + ggxL + EPSILON);
}

// Schlick-Fresnel 近似
vec3 F_Schlick(float cosTheta, vec3 F0) {
    return F0 + (1.0f - F0) * pow(clamp(1.0f - cosTheta, 0.0f, 1.0f), 5.0f);
}

// 完整 Cook-Torrance BRDF
vec3 cookTorranceBRDF(vec3 N, vec3 V, vec3 L,
                      vec3 F0, float roughness) {
    vec3 H = normalize(V + L);
    float NdotV = max(dot(N, V), 0.0f);
    float NdotL = max(dot(N, L), 0.0f);
    float NdotH = max(dot(N, H), 0.0f);
    float HdotV = max(dot(H, V), 0.0f);

    float alpha = roughness * roughness;
    vec3 F = F_Schlick(HdotV, F0);
    float D = D_GGX(NdotH, alpha);
    float G = G_Smith(NdotV, NdotL, alpha);

    // 忽略分母中的 4 因子（被重要性采样的 PDF 抵消）
    return F * D * G / (4.0f * NdotV * NdotL + EPSILON);
}
常见误区：很多初学者以为 GGX 的 roughness 参数直接对应材料的粗糙程度。实际上 roughness 控制的是微表面法线的分布宽度。roughness=0 表示完美镜面（所有微表面平行），roughness=1 表示完全漫反射。真实世界中，金属的 roughness 范围通常是 0.02-0.5，非金属是 0.1-0.9。

3.3 路径追踪（Path Tracing）

路径追踪是求解渲染方程的最直接方法。它的核心思想是：对于每个像素，随机采样一条从相机出发的光线路径，沿着路径累加光照贡献。

// 完整的路径追踪器
class PathTracer {
public:
    Color trace(const Scene& scene, int px, int py, RNG& rng) {
        // 1. 生成相机射线（含抗锯齿抖动）
        float j = (px + rng.float()) - 0.5f;
        float k = (py + rng.float()) - 0.5f;
        Ray ray = camera.generateRay(j, k, rng);

        Color throughput(1.0f);
        Color radiance(0.0f);

        // 2. 主路径循环
        for (int bounce = 0; bounce < MAX_BOUNCES; bounce++) {
            Intersection hit;
            if (!scene.intersect(ray, hit)) {
                radiance += throughput * scene.skyColor(ray.direction);
                break;
            }

            // 自发光采样
            if (hit.material.isEmitter()) {
                radiance += throughput * hit.material.emission();
            }

            // Next Event Estimation（直接光照采样）
            Color direct = sampleDirectLight(scene, hit, rng);
            radiance += throughput * direct;

            // 采样下一个反弹方向
            Vec3 wo = -ray.direction;
            Vec3 wi = hit.material.sample(wo, rng);
            float pdf = hit.material.pdf(wi, wo);

            if (pdf > 0.0f) {
                float NdotW = absDot(wi, hit.normal);
                throughput *= hit.material.brdf(wi, wo) * NdotW / pdf;

                // Russian Roulette
                float p = std::max(throughput.r, std::max(throughput.g, throughput.b));
                if (rng.float() > p) break;
                throughput /= p;

                ray = Ray(hit.point + hit.normal * BIAS, wi);
            } else {
                break;
            }
        }

        return radiance;
    }

private:
    Color sampleDirectLight(const Scene& scene,
                           const Intersection& hit, RNG& rng) {
        Color Li(0.0f);

        // 对每个光源采样
        int lightIdx = rng.intInRange(0, scene.lights.size() - 1);
        const Light& light = scene.lights[lightIdx];

        // 采样光源上的随机点
        Vec3 lightSample = light.samplePosition(rng);
        Vec3 toLight = lightSample - hit.point;
        float distSq = dot(toLight, toLight);
        float dist = sqrt(distSq);
        toLight /= dist;

        float NdotL = max(dot(hit.normal, toLight), 0.0f);
        if (NdotL > 0.0f) {
            // 阴影测试
            Ray shadowRay(hit.point + hit.normal * BIAS, toLight);
            Intersection shadowHit;
            if (!scene.intersect(shadowRay, shadowHit) ||
                shadowHit.distance > dist - BIAS) {

                // 光源的 PDF = cos(theta) / lightArea
                float lightPdf = NdotL / (light.area() + EPSILON);

                // BRDF * Li / PDF
                Li = hit.material.brdf(toLight, -ray.dir) *
                     light.emission() / lightPdf;
            }
        }

        // 乘以选择该光源的概率
        return Li / (1.0f / scene.lights.size());
    }
};

3.3.1 Bidirectional Path Tracing（BDPT）

单向路径追踪在以下场景表现差：

  • 间接光照：光线需要经过多次反弹才能到达光源（方差极大）
  • 镜面-漫反射-相机：通过镜面反射后才能看到光源的路径很难被采样到

BDPT 从相机和光源两端同时构建路径，然后连接它们：

┌──────────────────────────────────────────────────────────────────────┐ │ BDPT：双向路径构建 │ │ │ │ 相机路径: C ──► v1 ──► v2 ──► v3 │ │ 光源路径: L ──► l1 ──► l2 ──► l3 │ │ ╲ ╱ │ │ ╲ 连接 ╱ │ │ ╲ ╱ │ │ ╲ ╱ │ │ 连接成功！光线从光源经镜面反射(l2→v3)到达相机 │ │ │ │ 这解决了单向路径追踪无法处理"镜面→漫反射"路径的问题 │ └──────────────────────────────────────────────────────────────────────┘

3.4 光子映射（Photon Mapping）

光子映射是 Jensen 在 1996 年提出的两阶段算法，特别适合模拟焦散（caustics）和间接光照：

1

光子投射阶段（Photon Tracing）

从光源发射数百万个光子，追踪它们在场景中的路径。每当光子击中表面，就记录它的入射位置和方向到光子图中。

2

渲染阶段（Rendering）

用路径追踪渲染场景。在每个交点处，查找附近的光子，用核密度估计计算辐照度。

// 光子映射：核密度估计计算辐照度
Color photonGather(const Vec3& point, const Vec3& normal,
                   const PhotonMap& photons, int K = 100) {
    // 查找 K 个最近光子
    auto nearest = photons.kNearest(point, K);

    Color irradiance(0.0f);
    float radius = distanceToFarthest(nearest);

    for (const auto& photon : nearest) {
        // 核函数：圆柱形核
        float cosTheta = absDot(photon.direction, normal);
        float kernel = 1.0f / (PI * radius * radius);

        irradiance += photon.power * kernel * cosTheta;
    }

    return irradiance;
}

关键观察：

  • NEE（Next Event Estimation）将收敛速度提升约 30%，是路径追踪的标配
  • BDPT 质量最高但最慢，适合静态场景的离线渲染
  • 光子映射内存占用最大（存储百万光子），但查询速度快
  • 混合方法（路径追踪 + 预计算）是工业界的主流选择

3.7 本章小结

本章我们从辐射传输方程出发，建立了全局光照的理论框架：

  1. 渲染方程是全局光照的数学核心，描述了光的递归传播
  2. BRDF 模型从简单的 Lambertian 到复杂的 GGX+Cook-Torrance，精度递增
  3. 路径追踪是求解渲染方程的直接方法，NEE 和 Russian Roulette 是关键优化
  4. 光子映射通过两阶段算法高效处理焦散和间接光照
  5. 预计算技术在离线质量和实时性能之间找到了平衡
