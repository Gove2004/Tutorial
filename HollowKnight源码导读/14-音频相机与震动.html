第 14 章　音频、相机与震动

本章覆盖游戏的三类表现系统：音频（音乐与氛围）、相机（两级跟随与锁区）、震动（手柄反馈）。它们共享一个设计思路——用数据资产驱动、通过平台抽象适配不同设备。

14.1 表现层总装：GameCameras

GameCameras 是相机相关对象的总装单例，持有主相机、HUD 相机、CameraController、CameraTarget、相机震动 FSM、吉欧计数等引用，统一做 SceneInit 和生命周期管理。相机系统的各部件都从它这里取用。

14.2 音频：Cue 驱动的多通道体系

AudioManager 不直接播具体 clip，而是用 Cue 数据资产（MusicCue、AtmosCue）描述"该放什么"，再配合多通道 AudioSource 和 AudioMixerSnapshot 播放。

音乐切换：协程淡入淡出

public void ApplyMusicCue(MusicCue musicCue, float delayTime,
                          float transitionTime, bool applySnapshot)
{
    if (musicCue == null) { Debug.LogError("...null MusicCue"); return; }
    // 支持按 PlayerData 解析备选 Cue（如感染十字路替换）
    musicCue = musicCue.ResolveAlternatives(playerData);
    if (currentMusicCue != musicCue)
    {
        if (applyMusicCueRoutine != null) StopCoroutine(applyMusicCueRoutine);
        StartCoroutine(BeginApplyMusicCue(musicCue, delayTime,
                                         transitionTime, applySnapshot));
    }
}

BeginApplyMusicCue 协程按通道（MusicChannels）逐个设置 clip 并播放，过渡时间后停掉未启用的通道，实现多通道交叉淡入淡出。同一首音乐可由多个同步通道组成。

氛围音与混音快照

// AtmosCue：切换 Snapshot 并按通道开关氛围 AudioSource
atmosCue.Snapshot.TransitionTo(transitionTime);
if (atmosCue.IsChannelEnabled(channel)) audioSource.Play();

// 混音快照：整体调整混音参数
public void ApplyMusicSnapshot(AudioMixerSnapshot snapshot,
                               float delayTime, float transitionTime)
概念作用
MusicCue / AtmosCue数据资产，声明各通道用哪个 clip、是否启用、是否需同步
AudioMixerSnapshot混音状态快照，控制音量/效果的整体切换
多 AudioSource每个通道一个独立源，支持分层与交叉过渡

切换都用协程 + WaitForSecondsRealtime（真实时间，不受暂停时间缩放影响），保证暂停或慢动作时音频过渡仍正常。重复调用同一 Cue 会被 currentMusicCue 判断拦截，避免重复切换。

14.3 相机的两级跟随结构

相机不是直接跟主角，中间隔了一个 CameraTarget，形成两级链路：

flowchart LR H["主角 Transform"] -->|"SmoothDamp 跟随 + 吸附"| CT["CameraTarget
目标点"] CT -->|"SmoothDamp 跟随"| CC["CameraController
主相机"] CLA["CameraLockArea"] -->|"锁区边界"| CT CLA -->|"LockToArea"| CC

为什么要加一个目标点？

直接让相机跟主角，主角的瞬时动作（冲刺、弹跳、受击）会让镜头剧烈晃动。CameraTarget 作为缓冲层，先对主角位置做平滑、吸附、锁区钳制，相机再跟随这个稳定的目标点，镜头就平滑可控。两层各有独立的阻尼参数。

CameraTarget：目标点的跟随与吸附

if (mode == TargetMode.FOLLOW_HERO)
{
    destination = heroTransform.position;
    transform.position = new Vector3(
        Vector3.SmoothDamp(transform.position, new Vector3(destination.x, ...),
                           ref velocityX, dampTimeX).x,
        Vector3.SmoothDamp(transform.position, new Vector3(..., destination.y),
                           ref velocityY, dampTimeY).y, z);
    // 目标点追上主角（进入 snapDistance）后直接吸附贴住
    if (position >= heroX - snapDistance && position <= heroX + snapDistance)
        stickToHeroX = true;
    if (stickToHeroX) transform.SetPositionX(heroX);
}

LOCK_ZONE 模式下目标点被钳制在锁区四向边界内；吸附机制让目标点一旦追近就贴住主角，避免永远慢半拍。fallStick/fallCatcher 专门处理下落时的纵向跟随。

CameraController：LateUpdate 平滑跟随

相机在 LateUpdate（所有物体 Update 之后）更新，保证拿到目标点本帧的最终位置：

private void LateUpdate()
{
    // 上下看时增加镜头偏移
    if (hero_ctrl.cState.lookingUp) lookOffset = ... + 6f;
    // 计算目标位置，LOCKED 模式处理锁区与 preventLookUp/Down
    destination = KeepWithinSceneBounds(destination);
    // x/y 分别 SmoothDamp，阻尼独立控制
    Vector3 x = Vector3.SmoothDamp(transform.position,
        new Vector3(destination.x, y, z), ref velocityX, dampTimeX);
    Vector3 y = Vector3.SmoothDamp(transform.position,
        new Vector3(x0, destination.y, z), ref velocityY, dampTimeY);
    transform.SetPosition2D(x.x, y.y);
}
  • 相机模式：FOLLOWING（跟随）、LOCKED（锁区）、FROZEN（冻结，过场/死亡）
  • KeepWithinSceneBounds 把相机限制在场景边界内，硬边界（14.6/8.3 等）做最终钳制
  • 速度有上限，防止镜头移动过快

14.4 相机震动：FSM 驱动

前面章节反复出现的 cameraShakeFSM 是一个 PlayMaker 状态机，接收 "EnemyKillShake"、"AverageShake" 等事件，按事件类型产生不同强度的镜头震动。把震动做成 FSM 而非硬编码，能让设计师在编辑器里调震动曲线和时长，与战斗事件（顿帧、命中）配合。

14.5 震动：VibrationManager 与平台抽象

手柄震动由静态 VibrationManager 管理，它不直接驱动硬件，而是通过 VibrationMixer 抽象：

public static VibrationMixer GetMixer()
{
    // 优先从当前平台获取 Mixer，其次从活动输入设备获取
    if (Platform.Current is IVibrationMixerProvider provider)
        return provider.GetVibrationMixer();
    InputDevice device = InputManager.ActiveDevice;
    if (device is IVibrationMixerProvider p2)
        return p2.GetVibrationMixer();
    return null;
}

public static VibrationEmission PlayVibrationClipOneShot(
    VibrationData data, VibrationTarget? target, bool isLooping,
    string tag, bool isRealtime)
{
    if (_vibrationSetting == VibrationSettings.Off) return null;
    VibrationMixer mixer = GetMixer();
    return mixer?.PlayEmission(data, target ?? new VibrationTarget(
        VibrationMotors.All), isLooping, tag, isRealtime);
}
概念作用
VibrationData震动数据资产，描述强度、电机、时长
VibrationMixer平台/设备提供的混音器，实际驱动电机，可混合多个 emission
VibrationEmission一次震动的播放实例，可循环、带标签、可按标签停止

FadeVibration 用线性变化率（transitionRate）做强度渐变；全局开关 Off 时所有调用直接返回。震动 Mixer 经 IVibrationMixerProvider 接口由平台或设备提供，不同主机的差异化震动能力被这层抽象隔离。

14.6 贯穿表现层的两个设计原则

  1. 数据资产驱动：MusicCue、VibrationData、相机配置都是可在编辑器调整的资产，逻辑代码只读资产，迭代不用改代码。
  2. 平台抽象：音频输出、震动 Mixer、相机行为都通过 Platform 或接口适配，核心逻辑不绑定具体硬件。

14.7 设计权衡

收益代价
两级相机平滑稳定；音频/震动数据化、易调；平台差异被隔离；暂停不影响音频过渡 链路变长（主角→目标→相机），调试需跨多组件；阻尼/吸附参数多，调参成本高；字符串事件无编译期检查

思考与练习

  1. 解释相机为什么用"主角 → CameraTarget → CameraController"两级结构，直接跟随会有什么问题。
  2. 说明 CameraTarget 的吸附（stickToHero）机制解决了什么，若只有 SmoothDamp 会有什么现象。
  3. 梳理 AudioManager 从 MusicCue 到多通道播放的流程，为什么切换用真实时间的协程。
  4. 分析 VibrationManager 如何通过 VibrationMixer 适配不同平台，IVibrationMixerProvider 起什么作用。
  5. 结合相机震动 FSM，说明把震动做成 FSM 而非硬编码对调参的好处。
