业务与引擎模块特征地图

模块三 · 模块特征地图 ｜ 对应原文第二部分八大模块

模块二解决“怎么优化”，本章解决“哪里值得优化”。性能优化不只是找一个耗时函数，更要理解各模块的原理与特征。掌握模块特征，才能快速判断：哪里容易产生开销、哪里有冗余、谁适合缓存、谁能异步、谁能分级、谁能离线化。

分析时需要逐层了解模块的工作原理与性能特征。下面逐个拆解，注意区分业务架构意义上的“UI 框架”与引擎底层的“UI 系统（内核）”，它们是两个层次。

12.2 UI 框架（业务架构层）

典型 UI 架构可抽象为 MVC：

模块职责
Model数据、配置、数据服务
Control控制逻辑、业务逻辑
View面板、控件、显示逻辑

典型数据流：服务器消息 → Model → Control → View → UI 更新。

常见性能问题：事件响应产生冗余（重复监听、未取消订阅）、UI 重建产生额外开销、面板更新存在冗余。

优化抓手：事件订阅生命周期管理、静态/动态 Canvas 拆分、隐藏面板挂起刷新。

12.3 网络同步框架

方案机制特征
状态同步 服务器直接下发状态，客户端据状态产生表现 服务器权威、流量较大，客户端逻辑相对简单
帧同步 服务器广播操作指令，客户端据指令自行计算逻辑 流量小、要求确定性，客户端计算量大

无论哪种方案，都要关注逻辑与表现分离：把逻辑计算从表现系统独立出来，便于固定逻辑帧、插值回放与多线程。

常见性能问题：线程间数据同步、线程通信带来的缓存问题、逻辑帧卡顿、指令消息冗余。

优化抓手：减少跨线程数据搬运、消息合并去重、逻辑帧与渲染帧解耦。

12.4 技能框架

技能框架可拆分为四部分：实体、控制流、行为、数值。角色的动画、移动、材质、特效等行为独立开发，再通过控制流按时间轴组合。这种配置化方案提升了开发效率，但也带来特有的冗余：

  • 配置冗余：多个技能重复配置相同行为段。
  • 资源冗余：相似特效/动画被重复引用或复制。
  • 更新冗余：未生效的技能段仍在每帧检查。
  • 计算冗余：可共享的数值结果被反复计算。

优化抓手：行为段共享复用、时间轴驱动的按需激活、配置与数值缓存。

12.5 地图与内存管理

地图系统通常包含场景物件、位置与旋转信息、机关脚本、导航网格，重点关注场景渲染压力。内存管理由对象池、内存池、内存分配器组成。

常见性能问题：内存分配算法效率、内存碎片、对象池冗余、不合理的预分配。

优化抓手：按生命周期选择分配器、池容量治理、空间划分与分块加载。

12.6 渲染管线

典型渲染管线分为剔除管线 → 绘制管线。

阶段组成
剔除 Frustum、地形、Occlusion、Group、光照、反射剔除
绘制 动态网格、粒子条带/拖尾、深度图、阴影、不透明、半透明、排序、合批
常见性能问题：低端机仍执行不必要的管线功能、Camera Culling 不适合实际玩法、渲染对象重复计算、合批过程产生额外 CPU 开销。

优化抓手：分档管线裁剪、定制剔除策略、缓存渲染对象、空间分组合批。

12.7 动画模块

动画模块分为两部分：

  1. 动画逻辑：骨骼采样、插值、动画事件、状态机、Motion、IK。
  2. 蒙皮计算：骨骼矩阵计算 → Job System → 骨骼节点权重混合 → 提交绘制。
常见性能问题：镜头外动画仍运行、相同动画重复计算、动画逻辑更新频率过高。

优化抓手：距离分级调度、Job 并行化、动画重定向与共享、镜头外裁剪。

12.8 粒子系统

粒子系统分三部分：包围盒计算、粒子逻辑、粒子渲染。粒子逻辑持续计算生成数量、位置、运动、生命周期，只有判定可见时才进入渲染。

常见性能问题：粒子包围盒重复计算、镜头外粒子仍运行、粒子渲染产生大量 Overdraw。

优化抓手：包围盒缓存、可见性驱动逻辑启停、离线凸包裁剪、粒子数分档。

12.9 UI 系统（引擎内核层）

UI 从结构上分为组件层与内核层。组件层负责 UI 元素与逻辑；内核层负责合批计算、网格生成、渲染提交。

典型流程：UI 组件 → 顶点/材质更新 → 可见性判断 → 重建 → 排序 → 合批 → 渲染提交。

常见性能问题：UI 重建、合批计算、UI 更新频率过高。

优化抓手：限制重建范围、图集与材质一致性、刷新节流。

12.10 模块特征速查表

模块核心特征首选优化方向
UI 框架事件驱动、MVC 数据流事件治理 + Canvas 拆分
网络同步逻辑/表现分离、跨线程消息去重 + 线程解耦
技能框架配置化、时间轴组合按需激活 + 共享复用
地图/内存池化、碎片敏感分配器选型 + 容量治理
渲染管线剔除→绘制、状态切换管线裁剪 + 分组合批
动画逻辑+蒙皮、可并行Job 化 + 距离分级
粒子生命周期 + Overdraw可见性启停 + 离线裁剪

练习与思考

基础练习模块标注

在你自己的工程中，把现有性能问题按这八个模块归类，判断每个问题属于配置/资源/更新/计算哪类冗余。

思考题两个 UI 层次

用自己的话说明“UI 框架（MVC）”与“UI 系统（内核）”的区别，并解释为什么事件订阅问题和 Canvas 重建问题要在不同层次解决。

本章小结

  • 系统分基础支撑、游戏框架、业务系统三层，引擎核心模块横跨框架与基础层。
  • 八大模块各有架构特征与典型冗余，优化抓手不同：事件、线程、配置、内存、管线、并行、可见性、重建。
  • 判断“哪里值得优化”，本质是把模块特征映射到缓存、异步、分级、离线化四类手段。
