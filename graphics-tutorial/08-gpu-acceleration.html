第八章：GPU 加速

CPU 和 GPU 的本质区别在于并行架构。CPU 是延迟优化（少数几个强大核心），GPU 是吞吐优化（数千个精简核心）。理解这种差异，是将图形算法从 CPU 迁移到 GPU 的关键。本章将从硬件架构出发，深入光线追踪、粒子系统、SPH 流体等典型场景的 GPU 加速方案。

核心思想：GPU 加速不是简单地把代码搬到 Shader 里。它要求你重新思考算法——从" sequential processing "转向" massive parallelism "，从" random memory access "转向" coalesced access "。

一、CUDA / OpenCL 架构

1.1 GPU 层次结构

理解这个层次结构对编写高性能 GPU 代码至关重要：

Thread
最小执行单元，每个 thread 有自己的寄存器和本地变量
Warp
32 个 thread 的集合，SIMT（单指令多线程）执行。一个 warp 内的所有 thread 在同一时钟周期执行同一指令
Block (Thread Block)
一组 thread，可以共享 Shared Memory，支持同步（barrier）
SM
多个 block 可以同时驻留在同一个 SM 上，实现硬件级别的并发切换

性能黄金法则：Global Memory 访问延迟约 600 个时钟周期，而 Shared Memory 仅需 1-2 个。将全局内存中的数据加载到 Shared Memory 再处理，可以获得 300x 的延迟隐藏效果。这也是为什么所有高性能 GPU 算法都依赖 Shared Memory。

二、GPU 加速光线追踪

2.1 BVH on GPU

Bounding Volume Hierarchy（包围盒层次结构）是加速射线相交测试的核心数据结构。CPU 上的 BVH 通常用指针树存储，但 GPU 上指针跳转会导致严重的分支发散和缓存未命中。因此 GPU 使用扁平化 BVH（Flat BVH / SBVH）：

// 扁平 BVH：用数组存储节点，用索引替代指针
struct BvhNode {
    AABB bounds;           // 包围盒
    int leftChild;         // 左子节点索引（负数表示叶子，绝对值是三角形起始索引）
    int rightChild;
    uint8_t type;          // 0=内部节点, 1=叶子
};

// 用两个并行数组（SoA）提高缓存命中率
struct FlatBvh {
    std::vector<AABB> nodeBounds;
    std::vector<int> leftChild;
    std::vector<int> rightChild;
    std::vector<Triangle> triangles;
};

扁平化的好处是 BVH 节点可以连续存储在内存中，GPU 的纹理缓存可以高效地缓存相邻节点。遍历 BVH 时，内存访问模式更接近顺序读取，而非随机指针跳转。

2.2 GPU 光线追踪内核

// GLSL: GPU 光线遍历
struct Ray {
    vec3 origin;
    vec3 direction;
    float tNear;
    float tFar;
};

struct HitRecord {
    float t;
    vec3 position;
    vec3 normal;
    uint materialID;
};

// BVH 遍历 - 每个线程追踪一条光线
HitRecord traceRay(Ray ray, FlatBvh bvh) {
    int stack[64];
    int stackPtr = 0;
    stack[stackPtr++] = 0; // 从根节点开始

    HitRecord closest;
    closest.t = ray.tFar;
    closest.materialID = UINT_MAX;

    while (stackPtr > 0) {
        int nodeIdx = stack[--stackPtr];
        BvhNode node = bvh.nodes[nodeIdx];

        // 裁剪：只处理与光线相交的节点
        if (!intersectAABB(ray, node.bounds)) continue;

        if (node.isLeaf()) {
            // 叶子节点：测试三角形
            for (int i = node.triangleStart;
                 i < node.triangleStart + node.triangleCount; i++) {
                HitRecord hit;
                if (intersectTriangle(ray, bvh.triangles[i], hit)) {
                    if (hit.t < closest.t) {
                        closest = hit;
                    }
                }
            }
        } else {
            // 内部节点：优先压入远的子节点（近的先处理）
            float tLeft = aabbIntersectDistance(ray, bvh.nodes[node.left].bounds);
            float tRight = aabbIntersectDistance(ray, bvh.nodes[node.right].bounds);

            if (tLeft < tRight) {
                stack[stackPtr++] = node.left;
                stack[stackPtr++] = node.right;
            } else {
                stack[stackPtr++] = node.right;
                stack[stackPtr++] = node.left;
            }
        }
    }
    return closest;
}

三、GPU 粒子系统

3.1 Compute Shader + Transform Feedback

传统 CPU 粒子系统的瓶颈在于：每帧需要更新数百万个粒子的位置、速度、生命周期，然后上传到 GPU 渲染。GPU 粒子系统将整个 pipeline 移到 GPU 内部，消除了 CPU-GPU 数据传输的开销。

// Compute Shader: 粒子更新
#version 460
layout(local_size_x = 256) in;

layout(binding = 0) buffer ParticleData {
    vec4 particles[]; // xyz = position, w = lifetime
} incoming;

layout(binding = 1) buffer ParticleDataOut {
    vec4 particles[];
} outgoing;

layout(binding = 2) uniform Time {
    float deltaTime;
    vec3 gravity;
    uint emitCount;
} params;

void main() {
    uint idx = gl_GlobalInvocationID.x;
    if (idx >= params.emitCount) return;

    vec4 p = incoming.particles[idx];
    vec3 pos = p.xyz;
    float life = p.w;

    // 生命周期递减
    life -= params.deltaTime;

    if (life <= 0.0) {
        // 重新发射粒子
        pos = vec3(0.0);
        life = 1.0;
        // 随机速度（用 hash 函数保证确定性）
        uint hashVal = hash(uint(idx) * 374761393u);
        pos += vec3(sin(hashVal), cos(hashVal * 0.7), sin(hashVal * 1.3)) * 0.5;
    } else {
        // 物理更新
        pos += params.gravity * params.deltaTime;
    }

    outgoing.particles[idx] = vec4(pos, life);
}

四、GPU SPH 流体模拟

4.1 SPH 核心公式

Smoothed Particle Hydrodynamics（光滑粒子流体动力学）将流体离散为粒子，每个粒子携带密度、压力、速度等信息。核心计算是核函数卷积：

// 多项式核函数 (Poly6)
float poly6Kernel(float r, float h) {
    float diff = h*h - r*r;
    if (diff < 0.0f) return 0.0f;
    return 315.0f / (64.0f * PI * pow(h, 9.0f)) * diff * diff * diff;
}

// 核函数梯度 (用于压力梯度力)
vec3 spikyKernelGrad(float r, float h) {
    float diff = h - r;
    if (diff <= 0.0f) return vec3(0.0f);
    return -45.0f / (PI * pow(h, 6.0f)) * diff * diff * normalize(vec3(1e-5) + r);
}

4.2 Shared Memory 优化

SPH 的最大瓶颈是邻居搜索：每个粒子需要找到半径 h 内的所有其他粒子。朴素实现是 O(n²)，即每个粒子都要遍历所有其他粒子。使用 Shared Memory + Spatial Hash 可以将复杂度降到 O(n)：

GPU SPH 并行架构

Step 1: Spatial Hashing (Compute Shader)
粒子 → 网格桶 (Atomic Add)
↓
Step 2: Density Calculation (Compute Shader)
每个粒子加载邻居到 Shared Memory
↓
Step 3: Pressure Force (Compute Shader)
Shared Memory 内计算压力梯度
↓
Step 4: Velocity Integration (Compute Shader)
Verlet 积分更新位置和速度
↓
Step 5: Rendering (Transform Feedback)
粒子 → 球体实例渲染
// Shared Memory 中的邻居缓存
shared vec3 sharedPositions[256];
shared float sharedDensities[256];

void computeDensity(uint particleIdx) {
    // 加载当前粒子和邻居到 Shared Memory
    uint sharedIdx = gl_LocalInvocationID.x;
    uint groupSize = gl_WorkGroupSize.x;

    // Step 1: 每个 thread 加载一个粒子到 shared memory
    if (particleIdx < numParticles) {
        sharedPositions[sharedIdx] = positions[particleIdx];
        sharedDensities[sharedIdx] = 0.0;
    }
    barrier(); // 等待所有粒子加载完成

    // Step 2: 在 shared memory 中计算核函数卷积
    float density = 0.0;
    for (uint i = 0; i < groupSize; i++) {
        float dist = length(sharedPositions[i] - positions[particleIdx]);
        if (dist < smoothingRadius) {
            density += mass * poly6Kernel(dist, smoothingRadius);
        }
    }
    densities[particleIdx] = density;
}

4.3 Atomic Operations 在 SPH 中的应用

在 Spatial Hashing 阶段，多个粒子可能同时写入同一个网格桶。使用原子操作保证计数正确：

// 原子操作添加粒子到网格桶
atomicCounter bucketCounts[hashBucket];
uint particleIndices[hashBucket][MAX_NEIGHBORS];

void spatialHash(uint idx) {
    vec3 pos = positions[idx];
    ivec3 gridPos = ivec3(floor(pos / smoothingRadius));
    uint hashVal = hash(gridPos);

    // 原子递增桶计数，获取插入位置
    uint insertPos = atomicAdd(bucketCounts[hashVal], 1u);
    if (insertPos < MAX_NEIGHBORS) {
        particleIndices[hashVal][insertPos] = idx;
    }
}
Bank Conflict 避免：Shared Memory 被分成 32 个 bank。当同一个 warp 中的多个 thread 访问同一个 bank 的不同地址时，会发生 bank conflict，导致串行化访问。在 SPH 中，确保每个 thread 访问的 shared memory 地址跨越不同的 bank（例如用 padding 或 stride 调整布局）。

五、内存访问优化

5.1 Coalesced Memory Access

Coalesced（合并）访问是 GPU 内存性能的第一优化原则。当同一个 warp 中的 32 个 thread 访问连续的内存地址时，GPU 可以将这 32 次访问合并为 1-2 次全局内存事务。否则，每次访问都要单独发起内存请求，性能损失可达 32 倍。

// ❌ 差：非合并访问（stride = warp size）
__global__ void badAccess(float* data, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    // warp 中 thread i 访问 data[i * 32]，分散在不同 cache line
    float val = data[idx * 32];
}

// ✅ 好：合并访问（stride = 1）
__global__ void goodAccess(float* data, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    // warp 中 thread i 访问 data[start + i]，连续内存
    float val = data[idx];
}

5.2 Structure of Arrays (SoA) vs Array of Structures (AoS)

在 GPU 上，SoA 通常比 AoS 快 2-4 倍，因为 SoA 保证同类型数据连续存储，天然支持 coalesced access：

// ❌ AoS：粒子数据交错存储
struct Particle {
    float3 position;
    float3 velocity;
    float lifetime;
};
Particle particles[N]; // 访问 position 时会连带加载 velocity 和 lifetime

// ✅ SoA：同类型数据连续存储
struct ParticlesSoA {
    float3 positions[N];
    float3 velocities[N];
    float lifetimes[N];
};
// 访问 positions 时只加载需要的数据，cache 利用率更高

六、本章小结

本章从 GPU 硬件架构出发，系统讲解了图形算法的 GPU 加速方法：

  • GPU 层次结构：Thread → Warp → Block → SM，理解层次才能写出高效的并行代码
  • 内存层级：Shared Memory 比 Global Memory 快 300 倍，是所有高性能算法的基石
  • GPU 光线追踪：Flat BVH + RT Core 实现 478 倍加速，是实时路径追踪的前提
  • GPU 粒子系统：Compute Shader 消除 CPU-GPU 数据传输，百万粒子轻松 60fps
  • GPU SPH 流体：Shared Memory + Spatial Hash + Atomic Operations 实现 O(n) 复杂度
  • 内存优化：Coalesced Access、SoA、Bank Conflict Free 是 GPU 编程的基本功

GPU 加速的核心哲学是：用空间换时间，用并行换串行，用确定性换随机性。当你习惯了 GPU 的思维模式，你会发现 CPU 上看似不可能的问题，在 GPU 上迎刃而解。
