第 10 章　主角输入与动作机制（下）

本章追踪一次按键如何变成主角的动作，并完整拆解 TakeDamage 的判定流程。重点是两个动作游戏的核心机制：输入缓冲（让操作"跟手"）和分层的动作门控（CanXxx 判定）。

10.1 输入链路总览

游戏不直接读 UnityEngine.Input，而是用第三方库 InControl 统一键盘、鼠标、手柄，再经一层封装：

flowchart LR DEV["物理设备
键盘/鼠标/手柄"] --> IC["InControl 运行时
设备抽象 + 死区处理"] IC --> HA["HeroActions
PlayerActionSet：jump/dash/attack…"] HA --> IH["InputHandler
按键绑定/设备切换/UI 提示"] IH --> HC["HeroController
LookForInput / LookForQueueInput"]

HeroActions：动作与阈值

public class HeroActions : PlayerActionSet
{
    public PlayerAction jump;
    public PlayerAction dash;
    public PlayerAction attack;
    public PlayerTwoAxisAction moveVector;
    // ...
    public HeroActions()
    {
        left = CreatePlayerAction("Left");
        left.StateThreshold = 0.3f;          // 触发阈值
        moveVector = CreateTwoAxisPlayerAction(left, right, down, up);
        moveVector.LowerDeadZone = 0.15f;    // 摇杆死区
        moveVector.UpperDeadZone = 0.95f;
    }
}

StateThreshold 和死区在这里配置：摇杆轻微偏移不触发，避免误触；不同轴可设不同阈值。InControl 让同一套 PlayerAction 能被任意设备驱动，重绑按键只需改绑定，逻辑代码不变。

10.2 输入的三层门控

无论 LookForInput 还是 LookForQueueInput，开头都有同一道闸：

if (!acceptingInput || gm.isPaused || !isGameplayScene)
{
    return;
}
  • acceptingInput——过场、进场、控制权移交时关闭
  • gm.isPaused——暂停时不处理游戏输入
  • isGameplayScene——菜单场景下主角不响应

三个条件任一不满足就整体跳过，这是集中控制主角响应范围的第一道防线。

10.3 两类输入：持续状态与瞬时动作

方法处理对象典型内容
LookForInput持续按住的状态、松开检测墙滑进入/取消、跳跃松开、重置排队标记
LookForQueueInput按下瞬间（WasPressed）的动作跳/冲刺/攻击的触发与缓冲

区分 WasPressed（这一帧刚按下）、IsPressed（正按住）、WasReleased（这一帧刚松开）三种时态是理解代码的关键。持续逻辑（墙滑需要一直朝墙推）放 LookForInput，瞬时触发放 LookForQueueInput。

10.4 输入缓冲：动作跟手的关键

看 LookForQueueInput 里跳跃的处理：按下时先尝试执行，不能执行就进入排队：

if (inputActions.jump.WasPressed)
{
    if (CanWallJump()) DoWallJump();
    else if (CanJump()) HeroJump();
    else if (CanDoubleJump()) DoDoubleJump();
    else
    {
        jumpQueueSteps = 0;
        jumpQueuing = true;        // 进入缓冲，而非直接丢弃
    }
}
// 后续每帧：窗口期内一旦条件满足就补执行
if (inputActions.jump.IsPressed
    && jumpQueueSteps <= JUMP_QUEUE_STEPS
    && CanJump() && jumpQueuing)
{
    HeroJump();
}

为什么需要缓冲？

玩家常在落地前几帧就按跳、在攻击硬直中按冲刺。若输入只在"能执行的那一帧"有效，这些略早的按键会被吞掉，手感就"不跟手"。缓冲机制把按下事件保留一个步数窗口（JUMP_QUEUE_STEPS 等），期间条件一旦满足立即补执行，玩家感知不到那几帧的时差。冲刺、攻击各有独立的 queuing 布尔和队列步数。

队列步数是帧计数器，每帧递增、超过窗口就失效。读这类代码要同时跟踪"排队布尔"和"步数"两个字段：布尔标记是否在等待，步数决定等待何时过期。

10.5 动作方法的统一模式

所有动作都遵循同一套三段式结构，这是 HeroController 内部最一致的编码模式：

flowchart LR A["CanXxx()
判定当前能否执行
（状态/地面/冷却/能力）"] --> B["DoXxx()
执行动作：改速度/启动协程
置 cState 标记"] B --> C["冷却/计时
设 cooldownTimer
窗口期内禁止重复"]

攻击：方向由输入决定

private void DoAttack()
{
    if (playerData.equippedCharm_32)
        attack_cooldown = ATTACK_COOLDOWN_TIME_CH;   // 护符缩短冷却
    else
        attack_cooldown = ATTACK_COOLDOWN_TIME;

    if (vertical_input > Mathf.Epsilon)
        Attack(AttackDirection.upward);              // 上劈
    else if (vertical_input < -Mathf.Epsilon
             && hero_state != ActorStates.idle
             && hero_state != ActorStates.running)
        Attack(AttackDirection.downward);            // 下劈（空中）
    else
        Attack(AttackDirection.normal);
}

注意下劈只在非地面状态触发，地面按上下不影响普通挥砍。CheckForTerrainThunk 协程还会检测骨钉是否打到墙壁，触发"砍墙"反馈。

冲刺：地面/空中与暗影冲刺

private void HeroDash()
{
    if (!cState.onGround && !inAcid) airDashed = true;
    // 朝向、特效位置、冷却……
    cState.dashing = true;
    if (playerData.hasShadowDash && shadowDashTimer <= 0f)
    {
        shadowDashTimer = SHADOW_DASH_COOLDOWN;
        cState.shadowDashing = true;   // 暗影冲刺：无敌帧 + 穿过危险
    }
}

冲刺方法集中处理了空中冲刺标记、方向、冷却、下冲（护符 31）、暗影冲刺等多个分支，是动作方法里分支最多的一个。

10.6 TakeDamage 全流程

HeroBox 检测到伤害源后调用 TakeDamage，整个判定是一条分层过滤链：

flowchart TB A["入口：damageAmount <= 0 直接返回
Boss 场景按等级加倍率（×2 / 9999）"] --> B{"CanTakeDamage?"} B -->|"否"| Z["仅处理危险伤害，普通伤害忽略"] B -->|"是"| C{"危险豁免？
HAZARD_ONLY / 暗影冲刺 / 格挡无敌"} C -->|"命中豁免"| END["返回，不受伤"] C -->|"通过"| D{"无忧旋律护符
按命中次数概率格挡"} D -->|"触发"| E["伤害归零，播放护盾"] D -->|"未触发"| F{"快速凝聚护符
blockerHits 抵挡"} F --> G["清理当前动作
取消攻击/墙滑/弹跳"] G --> H["playerData.TakeHealth
overcharmed 双倍扣血"] H --> I{"health == 0?"} I -->|"是"| J["Die()"] I -->|"否"| K{"hazardType"} K -->|"尖刺/酸液/深坑"| L["DieFromHazard"] K -->|"普通"| M["StartRecoil 硬直"]

前置的倍率与豁免

if (BossSceneController.IsBossScene)
{
    switch (BossSceneController.Instance.BossLevel)
    {
        case 1: damageAmount *= 2; break;
        case 2: damageAmount = 9999; break;   // 调谐级直接致命
    }
}
if (damageMode == DamageMode.HAZARD_ONLY && hazardType == 1) return;
if (cState.shadowDashing && hazardType == 1) return;

护符概率护盾：硬编码的概率表

无忧旋律（carefreeShield）的格挡概率随连续受击次数递增，是一张硬编码的 switch 表：

switch (hitsSinceShielded)
{
    case 1: if (Random.Range(1, 100) <= 10) blocked = true; break;
    case 4: if (Random.Range(1, 100) <= 50) blocked = true; break;
    case 7: if (Random.Range(1, 100) <= 90) blocked = true; break;
    // 概率 10% → 90% 递增
}

扣血、死亡与硬直

if (playerData.overcharmed)
    playerData.TakeHealth(damageAmount * 2);   // 过载护符：双倍伤害
else
    playerData.TakeHealth(damageAmount);

if (playerData.health == 0)
{
    StartCoroutine(Die());
    return;
}
switch (hazardType)
{
    case 2: StartCoroutine(DieFromHazard(HazardType.SPIKES, ...)); break;
    case 3: StartCoroutine(DieFromHazard(HazardType.ACID, ...)); break;
    case 5: StartCoroutine(DieFromHazard(HazardType.PIT, ...)); break;
    default: StartCoroutine(StartRecoil(damageSide, spawnDamageEffect, damageAmount)); break;
}

普通伤害与环境危险的结局不同：普通伤害走 StartRecoil，主角被击退并进入短暂硬直（no_input 状态），硬直结束恢复控制；尖刺/酸液/深坑这类环境危险无论剩余血量都直接 DieFromHazard。这解释了为什么踩尖刺总是直接死亡，而被敌人打到只掉血并击退。

10.7 受击硬直的恢复

回忆第 9 章 Update：no_input 状态下用 recoilTimer 计时，达到 RECOIL_DURATION 就 CancelDamageRecoil 并恢复到之前的状态；装备硬直护符（Charm_4）时用更长的 RECOIL_DURATION_STAL。硬直期间 cState.recoiling 为真、重力被调整，主角无法主动操作，这套"计时 + 状态恢复"保证硬直一定会结束，不会永久失控。
