第 9 章：部署与运行模式

代码写完了，功能跑通了——但现在你面对一个全新的问题：怎么让别人连进来玩？ 从 Editor 中的 Host 模式到生产环境中的专用服务器，部署涉及到编译、配置、网络、运维多个层面。 本章覆盖从本地测试到云端部署的完整链路。

📌 Mirror 96 API 更新要点（本章涉及）：
• 命令行参数解析使用 Environment.GetCommandLineArgs()（非 System.ArgumentList）
• NetworkClient.Connect(string address) 只接受地址字符串，端口在 Transport 上配置
• ClientScene 已合并入 NetworkClient：NetworkClient.localPlayer 代替 ClientScene.localPlayers
• 认证通过 NetworkServer.RegisterHandler<T> + NetworkConnectionToClient 实现
• 断开连接使用 conn.Disconnect()（非 NetworkServer.RemoveConnection）
• NetworkServer.connections 为 Dictionary<int, NetworkConnectionToClient>

9.1 三种运行模式

Mirror 支持三种运行模式，每种适用于不同场景：

模式角色适用场景Mirror 96 启动方式
Client Only仅客户端玩家正常进入游戏NetworkManager.StartClient()
Host客户端 + 服务器开发测试、P2P 主机游戏NetworkManager.StartHost()
Dedicated Server仅服务器生产环境、正式服NetworkManager.StartServer()
Mirror 96 说明：StartServer()、StartClient()、StartHost() 是 NetworkManager 上供外部调用的启动方法。 而 OnStartServer()、OnStartClient() 是供你重写的虚回调方法——分别在服务器/客户端启动完成后被调用。不要混淆两者。

9.2 编译专用服务器

专用服务器（Dedicated Server）是无头进程——没有图形渲染，只有服务器逻辑。

9.2.1 Unity 构建设置

Build Settings 配置：
• Build Target: Standalone Server (Windows/Linux/macOS)
  注意：Unity 6+ 支持 Dedicated Server 构建目标
  （File → Build Profiles → Dedicated Server）
• Architecture: x86_64
• Development Build: 关闭（发布时）/ 开启（调试时）
• Compression Method: LZ4（减小体积）

9.2.2 命令行启动参数

# Windows
YourGame.exe -batchmode -nographics -port 7777

# Linux
./YourGame.x86_64 -batchmode -nographics -port 7777

# macOS
./YourGame.app/Contents/MacOS/YourGame -batchmode -nographics -port 7777

参数说明：

参数作用必需？
-batchmode无 UI 模式，不等待用户输入✅ 必须
-nographics不初始化 Graphics 模块，节省内存和 CPU✅ 必须
-port 7777自定义端口（在你的代码中读取并设置到 Transport）推荐
-logFile /tmp/game.log指定日志文件路径可选
-screenWidth 0 -screenHeight 0避免某些平台上 GPU 初始化可选

9.2.3 在代码中处理专用服务器模式

using Mirror;
using UnityEngine;
using UnityEngine.SceneManagement;

public class GameBootstrapper : MonoBehaviour
{
    [SerializeField] NetworkManager networkManager;
    [SerializeField] Transport transport;

    void Start()
    {
        // Mirror 96: 使用 Environment.GetCommandLineArgs() 解析命令行参数
        // System.ArgumentList 在 .NET/Unity 中不存在
        string[] args = System.Environment.GetCommandLineArgs();

        bool isDedicated = false;
        int port = 7777;

        for (int i = 0; i < args.Length; i++)
        {
            if (args[i] == "-dedicated")
                isDedicated = true;
            else if (args[i] == "-port" && i + 1 < args.Length)
            {
                if (int.TryParse(args[i + 1], out int parsed))
                    port = parsed;
            }
        }

        if (isDedicated)
        {
            StartDedicatedServer(port);
        }
        else
        {
            StartClientOrHost();
        }
    }

    void StartDedicatedServer(int port)
    {
        // Mirror 96: 端口配置在 Transport 上，不在 NetworkServer.Listen() 中
        // KcpTransport 是默认 Transport，Port 属性设置端口
        if (transport is KcpTransport kcp)
        {
            kcp.Port = (ushort)port;
        }
        // 其他 Transport 按各自方式设置端口...

        // 通过 NetworkManager 启动服务器
        // StartServer() 是外部调用方法（非虚回调 OnStartServer）
        networkManager.StartServer();

        Debug.Log($"[Server] 专用服务器已启动，端口 {port}");

        // 加载游戏场景
        SceneManager.LoadScene("GameScene");
    }

    void StartClientOrHost()
    {
        // Mirror 96: NetworkClient.Connect(string address) 只接受地址字符串
        // 端口已在 Transport 上配置（通过 Inspector 或代码设置）
        // 例如：transport 组件上的 Port 设置为 7777
        networkManager.networkAddress = "localhost";
        networkManager.StartClient();

        // 或者直接使用 NetworkClient：
        // NetworkClient.Connect("localhost");
    }
}
Mirror 96 变化：
  • NetworkClient.Connect(string address) 只接受地址字符串（如 "localhost"、"192.168.1.100"），不接受端口参数。端口在 Transport 组件上配置。
  • 命令行参数解析必须使用 System.Environment.GetCommandLineArgs()，这是 .NET/Unity 标准方法。
  • 服务器端口设置在 Transport 上（如 KcpTransport.Port），然后调用 NetworkManager.StartServer() 启动。
内存优化：使用 -nographics 后，Unity 不会初始化 GPU 驱动， 服务器进程的内存占用可以从 ~500MB 降到 ~100MB。这对云服务器成本影响很大—— 一台 2GB 内存的机器可以跑 20 个服务器实例，而不是 4 个。

9.3 本地测试流程

9.3.1 Editor 内测试

步骤 1: 打开 Unity Editor → NetworkManager 组件点击 "Host"（服务器 + 本地客户端）
        此时调用 NetworkManager.StartHost()
步骤 2: 再打开一个 Editor → NetworkManager 点击 "Client Only"（连接到 Host）
        此时调用 NetworkManager.StartClient()
步骤 3: 验证 Player 对象生成、移动同步、RPC 调用

9.3.2 独立客户端测试

步骤 1: 构建服务器 → YourGame.exe -batchmode -nographics -port 7777
步骤 2: 打开另一个 Unity Editor → Client Only → 连接 localhost
步骤 3: 或者构建独立客户端 → YourGameClient.exe → 连接 localhost

注意：Mirror 96 中端口在 Transport 上设置，连接时只需指定地址

9.3.3 多客户端测试

步骤 1: 启动专用服务器
步骤 2: 同时打开 4 个 Editor/客户端实例
步骤 3: 依次连接，验证多人同步
为什么不在 Editor 的 Host 模式下测试多客户端？
Host 模式只包含一个服务器实例和一个客户端实例。 要测试"多个玩家"，至少需要两个客户端连接同一个服务器。 最方便的方式是：一个构建的服务器 + 多个 Editor 客户端。

9.4 NAT 穿透与中继服务

当服务器和客户端不在同一局域网时，NAT（网络地址转换）会阻止直连。 需要中继服务（Relay）作为中间代理转发数据。

Mirror 96 与 Relay 的关系：Mirror 本身不绑定特定 Relay 服务。 你可以通过以下方式实现 NAT 穿透：
  • Edgegap：Mirror 官方推荐的合作平台，提供自动部署和匹配服务。
  • Steamworks Relay：如果游戏发布在 Steam，可使用 Steam P2P Relay（需第三方插件如 Mirror-Steam）。
  • 自定义 Relay Transport：继承 Transport 抽象类实现自定义中继逻辑。
  • 端口转发：在路由器上手动映射端口（仅适合测试，不适合生产环境）。
// 示例：使用自定义 Transport 实现 Steam P2P 中继
// 需要安装 Mirror-Steam 或类似社区扩展
using Mirror;
using Steamworks;

public class SteamTransport : Transport
{
    public override void ServerStart(string address)
    {
        // 通过 Steam P2P 启动服务器
        // Steamworks 自动处理 NAT 穿透
    }

    public override void ClientConnect(string address)
    {
        // 通过 Steam ID 连接（非 IP 地址）
        // Steam Relay 自动转发数据
    }

    // ... 实现 Transport 抽象类的其他方法
    public override bool ServerActive() { return true; }
    public override void ServerSend(List<int> connectionIds, ArraySegment<byte> data, int channelId) { }
    public override bool ServerDisconnect(int connectionId) { return true; }
    public override string ServerGetClient(int connectionId) { return ""; }
    public override void ClientSend(ArraySegment<byte> data, int channelId) { }
    public override bool ClientConnected() { return true; }
    public override void ClientDisconnect() { }
    public override void Shutdown() { }
    public override int GetMaxPacketSize(int channelId) { return 1200; }
    public override bool Available() { return true; }
}

9.4.1 Relay vs 直连的权衡

维度直连（专用服务器）Relay 中继
延迟低（直连）较高（多一跳转发）
带宽成本服务器承担Relay 服务商承担
NAT 穿透需要端口转发或公网 IP自动处理
部署复杂度需要 VPS / 云服务器零服务器管理
适用规模任意规模中小规模（<500 并发）
成本模型固定（服务器费用）按流量/CCU 付费
推荐方案：开发阶段用直连（本地服务器），发布初期用 Relay（快速上线）， 用户量增长后用专用服务器 + CDN 加速。三者可以共存——你的游戏应该支持多种连接方式。

using Mirror;
using UnityEngine;
using UnityEngine.TestTools;
using NUnit.Framework;
using System.Collections;

public class ServerTests
{
    IEnumerator TestPlayerSpawn()

        // 端口在 Transport 上配置（需在测试设置中预先配置）
        NetworkClient.Connect("localhost");
        yield return new WaitUntil(() => NetworkClient.isConnected);

        // Mirror 96: ClientScene 已合并入 NetworkClient

        var player = NetworkClient.localPlayer;

        // 等待服务器广播
        yield return new WaitForSeconds(0.5f);

        // 验证其他客户端收到了位置更新
        // ...
    }
}
Mirror 96 变化：
  • ClientScene.localPlayers（列表）→ NetworkClient.localPlayer（单个 NetworkIdentity），因为每个连接只有一个本地玩家。
  • NetworkClient.Connect("localhost", 7777) → NetworkClient.Connect("localhost")，端口在 Transport 上设置。

9.6.2 Docker 容器化部署

# Dockerfile for Unity Mirror Server
FROM ubuntu:22.04

# 安装 Unity 运行时依赖
RUN apt-get update && apt-get install -y \
    libgl1-mesa-glx \
    libssl3 \
    libstdc++6 \
    zlib1g \
    ca-certificates \
    && rm -rf /var/lib/apt/lists/*

# 复制服务器二进制
COPY MyGameServer /game/
COPY GameData /game/Data/

WORKDIR /game

# 暴露 KCP 默认端口
EXPOSE 7777/udp

# 启动命令（端口通过环境变量或参数传递）
ENTRYPOINT ["./MyGameServer", "-batchmode", "-nographics"]
CMD ["-port", "7777"]
# 构建和运行
docker build -t mygame-server .
docker run -d -p 7777:7777/udp --name mygame-1 mygame-server

# 多实例部署（注意 KCP 使用 UDP）
docker run -d -p 7778:7777/udp mygame-server
docker run -d -p 7779:7777/udp mygame-server
注意：Mirror 默认的 KcpTransport 使用 UDP 协议。 Docker 端口映射需要指定 /udp 后缀，否则默认为 TCP 映射，客户端将无法连接。

9.6.3 服务器扩缩策略

静态部署（简单但浪费）：
  始终运行 N 个服务器实例
  适合：日活稳定、峰值可预估

动态扩缩（推荐）：
  监控在线人数 → 低于阈值时缩减 → 高于阈值时扩展
  适合：日活波动大、成本控制严格

混合模式（最佳）：
  基础 N 个实例常驻 + 高峰期自动扩展 M 个实例
  适合：大多数商业游戏

9.7.1 服务器健康检查

using Mirror;
using UnityEngine;

public class ServerMonitor : NetworkBehaviour
{
    void Update()
    {
        // Mirror 96: NetworkServer.connections 是 Dictionary<int, NetworkConnectionToClient>
        int connectedClients = NetworkServer.connections.Count;

        // 异常检测
        if (connectedClients == 0 && Time.time > 300)
        {
            Debug.LogWarning("服务器运行 5 分钟但无客户端连接");
        }

        // 定期输出性能报告
        if (Time.frameCount % 300 == 0)  // 每 5 秒（假设 60fps）
        {
            Debug.Log($"[Perf] 客户端:{connectedClients} " +
                      $"帧:{Time.frameCount} " +
                      $"时间:{Time.time:F0}s");
        }
    }
}

9.7.2 日志管理

using Mirror;
using System;
using System.Collections.Generic;
using UnityEngine;

// 结构化日志输出（方便 ELK/Grafana 等工具采集）
public static class StructuredLogger
{
    public static void LogEvent(string eventType, Dictionary<string, string> data)
    {
        // JSON 格式输出，便于解析
        string json = $"{{\"timestamp\":\"{DateTime.UtcNow:O}\",\"type\":\"{eventType}\",\"data\":{{";
        bool first = true;
        foreach (var kv in data)
        {
            if (!first) json += ",";
            json += $"\"{kv.Key}\":\"{kv.Value}\"";
            first = false;
        }
        json += "}}";

        Debug.Log(json);
    }
}

9.8 安全与防护

9.8.1 连接认证

Mirror 96 使用消息处理器实现认证流程。客户端在连接后发送认证消息，服务器验证后接受或拒绝。

using Mirror;
using UnityEngine;

// Mirror 96: 自定义消息必须是 struct : INetworkMessage
public struct AuthMessage : INetworkMessage
{
    public string token;  // JWT / Session Token

    public void Serialize(NetworkWriter writer)
    {
        writer.WriteString(token);
    }

    public void Deserialize(NetworkReader reader)
    {
        token = reader.ReadString();
    }
}

// Mirror 96: 认证响应消息
public struct AuthResponseMessage : INetworkMessage
{
    public bool success;
    public string errorMessage;

    public void Serialize(NetworkWriter writer)
    {
        writer.WriteBool(success);
        writer.WriteString(errorMessage);
    }

    public void Deserialize(NetworkReader reader)
    {
        success = reader.ReadBool();
        errorMessage = reader.ReadString();
    }
}

public class AuthManager : NetworkBehaviour
{
    public override void OnStartServer()
    {
        // Mirror 96: 服务器端注册认证消息处理器
        // 签名：void Handler(NetworkConnectionToClient conn, T msg)
        NetworkServer.RegisterHandler<AuthMessage>(OnServerAuthenticate);
    }

    public override void OnStartClient()
    {
        // Mirror 96: 客户端注册认证响应处理器
        // 签名：void Handler(T msg) —— 无连接参数
        NetworkClient.RegisterHandler<AuthResponseMessage>(OnClientAuthResponse);

        // 连接后自动发送认证
        // 注意：需要在 OnClientConnect 回调中发送
    }

    // 服务器端处理器：注意签名包含 NetworkConnectionToClient
    void OnServerAuthenticate(NetworkConnectionToClient conn, AuthMessage msg)
    {
        if (ValidateToken(msg.token))
        {
            // 认证成功
            conn.isAuthenticated = true;

            // 发送成功响应
            conn.Send(new AuthResponseMessage { success = true, errorMessage = "" });

            // 可以在这里创建 Player 对象
            // NetworkServer.AddPlayerForConnection(conn, playerPrefab);
        }
        else
        {
            // 认证失败，发送错误响应
            conn.Send(new AuthResponseMessage { success = false, errorMessage = "Invalid token" });

            // Mirror 96: 断开连接使用 conn.Disconnect()
            // 不要使用 NetworkServer.RemoveConnection()（已废弃）
            conn.Disconnect();
        }
    }

    // 客户端处理器：无连接参数
    void OnClientAuthResponse(AuthResponseMessage msg)
    {
        if (msg.success)
        {
            Debug.Log("认证成功！");
        }
        else
        {
            Debug.LogError($"认证失败：{msg.errorMessage}");
            NetworkClient.Disconnect();
        }
    }

    bool ValidateToken(string token)
    {
        // 验证 JWT / Session Token / 自定义加密签名
        // 这里应该调用你的后端 API
        return !string.IsNullOrEmpty(token);
    }
}
Mirror 96 变化（认证 API）：
  • 不再使用 [ServerCallback] 处理认证消息。[ServerCallback] 用于 Unity 生命周期回调（如 OnTriggerEnter），不用于消息处理。
  • 使用 NetworkServer.RegisterHandler<T>(handler) 注册服务器端消息处理器，签名为 void Handler(NetworkConnectionToClient conn, T msg)。
  • 使用 NetworkClient.RegisterHandler<T>(handler) 注册客户端消息处理器，签名为 void Handler(T msg)（无连接参数）。
  • 断开连接使用 conn.Disconnect()（非 NetworkServer.RemoveConnection()）。
  • 连接 ID 通过 conn.connectionId 获取（非 conn.userId）。
  • 发送消息使用 conn.Send(new SomeMessage { ... })。

9.8.2 防 DDoS 基础措施

  • 速率限制：每个连接每秒最多 N 条消息
  • 连接限制：单个 IP 最多 M 个并发连接
  • 消息大小限制：拒绝超过 MTU × 2 的消息（Transport.GetMaxPacketSize()）
  • Cloudflare / AWS Shield：在服务器前加 CDN 做 L3/L4 防护
  • 认证前置：未认证连接不接收游戏消息，超时自动断开
