第 8 章 · PPO 与连续动作控制

Actor-Critic 很强大，但有个微妙难题：每次策略该更新多大步？太大学崩、太小学得慢。PPO（近端策略优化）用一个异常简洁的"裁剪"机制把"别走太远"直接做进目标函数，成为工业界最常用的深度 RL 算法。本章讲清它的原理，并了解连续动作下的 DDPG/TD3/SAC。

8.1 核心思想：把"新策略别离旧策略太远"做进目标

策略梯度每更新一次，策略就变一点。若一次更新过猛，新策略可能突然变差、且难以恢复。TRPO 用 KL 散度划定一个"信赖域"硬约束来防止此事，但实现复杂。PPO 的思路是：不另加约束，而是在目标函数里"一旦想走远就不再给奖励"。

重要性采样与概率比率

我们要优化新策略 πθ，但手里的数据是旧策略 πold 采的。重要性采样给出修正：定义新旧策略对同一动作的概率比率

rₜ(θ) = πθ(aₜ|sₜ) / πold(aₜ|sₜ)

r=1 表示新旧策略完全一致；r>1 表示新策略更倾向这个动作，r<1 表示更回避。普通策略梯度目标就是 r·A。

PPO 的裁剪目标

L = E[ min( r·A , clip(r, 1−ε, 1+ε)·A ) ]

取两者中更悲观（更小）的一个，ε 常取 0.2。直觉分两种情况：

  • 优势 A>0（好动作）：希望增大其概率；但 r 一旦超过 1+ε，裁剪项固定，继续增大概率不再有额外收益——防止一步冒进。
  • 优势 A<0（坏动作）：希望降低其概率；但 r 一旦低于 1−ε，同样被截断，防止一步把该动作概率砍光。

最终目标再加上价值函数损失（减去）和熵奖励：

L_total = L_policy − c₁·L_value + c₂·S[π]
为什么 PPO 如此受欢迎：它像 TRPO 一样可靠地限制更新幅度，却只需普通的一阶梯度下降，实现简单、易于并行、对超参不敏感，能在离散与连续、游戏与机器人上广泛工作。

8.2 PPO 的工程要素与监控指标

  • Rollout 收集：用当前策略采样一批数据，记录旧 log 概率、价值。
  • GAE 优势与回报：用上一章 GAE 计算优势，并对优势做归一化。
  • 多 epoch + minibatch：对同一批数据复用若干轮、分小批更新（这是 PPO 与第 7 章 A2C 的重要区别，提高样本效率）。
  • 必看指标：approx KL（新旧策略差异，过大说明 ε 该调）、clip fraction（被裁剪比例，过高=更新过猛）、价值的解释方差（评论家是否靠谱）。

8.3 完整 PPO 案例（CartPole，PyTorch）

import numpy as np, torch, torch.nn as nn
from torch.distributions import Categorical
import gymnasium as gym

class ActorCritic(nn.Module):
    def __init__(self, s_dim, n_act):
        super().__init__()
        self.body = nn.Sequential(nn.Linear(s_dim, 64), nn.Tanh())
        self.pi = nn.Linear(64, n_act)
        self.v = nn.Linear(64, 1)
    def forward(self, x):
        h = self.body(x)
        return Categorical(logits=self.pi(h)), self.v(h)

def compute_gae(rewards, values, last_v, gamma=0.99, lam=0.95):
    """用 GAE 计算优势与回报。rewards/values 为等长 numpy 数组，
    last_v 为 rollout 结束后下一状态的 V（回合结束则为 0）。"""
    gaes = np.zeros_like(rewards, dtype=np.float32)
    running = 0.0
    for t in reversed(range(len(rewards))):
        next_v = last_v if t == len(rewards) - 1 else values[t + 1]
        delta = rewards[t] + gamma * next_v - values[t]
        running = delta + gamma * lam * running
        gaes[t] = running
    returns = gaes + np.array(values)
    return gaes, returns

env = gym.make("CartPole-v1")
model = ActorCritic(env.observation_space.shape[0], env.action_space.n)
opt = torch.optim.Adam(model.parameters(), lr=3e-4)
rollout, epochs, mb = 256, 4, 64
history = []

for it in range(60):
    O, A, LP, R, V = [], [], [], [], []
    s, _ = env.reset()
    ep_r, done = 0, False
    for t in range(rollout):
        x = torch.tensor(s, dtype=torch.float32)
        dist, val = model(x)
        a = dist.sample()
        O.append(s); A.append(a.item()); LP.append(dist.log_prob(a).item())
        V.append(val.item())
        s, r, term, trunc, _ = env.step(a.item())
        done = term or trunc
        R.append(r); ep_r += r
        if done:
            s, _ = env.reset()
            history.append(ep_r); ep_r = 0
    last_v = 0 if done else model(torch.tensor(s, dtype=torch.float32))[1].item()
    adv, ret = compute_gae(np.array(R), np.array(V), last_v)
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)

    O = torch.tensor(np.array(O), dtype=torch.float32)
    A = torch.tensor(A); OLD = torch.tensor(LP)
    RET = torch.tensor(ret, dtype=torch.float32)

    for _ in range(epochs):                       # 多 epoch 复用同一批
        idx = np.random.permutation(rollout)
        for start in range(0, rollout, mb):
            b = idx[start:start+mb]
            dist, val = model(O[b])
            val = val.view(-1)
            ratio = torch.exp(dist.log_prob(A[b]) - OLD[b])
            a_b = torch.tensor(adv[b], dtype=torch.float32)
            l1 = ratio * a_b
            l2 = torch.clamp(ratio, 0.8, 1.2) * a_b
            pi_loss = -torch.min(l1, l2).mean()
            v_loss = ((val - RET[b]) ** 2).mean()
            ent = dist.entropy().mean()
            loss = pi_loss + 0.5*v_loss - 0.01*ent
            opt.zero_grad(); loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 0.5)
            opt.step()
    if history:
        print(f"迭代{it+1}  近20局平均 {np.mean(history[-20:]):6.1f}")
通关信号：近 20 局平均分稳定逼近 500；同时 approx KL 保持在较小量级、clip fraction 不长期过高（经验上若长期接近或超过 0.3，说明更新过猛，应调小学习率或 ε）。

8.4 连续动作控制：DDPG / TD3 / SAC

连续动作下，策略不再对离散动作分类，而是直接输出动作数值（或输出一个高斯分布的均值/方差）。三个代表性算法层层递进：

算法类型关键机制解决的问题
DDPG确定性策略 / off-policy演员直接输出确定动作；演员与评论家各配目标网络并软更新；用回放与噪声探索把 DQN 思想用于连续动作
TD3确定性策略 / off-policy双评论家取小、延迟更新演员、目标动作加平滑噪声抑制评论家过估计
SAC随机策略 / 最大熵 / off-policy目标同时最大化回报与策略熵；双评论家；自动调节温度系数兼顾高回报与探索/鲁棒性，连续控制的强基线
"最大熵"直觉：SAC 不仅想拿高分，还想"在拿高分的同时尽量保持策略不确定、多保留几条可行路径"。这让它在复杂连续控制中既高效又稳健，是连续控制任务的常用首选。

本章小结

  • PPO 用概率比率 r 与裁剪目标 min(rA, clip(r)A)，把"新策略别离旧策略太远"做进目标，简单可靠。
  • 工程上配合 GAE、优势归一化、多 epoch/minibatch，并监控 KL、clip fraction、解释方差。
  • 连续动作用 DDPG（确定性+软更新）、TD3（双Q抑过估计）、SAC（最大熵，强基线）。
