T2 宝藏探险：前后缀极值

题目描述

A 级 · 17noi #1718 原题 第一届区域赛 100 分（推定） 时间 1s / 内存 256MB

在一个从 1 到 n 的数轴上，每个位置有一个宝藏辐射值。 两位勘探员正在勘探宝藏，勘探过的位置中的最大值和最小值之差代表整块数轴地的辐射值，能反映这地方的宝藏可能性。

两位勘探员分别从数轴的两侧相向而行，但是他们之间有矛盾，不愿意隔得太近，两位勘探员中间只剩 k 个单位长度时，就会停止前进。

目前不知道两位勘探员谁先出发，只知道他们各自从两端相向而行向中间靠拢，每个人至少探测了一个位置， 中间相隔 k 个位置的时候就停止勘探。 问这块数轴地可能最小的宝藏辐射值是多少？

输入描述

第一行两个整数 n, k，代表数轴长度和停止距离。

第二行是 n 个数字，代表每个位置的辐射值。

输出描述

一个数字，表明可能的最小辐射值。

样例

输入：
10 2
3 6 4 6 5 1 9 3 7 4

输出：
4

数据范围：3 ≤ n ≤ 105，1 ≤ k < n−2；辐射值在 1 到 106。

先自己想一想（建议 15 分钟）
  • 「中间相隔 k 个位置」到底对应左边探测到哪、右边探测到哪？
  • 如果枚举「左勘探员停在 i」，右侧从哪里开始？
  • 直接对每个 i 重新扫一遍数组求最值，复杂度是多少？能过吗？

把题意翻译成区间

两位勘探员从两端往中间走，停止时中间隔着 k 个未被探测的位置。 假设左边的人探测了 [1, i−1]，那么中间空出来的是 [i, i+k−1]（共 k 个位置）， 右边的人探测的是 [i+k, n]。

两个人至少各探测一个位置，所以：

  • 左边至少一个 → i−1 ≥ 1 → i ≥ 2；
  • 右边至少一个 → i+k ≤ n → i ≤ n−k。

于是答案就是：

mini=2..n−k [ max(左段最大值, 右段最大值) − min(左段最小值, 右段最小值) ]

其中左段是 [1, i−1]，右段是 [i+k, n]。

为什么不能每次重扫

枚举 i 有 O(n) 个，每个 i 扫两段求最值是 O(n)，总 O(n²)。 n = 105 时是 1010，必然超时。

但注意：随着 i 增大，左段只会在右边追加一个元素，右段只会从左边删掉一个元素。 两类「只增/只删」的区间最值，都可以用预处理解决：

  • 前缀最值：lmax[i] = max(a[1..i])，lmin[i] = min(a[1..i])；
  • 后缀最值：rmax[i] = max(a[i..n])，rmin[i] = min(a[i..n])。

两遍 O(n) 预处理，之后每个 i 用 O(1) 合并，总复杂度 O(n)。

合并公式

mx = max(lmax[i−1], rmax[i+k]) mn = min(lmin[i−1], rmin[i+k]) ans = min(ans, mx − mn)

样例逐步验证

数组 a = [3, 6, 4, 6, 5, 1, 9, 3, 7, 4]，k = 2，i 从 2 到 8：

i左段右段maxmin差

3[3,6][5,1,9,3,7,4]918

代码

#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
const int INF  = 1000000009;

int a[MAXN];
int lmin_[MAXN], lmax_[MAXN];
int rmin_[MAXN], rmax_[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    for (int i = 1; i <= n; ++i) cin >> a[i];

    lmin_[0] = INF;  lmax_[0] = -INF;
    for (int i = 1; i <= n; ++i) {
        lmin_[i] = min(lmin_[i - 1], a[i]);
        lmax_[i] = max(lmax_[i - 1], a[i]);
    }

    rmin_[n + 1] = INF;  rmax_[n + 1] = -INF;
    for (int i = n; i >= 1; --i) {
        rmin_[i] = min(rmin_[i + 1], a[i]);
        rmax_[i] = max(rmax_[i + 1], a[i]);
    }

    int ans = INF;
    for (int i = 2; i <= n - k; ++i) {
        int mx = max(lmax_[i - 1], rmax_[i + k]);
        int mn = min(lmin_[i - 1], rmin_[i + k]);
        ans = min(ans, mx - mn);
    }

    cout << ans << '\n';
    return 0;
}

复杂度 O(n)，空间 O(n)。lmin_[0] 和 rmin_[n+1] 的哨兵值必须覆盖到值域之外： 本题辐射值最大 106，所以 INF = 1e9+9 够用。

对拍脚本（Python）

如果不想手推边界，可以用这段脚本验证 i 的范围：

import random

def fast(a, k):
    n = len(a)
    lmin = [10**18] * (n + 1)
    lmax = [-10**18] * (n + 1)
    rmin = [10**18] * (n + 2)
    rmax = [-10**18] * (n + 2)
    for i in range(1, n + 1):
        lmin[i] = min(lmin[i - 1], a[i - 1])
        lmax[i] = max(lmax[i - 1], a[i - 1])
    for i in range(n, 0, -1):
        rmin[i] = min(rmin[i + 1], a[i - 1])
        rmax[i] = max(rmax[i + 1], a[i - 1])
    ans = 10**18
    for i in range(2, n - k + 1):
        ans = min(ans, max(lmax[i-1], rmax[i+k]) - min(lmin[i-1], rmin[i+k]))
    return ans

def brute(a, k):
    n = len(a)
    ans = 10**18
    for i in range(2, n - k + 1):
        vals = a[:i-1] + a[i+k-1:]
        ans = min(ans, max(vals) - min(vals))
    return ans

for _ in range(1000):
    n = random.randint(4, 12)
    k = random.randint(1, n - 3)
    a = [random.randint(1, 20) for _ in range(n)]
    assert fast(a, k) == brute(a, k)
print("ok")

易错点清单

  • 把「中间隔 k 个位置」理解成「两人坐标差为 k」，导致右段起点写成 i+k−1 或 i+k+1。
  • 循环写成 i ≤ n−k+1，让右边一个位置都没探测。
  • 循环从 i = 1 开始，左边为空，lmax[0] 的哨兵参与运算后答案错乱。
  • 哨兵设成 0：本题辐射值恒正，lmax[0]=0 看起来没事，但换一道有负数的题就会错。
  • 用 INT_MAX 做 max 的初值，再参与减法，溢出。

延伸练习

1

求最大值

把「可能最小」改成「可能最大」。答案会出现在哪个 i？还是同样的枚举吗？

2

输出方案

在求最小值的同时，输出取得最小值的 i（即两人停止的位置）。注意可能存在多个 i，题目没有要求字典序，任取一个即可。

3

带单点修改

如果数组会被修改（单点更新 + 查询同样的最小值），前后缀就失效了。此时需要线段树维护区间最值，再在树上二分/枚举。试着分析复杂度。

本章小结

  • 「区间只增/只删」的最值问题，优先想前后缀预处理，而不是数据结构。
  • 边界由「每个人至少探测一个位置」推出：i ∈ [2, n−k]。
  • 哨兵值要覆盖值域之外，不要图省事写 0。
