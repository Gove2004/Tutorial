第三章：数学基础——向量、矩阵与四元数

学习目标：掌握 3D 图形学的所有核心数学工具。不只是记住公式，而是理解每个运算的物理意义和性能特征。学会用数学思维解决空间变换、插值、碰撞检测等问题。

向量：空间中的箭头

向量是 3D 图形学最基本的概念。它不是一个数字，而是一个有方向的箭头——从原点指向空间中的某个点。在 C++ 中，我们用一个结构体来表示：

struct Vec3 {
    float x, y, z;

    // 加法：两个箭头的合成
    Vec3 operator+(const Vec3& other) const {
        return {x + other.x, y + other.y, z + other.z};
    }

    // 减法：从一个点到另一个点的方向
    Vec3 operator-(const Vec3& other) const {
        return {x - other.x, y - other.y, z - other.z};
    }

    // 标量乘法：拉伸或压缩箭头
    Vec3 operator*(float s) const {
        return {x * s, y * s, z * s};
    }

    // 长度（模）
    float length() const {
        return std::sqrt(x*x + y*y + z*z);
    }

    // 归一化：变成单位长度（方向不变）
    Vec3 normalized() const {
        float len = length();
        if (len > 0.0f) return *this / len;
        return {0, 0, 0};
    }
};

点积（Dot Product）

点积的结果是一个标量（单个数字），表示两个向量的「相似度」。

float dot(Vec3 a, Vec3 b) {
    return a.x*b.x + a.y*b.y + a.z*b.z;
}

几何意义：dot(a, b) = |a| * |b| * cos(theta)。其中 theta 是两个向量的夹角。

  • dot(a, b) > 0：夹角小于 90 度，方向大致相同
  • dot(a, b) == 0：夹角等于 90 度，互相垂直
  • dot(a, b) < 0：夹角大于 90 度，方向相反

引擎中的应用：

应用场景原理
光照计算漫反射强度 = max(dot(法线, 光照方向), 0)
摄像机朝向判断物体是否在摄像机前方
碰撞检测判断两个表面的朝向关系
角度检测玩家是否面向目标（FPS 瞄准辅助）

叉积（Cross Product）

叉积的结果是一个新的向量，垂直于输入的两个向量。

Vec3 cross(Vec3 a, Vec3 b) {
    return {
        a.y * b.z - a.z * b.y,
        a.z * b.x - a.x * b.z,
        a.x * b.y - a.y * b.x
    };
}

几何意义：结果向量的方向遵循右手定则，大小等于两个向量构成的平行四边形面积。

引擎中的应用：

  • 计算法线：三角形两条边的叉积就是该三角形的法线方向
  • 构建坐标系：给定前向向量和上方向，叉积可以得到右方向向量
  • 遮挡检测：判断一个点是否在平面的某一侧

归一化与插值

归一化（Normalize）将向量变成单位长度，保留方向。这在计算光照方向、移动方向时必不可少——你不希望玩家按下「前进」键时，斜着走比直着走更快。

Lerp（线性插值）在两个值之间 smoothly 过渡：

// 在 a 和 b 之间插值，t ∈ [0, 1]
Vec3 lerp(Vec3 a, Vec3 b, float t) {
    return a + (b - a) * t;
    // 等价于：a * (1 - t) + b * t
}

// 实际应用：平滑相机跟随
Vec3 cameraTarget = playerPos + forward * 5.0f;
cameraPos = lerp(cameraPos, cameraTarget, deltaTime * 5.0f);
// 相机不会瞬间跳到目标位置，而是以 5.0 的速度平滑接近

矩阵：变换的数学表达

矩阵是 3D 变换的核心工具。一个 4x4 矩阵可以同时表达平移、旋转、缩放三种变换。这就是为什么 3D 引擎统一使用 4x4 矩阵而不是分别存储位置、旋转、缩放。

struct Mat4 {
    float m[4][4];

    // 单位矩阵（恒等变换）
    static Mat4 identity() {
        Mat4 result;
        for (int i = 0; i < 4; ++i)
            for (int j = 0; j < 4; ++j)
                result.m[i][j] = (i == j) ? 1.0f : 0.0f;
        return result;
    }

    // 平移矩阵
    static Mat4 translation(float x, float y, float z) {
        Mat4 t = identity();
        t.m[3][0] = x;  // 第四行第一列
        t.m[3][1] = y;
        t.m[3][2] = z;
        return t;
    }

    // 缩放矩阵
    static Mat4 scale(float sx, float sy, float sz) {
        Mat4 s = identity();
        s.m[0][0] = sx;  // 对角线元素
        s.m[1][1] = sy;
        s.m[2][2] = sz;
        return s;
    }

    // 矩阵乘法（变换的组合）
    Mat4 operator*(const Mat4& other) const {
        Mat4 result = {{0}};
        for (int i = 0; i < 4; ++i)
            for (int j = 0; j < 4; ++j)
                for (int k = 0; k < 4; ++k)
                    result.m[i][j] += m[k][j] * other.m[i][k];
        return result;
    }
};

变换矩阵的组合

多个变换的组合通过矩阵乘法实现。注意乘法顺序很重要——矩阵乘法不满足交换律。

// 正确的变换顺序：先缩放，再旋转，最后平移
Mat4 modelMatrix = Mat4::translation(tx, ty, tz)
                 * Mat4::rotationY(angle)
                 * Mat4::scale(sx, sy, sz);

// 错误：先平移再缩放会导致物体被移到远处后再放大
Mat4 wrong = Mat4::scale(sx, sy, sz)
           * Mat4::translation(tx, ty, tz);
// 结果：物体不仅被缩放了，还被移到了奇怪的位置
为什么是反序？：因为矩阵乘法是右结合的。model * vertex 中，最右边的变换最先执行。所以代码中写的顺序（translation * rotation * scale）对应的是实际执行的逆序（先 scale，再 rotation，最后 translation）。这种「写入顺序与执行顺序相反」的特性是初学者最容易困惑的地方。

视图矩阵（View Matrix）

视图矩阵将世界坐标转换为相机坐标。它的本质是相机位置的逆变换——想象把整个世界反向移动到相机的位置。

// 从相机参数构建视图矩阵
Mat4 lookAt(Vec3 eye, Vec3 center, Vec3 up) {
    // 1. 计算相机的三个正交轴
    Vec3 forward = (center - eye).normalized();
    Vec3 right = cross(forward, up).normalized();
    Vec3 actualUp = cross(right, forward);

    // 2. 构建旋转部分
    Mat4 rot;
    rot.m[0][0] = right.x;     rot.m[0][1] = right.y;   rot.m[0][2] = right.z;
    rot.m[1][0] = actualUp.x;  rot.m[1][1] = actualUp.y; rot.m[1][2] = actualUp.z;
    rot.m[2][0] = -forward.x;  rot.m[2][1] = -forward.y; rot.m[2][2] = -forward.z;

    // 3. 构建平移部分（将相机移到原点）
    Mat4 trans = Mat4::translation(-eye.x, -eye.y, -eye.z);

    // 4. 组合
    return rot * trans;
}

投影矩阵（Projection Matrix）

投影矩阵将 3D 场景映射到 2D 屏幕。有两种主要类型：

  • 透视投影（Perspective）：近大远小，模拟人眼。用于 3D 游戏。
  • 正交投影（Orthographic）：没有透视变形。用于 2D 游戏、UI、CAD。
// 透视投影矩阵
Mat4 perspective(float fov, float aspect, float near, float far) {
    Mat4 proj = {{0}};
    float tanHalfFov = std::tan(fov / 2.0f);
    proj.m[0][0] = 1.0f / (aspect * tanHalfFov);
    proj.m[1][1] = 1.0f / tanHalfFov;
    proj.m[2][2] = -(far + near) / (far - near);
    proj.m[2][3] = -1.0f;
    proj.m[3][2] = -(2.0f * far * near) / (far - near);
    proj.m[3][3] = 0.0f;
    return proj;
}

四元数：旋转的正确方式

为什么需要四元数？

旋转是 3D 图形中最容易出错的部分。很多人直觉上使用欧拉角（Euler Angles：绕 X/Y/Z 轴的三个角度），但欧拉角有三个致命问题：

  1. Gimbal Lock（万向节死锁）：当两个旋转轴对齐时，丢失一个自由度。想象飞机的俯仰角达到 90 度时，偏航和滚转变成了同一个轴。
  2. 插值困难：两个欧拉角的线性插值会产生非均匀旋转，看起来像抖动。
  3. 累积误差：多次旋转后，基向量不再正交，需要反复重新正交化。

四元数的数学定义

四元数是复数的扩展，由一个实部和三个虚部组成：

struct Quaternion {
    float w, x, y, z;  // w 是标量部分，(x,y,z) 是向量部分

    // 从轴角构造四元数
    // axis: 旋转轴（单位向量）
    // angle: 旋转角度（弧度）
    static Quaternion fromAxisAngle(Vec3 axis, float angle) {
        float halfAngle = angle / 2.0f;
        float sinHalf = std::sin(halfAngle);
        return {
            std::cos(halfAngle),    // w
            axis.x * sinHalf,       // x
            axis.y * sinHalf,       // y
            axis.z * sinHalf        // z
        };
    }

    // 四元数乘法（组合旋转）
    Quaternion operator*(const Quaternion& other) const {
        return {
            w*other.w - x*other.x - y*other.y - z*other.z,
            w*other.x + x*other.w + y*other.z - z*other.y,
            w*other.y - x*other.z + y*other.w + z*other.x,
            w*other.z + x*other.y - y*other.x + z*other.w
        };
    }

    // 共轭（逆旋转）
    Quaternion conjugate() const {
        return {w, -x, -y, -z};
    }

    // 归一化
    Quaternion normalized() const {
        float len = std::sqrt(w*w + x*x + y*y + z*z);
        return {w/len, x/len, y/len, z/len};
    }
};

SLERP 球面线性插值

四元数的最大优势之一是可以在两个旋转之间做平滑插值（SLERP），这对于动画、相机跟随、平滑转向至关重要。

// SLERP：在 q1 和 q2 之间插值，t ∈ [0, 1]
Quaternion slerp(Quaternion q1, Quaternion q2, float t) {
    // 1. 计算点积
    float dot = q1.w*q2.w + q1.x*q2.x + q1.y*q2.y + q1.z*q2.z;

    // 2. 如果点积为负，翻转 q2 以保证最短路径
    if (dot < 0.0f) {
        q2 = {-q2.w, -q2.x, -q2.y, -q2.z};
        dot = -dot;
    }

    // 3. 如果接近平行，使用线性插值
    if (dot > 0.995f) {
        return Quaternion{
            q1.w + t*(q2.w - q1.w),
            q1.x + t*(q2.x - q1.x),
            q1.y + t*(q2.y - q1.y),
            q1.z + t*(q2.z - q1.z)
        }.normalized();
    }

    // 4. 标准 SLERP
    float theta_0 = std::acos(dot);
    float theta = theta_0 * t;
    float sinTheta = std::sin(theta_0);
    float s0 = std::cos(theta) - dot * std::sin(theta) / sinTheta;
    float s1 = std::sin(theta) / sinTheta;

    return Quaternion{
        s0 * q1.w + s1 * q2.w,
        s0 * q1.x + s1 * q2.x,
        s0 * q1.y + s1 * q2.y,
        s0 * q1.z + s1 * q2.z
    };
}

SLERP 的视觉效果：两个旋转之间的过渡是匀速且沿最短路径的。而欧拉角的线性插值会在中间某个时刻出现旋转加速或减速的异常现象。

齐次坐标：为什么用 4D 表示 3D

你可能会疑惑：3D 世界为什么需要用 4 个分量来表示？答案在于仿射变换的统一表达。

平移操作不能用 3x3 矩阵表示——矩阵乘法只能表达线性变换（旋转、缩放、剪切），而平移是非线性的（加法）。解决方案是使用齐次坐标：

// 3D 点 (x, y, z) → 齐次坐标 (x, y, z, w)
// w = 1 表示点，w = 0 表示方向向量

// 在 3x3 矩阵中无法表达平移：
// [a b c]   [x]   [ax + by + cz]
// [d e f] * [y] = [dx + ey + fz]
// [g h i]   [z]   [gx + hy + iz]
// 没有地方放平移量 tx, ty, tz！

// 但在 4x4 矩阵中可以统一表达所有变换：
// [R  t]   [v]   [R*v + t]    ← R 是 3x3 旋转缩放，t 是 3x1 平移
// [0  1] * [1] = [    1   ]

这就是为什么 3D 引擎统一使用 4x4 矩阵——它同时包含了旋转（3x3 部分）、平移（最后一列的前三个元素）、缩放（对角线）和剪切（非对角线元素），用一个数据结构搞定所有仿射变换。

空间划分：BVH / Octree / BSP

当场景中有成千上万个物体时，逐一检查每个物体会导致 O(n) 的复杂度。空间划分数据结构将空间分成区域，只检查与查询相关的区域，可以将复杂度降到 O(log n)。

BVH（Bounding Volume Hierarchy）

包围体层次结构。每个节点包含一个包围体（通常是 AABB），叶子节点包含实际几何体。

struct BVHNode {
    AABB boundingBox;
    BVHNode* children[2];  // 内部节点有两个子节点
    Mesh* mesh;             // 叶子节点存储网格指针

    // 构建：递归地将物体分成两组
    static BVHNode* build(const std::vector<Mesh*>& meshes, int depth = 0) {
        if (meshes.empty()) return nullptr;

        // 找到最小包围盒
        AABB bounds = computeBounds(meshes);

        if (meshes.size() <= MAX_LEAF_SIZE || depth >= MAX_DEPTH) {
            // 叶子节点
            return new BVHNode{{bounds, nullptr, nullptr, meshes.data()}};
        }

        // 按最长轴分割
        Axis axis = bounds.longestAxis();
        std::sort(meshes.begin(), meshes.end(), [axis](Mesh* a, Mesh* b) {
            return getCenter(a, axis) < getCenter(b, axis);
        });

        auto mid = meshes.begin() + meshes.size() / 2;
        BVHNode* node = new BVHNode;
        node->boundingBox = bounds;
        node->children[0] = build(std::vector<Mesh*>(meshes.begin(), mid), depth + 1);
        node->children[1] = build(std::vector<Mesh*>(mid, meshes.end()), depth + 1);
        return node;
    }

    // 光线追踪：递归检查射线是否与节点相交
    bool intersect(const Ray& ray) const {
        if (!boundingBox.intersects(ray)) return false;

        if (!children[0]) {
            // 叶子节点：检查所有网格
            for (auto* mesh : meshes) {
                if (mesh->intersect(ray)) return true;
            }
            return false;
        }

        // 内部节点：递归检查子节点
        return children[0]->intersect(ray) || children[1]->intersect(ray);
    }
};

Octree（八叉树）

将空间均匀分成 8 个子区域，每个子区域可以再分。适合分布均匀的物体集合。

BSP（Binary Space Partitioning）

用平面递归地将空间分成两半。适合室内场景（如 Doom 引擎），可以精确判断可见性。

数据结构 构建复杂度 查询复杂度 适用场景 内存开销
BVHO(n log n)O(log n)光线追踪、动态场景中
OctreeO(n log n)O(log n)均匀分布的静态场景高（空节点）
BSPO(n²)O(log n)室内场景、可见性裁剪中

本章小结

本章核心知识点回顾：
  1. 向量运算：点积判断方向/角度，叉积计算法线/正交向量，归一化保证速度一致，Lerp 实现平滑过渡。
  2. 矩阵变换：4x4 矩阵统一表达平移、旋转、缩放。乘法顺序重要（先缩放→旋转→平移）。
  3. 四元数：解决 Gimbal Lock、支持 SLERP 插值、存储紧凑（4 浮点数 vs 9 浮点数）。
  4. 齐次坐标：w 分量让平移可以用矩阵乘法表示，是 4x4 矩阵的基础。
  5. 空间划分：BVH 适合光线追踪，Octree 适合均匀场景，BSP 适合室内可见性。
