第 4 章：对象生成与 Spawn — 网络实体管理

Spawn（生成）是网络游戏中最核心的操作之一。 一个对象什么时候被创建、在哪台机器上创建、用什么模板创建、初始状态是什么—— 每一个环节都可能出错。本章将深入理解 Mirror 的 Spawn 系统，从 Prefab 注册到对象生命周期管理。

Mirror 96 API 更新
本章已全面适配 Mirror 96.x。主要变化包括： ClientScene 已合并入 NetworkClient（ClientScene.RegisterPrefab → NetworkClient.RegisterPrefab）； Authority API 使用 AssignClientAuthority / RemoveClientAuthority； NetworkManager 回调方法名修正（OnStartServer 而非 StartServer）； playerPrefab 通过 Inspector/字段设置而非 AddPlayerPrefab()； 移除了 NetworkHash128 和 ClientScene.ReconnectForNewPlayer 等已废弃 API。

4.1 Spawn 的基本流程

Mirror 的 Spawn 不是简单的 Instantiate。它涉及服务器和客户端之间的协调：

服务器                              客户端 A         客户端 B
  |                                    |                |
  | Instantiate(prefab)               |                |
  | NetworkServer.Spawn(obj)           |                |
  |                                    |                |
  |--- SpawnMessage(prefabHash, netId) ->|                |
  |--- SpawnMessage(prefabHash, netId) ----------------->|
  |                                    |                |
  |                                    |Instantiate()   |Instantiate()
  |                                    |set netId       |set netId
  |                                    |sync vars       |sync vars
  |                                    |OnStartClient   |OnStartClient

关键点：服务器负责"决定谁存在"，客户端负责"根据指令实例化"。 客户端从不自己决定要 Spawn 什么对象——一切由服务器发起。

4.2 Prefab 注册：Spawn 的前提条件

在 Spawn 一个对象之前，客户端必须知道这个对象的 Prefab 模板长什么样。 这就是Prefab 注册的作用。

4.2.1 通过 NetworkManager 注册

最简单的方式：在 NetworkManager 组件的 Inspector 中配置 Spawnable Prefabs 列表（通过 Prefab 列表拖入）。 playerPrefab 字段专门用于注册 Player Prefab，Mirror 会自动处理。

public class MyNetworkManager : NetworkManager
{
    // playerPrefab 在 Inspector 中设置——Mirror 自动注册
    // 不需要手动调用任何注册方法

    [Header("额外可 Spawn 的 Prefab")]
    public GameObject[] spawnablePrefabs;

    public override void OnStartServer()
    {
        base.OnStartServer();
        // playerPrefab 已由 NetworkManager 自动注册
        // 额外的 Prefab 需要手动注册
        foreach (var prefab in spawnablePrefabs)
        {
            NetworkClient.RegisterPrefab(prefab);
        }
    }
}
Mirror 96 API 变化
• AddPlayerPrefab() 已移除——直接设置 playerPrefab 字段即可
• ClientScene.RegisterPrefab() 已合并为 NetworkClient.RegisterPrefab() （ClientScene 类已合并入 NetworkClient）
• NetworkHash128 已移除——Mirror 96 使用 Prefab 的 hash 值（基于名称或 GUID）

4.2.2 手动注册 Prefab（含自定义 Spawn 函数）

对于需要特殊初始化逻辑的 Prefab，Mirror 96 支持注册自定义 Spawn/Unspawn 处理器：

// Mirror 96 的自定义 Spawn 处理器注册
using Mirror;

public class PrefabRegistry : NetworkBehaviour
{
    public GameObject enemyPrefab;

    public override void OnStartServer()
    {
        base.OnStartServer();

        // 方式 1：简单注册（默认行为：Instantiate + 初始化 SyncVar）
        NetworkClient.RegisterPrefab(enemyPrefab);

        // 方式 2：注册自定义 Spawn/Unspawn 处理器
        // 用于对象池、特殊初始化等场景
        NetworkClient.RegisterPrefab(
            enemyPrefab,
            HandleSpawn,    // 自定义生成回调
            HandleUnspawn    // 自定义销毁回调
        );
    }

    // 自定义 Spawn 处理器：当客户端收到 Spawn 消息时调用
    GameObject HandleSpawn(Vector3 position, Quaternion rotation, uint assetId)
    {
        // 从对象池获取而非 Instantiate
        GameObject obj = EnemyPool.Get(position, rotation);
        // 初始化逻辑...
        return obj;
    }

    // 自定义 Unspawn 处理器：当客户端收到 Destroy 消息时调用
    void HandleUnspawn(GameObject obj)
    {
        // 返回对象池而非 Destroy
        EnemyPool.Return(obj);
    }
}
自定义处理器 vs 默认行为：
默认情况下，Mirror 在客户端收到 Spawn 消息时会 Instantiate 对应的 Prefab。 注册自定义处理器后，你可以完全控制生成和销毁逻辑—— 这对对象池尤其有用（避免频繁 Instantiate/Destroy 导致的 GC 压力）。

4.3 NetworkServer.Spawn 详解

这是服务器端最核心的 Spawn 方法：

// 基本用法
GameObject enemy = Instantiate(enemyPrefab, spawnPoint, Quaternion.identity);
NetworkServer.Spawn(enemy);

// Spawn 后修改 SyncVar 会自动同步
HealthSystem health = enemy.GetComponent<HealthSystem>();
health.Initialize(maxHealth: 500);  // 修改 SyncVar → 自动同步

4.3.1 Spawn 的内部流程

当调用 NetworkServer.Spawn(obj) 时，Mirror 执行以下操作：

  1. 检查对象是否已有 netId。如果已 Spawn，跳过。
  2. 分配一个新的 netId（全局唯一递增的 uint）。
  3. 将 netId → NetworkIdentity 映射加入服务器的 spawned 字典。
  4. 序列化对象的初始状态（所有 SyncVar 的当前值）。
  5. 向所有已连接的客户端发送 SpawnMessage（含 Prefab hash、netId、初始数据、所有权信息）。
  6. 触发服务器端的 OnStartServer() 回调。
// Mirror 内部简化版逻辑（伪代码）
public static void Spawn(GameObject obj)
{
    NetworkIdentity identity = obj.GetComponent<NetworkIdentity>();

    // 分配 netId（只读，由 Mirror 内部设置）
    uint newNetId = AllocateNewNetId();

    // 注册到 spawned 字典
    spawned[newNetId] = identity;

    // 发送 Spawn 消息给所有客户端
    foreach (var conn in connections)
    {
        SendToClient(conn, new SpawnMessage
        {
            netId = newNetId,
            assetHash = identity.assetHash,
            // 序列化初始 SyncVar 值
            payload = SerializeInitialSyncVars(identity),
            // 所有权：此对象是否已分配给某客户端
            owner = identity.connectionToClient
        });
    }

    // 触发回调
    identity.OnStartServer();
}
关于 SyncVar 初始值：Spawn 时，Mirror 会序列化当前时刻所有 SyncVar 的值并发送给客户端。 这意味着你可以在 Spawn 前设置初始值——它们会被包含在 Spawn 消息中。 但 Spawn 后修改的 SyncVar 会通过正常的状态同步流程发送（有约一帧延迟）。

4.4 对象的销毁

销毁网络对象只需要调用 NetworkServer.Destroy()：

// 服务器销毁对象（所有客户端同步销毁）
NetworkServer.Destroy(deadEnemy);

// 注意：不需要手动调用 Destroy()
// NetworkServer.Destroy 内部会：
// 1. 发送 Destroy 消息给所有客户端
// 2. 客户端收到后执行销毁（或调用自定义 Unspawn 处理器）
// 3. 服务器端调用 GameObject.Destroy
错误做法：在服务器上直接用 Destroy(gameObject) 而不是 NetworkServer.Destroy()。前者只销毁了服务器上的 GameObject，但没有通知客户端—— 客户端上这个对象仍然"活着"，成为幽灵对象。

4.5 Player 对象的特殊处理

Player 对象在网络游戏中有特殊的地位。它们不仅是"普通的网络对象"， 还承载着"玩家身份"和"控制权限"。

4.5.1 Player vs 普通网络对象

特性Player 对象普通网络对象
数量限制每客户端通常 1 个无限制
自动生成通过 AddPlayer 流程手动 Spawn
Authority（isOwned）自动绑定到对应客户端需要显式设置或无
场景切换可能被保留或重建通常随场景销毁
Destroy 时机断线时自动处理手动或逻辑驱动

4.5.2 完整的 Player 生成流程

public class MyNetworkManager : NetworkManager
{
    // playerPrefab 通过 Inspector 设置，Mirror 自动注册

    public override void OnServerAddPlayer(NetworkConnection conn)
    {
        // 1. 创建 Player 对象
        GameObject player = Instantiate(
            playerPrefab,
            GetSpawnPosition(),
            Quaternion.identity
        );

        // 2. Spawn 并绑定到此连接
        // AddPlayerForConnection 内部会：
        //   - 调用 NetworkServer.Spawn
        //   - 将 connectionToClient 设置为此连接
        //   - 触发客户端的 OnStartLocalPlayer
        NetworkServer.AddPlayerForConnection(conn, player);

        // 此时在拥有此 player 的客户端上：
        //   isOwned = true（拥有控制权）
        //   isLocalPlayer = true（是本地玩家）
    }

    public override void OnServerRemovePlayer(NetworkConnection conn, NetworkIdentity player)
    {
        // 移除 Player 对象
        if (player != null)
        {
            NetworkServer.Destroy(player.gameObject);
        }
    }

    Vector3 GetSpawnPosition()
    {
        // 随机选择 Spawn 点
        Transform[] spawnPoints = FindObjectsOfType<Transform>()
            .Where(t => t.CompareTag("SpawnPoint"))
            .ToArray();
        if (spawnPoints.Length == 0) return Vector3.zero;
        return spawnPoints[Random.Range(0, spawnPoints.Length)].position;
    }
}

4.5.3 Client Authority 与 isOwned

Player 对象默认将 Authority 授予绑定它的客户端。这意味着：

  • 该客户端可以在此对象上调用 [Command]（requiresAuthority 默认为 true）
  • 该客户端的 isOwned 为 true
  • 其他客户端对此对象只有"观察权"

你也可以对非 Player 对象动态分配/回收 Authority：

public class OwnershipManager : NetworkBehaviour
{
    // 将对象控制权分配给某个客户端
    [Server]
    public void GiveAuthorityTo(uint objectId, NetworkConnectionToClient newOwner)
    {
        if (NetworkServer.spawned.TryGetValue(objectId, out var identity))
        {
            // Mirror 96 的 Authority API
            identity.AssignClientAuthority(newOwner);
            // 新拥有者客户端上 isOwned 变为 true
            // 旧拥有者客户端上 isOwned 变为 false
        }
    }

    // 回收控制权到服务器
    [Server]
    public void ReclaimAuthority(uint objectId)
    {
        if (NetworkServer.spawned.TryGetValue(objectId, out var identity))
        {
            identity.RemoveClientAuthority();
            // 所有客户端上 isOwned 变为 false
        }
    }
}
Mirror 96 Authority API 变化
• AssignAuthority() → AssignClientAuthority(NetworkConnection conn)
• GrantAuthority() → AssignClientAuthority(NetworkConnection conn)
• RevokeAuthority() → RemoveClientAuthority()
• 所有方法都在 NetworkIdentity 上，且只能在服务器端调用

4.6 Spawn 场景中的已有对象

有些网络对象一开始就在场景中（不是运行时 Spawn 的）。比如地图上的炮塔、宝箱等。

4.6.1 场景预置对象的处理

// 场景中的预置网络对象处理方式：
// 1. 在场景编辑器中放置带 NetworkIdentity 的 GameObject
// 2. NetworkManager 在服务器启动时会自动 Spawn 场景中的所有 NetworkIdentity
// 3. 客户端加载相同场景后，会自动收到这些对象的 Spawn 消息

// 关键：不需要手动调用 NetworkServer.Spawn 来 Spawn 场景对象
// Mirror 的 NetworkManager 在 OnStartServer 中自动处理：
public class MyNetworkManager : NetworkManager
{
    public override void OnStartServer()
    {
        base.OnStartServer();
        // base.OnStartServer() 内部会：
        // 1. 扫描场景中所有带 NetworkIdentity 的对象
        // 2. 为它们分配 netId
        // 3. Spawn 它们到所有客户端
        // 4. 触发 OnStartServer 回调
    }
}
关键约束：服务器和客户端必须加载完全相同的场景。 如果服务器加载了 Scene_A，而客户端加载了 Scene_B，那么 Scene_A 中的预置对象 在客户端上不存在——会导致严重的状态不一致。

4.6.2 场景切换的正确方式

// ❌ 错误：直接切换场景——Mirror 无法同步
SceneManager.LoadScene("Arena");

// ✅ 正确：通过 NetworkManager 切换场景
// ServerChangeScene 是 NetworkManager 的静态方法
NetworkManager.ServerChangeScene("Arena");

// Mirror 内部会：
// 1. 调用 OnServerChangeScene 回调
// 2. 向所有客户端发送 ChangeScene 消息
// 3. 旧场景中的非持久对象被清理
// 4. 新场景被加载到所有客户端
// 5. 新场景中的预置 NetworkIdentity 被自动 Spawn
// 6. Player 对象在新场景中重新生成
// 7. 调用 OnServerSceneChanged / OnClientSceneChanged 回调

4.7 对象池与 Spawn 性能优化

频繁地 Instantiate / Destroy 网络对象会产生 GC 压力。使用对象池可以显著改善性能。 Mirror 96 推荐使用自定义 Spawn/Unspawn 处理器实现对象池：

// 服务器端：对象池管理器
public class NetworkObjectPool : NetworkBehaviour
{
    [SerializeField] GameObject bulletPrefab;
    [SerializeField] int poolSize = 50;
    Queue<GameObject> pool = new Queue<GameObject>();

    public override void OnStartServer()
    {
        base.OnStartServer();

        // 预创建对象池
        for (int i = 0; i < poolSize; i++)
        {
            GameObject bullet = Instantiate(bulletPrefab);
            bullet.SetActive(false);
            pool.Enqueue(bullet);
        }

        // 注册自定义 Spawn/Unspawn 处理器
        NetworkClient.RegisterPrefab(bulletPrefab, SpawnBullet, UnspawnBullet);
    }

    // 客户端收到 Spawn 消息时调用
    GameObject SpawnBullet(Vector3 position, Quaternion rotation, uint assetId)
    {
        GameObject bullet = pool.Count > 0 ? pool.Dequeue() : Instantiate(bulletPrefab);
        bullet.transform.SetPositionAndRotation(position, rotation);
        bullet.SetActive(true);
        return bullet;
    }

    // 客户端收到 Destroy 消息时调用
    void UnspawnBullet(GameObject bullet)
    {
        bullet.SetActive(false);
        pool.Enqueue(bullet);
    }
}

// 服务器端使用：
public class WeaponSystem : NetworkBehaviour
{
    public void FireBullet(Vector3 position, Vector3 direction)
    {
        // 从池中获取并 Spawn
        GameObject bullet = Instantiate(bulletPrefab, position, Quaternion.identity);
        NetworkServer.Spawn(bullet);  // 客户端会调用 SpawnBullet 处理器

        // 子弹飞行逻辑...
        // 销毁时：
        NetworkServer.Destroy(bullet);  // 客户端会调用 UnspawnBullet 处理器（返回池而非销毁）
    }
}
对象池的关键：使用自定义 Unspawn 处理器， 当 NetworkServer.Destroy() 被调用时，客户端不是真正 Destroy 对象， 而是将其返回到池中。下次 Spawn 时从池中取出复用。这避免了频繁的 Instantiate/Destroy。

4.8 网络对象的生命周期

每个网络对象从 Spawn 到 Destroy 都会经历一系列生命周期回调。理解这些回调的调用时机至关重要：

回调方法调用端调用时机
OnStartServer()服务器对象在服务器上 Spawn 后
OnStartClient()客户端对象在客户端上 Spawn 后（所有客户端）
OnStartAuthority()拥有者客户端客户端获得控制权时
OnStopAuthority()拥有者客户端客户端失去控制权时
OnStartLocalPlayer()本地客户端对象被设为本地玩家的 Player 时
OnStopServer()服务器对象在服务器上销毁前
OnStopClient()客户端对象在客户端上销毁前
 
public class NetworkedObject : NetworkBehaviour
{
    // 服务器端初始化
    public override void OnStartServer()
    {
        base.OnStartServer();
        // 此时 isServer == true，netId 已分配
        InitializeServerState();
    }

    // 客户端端初始化
    public override void OnStartClient()
    {
        base.OnStartClient();
        // 此时 isClient == true，SyncVar 初始值已同步
        InitializeClientVisuals();
    }

    // 获得控制权时
    public override void OnStartAuthority()
    {
        base.OnStartAuthority();
        // 此时 isOwned == true
        EnableLocalControl();
    }

    // 被设为本地玩家时
    public override void OnStartLocalPlayer()
    {
        base.OnStartLocalPlayer();
        // 此时 isLocalPlayer == true
        // 适合：绑定摄像机、启用输入控制、初始化 HUD
        CameraController.Instance.Follow(transform);
    }

    // 服务器端销毁前
    public override void OnStopServer()
    {
        base.OnStopServer();
        // 清理服务器端资源
    }

    // 客户端端销毁前
    public override void OnStopClient()
    {
        base.OnStopClient();
        // 清理客户端表现（取消摄像机跟随等）
        CleanupVisuals();
    }
}

4.9 常见 Spawn 陷阱

陷阱 1：在客户端 Spawn 了服务器不认可的对象

// ❌ 客户端自己 Spawn 的对象，服务器不知道
void SpawnEnemyLocally()
{
    Instantiate(enemyPrefab, position, rotation);
    // 服务器没有收到任何 Spawn 请求——这个对象只对本地可见
    // 其他客户端看不到，服务器也无法对它调用 RPC
}

// ✅ 通过 Command 请求服务器 Spawn
[Command]
void CmdSpawnEnemy(Vector3 position)
{
    // 这段代码在服务器上运行
    GameObject enemy = Instantiate(enemyPrefab, position, rotation);
    NetworkServer.Spawn(enemy);
}

陷阱 2：重复 Spawn 同一个对象

// ❌ 没有检查是否已 Spawn
NetworkServer.Spawn(obj);
NetworkServer.Spawn(obj);  // 第二次调用会跳过（netId 已分配）

// ✅ 检查后再 Spawn
if (netIdentity.isSpawned == false)  // Mirror 96 提供 isSpawned 标志
{
    NetworkServer.Spawn(obj);
}

陷阱 3：Prefab 未注册导致 Spawn 失败

// ❌ 在服务器上 Spawn 了未注册的 Prefab
GameObject enemy = Instantiate(enemyPrefab, pos, rot);
NetworkServer.Spawn(enemy);
// 服务器上正常，但客户端收到 SpawnMessage 时找不到匹配的 Prefab
// Console 输出警告："Spawn failed: prefab hash not found"

// ✅ 确保所有可 Spawn 的 Prefab 都已注册
// 1. 在 NetworkManager 的 Spawnable Prefabs 列表中添加
// 2. 或在 OnStartServer 中调用 NetworkClient.RegisterPrefab

4.10 调试 Spawn 问题

// 列出服务器上所有 Spawn 的对象
void DebugPrintServerSpawned()
{
    foreach (var kvp in NetworkServer.spawned)
    {
        Debug.Log($"[Server Spawned] netId={kvp.Key} name={kvp.Value.name} " +
                  $"isServer={kvp.Value.isServer}");
    }
}

// 列出客户端上所有 Spawn 的对象
void DebugPrintClientSpawned()
{
    foreach (var kvp in NetworkClient.spawned)
    {
        Debug.Log($"[Client Spawned] netId={kvp.Key} name={kvp.Value.name} " +
                  $"isClient={kvp.Value.isClient}");
    }
}

// 检查某个 netId 是否存在
bool IsSpawned(uint netId)
{
    return NetworkClient.spawned.ContainsKey(netId);
}
Mirror 96 Spawn 调试要点：
  • NetworkServer.spawned 是 Dictionary<uint, NetworkIdentity>——键是 netId
  • NetworkClient.spawned 同理，在客户端上使用
  • 如果客户端找不到 Prefab，检查是否通过 NetworkClient.RegisterPrefab 或 NetworkManager 列表注册
  • 如果 Command 不执行，检查对象的 isOwned 和 requiresAuthority 设置

{

    e.GetComponent<HealthSystem>().health = 500;
    // 忘记调用 NetworkServer.Spawn(e)!
}
  3. Mirror 96 变化题：旧代码使用了 ClientScene.RegisterPrefab(enemyPrefab) 和 identity.AssignAuthority(conn)。 在 Mirror 96 中应该怎么修改？
参考答案：
1) 默认情况下不能。重连后的客户端是"全新"的连接， 服务器需要将所有已 Spawn 对象的 SpawnMessage 重新发给这个客户端。 可以通过在 OnServerConnect 中手动遍历 NetworkServer.spawned 并发送 SpawnMessage 来实现重连恢复。Mirror 没有内置的一键重连恢复 API。

2) 对象只在服务器内存中存在，不会同步给任何客户端。 而且 HealthSystem 的 health SyncVar 变更也不会被同步。 必须调用 NetworkServer.Spawn(e)。

3) 两处需要修改：① ClientScene.RegisterPrefab → NetworkClient.RegisterPrefab（ClientScene 已合并入 NetworkClient）； ② AssignAuthority(conn) → AssignClientAuthority(conn) （方法名已更新）。
