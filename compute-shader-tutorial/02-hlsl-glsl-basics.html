HLSL/GLSL 语言基础

Compute Shader 用 HLSL（DirectX）或 GLSL（OpenGL/Vulkan）编写。本章不追求全面覆盖语言规范——那是参考手册的工作。我们聚焦于 Compute Shader 特有的语法、类型和语义，以及 HLSL 和 GLSL 的关键差异。

Shader Model 版本演进

HLSL 的版本由 Shader Model (SM) 定义，每个 SM 版本带来新的语言和运行时能力：

Shader Model发布年份Compute Shader 能力关键特性
SM 5.0 2010 (DX11) CS 5.0 初始 Compute Shader 支持，numthreads 最多 768 线程
SM 5.1 2012 (DX11.1) CS 5.1 3D Thread Group，DispatchIndirect， UAV 计数器
SM 6.0 2016 (DX12) CS 6.0 WaveOps，Memory Model，Inline HLSL，Root Constants
SM 6.1 2017 (Vulkan 1.1) CS 6.1 Primitive Shader，Mesh Shader 前置
SM 6.2 2018 (DX12 Ultimate) CS 6.2 Wave Shuffle，Sampler Feedback，Raytracing
SM 6.5+ 2020+ CS 6.5+ Mesh Shader，Amplification Shader，Enhanced Barriers
本教程默认使用 SM 6.0+（DX12）。SM 6.0 引入了 [shader(…)] 注解风格取代旧的 #: hlsl_bytecode 风格，并增加了 Wave-level 原语和 Memory Model 限定符，这些是现代 Compute Shader 的最佳实践。

Compute Shader 声明

一个 Compute Shader 函数的声明包含三个要素：

// SM 6.0+ 风格（DX12 推荐）
[numthreads(8, 8, 1)]          // 线程组大小
[shader("compute")]             // 着色器类型
void CSMain(uint3 threadID : SV_DispatchThreadID)
{
    // 计算逻辑
}

三个要素的含义：

  • [numthreads(x, y, z)]：每个 Thread Group 包含 x * y * z 个线程。上限：总数 ≤ 1024，单个维度 ≤ 1024，且受 Driver 限制（Windows 通常 x+y+z 维度乘积上限 1024）
  • [shader("compute")]：告诉编译器这是一个 Compute Shader，不是 Vertex/Fragment/Pipeline Shader
  • void CSMain(…)：入口函数，名称随意（但 CSMain 是惯例），参数必须是内置语义类型

数据类型

标量类型

// 整数类型（有符号/无符号）
int i;           // 32-bit signed
uint u;          // 32-bit unsigned
int8_t s8;       // 8-bit signed (SM 6.2+)
uint8_t u8;      // 8-bit unsigned (SM 6.2+)
int16_t s16;     // 16-bit signed (SM 6.2+)
uint16_t u16;    // 16-bit unsigned (SM 6.2+)

// 浮点类型
float f;         // 32-bit IEEE 754
half h;          // 16-bit floating point
min16float mf;   // 最小化 16-bit float (编译器可能用 16/20/32 bit)
min16int mi;     // 最小化 16-bit int
min16uint mu;    // 最小化 16-bit uint

// 布尔（实际以 uint 存储）
bool b;

向量类型

HLSL 的向量类型是 float2、float3、float4 等。它们对应 GLSL 的 vec2、vec3、vec4。

float3 position = float3(1.0, 2.0, 3.0);
float4 color = float4(1.0, 0.5, 0.25, 1.0);

// 组件访问
color.r = 1.0;     // red
color.g = 0.5;     // green
color.b = 0.25;    // blue
color.a = 1.0;     // alpha
color.x = 1.0;     // 也可以用 xyzw
color.w = 1.0;

//  Swizzle（重排组件）
float2 xy = color.xy;
float3 bgra = color.bgra;
float2 ww = float2(color.w, color.w);  // 重复分量
float3 的对齐陷阱：在 Structured Buffer 或 cbuffer 中，float3 按 float4 对齐。也就是说 float3 占用 16 字节而非 12 字节。这会导致结构体偏移计算出错。

解决方案：用 cbuffer 时手动加 padding，或用 rowmajor 矩阵 + 显式 packoffset，或直接改用 float4。

矩阵类型

HLSL 矩阵默认是列优先（column-major），这是与 GLSL 最大的区别之一：

// HLSL: 列优先，m[col][row]
float4x4 m = float4x4(
    1, 0, 0, 0,   // 第 0 列
    0, 1, 0, 0,   // 第 1 列
    0, 0, 1, 0,   // 第 2 列
    0, 0, 0, 1    // 第 3 列
);

// 访问第 i 列第 j 行
float val = m[j][i];  // 注意行列反转！

// 显式指定行优先（与 GLSL 一致）
row_major float4x4 rowMajorMat = ...;

内置变量与语义

Compute Shader 有特定的内置输入语义，用于获取线程位置和组信息：

HLSLGLSL (Vulkan)含义范围
SV_DispatchThreadID gl_GlobalInvocationID 全局线程 ID [0, Dispatch×numthreads)
SV_GroupThreadID gl_LocalInvocationID 组内线程 ID [0, numthreads)
SV_GroupID gl_WorkGroupID 组 ID [0, Dispatch)
SV_GroupIndex gl_LocalInvocationIndex 组内线性索引 [0, numthreads-1]
SV_DispatchThreadID gl_DrawID (间接) 间接 Dispatch 支持 N/A

资源绑定类型

Compute Shader 可以读写三种核心资源：

2.1 Structured Buffer（通用缓冲区）

// 只读（类似 GPU 端的 const）
cbuffer PerObject : register(b0) {
    float4x4 worldViewProj;
    float3 cameraPos;
    int particleCount;
};

// 只读结构化缓冲
StructuredBuffer positions : register(t0);
StructuredBuffer velocities : register(t1);

// 读写结构化缓冲（Unordered Access View）
RWStructuredBuffer newPositions : register(u0);
RWStructuredBuffer lifetimes : register(u1);

// 原子计数器
RWByteAddressBuffer counters : register(u2);

2.2 Texture UAV/SRV（纹理资源）

// 只读纹理采样
Texture2D inputTexture : register(t2);
SamplerState bilinearSampler : register(s0);

// 可写纹理（UAV）— Compute Shader 的核心优势
RWTexture2D outputTexture : register(u3);

// 直接采样（SRV）
float4 color = inputTexture.Sample(bilinearSampler, uv);

// 直接写入（UAV）— 无插值，随机访问
outputTexture[int2(x, y)] = float4(1.0, 0.0, 0.0, 1.0);

// 原子操作（SM 5.0+）
outputTexture[int2(x, y)].r += 1.0;  // 注意：这不一定原子！
// 要用 InterlockedAdd 做真正的原子操作：
uint oldVal;
InterlockedAdd(uavCounter, 1u, oldVal);
纹理写入不是原子的：多个线程同时写入同一个 texel 的结果是未定义的。如果需要原子累加，使用 AppendStructuredBuffer 或在主机端用 DispatchIndirect 做同步。对于需要原子操作的场景，考虑用 RWTexture2D<uint> + InterlockedAdd。

内置函数精选

HLSL 内置了大量数学函数。以下是 Compute Shader 中最常用的：

// 向量数学
float dot(float3 a, float3 b);
float3 cross(float3 a, float3 b);
float length(float3 v);
float3 normalize(float3 v);
float3 lerp(float3 a, float3 b, float t);
float3 saturate(float3 x);        // clamp(x, 0, 1)
float3 clamp(float3 x, float3 min, float3 max);
float3 step(float edge, float3 x); // x < edge ? 0 : 1
float3 smoothstep(float a, float b, float3 x);

// 位操作（SM 6.0+）
uint countbits(uint v);       // 统计 1 的位数
uint firstbit低位(uint v);    // 最低位 1 的位置
uint mul24(uint a, uint b);   // 24 位乘法（节省寄存器和带宽）

// Warp 级原语（SM 6.0+）
uint waveActiveCountBits(bool pred);
uint waveActiveAllEqual(bool pred);
float waveReadLaneAt(float val, int lane);

// 原子操作
void InterlockedAdd(RWStructuredBuffer<uint> buf, uint index, uint value, out uint result);
void InterlockedAnd(RWStructuredBuffer<uint> buf, uint index, uint value, out uint result);
void InterlockedMax(RWStructuredBuffer<uint> buf, uint index, uint value, out uint result);
void InterlockedMin(RWStructuredBuffer<uint> buf, uint index, uint value, out uint result);
void InterlockedOr(RWStructuredBuffer<uint> buf, uint index, uint value, out uint result);
bool InterlockedCompareExchange(RWStructuredBuffer<uint> buf, uint index, uint compareValue, inout uint value, out uint result);

HLSL vs GLSL 关键差异

// HLSL 声明资源
StructuredBuffer<float3>> positions : register(t0);
RWStructuredBuffer<float3> output : register(u0);
Texture2D<float4> tex : register(t1);
SamplerState samp : register(s0);

// 线程 ID
void CSMain(uint3 tid : SV_DispatchThreadID) {}

// 屏障
GroupMemoryBarrierWithGroupSync();
// GLSL 声明资源
layout(set = 0, binding = 0, r32ui) uniform uimageBuffer positions;
layout(set = 0, binding = 1, r32f) uniform imageBuffer output;
layout(set = 0, binding = 2) uniform sampler texSampler;

// 线程 ID
layout(local_size_x = 8, local_size_y = 8, local_size_z = 1) in;

void main() {
    ivec3 tid = ivec3(gl_GlobalInvocationID);
}

// 屏障
memoryBarrier();
barrier();  // GLSL 中 barrier() = GroupMemoryBarrierWithGroupSync + 更多

差异总结

特性HLSLGLSL
线程组声明[numthreads(8,8,1)] 注解layout(local_size_x=8, ...) in;
资源绑定注册表位置 (:register(t0))Set + Binding (layout(set=0, binding=0))
矩阵布局列优先（默认）列优先
向量组件.rgba 和 .xyzw 混用只有 .rgba（GLSL 4.40+ 支持 .xyzw）
纹理采样tex.Sample(sampler, uv)texture(sampler, uv)
屏障GroupMemoryBarrierWithGroupSync()barrier()（等同于全部屏障+同步）
精度修饰min16float 等类型precision mediump/high/low
原子操作InterlockedXXX()atomicAdd() 等
学习策略：如果你主要用 DX12，专注 HLSL 就够了。如果同时支持 Vulkan，理解 GLSL 差异有助于跨平台移植。大多数 Compute Shader 概念在两种语言间是等价的，差异主要在语法层面。

精度修饰符

GPU 在不同精度下执行运算的代价不同。理解精度选择对性能至关重要：

精度HLSL 类型位数用途相对速度
Fullfloat32矩阵运算、物理模拟、需要高精度的场景基准
Mediummin16float16/20颜色处理、UV 坐标、一般中间计算1-2x（取决于 GPU）
Lowhalf16粒子位置（低精度够用）、批量数据2-4x

但要注意：精度不是免费的。在 SM 6.0+ 之前，min16float 需要在硬件上做提升（promote to float → 计算 → demote back），某些 GPU 上这可能反而更慢。SM 6.2+ 有了原生 16-bit ALU，精度优势才能真正发挥。

实用建议：先用 float 保证正确性，Profiling 发现瓶颈后再尝试降精度。不要过早优化精度。

编译与调试

HLSL 代码需要通过 dxc（DirectX Shader Compiler）编译为 .cso（Compiled Shader Object）：

# 编译 Compute Shader
dxc -T cs_6_0 myshader.hlsl -Fo myshader.cso

# 带调试信息
dxc -T cs_6_0 myshader.hlsl -Zi -Fo myshader.pdb

# 开启详细警告
dxc -T cs_6_0 myshader.hlsl -WarnOnAll -Fo myshader.cso

# 指定目标平台
dxc -T cs_6_5 myshader.hlsl -DVARIABLE_DEFINE -Fo myshader.cso

本章小结

  • Compute Shader 用 [numthreads] + [shader("compute")] 声明
  • 核心数据类型：float/int/uint/half，向量 float2-4，矩阵 float4x4
  • 资源分三类：只读 Buffer/Texture、可写 UAV Buffer/Texture、常量 Buffer
  • HLSL 列优先矩阵，GLSL 也是列优先——两者在此处一致
  • 原子操作用 InterlockedXXX（HLSL）或 atomicXXX（GLSL）
  • 精度修饰是优化手段，不是银弹——先正确再优化
