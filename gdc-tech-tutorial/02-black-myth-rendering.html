02 - 黑神话：悟空 — 渲染与性能优化

Game Science 团队基于 UE5 进行了大量深度定制，从 Niagara 毛发系统到 China Lake 流送改造，每一处都是针对中国古典美学和大规模战斗场景的特殊优化。本章将深入拆解这些技术决策背后的思考过程。

前置知识：UE5 基础、Niagara 粒子系统、PBR 材质原理、基本的 GPU 架构知识

一、Game Science 引擎架构概述

《黑神话：悟空》虽然基于 Unreal Engine 5 构建，但 Game Science 对其底层架构做了大量定制。他们并没有直接使用"开箱即用"的 UE5，而是围绕自身需求重新组织了渲染管线和资源管理系统。

为什么不完全自研引擎？

Game Science 在 GDC 讲座中坦诚地讨论了技术选型决策。团队的核心考量包括：

  1. 时间成本：自研引擎需要 3-5 年才能达到 UE5 的生产力水平
  2. 人才密度：引擎程序员培养周期长，团队更擅长内容创作
  3. 风险分散：基于成熟引擎可以将精力集中在游戏性上
  4. 定制化空间：UE5 提供了足够的修改接口
关键洞察：Game Science 的策略是"在引擎框架内做最大程度的定制"，而非推翻重来。这种策略使他们能够在 4 年内交付一款画面达到 3A 水准的作品。

二、Niagara 毛发渲染系统

毛发渲染是《黑神话：悟空》最具视觉冲击力的技术亮点之一。游戏中的角色（包括主角和各类妖王）拥有大量高质量的毛发效果，从悟空的猴毛到各种妖怪的鬃毛、尾巴。

技术选型：GPU 实例化 + 自定义 Niagara 模块

传统的毛发渲染方案有几种：Shader-based（顶点偏移）、Geometry Shader、Tessellation、GPU Compute。Game Science 选择了 GPU 实例化为主、Compute Shader 辅助的方案。

GPU 实例化（GPU Instancing）

将相同几何体的多个实例合并为单次 Draw Call，通过 GPU 在顶点着色器中实例化数据来渲染。对于毛发这种大量细长的几何体，每次 Draw Call 可以处理成千上万根毛发。

毛发的物理模拟

每根毛发不是静态的，而是带有简单的物理模拟——风场影响、角色运动惯性、碰撞检测。Game Science 实现了以下策略：

1

分层 LOD 策略

根据摄像机距离将毛发分为三个层级：

  • LOD0（近距离，< 2m）：每根毛发独立模拟，使用 16 段分段物理，支持风场交互
  • LOD1（中距离，2-8m）：每根毛发 4 段分段，简化风场计算
  • LOD2（远距离，> 8m）：合并为单一 Mesh 变形，不做物理模拟
2

风场系统

使用简化的 Perlin Noise 生成全局风场，每个毛发实例在 GPU 上采样风场值并施加位移。

3

碰撞简化

毛发碰撞不使用精确网格检测，而是用球体近似角色身体，减少碰撞检测开销。

自定义 Niagara 毛发模块

以下是 Game Science 定制的 Niagara 毛发发射器模块核心逻辑：

// HairPhysicsModule.cpp - Niagara 自定义物理模块
// 在 GPU 端运行，每帧更新毛发顶点位置

struct HairInstanceData
{
    float3  RootPosition;     // 毛发根部在世界空间的位置
    float3  RootNormal;       // 根部法线方向
    float   Length;           // 毛发长度
    int     Segments;         // 分段数（LOD 决定）
    float   Thickness;        // 毛发粗细
    float   WindMultiplier;   // 风力系数
};

struct HairVertexData
{
    float3 Position;          // 当前顶点世界坐标
    float3 Tangent;           // 切线方向
    float  BendResistance;    // 弯曲阻力
};

// GPU 端的毛发物理模拟
[numthreads(64, 1, 1)]
void MainCS(uint3 ThreadID : SV_DispatchThreadID)
{
    uint instanceIndex = ThreadID.x / MaxSegmentsPerHair;
    uint segmentIndex  = ThreadID.x % MaxSegmentsPerHair;

    HairInstanceData hair = GetHairInstance(instanceIndex);
    if (segmentIndex >= hair.Segments) return;

    // 计算当前段的比例位置 (0.0 ~ 1.0)
    float t = (float)(segmentIndex + 1) / (float)hair.Segments;

    // 基础位置：根部 + 法线方向 * 长度 * t
    float3 position = hair.RootPosition + hair.RootNormal * hair.Length * t;

    // 风场影响：采样全局风场
    float3 wind = SampleWindField(position + WorldTime * WindSpeed);
    position += wind * hair.WindMultiplier * t * t; // 末端效应更强

    // 重力影响
    position += float3(0, -1, 0) * gravityStrength * t * t;

    // 碰撞检测：简化球体碰撞
    float3 bodyCenter = GetCharacterBodyCenter();
    float dist = distance(position, bodyCenter);
    if (dist < hair.Thickness + BodyRadius)
    {
        float3 toSurface = normalize(position - bodyCenter);
        position = bodyCenter + toSurface * (BodyRadius + hair.Thickness);
    }

    // 写入更新后的位置
    SetHairVertexPosition(instanceIndex, segmentIndex, position);
}

三、大规模场景流送系统

《黑神话：悟空》的世界由多个大型区域组成——从花果山到小西天，每个区域都包含复杂的建筑、地形和植被。China Lake 流送系统（UE5 默认的 World Partition）经过了大量定制。

China Lake 改造要点

World Partition 基础原理

UE5 的 World Partition 系统将世界划分为规则的 Cell（默认 1024x1024 单位），根据摄像机位置动态加载/卸载 Cell 中的数据。China Lake 是底层的数据流送管理器。

Game Science 的主要改造包括：

  1. 非规则 Cell 划分：根据关卡重要性调整 Cell 大小，重要区域（Boss 战场景）使用更小的 Cell 以获得更高的细节精度
  2. 预取策略优化：基于摄像机速度和方向预测下一步需要加载的区域，提前启动异步加载
  3. 资源优先级队列：为不同类型的资源设置不同的加载优先级（角色模型 > 环境模型 > 植被 > 装饰物）
  4. 内存预算控制：PS5 版本严格限制在 14GB 可用内存内，通过动态卸载远处资源实现

异步加载管线

// StreamingManager.cpp - 自定义流送管理器
class StreamingManager
{
public:
    void Update(float DeltaTime)
    {
        // 1. 计算当前需要的 Cell 集合
        auto requiredCells = ComputeVisibleCells(CameraPosition, CameraFrustum);

        // 2. 对比当前已加载的 Cell，确定需要加载/卸载的
        auto toLoad = FindCellsToLoad(requiredCells, loadedCells);
        auto toUnload = FindCellsToUnload(requiredCells, loadedCells);

        // 3. 按优先级排序
        SortByPriority(toLoad);
        SortByPriority(toUnload);

        // 4. 异步提交加载请求
        for (auto& cell : toLoad)
        {
            if (MemoryBudgetAvailable(cell.EstimatedSize))
            {
                AsyncLoadCell(cell.ID);
            }
            else
            {
                // 内存不足时，先卸载最低优先级的 Cell
                auto victim = FindLowestPriorityLoadedCell();
                UnloadCell(victim.ID);
                AsyncLoadCell(cell.ID);
            }
        }

        // 5. 卸载不再需要的 Cell（延迟执行，避免频繁切换）
        for (auto& cell : toUnload)
        {
            if (cell.LastAccessTime > UnloadDelayThreshold)
            {
                ScheduleCellUnload(cell.ID);
            }
        }
    }

private:
    bool MemoryBudgetAvailable(uint64 size)
    {
        // PS5: 14GB 硬限制，PC: 根据显存动态调整
        return (currentUsedMemory + size) < GetMemoryBudget();
    }

    uint64 GetMemoryBudget()
    {
#ifdef PLATFORM_PS5
        return 14ULL * 1024 * 1024 * 1024; // 14GB
#else
        return GetGPUMemorySize() * 0.85;   // PC: 使用 85% 显存
#endif
    }
};

四、CPU/GPU 平衡策略

《黑神话：悟空》的战斗系统非常复杂——主角的棍法有 4 套连招系统，每套最多 12 种招式，加上敌人的 AI 决策、物理模拟、特效触发，CPU 负载很高。Game Science 采用了以下策略来平衡 CPU 和 GPU 的负载。

Gameplay 线程与渲染线程分离

┌─────────────────────────────────────────────────┐ │ CPU (多核) │ │ │ │ ┌──────────────┐ ┌──────────────┐ │ │ │ Gameplay 线程 │ │ 渲染主线程 │ │ │ │ (AI/物理/输入) │───▶│ (命令录制) │ │ │ └──────────────┘ └──────┬───────┘ │ │ │ │ │ ┌──────────────┐ ┐ ▼ ┌────────────┐ │ │ │ Job System │ │ GPU │ 渲染命令队列 │ │ │ │ (并行任务分发) │◀───┘ └────────────┘ │ │ └──────────────┘ │ │ │ │ Job 队列: │ │ [AI决策] [物理模拟] [动画更新] [特效更新] [资源流送] │ └─────────────────────────────────────────────────┘

Game Science 将 UE5 的 Task Graph 系统扩展为更细粒度的 Job System，每个 Job 有明确的依赖关系和执行优先级：

// JobSystem.cpp - 游戏内 Job 调度
void CombatFrameUpdate(float DeltaTime)
{
    // 创建 Job 依赖图
    FGraphEventRef AIJob = FFunctionGraphTask::CreateAndDispatchWhenReady(
        []() { UpdateEnemyAI(); },
        TStatId(),
        nullptr,
        ENamedThreads::GameThread
    );

    FGraphEventRef PhysicsJob = FFunctionGraphTask::CreateAndDispatchWhenReady(
        []() { SimulateCombatPhysics(); },
        TStatId(),
        nullptr,
        ENamedThreads::GameThread
    );

    // 等待 AI 和物理完成后更新动画
    FFunctionGraphTask::CreateAndDispatchWhenReady(
        [AIJob, PhysicsJob]()
        {
            UpdateAnimationBlending(AIJob, PhysicsJob);
        },
        TStatId(),
        { AIJob, PhysicsJob },
        ENamedThreads::GameThread
    );
}

渲染线程优化

渲染线程的主要瓶颈在于 Command Buffer 的构建。Game Science 通过以下方式减少渲染线程的压力：

  1. 延迟渲染命令录制：将部分渲染决策（如哪些物体可见）提前到 Gameplay 线程完成
  2. GPU 驱动渲染：利用 DX12 的 Indirect Draw 和 Dispatch 减少 CPU 端 Draw Call 准备
  3. 渲染批次合并：将同材质的物体合并为大的 Draw Call，减少状态切换

五、三级 LOD 系统

《黑神话：悟空》实现了几何 LOD、材质 LOD、特效 LOD 三个维度的 LOD 系统，形成了一套立体的细节管理方案。

几何 LOD（Geometric LOD）

使用 UE5 的 Static Mesh LOD 系统，但做了大量定制：

  • 每个角色模型有 5 级几何 LOD（0-4），Boss 角色甚至做到 7 级
  • LOD0 使用 Nanite（如果硬件支持），否则使用传统 LOD 网格
  • LOD 切换使用混合过渡（HLOD Blend），避免 popping 现象
  • 自定义 LOD 距离曲线，根据角色在屏幕上的像素尺寸而非距离来决定

材质 LOD（Material LOD）

LOD 级别材质特性适用距离
MatLOD0完整 PBR，含 SSS、次表面散射、各向异性< 5m
MatLOD1去掉 SSS，保留基础 PBR5-15m
MatLOD2简化为 Diffuse + Roughness/Metallic15-40m
MatLOD3纯 Diffuse 贴图，无光照计算> 40m

特效 LOD（VFX LOD）

特效（Niagara 粒子系统）的 LOD 是最容易被忽视但影响最大的部分：

// VFXLODManager.cpp - 特效 LOD 控制器
class VFXLODManager
{
    enum class VFXQualityLevel
    {
        High,    // PC 高端 / 近景特写
        Medium,  // PC 中端 / 常规视角
        Low,     // PS5 标准 / 移动端

    {

        bool EnableCollisions;   // 是否启用碰撞

    {

        {

                     .EnablePhysics = false, .EnableCollisions = false,

六、光照方案：Lumen 混合策略

《黑神话：悟空》的光照方案是混合式的——既不完全依赖实时 GI，也不完全烘焙。这是因为游戏需要在不同光照条件下保持一致的画面质量，同时又要支持动态效果（如火焰、闪电、法术光效）。

光照分层架构

┌─────────────────────────────────────────────────┐ │ 光照系统分层 │ │ │ │ Layer 0: 动态光源（火焰、法术、武器发光） │ │ └─ 实时阴影 + 实时间接照明（Lumen 快速路径） │ │ │ │ Layer 1: 环境光（天空盒、环境反射） │ │ └─ 静态环境光 + 动态环境捕捉 │ │ │ │ Layer 2: 烘焙 GI（静态场景） │ │ └─ Lightmass 预计算 + 光照探针（Light Probes） │ │ │ │ Layer 3: 屏幕空间反射（SSR） │ │ └─ 水面、金属表面的实时反射 │ │ │ │ Layer 4: 后处理泛光（Bloom） │ │ └─ 基于亮度的全屏后处理 │ └─────────────────────────────────────────────────┘

关键决策点：

  • 静态建筑使用烘焙光照（Lightmass），质量高且零运行时开销
  • 动态光源（如火把、法术）使用 Lumen 的快速 GI 路径
  • 角色使用混合方案：面部 SSS + 身体 PBR，光照来自最近的动态光源 + 环境光
  • Boss 战的特殊光照效果使用自定义 Shader 实现

批量合并策略

Game Science 实现了自定义的 Batch Manager，将具有相同材质的物体自动合并：

// BatchManager.cpp - 自动批量合并
void BatchManager::ProcessFrame()
{
    // 1. 收集所有可见物体的材质信息
    struct MaterialBatchKey
    {
        uint64 MaterialHash;
        uint64 TextureSetHash;
        int    LODLevel;
        bool   bIsTransparent;
        bool   operator==(const MaterialBatchKey& Other) const
        {
            return MaterialHash == Other.MaterialHash &&
                   TextureSetHash == Other.TextureSetHash &&
                   LODLevel == Other.LODLevel &&
                   bIsTransparent == Other.bIsTransparent;
        }
    };

    // 2. 按材质键分组
    TMap<MaterialBatchKey, TArray<MeshInstance*>> Batches;
    for (auto& Mesh : VisibleMeshes)
    {
        MaterialBatchKey Key = ComputeBatchKey(Mesh);
        Batches.FindOrAdd(Key).Add(Mesh);
    }

    // 3. 对每个批次进行 GPU Instancing 绘制
    for (auto& Pair : Batches)
    {
        if (Pair.Value.Num() > 1)
        {
            // 合并为单次 Instanced Draw
            DrawInstancedMesh(Pair.Key, Pair.Value);
        }
        else
        {
            // 单独绘制
            DrawSingleMesh(Pair.Value[0]);
        }
    }
}

本章小结

《黑神话：悟空》的技术成功不在于某一项突破性的创新，而在于对 UE5 框架下每个子系统的精细调优。Game Science 团队证明了：在成熟引擎的基础上，通过深度定制和优化，同样可以达到世界一流的画面水平和性能表现。

核心经验总结：

  1. 毛发渲染：GPU 实例化 + 自定义 Niagara 模块 + 三层 LOD 是性价比最高的方案
  2. 场景流送：China Lake 改造的核心是预取策略和内存预算控制
  3. CPU/GPU 平衡：Job System 的细粒度任务调度是解决 CPU 瓶颈的关键
  4. 三级 LOD：几何 + 材质 + 特效的立体 LOD 体系比单一 LOD 更有效
  5. 混合光照：烘焙 + 实时的混合方案在画面质量和性能之间取得了最佳平衡
