第 7 章：权威服务器与客户端权限

这是单机开发者转联机时最难跨越的思维障碍。 在单机游戏中，你的代码说"玩家移动到那里"，玩家就到了那里。 在网络游戏中，你的代码说"玩家想移动到那里"——但最终决定权在服务器手里， 服务器可能说"不行，你不可能这么快"。理解并实践"服务器权威"模型，是联网开发的分水岭。

Mirror 96 API 更新
本章已全面适配 Mirror 96.x。主要变化包括： hasAuthority → isOwned； Authority API 使用 AssignClientAuthority / RemoveClientAuthority（非 AssignAuthority / GrantAuthority / RevokeAuthority）； FindObjectById → NetworkServer.spawned.TryGetValue(netId, out var identity)； 断开连接使用 conn.Disconnect()（非 NetworkServer.RemoveConnection）。

7.1 为什么需要权威服务器？

先想一个场景：你在开发一个平台跳跃游戏。玩家在单机模式下按空格跳跃，角色腾空而起。

// 单机版：简单直接
void Update()
{
    if (Input.GetKeyDown(KeyCode.Space))
    {
        rigidbody.velocity = Vector3.up * jumpForce;
    }
}

现在联网了。如果同样的代码跑在客户端上：

  • 玩家可以修改内存，把 jumpForce 从 10 改成 1000
  • 玩家可以拦截网络包，把自己的位置从 (5, 0, 0) 改成 (5, 50, 0)（飞天）
  • 玩家可以重放"跳跃"消息 100 次/秒，实现悬浮
核心原则：永远不要信任客户端。
这不是"防备某个特定玩家"，而是"防备所有玩家"。 任何运行客户端代码的人都有能力修改、拦截、重放你的数据。 这是客观事实，不是道德判断。

7.2 服务器权威模型的三种级别

7.2.1 完全权威（Fully Authoritative）— 推荐

服务器拥有全部真相。客户端只做两件事：收集输入和播放表现。

public class PlayerController : NetworkBehaviour
{
    [SerializeField] float maxSpeed = 10f;

    void Update()
    {
        // ❌ 绝对不要在客户端直接修改网络状态
        // transform.position += direction;  // 危险！

        // ✅ 正确：只收集输入，发送给服务器
        if (isLocalPlayer)  // isLocalPlayer 已隐含 isOwned
        {
            Vector2 input = new Vector2(
                Input.GetAxis("Horizontal"),
                Input.GetAxis("Vertical")
            );
            CmdSendInput(input, Time.time);
        }
    }

    [Command]
    void CmdSendInput(Vector2 input, float timestamp)
    {
        // 服务器收到输入后验证并执行
        ProcessInput(input, timestamp);
    }

    void ProcessInput(Vector2 input, float timestamp)
    {
        // 验证 1：输入范围是否合法
        if (input.magnitude > 1.01f) return;

        // 验证 2：时间戳是否合理（不能是未来时间）
        if (timestamp > Time.time) return;

        // 服务器端执行移动
        Vector3 move = new Vector3(input.x, 0, input.y) * maxSpeed * Time.deltaTime;
        transform.position += move;

        // 位置同步由 NetworkTransform 自动处理
        // 或使用 SyncVar + hook 手动同步
    }
}
简化方案：使用 NetworkTransform
在实际项目中，位置同步通常使用 NetworkTransform 组件。 客户端在本地移动（isOwned 为 true 时），NetworkTransform 自动将位置同步给服务器和其他客户端。 服务器可以通过 SyncVar 或 Command 验证来限制移动速度。

7.2.2 部分权威（Client Authority）

某些对象的所有权可以交给客户端。但"所有权"不等于"不受验证"：

// 场景：NPC 跟随玩家
// NPC 的位置更新由绑定它的客户端负责（减少 RPC 开销）
// 但服务器仍然验证 NPC 的速度是否合理

public class NPCTracker : NetworkBehaviour
{
    public Transform target;
    [SerializeField] float speed = 3f;
    Vector3 serverPosition;
    float lastReportTime;

    [Server]
    void Start()
    {
        // 将 NPC 的 Authority 授予绑定它的客户端
        // Mirror 96 使用 AssignClientAuthority
        NetworkIdentity identity = GetComponent<NetworkIdentity>();
        identity.AssignClientAuthority(connectionToClient);
        serverPosition = transform.position;
    }

    // 拥有 isOwned 的客户端可以驱动这个 NPC
    void Update()
    {
        if (isOwned && target != null)
        {
            transform.position = Vector3.MoveTowards(
                transform.position, target.position, speed * Time.deltaTime
            );

            // 即使有 isOwned，也应该定期向服务器报告位置
            if (Time.time - lastReportTime > 0.1f)
            {
                CmdReportPosition(transform.position);
                lastReportTime = Time.time;
            }
        }
    }

    [Command]
    void CmdReportPosition(Vector3 pos)
    {
        // 服务器验证：这个移动速度是否合理？
        float distance = Vector3.Distance(serverPosition, pos);
        float maxAllowed = speed * 0.1f + 0.5f;  // 允许一些误差

        if (distance > maxAllowed)
        {
            Debug.LogWarning($"[反作弊] NPC 速度异常: {distance / 0.1f:F1} m/s");
            transform.position = serverPosition;  // 回滚
            return;
        }

        serverPosition = pos;
        // 位置同步由 NetworkTransform 处理
    }
}

7.2.3 无权威（No Authority）— 纯观察对象

有些网络对象只用于视觉表现，不需要任何人控制：

// 场景：地图上的装饰物、特效粒子、静态陷阱
// 这些对象 Spawn 后由服务器完全管理，客户端只负责渲染

public class Trap : NetworkBehaviour
{
    [SerializeField] int damage = 20;
    [SerializeField] GameObject trapEffect;

    // [ServerCallback]：只在服务器执行，不打印警告
    [ServerCallback]
    void OnTriggerEnter(Collider other)
    {
        // 服务器端碰撞检测
        if (other.TryGetComponent<NetworkIdentity>(out var targetIdentity))
        {
            if (targetIdentity.TryGetComponent<HealthSystem>(out var hs))
            {
                hs.TakeDamage(damage);
                RpcTriggerEffect(transform.position);
            }
        }
    }

    [ClientRpc]
    void RpcTriggerEffect(Vector3 pos)
    {
        // 客户端只播放特效
        Instantiate(trapEffect, pos, Quaternion.identity);
    }
}

7.3 Client Authority 详解

Client Authority 不是"让客户端为所欲为"，而是"让最合适的机器做决策"。

7.3.1 什么时候给客户端 Authority？

场景建议原因
Player 角色✅ 自动拥有Player 对象 Spawn 时自动获得 Authority
NPC 跟随 Player✅ 可分配减少 RPC 频率，但需服务器验证
可拾取物品❌ 不给物品不应该被"控制"
载具/载具上的乘客⚠️ 视情况载具本身服务器权威，乘客同步位置
投射物（子弹）⚠️ 视情况高精度游戏服务器权威，低精度可客户端预测

7.3.2 获取和释放 Authority

// 服务器转移 Authority
public class AuthorityManager : NetworkBehaviour
{
    [Command]
    public void CmdRequestAuthority(uint targetNetId)
    {
        // 通过 netId 查找对象
        if (NetworkServer.spawned.TryGetValue(targetNetId, out var identity))
        {
            // 检查请求者是否有资格获得 Authority
            if (identity.connectionToClient == null)  // 当前无人拥有
            {
                // Mirror 96 的 Authority API
                identity.AssignClientAuthority(connectionToClient);
                // 客户端上 isOwned 变为 true
                // 触发 OnStartAuthority 回调
            }
            else
            {
                Debug.LogWarning("该对象已被其他客户端拥有");
            }
        }
    }

    // 释放 Authority（服务器端调用）
    [Server]
    public void ReleaseAuthority(uint targetNetId)
    {
        if (NetworkServer.spawned.TryGetValue(targetNetId, out var identity))
        {
            // Mirror 96 的移除 Authority API
            identity.RemoveClientAuthority();
            // 客户端上 isOwned 变为 false
            // 触发 OnStopAuthority 回调
        }
    }
}
Mirror 96 Authority API 变化
旧版 Mirror 使用 AssignAuthority / GrantAuthority / RevokeAuthority 等方法名。

Mirror 96 统一为：
  • NetworkIdentity.AssignClientAuthority(NetworkConnection conn) — 分配控制权
  • NetworkIdentity.RemoveClientAuthority() — 移除控制权
所有 Authority 方法都在 NetworkIdentity 上，且只能在服务器端调用。 客户端感知 Authority 变化通过 isOwned 属性（旧版 hasAuthority）和 OnStartAuthority / OnStopAuthority 回调。

7.4 常见作弊手段与防御策略

7.4.1 速度作弊

// 作弊方式：客户端发送超快的移动速度
// 防御：服务器验证移动速度

public class MovementValidator : NetworkBehaviour
{
    [SerializeField] float maxSpeed = 10f;
    Vector3 lastPosition;
    float lastUpdateTime;

    [Command]
    void CmdUpdatePosition(Vector3 newPos, float timestamp)
    {
        float dt = timestamp - lastUpdateTime;
        if (dt <= 0)
        {
            Debug.LogWarning("时间戳异常");
            return;
        }

        float distance = Vector3.Distance(transform.position, newPos);
        float actualSpeed = distance / dt;

        if (actualSpeed > maxSpeed * 1.5f)  // 允许 50% 的余量
        {
            Debug.LogWarning($"[速度作弊检测] 玩家速度: {actualSpeed:F1} m/s (上限: {maxSpeed})");
            // 选项 1: 回滚位置
            transform.position = lastPosition;
            return;
        }

        lastPosition = transform.position;
        lastUpdateTime = timestamp;
        transform.position = newPos;
    }
}

7.4.2 传送作弊

// 作弊方式：客户端直接设置位置到远处
// 防御：验证位移距离

[Command]
void CmdTeleport(Vector3 targetPos)
{
    float distance = Vector3.Distance(transform.position, targetPos);
    float maxTeleportDistance = 5f;  // 允许的最大传送距离

    if (distance > maxTeleportDistance)
    {
        Debug.LogWarning($"[传送作弊检测] 距离: {distance:F1}m");
        return;
    }

    transform.position = targetPos;
}

7.4.3 伤害注入

// 作弊方式：客户端发送虚假的"我打中了你"消息
// 防御：服务器自己计算命中判定

[Command]
void CmdReportHit(uint targetNetId, Vector3 hitPoint)
{
    // ❌ 错误做法：相信客户端说的"我打中了 netId=X 的对象"
    // if (NetworkServer.spawned.TryGetValue(targetNetId, out var target))
    // {
    //     target.GetComponent<HealthSystem>().TakeDamage(damage);
    // }

    // ✅ 正确做法：服务器自己做射线检测
    Vector3 shootOrigin = transform.position + Vector3.up * 1.5f;
    Vector3 shootDirection = (hitPoint - shootOrigin).normalized;

    if (Physics.Raycast(shootOrigin, shootDirection, out RaycastHit hit, weaponRange))
    {
        if (hit.collider.TryGetComponent<NetworkIdentity>(out var targetIdentity))
        {
            if (targetIdentity.TryGetComponent<HealthSystem>(out var hs))
            {
                hs.TakeDamage(CalculateDamage(hit));
            }
        }
    }
}

7.4.4 重复消息攻击（Replay Attack）

// 作弊方式：客户端反复发送相同的"使用药水"消息
// 防御：序列号 + 去重

public class AntiReplay : NetworkBehaviour
{
    HashSet<int> processedCommands = new HashSet<int>();
    int lastSequence = 0;

    [Command]
    void CmdUseItem(int sequence, int itemId)
    {
        // 检查序列号是否过时
        if (sequence <= lastSequence - 100)
        {
            Debug.LogWarning("过时命令，忽略");
            return;
        }

        // 检查是否已处理过
        if (processedCommands.Contains(sequence))
        {
            Debug.LogWarning("重复命令，忽略");
            return;
        }

        processedCommands.Add(sequence);
        lastSequence = sequence;

        // 清理历史记录
        if (processedCommands.Count > 200)
        {
            processedCommands.RemoveWhere(s => s <= lastSequence - 100);
        }

        // 执行命令
        UseItem(itemId);
    }
}

7.4.5 输入频率作弊

// 作弊方式：客户端以 1000 次/秒的频率发送"攻击"命令
// 防御：服务端限速

public class RateLimiter : NetworkBehaviour
{
    [SerializeField] int maxCommandsPerSecond = 30;
    Queue<float> commandTimes = new Queue<float>();

    [Command]
    void CmdAttack()
    {
        float now = Time.time;

        // 清理超过 1 秒的记录
        while (commandTimes.Count > 0 && commandTimes.Peek() < now - 1f)
        {
            commandTimes.Dequeue();
        }

        // 检查频率
        if (commandTimes.Count >= maxCommandsPerSecond)
        {
            Debug.LogWarning($"输入频率过高: {commandTimes.Count} 次/秒");
            // 持续违规可踢出
            // connectionToClient.Disconnect();
            return;
        }

        commandTimes.Enqueue(now);
        PerformAttack();
    }
}

7.5 服务器验证的粒度

验证太松 → 容易被作弊。验证太紧 → 正常玩家也可能被误判。
找到平衡点需要理解网络的本质：延迟是不可避免的。

public class ValidationTuner : NetworkBehaviour
{
    [SerializeField] float maxSpeed = 10f;

    float GetRTT()
    {
        // Mirror 96 中，NetworkConnection 有 rtt 属性（如果 Transport 支持）
        // rtt 是往返延迟时间（Round-Trip Time），单位毫秒
        if (connectionToClient != null)
            return connectionToClient.rtt;
        return 0f;
    }

    float CalculateAcceptableMoveDistance()
    {
        float rttSeconds = GetRTT() / 1000f;  // 转为秒
        // 允许的位移 = 最大速度 × (更新时间 + 往返延迟)
        // 给网络延迟留余量
        return maxSpeed * (0.1f + rttSeconds);
    }

    [Command]
    void CmdUpdatePosition(Vector3 newPos)
    {
        float maxDist = CalculateAcceptableMoveDistance();
        float actualDist = Vector3.Distance(transform.position, newPos);

        if (actualDist > maxDist)
        {
            // 根据当前网络状况，这个位移不可接受
            Debug.LogWarning($"位移过大: {actualDist:F2}m (允许 {maxDist:F2}m)");
            return;
        }

        transform.position = newPos;
    }
}
验证容差的黄金法则：
  • 验证阈值应该动态调整——基于当前网络延迟
  • 高延迟玩家需要更大的容差
  • 使用累积违规而非单次违规来判定作弊
  • 宁可放过一些边界作弊，也不要误判正常玩家

7.6 本章小结

概念Mirror 96 API要点
服务器权威 [Command] + isServer 所有游戏逻辑在服务器执行，客户端只发请求
对象控制权 isOwned（旧 hasAuthority） 表示本地客户端是否拥有此对象
分配控制权 identity.AssignClientAuthority(conn) 服务器端调用，分配对象控制权给客户端
移除控制权 identity.RemoveClientAuthority() 服务器端调用，回收对象控制权
连接断开 conn.Disconnect() 踢出特定客户端

  3. Mirror 96 变化题：旧代码使用了 
    if (hasAuthority)
    MovePlayer();
identity.AssignAuthority(conn);
    在 Mirror 96 中应该怎么修改？
参考答案：
1) 复活请求应该由队友发起 CmdRequestResurrect(targetNetId)， 服务器验证：① 请求者是否在复活范围内 ② 目标是否真的死亡 ③ 复活技能是否在冷却中 ④ 目标是否在同一场景。全部通过才执行复活。

2) 缺少距离验证——任何人都可以拾取远处的物品。 应添加：if (Vector3.Distance(transform.position, identity.transform.position) > pickupRange) return; 还缺少频率限制——应该防止快速拾取攻击。

3) 两处修改：① hasAuthority → isOwned； ② AssignAuthority(conn) → AssignClientAuthority(conn)。
