15 模组生态、DLC 导读与逆向实战

Rain World 的模组系统有一个核心设计：官方 DLC 与第三方模组走完全相同的加载管线，DLC 只是“预装且受信任的模组”。本章先讲模组的发现、应用与钩子机制，再说明 DLC 如何复用这套体系，最后落到如何阅读与利用这份反编译工程的逆向实战。

15.1 模组架构总览

flowchart TD
    A["mods 目录 + Steam 创意工坊"] --> B["RefreshModsLists：读取 modinfo.json"]
    B --> C["ApplyModsThread（后台线程）"]
    C --> D["版本化资源合并 / DLL 加载"]
    D --> E["MonoMod 运行时钩子"]
    E --> F["RainWorld.OnModsInit 入口"]
    F --> G["模组逻辑生效"]

15.2 模组元数据：Mod 与 modinfo.json

每个模组由一个 Mod 对象描述，字段来自其目录下的 modinfo.json：

public class Mod
{
    public string id = "Unknown";
    public string name = "Unknown";
    public string version = "";
    public string targetGameVersion = "v1.11.6";
    public string authors = "Unknown";
    public string description = "No Description.";
    public string[] requirements = new string[0];
    public int loadOrder;
    public bool enabled;
    public string checksum = "";
    public bool workshopMod;
    public ulong workshopId;
    public bool hasDLL;
}

requirements 声明依赖的其他模组，loadOrder 决定应用顺序，checksum 用于检测文件是否被改动。模组发现同时扫描本地 mods 目录与 Steam 创意工坊的订阅安装目录，并按 id 去重。

15.3 模组应用：后台线程与版本文件夹

应用过程在独立后台线程执行，强制使用 en-US 文化，避免数字与路径解析受系统区域影响：

private void ApplyModsThread()
{
    CultureInfo.CurrentCulture = CultureInfo.GetCultureInfoByIetfLanguageTag("en-US");
    try
    {
        // 版本化文件夹：优先精确版本，其次 newest，再到根目录
        string[] candidates = new string[] {
            path + "\\v1.11.6\\modify\\world",
            path + "\\v1.11.6\\world",
            path + "\\newest\\modify\\world",
            path + "\\modify\\world",
            path + "\\world"
        };
        if (ModFolderHasDLLContent(InstalledMods[i].path))
        {
            if (pendingEnabled[i] && !InstalledMods[i].enabled)
                assembliesToLoad.Add(Path.GetFileName(InstalledMods[i].path));
        }
        InstalledMods[i].enabled = pendingEnabled[i];
    }
    catch (Exception e)
    {
        // 记录失败并触发回退，而不是让整个游戏崩溃
    }
}

这种“按版本号取目录 + newest 兜底”的结构，让同一模组可以为不同游戏版本提供不同资源，升级游戏后旧模组仍有兼容路径。

15.4 钩子机制：MonoMod RuntimeDetour

模组不修改游戏原始程序集，而是在运行时用 MonoMod 对方法打补丁（detour）。工程引用了 MonoMod.RuntimeDetour 与生成的 HOOKS-Assembly-CSharp，提供两类访问：

  • On. 命名空间：方法级拦截，可在原方法前后插入逻辑，通过 orig 委托决定是否、如何调用原方法。
  • Hook. 命名空间 / HookGen：事件风格的钩子，多个模组可同时订阅同一方法。

生成的委托类型以 orig_（原方法签名）与 hook_（含 orig 参数）命名。一个典型的 On 钩子结构如下：

// 模组在初始化时注册：拦截 Player.Update
On.Player.Update += (orig, self, eu) =>
{
    // 原方法执行前的自定义逻辑
    try
    {
        orig(self, eu);                 // 调用原始实现
    }
    catch (Exception ex)
    {
        Custom.LogWarning("Hook 中调用原方法失败: " + ex.Message);
        throw;                          // 不吞掉异常，避免掩盖真实错误
    }
    // 原方法执行后的自定义逻辑
};

orig 必须被正确处理：跳过 orig 会完全替换原方法行为，多个模组叠加时容易冲突。除非有意覆盖，否则应调用 orig 并原样传递参数。ModManager 还专门包装了钩子，对“未能调用 orig”的情况记录警告。

15.5 模组入口点

RainWorld 提供一组静态事件作为模组生命周期入口，ModManager 通过钩子包装它们：

RainWorld.PreModsInit;      // 模组初始化前
RainWorld.OnModsInit;       // 模组初始化主入口（注册钩子、枚举）
RainWorld.OnModsDisabled;   // 模组被禁用时清理
RainWorld.LoadResources;    // 资源加载
RainWorld.UnloadResources;  // 资源卸载

模组 DLL 的入口通常在 OnModsInit 阶段完成所有钩子注册与 ExtEnum 注册，在 OnModsDisabled 时解绑，保证禁用后不残留对已卸载程序集的引用。

15.6 ExtEnum：运行时可扩展枚举

大量“类型”都用 ExtEnum 而非普通枚举（SoundID、SlugcatStats.Name、BodyModeIndex、各种 Type）。它在运行时维护全局条目表，模组可注册新值：

public abstract class ExtEnum : ExtEnumBase, IEquatable where T : class
{
    public static ExtEnumType values;
    public ExtEnum(string value, bool register = false)
    {
        if (values.entries.Contains(value))
            index = values.entries.IndexOf(value);
        else if (register)
        {
            values.AddEntry(value);     // 新值注册进全局表
            index = values.Count - 1;
        }
        else
            index = -1;
    }
}

这使模组能新增声音、角色、对象类型、生物品种而不触碰游戏源码，是整套可扩展性的底层基石。

15.7 DLC 即模组：标志与共享能力

ModManager 用静态布尔标志记录哪些内容处于启用状态，DLC 与第三方模组用同一套字段：

public static bool MSC;          // MoreSlugcats
public static bool MMF;          // MoreSlugcats.MMF
public static bool Watcher;
public static bool Expedition;
public static bool JollyCoop;
public static bool CoopAvailable;
public static bool DevTools;

public static bool DLCShared
{
    get { return MSC || Watcher; }   // 两大 DLC 共享的能力
}

在 ApplyModsThread 中，DLC 通过其 MOD_ID（如 MoreSlugcats.MMF.MOD_ID、Watcher.MOD_ID）被识别并置位，与识别一个普通模组没有本质区别。代码里大量出现的 if (ModManager.MSC && ...)、if (ModManager.Watcher && ...) 就是在读取这些模组开关，按启用内容走不同分支。

15.8 容错与回退

模组可能出错，系统为此准备了多层保护：

public enum ModApplyFallbackStep
{
    None,
    PreviousEnabled,   // 回退到上一次可用的启用配置
    Vanilla            // 全部禁用，回到原版
}
public static Dictionary> ProblematicAssemblies
    = new Dictionary>();
  • 有问题的程序集记入 ProblematicAssemblies，应用失败时按 PreviousEnabled → Vanilla 逐级回退。
  • checksumChanged 检测文件被改动，DLCMissing 阻止依赖缺失的模组启用。
  • 后台线程的异常被捕获并转化为可提示的错误，而不是拖垮主线程。

15.9 逆向实战：如何读这份反编译工程

这份工程是用 ILSpy/dnSpy 一类工具从托管 DLL 反编译得到的 C# 源码，能编译但带有反编译特征。结合前 14 章，建议按以下方法阅读。

阅读顺序（自顶向下）

flowchart LR
    A["RainWorld / ProcessManager"] --> B["MainLoopProcess"]
    B --> C["RainWorldGame / World"]
    C --> D["Abstract* 抽象层"]
    D --> E["Room / PhysicalObject"]
    E --> F["Creature / AI / PathFinder"]
    F --> G["Player / Graphics / Mod"]

定位技巧

  • 先抓继承树再抓 Update：每个类先看它继承谁、字段有哪些，再看构造与 Update，能快速建立“它在管线里的位置”。
  • 用类规模判断核心度：Player（约 1.4 万行）、Room（约 1 万行）、ModManager（约 4 千行）是核心，小类（PathfinderResourceDivider 53 行、IDrawable 12 行）往往是关键接口/工具。
  • 顺着双向引用跳：realizedObject ↔ abstractPhysicalObject、BodyChunk ↔ PhysicalObject、AI ↔ Creature，是理解双层世界的导航线。
  • 看 ExtEnum 静态实例：一个类型系统的全部取值，直接看类内静态字段即可列全。

反编译代码的注意事项

展开：反编译产物的典型特征
  • 变量名可能是 num、text、num2 这类泛化名字，需结合用法推断含义。
  • switch/字符串拼接、yield、lambda 可能被还原成带状态机或额外类的等价写法，与原始手写代码结构略有出入。
  • 工程文件里的 HintPath 是原构建机器的绝对路径（如 D:\SteamLibrary\...），换机器需重新引用，不能直接编译。
  • unsafe 代码、Burst/Mathematics、MonoMod 生成的钩子程序集，要结合对应库一起理解。

做模组的最小工作流

  1. 在本工程中定位目标方法（如 Player.Update、某生物的 AI.Update），确认其签名与 orig 委托。
  2. 在独立模组工程中引用游戏程序集与 HookGen 程序集，于 OnModsInit 注册 On./Hook. 钩子。
  3. 需要新类型时用 ExtEnum 注册新值，需要新角色时提供 SlugcatStats 而非改 Player。
  4. 在 OnModsDisabled 中解绑，打包为 mods 目录下带 modinfo.json 的模组，由游戏原有管线加载。

15.11 常见陷阱

陷阱一：直接修改游戏原始程序集

应使用 MonoMod 运行时钩子，改原程序集会破坏校验、无法与其他模组共存，且升级即失效。

陷阱二：模组禁用后不解绑钩子/枚举

残留引用会指向已卸载程序集导致报错。必须在 OnModsDisabled 中完整清理。

陷阱三：多个钩子都不调用 orig

链式替换会让原方法行为被覆盖、模组互相冲突。应保留 orig 调用，仅在确需替换时跳过。

本章小结

  • 模组经发现、后台应用、MonoMod 钩子与生命周期入口生效，DLC 与第三方模组共用同一管线。
  • ExtEnum 支持运行时扩展类型，容错机制按 PreviousEnabled → Vanilla 回退。
  • 阅读反编译工程应自顶向下、先继承树后 Update，并注意反编译特征与失效的 HintPath。

全教程总结

贯穿 Rain World 的几条主线：固定 40FPS 的时间累加器与插值渲染；抽象/现实双层世界与双向转换；自研弹簧质点物理；组合式生物与模板、确定性人格；效用 AI 与分帧预算寻路；输入驱动的玩家状态机；以及让一切可扩展的 ExtEnum、IDrawable 与 MonoMod。理解了这些，你既能读懂这份源码，也具备了在此基础上制作模组的完整认知。建议从 index.html 回看目录，按自己的兴趣深入对应章节。
