第 5 章：数据同步 — SyncList 与自定义消息

SyncVar 能同步单个值，但真实项目中你需要同步列表、字典、复杂数据结构。 Mirror 提供了 SyncList 来处理集合类型，也提供了自定义 NetworkMessage 来支持灵活的消息设计。 本章将深入这两个主题。

Mirror 96 API 更新
本章已全面适配 Mirror 96.x。主要变化包括： SyncList 改为泛型 SyncList<T>（移除了 SyncListInt / SyncListString 等专用类型）； SyncList 回调改为事件驱动（OnAdd / OnInsert / OnSet / OnRemoveAt / OnClear）； 操作枚举改为 OP_ADD / OP_INSERT / OP_SET / OP_REMOVEAT / OP_CLEAR； 自定义消息从 MessageBase（class）改为 NetworkMessage（struct 接口）。

5.1 SyncList：同步集合数据

SyncList<T> 是 Mirror 提供的同步集合类型。 它可以同步任何可序列化类型的列表，并且支持自定义结构体。

SyncList 的核心特性

• 服务器修改后自动同步到所有客户端
• 支持事件回调（元素增删改时触发）
• 泛型设计：SyncList<int>、SyncList<string>、SyncList<MyStruct>
• 支持自定义结构体作为元素类型
• 只能在 NetworkBehaviour 中使用

5.1.1 基本用法

using Mirror;

public class InventorySystem : NetworkBehaviour
{
    // Mirror 96 使用泛型 SyncList<T>
    public SyncList<string> itemNames = new SyncList<string>();
    public SyncList<int> teamHealths = new SyncList<int>();

    public override void OnStartServer()
    {
        base.OnStartServer();
        // 服务器端初始化
        itemNames.Add("铁剑");
        itemNames.Add("护甲");
        itemNames.Add("药水");
    }

    public override void OnStartClient()
    {
        base.OnStartClient();

        // 注册事件回调——在客户端收到同步变更时触发
        // Mirror 96 使用事件（Event）而非旧的 Callback 属性
        itemNames.OnAdd += OnItemAdded;
        itemNames.OnSet += OnItemChanged;
        itemNames.OnRemoveAt += OnItemRemoved;
        itemNames.OnClear += OnItemsCleared;
    }

    void OnItemAdded(int index, string newItem)
    {
        Debug.Log($"新增物品: {newItem} 在索引 {index}");
        RefreshInventoryUI();
    }

    void OnItemChanged(int index, string oldItem, string newItem)
    {
        Debug.Log($"物品变更: 索引 {index} 从 {oldItem} 变为 {newItem}");
        RefreshInventoryUI();
    }

    void OnItemRemoved(int index, string oldItem)
    {
        Debug.Log($"移除物品: {oldItem} 在索引 {index}");
        RefreshInventoryUI();
    }

    void OnItemsCleared()
    {
        Debug.Log("物品列表已清空");
        RefreshInventoryUI();
    }

    void RefreshInventoryUI()
    {
        // 遍历 SyncList（和普通 List 一样）
        for (int i = 0; i < itemNames.Count; i++)
        {
            Debug.Log($"  格子 {i}: {itemNames[i]}");
        }
    }
}
Mirror 96 SyncList API 变化
旧版 Mirror 使用专用类型：SyncListInt、SyncListString、SyncListFloat 等， 以及 Callback 属性和 Operation 枚举（OP_ADD、OP_DIRTY 等）。

Mirror 96 改为：
  • 泛型：SyncList<T> 支持任意可序列化类型
  • 事件驱动：OnAdd、OnInsert、OnSet、OnRemoveAt、OnClear
  • 操作枚举：OP_ADD、OP_INSERT、OP_SET、OP_REMOVEAT、OP_CLEAR

5.1.2 使用自定义结构体作为 SyncList 元素

Mirror 96 的泛型设计让你可以同步自定义结构体——这在旧版中是不可能的：

// 定义可序列化的结构体
public struct ItemSlot : INetworkMessage
{
    public int itemId;
    public int count;
    public bool isEquipped;

    public ItemSlot(int id, int cnt, bool equipped)
    {
        itemId = id;
        count = cnt;
        isEquipped = equipped;
    }
}

public class PlayerInventory : NetworkBehaviour
{
    // 同步装备栏——元素是自定义结构体
    public SyncList<ItemSlot> equipment = new SyncList<ItemSlot>();

    public override void OnStartClient()
    {
        base.OnStartClient();
        equipment.OnAdd += (index, slot) =>
        {
            Debug.Log($"装备栏 {index}: 物品 {slot.itemId} x{slot.count}");
        };
        equipment.OnSet += (index, oldSlot, newSlot) =>
        {
            Debug.Log($"装备栏 {index} 变更: {oldSlot.itemId} → {newSlot.itemId}");
        };
    }

    // 服务器端操作
    [Server]
    public void EquipItem(int slotIndex, int itemId, int count)
    {
        if (slotIndex < 0 || slotIndex >= equipment.Count) return;
        // 直接修改元素——自动触发同步
        equipment[slotIndex] = new ItemSlot(itemId, count, true);
    }

    [Server]
    public void AddItem(int itemId, int count)
    {
        equipment.Add(new ItemSlot(itemId, count, false));
    }

    [Server]
    public void RemoveItemAt(int index)
    {
        if (index >= 0 && index < equipment.Count)
            equipment.RemoveAt(index);
    }
}

5.1.3 SyncList 的操作与事件

操作方法事件回调回调参数说明
Add(item)OnAdd(int index, T newItem)末尾添加元素
Insert(index, item)OnInsert(int index, T newItem)指定位置插入
this[index] = itemOnSet(int index, T oldItem, T newItem)替换指定位置元素
RemoveAt(index)OnRemoveAt(int index, T oldItem)移除指定位置元素
Clear()OnClear()（无参数）清空列表
性能警告：每次 Add / Remove / Insert 都会触发同步。如果你在循环中逐个添加 100 个物品，会触发 100 次同步事件。 虽然Mirror会在同一帧内合并网络消息，但事件回调会触发 100 次。 考虑在批量操作时暂时取消注册事件，操作完成后再重新注册。

5.1.4 其他同步集合类型

除了 SyncList<T>，Mirror 96 还提供了其他同步集合：

类型说明典型用途
SyncList<T>同步列表背包、排行榜、玩家列表
SyncHashSet<T>同步集合（唯一元素）已解锁成就、已发现区域
SyncDictionary<K,V>同步字典键值映射、配置表
 
// SyncDictionary 示例
public class ScoreBoard : NetworkBehaviour
{
    public SyncDictionary<string, int> playerScores = new SyncDictionary<string, int>();

    public override void OnStartClient()
    {
        base.OnStartClient();
        playerScores.OnAdd += (key, value) => Debug.Log($"新增分数: {key} = {value}");
        playerScores.OnSet += (key, oldValue, newValue) => Debug.Log($"分数变更: {key} {oldValue} → {newValue}");
        playerScores.OnRemove += (key, oldValue) => Debug.Log($"移除分数: {key}");
    }

    [Server]
    public void UpdateScore(string playerName, int score)
    {
        if (playerScores.ContainsKey(playerName))
            playerScores[playerName] = score;  // 触发 OnSet
        else
            playerScores[playerName] = score;  // 触发 OnAdd
    }
}

5.2 自定义 NetworkMessage

当 SyncVar / SyncList 不够用时，你可以定义完全自定义的消息结构。 自定义消息适合一次性事件通知，而非持续状态同步。

5.2.1 消息的定义

在 Mirror 96 中，自定义消息是结构体（struct），需实现 INetworkMessage 接口 （或旧版的 NetworkMessage 接口）。Mirror 的 Weaver 会自动生成序列化代码。

using Mirror;
using UnityEngine;

// Mirror 96 的消息定义：struct + INetworkMessage
// Weaver 会自动生成序列化/反序列化代码
public struct PlayerMoveMessage : INetworkMessage
{
    public Vector3 position;
    public Vector3 rotation;
    public float timestamp;       // 用于预测/插值
    public int sequenceNumber;    // 用于排序和去重
}

public struct CombatReportMessage : INetworkMessage
{
    public uint attackerNetId;
    public uint targetNetId;
    public int damage;
    public Vector3 hitPosition;
    public DamageType damageType;  // 自定义 enum
}

public enum DamageType
{
    Physical,
    Magic,
    True,
    Burst
}
Mirror 96 消息定义变化
旧版使用 class XXXMessage : MessageBase（引用类型，需手动实现 Serialize/Deserialize）。
Mirror 96 改为 struct XXXMessage : INetworkMessage（值类型，Weaver 自动生成序列化）。 优点：
  • 值类型避免了 GC 压力
  • 无需手写序列化代码
  • Mirror 的 Weaver 会在编译时自动生成高效的序列化逻辑

5.2.2 注册与发送消息

public class GameServer : NetworkBehaviour
{
    public override void OnStartServer()
    {
        base.OnStartServer();
        // 服务器端注册消息处理器
        // Mirror 96 的处理器签名：(NetworkConnectionToClient conn, T message)
        NetworkServer.RegisterHandler<PlayerMoveMessage>(OnPlayerMove);
        NetworkServer.RegisterHandler<CombatReportMessage>(OnCombatReport);
    }

    // 服务器端消息处理器
    void OnPlayerMove(NetworkConnectionToClient conn, PlayerMoveMessage msg)
    {
        if (conn == null) return;

        // 通过 conn 查找对应的 Player 对象
        if (conn.identity == null) return;

        // 验证合理性（防作弊）
        Vector3 expectedPos = conn.identity.transform.position;
        float maxSpeed = conn.identity.GetComponent<PlayerController>().moveSpeed;
        float maxDist = maxSpeed * 0.5f;

        if ((msg.position - expectedPos).sqrMagnitude > maxDist * maxDist)
        {
            Debug.LogWarning($"[反作弊] 连接 {conn.connectionId} 位置异常");
            return;
        }

        // 应用移动
        conn.identity.transform.position = msg.position;

        // 广播给其他客户端（通过 TargetRpc 或 ClientRpc）
        // 或使用 NetworkServer.SendToAll
        foreach (var kvp in NetworkServer.connections)
        {
            if (kvp.Value != conn)  // 不回发给发送者
            {
                kvp.Value.Send(new PlayerMoveMessage
                {
                    position = msg.position,
                    rotation = msg.rotation,
                    timestamp = msg.timestamp,
                    sequenceNumber = msg.sequenceNumber
                });
            }
        }
    }

    // 服务器向特定客户端发送消息
    void SendCombatReportToClient(NetworkConnection client, CombatReport report)
    {
        client.Send(new CombatReportMessage
        {
            attackerNetId = report.attacker.netId,
            targetNetId = report.target.netId,
            damage = report.damage,
            hitPosition = report.hitPosition,
            damageType = report.type
        });
    }
}

5.2.3 客户端注册与发送

public class GameClient : NetworkBehaviour
{
    public override void OnStartClient()
    {
        base.OnStartClient();
        // 客户端注册消息处理器
        // 注意：客户端处理器签名只需要消息参数（不需要 NetworkConnection）
        NetworkClient.RegisterHandler<CombatReportMessage>(OnCombatReport);
        NetworkClient.RegisterHandler<PlayerMoveMessage>(OnOtherPlayerMove);
    }

    void OnCombatReport(CombatReportMessage msg)
    {
        // 显示伤害数字、播放命中特效
        ShowDamageNumber(msg.targetNetId, msg.damage, msg.hitPosition);
    }

    void OnOtherPlayerMove(PlayerMoveMessage msg)
    {
        // 更新其他玩家的位置（用于插值）
        UpdateRemotePlayerPosition(msg);
    }

    // 客户端发送自定义消息给服务器
    void SendMoveCommand(Vector3 pos, Vector3 rot)
    {
        NetworkClient.connection.Send(new PlayerMoveMessage
        {
            position = pos,
            rotation = rot,
            timestamp = Time.time,
            sequenceNumber = ++moveSequence
        });
    }

    int moveSequence = 0;
}
处理器签名差异：
• 服务器端处理器：void Handler(NetworkConnectionToClient conn, T msg)——有连接参数
• 客户端处理器：void Handler(T msg)——无连接参数

这是因为客户端不需要知道消息来自哪个连接（消息只来自服务器）， 而服务器需要知道消息来自哪个客户端连接。

5.3 消息设计最佳实践

5.3.1 小消息优先

每条网络消息都有头部开销（约 4-8 字节）。消息越小、越精简，带宽利用率越高：

// ❌ 浪费：发送了整个 Transform 数据
public struct BadMoveMessage : INetworkMessage
{
    public float x, y, z;        // 12 bytes
    public float rx, ry, rz, rw; // 16 bytes
    public float scaleX, scaleY, scaleZ; // 12 bytes
    public int animationState;   // 4 bytes
    public float sprintMultiplier; // 4 bytes
    // 总共 ~48 字节
}

// ✅ 精简：只发送必要的差分数据
public struct EfficientMoveMessage : INetworkMessage
{
    public int sequence;      // 4 bytes
    public short posX, posZ;  // 4 bytes（缩放 100 倍，精度 0.01m）
    public short rotY;        // 2 bytes（只需要 Y 轴旋转）
    public byte animState;    // 1 byte
    // 总共 ~11 bytes
}

5.3.2 使用固定精度而非浮点数

// ❌ float 占 4 字节，且浮点数在网络中可能有精度问题
public float positionX;

// ✅ 用 short 存储缩放后的坐标（精度 0.01 米，范围 ±327m）
public short positionX_Scaled;

// 转换函数
public static short ToNetworkFloat(float value) => (short)(value * 100f);
public static float FromNetworkShort(short value) => value / 100f;

5.3.3 消息频率控制

不同类型的消息需要不同的发送频率：

消息类型频率传输要求示例
高频位置同步每帧 30-60 次不可靠，丢帧可接受MoveMessage
技能释放每秒几次可靠，必须送达AttackMessage
聊天/系统通知偶尔可靠，有序ChatMessage
状态快照每秒 10-20 次可靠，最新覆盖SyncVar 自动处理
 
// 高频消息的频率限制示例
public class MoveSyncSystem : NetworkBehaviour
{
    float lastSendTime;
    float sendInterval = 1f / 30f;  // 每秒最多 30 次

    void Update()
    {
        if (!isOwned) return;

        if (Time.time - lastSendTime >= sendInterval)
        {
            SendMoveCommand(transform.position, transform.rotation);
            lastSendTime = Time.time;
        }
    }

    void SendMoveCommand(Vector3 pos, Vector3 rot)
    {
        NetworkClient.connection.Send(new PlayerMoveMessage
        {
            position = pos,
            rotation = rot,
            timestamp = Time.time,
            sequenceNumber = ++moveSequence
        });
    }
}

5.4 序列化与反序列化

Mirror 96 的消息序列化由 Weaver（编译时代码生成器）自动处理。 你只需定义结构体字段，Weaver 会生成高效的序列化代码。

5.4.1 Mirror 的序列化管道

C# 结构体
   │
   ▼
Weaver 生成的 Serialize()   ← 将结构体字段写入 NetworkWriter
   │
   ▼
Transport.Send(byte[])        ← 通过 KCP/UDP/WebSocket 发送
   │
   ▼
Transport.OnData(byte[])      ← 接收字节数据
   │
   ▼
Weaver 生成的 Deserialize()  ← 从 NetworkReader 读取字节到结构体
   │
   ▼
Handler(T message)            ← 业务逻辑处理

5.4.2 支持的字段类型

类型支持说明
基本类型✅int, float, bool, string, byte, long 等
Vector2/3/4✅Mirror 内置支持
Quaternion✅Mirror 内置支持
Color / Color32✅Mirror 内置支持
Enum✅序列化为底层整型
数组✅支持，注意大小
自定义 struct（含 INetworkMessage）✅嵌套消息结构
class（引用类型）❌不支持，请用 struct

5.4.3 常见序列化问题

问题症状解决方案
消息大小过大传输延迟增加拆分消息，使用量化精度
版本不一致反序列化后数据错乱确保服务器和客户端使用相同的消息结构定义
枚举值变更旧客户端解析错误枚举只追加不删除中间值

5.5 实战：设计一个消息系统

让我们为一个多人竞技游戏设计完整的消息系统：

// ==================== 消息定义 ====================

public struct MoveMessage : INetworkMessage
{
    public int sequence;
    public short inputX, inputY;  // 输入方向，缩放 1000 倍
    public float timestamp;
}

public struct AttackMessage : INetworkMessage
{
    public int weaponId;
    public short aimX, aimY, aimZ;  // 瞄准方向，量化
    public float timestamp;
}

public struct ChatMessage : INetworkMessage
{
    public string senderName;
    public string content;
    public ChatType type;  // All / Team / Whisper
}

public enum ChatType { All = 0, Team = 1, Whisper = 2 }

// ==================== 消息路由 ====================

public class MessageRouter : NetworkBehaviour
{
    public override void OnStartServer()
    {
        base.OnStartServer();
        // 注册所有消息处理器
        NetworkServer.RegisterHandler<MoveMessage>(OnMove);
        NetworkServer.RegisterHandler<AttackMessage>(OnAttack);
        NetworkServer.RegisterHandler<ChatMessage>(OnChat);
    }

    // 移动消息：高频，需要频率限制
    void OnMove(NetworkConnectionToClient conn, MoveMessage msg)
    {
        // 频率限制：每秒最多 30 条移动消息
        if (Time.time - conn.lastMoveTime < 1f / 30f) return;
        conn.lastMoveTime = Time.time;

        // 处理移动输入
        Vector2 input = new Vector2(msg.inputX / 1000f, msg.inputY / 1000f);
        ProcessPlayerInput(conn, input, msg.sequence);
    }

    // 攻击消息：中频，需要冷却限制
    void OnAttack(NetworkConnectionToClient conn, AttackMessage msg)
    {
        // 冷却限制
        if (Time.time - conn.lastAttackTime < 0.2f) return;
        conn.lastAttackTime = Time.time;

        // 执行攻击
        ExecuteAttack(conn, msg);
    }

    // 聊天消息：低频，需要内容验证
    void OnChat(NetworkConnectionToClient conn, ChatMessage msg)
    {
        // 内容过滤
        if (string.IsNullOrEmpty(msg.content)) return;
        if (msg.content.Length > 256) return;

        // 广播给所有客户端
        foreach (var kvp in NetworkServer.connections)
        {
            kvp.Value.Send(msg);
        }
    }

    void ProcessPlayerInput(NetworkConnectionToClient conn, Vector2 input, int sequence)
    {
        if (conn.identity == null) return;
        var controller = conn.identity.GetComponent<PlayerController>();
        if (controller != null)
        {
            controller.ApplyInput(input, sequence);
        }
    }

    void ExecuteAttack(NetworkConnectionToClient conn, AttackMessage msg)
    {
        if (conn.identity == null) return;
        // 攻击逻辑...
    }
}
消息 vs RPC 的选择：
• 用 RPC（[Command] / [ClientRpc]）当通信绑定在特定网络对象上—— Mirror 会自动处理对象序列化和路由。
• 用 自定义消息当通信是全局性的—— 不绑定特定对象（如聊天消息、全局事件通知、登录认证）。

大多数情况下，RPC 更简单、更安全。只在 RPC 不适用的场景才使用自定义消息。

点击展开自测题
  1. 设计题：你需要同步一个玩家的装备栏，包含 20 个格子，每个格子有物品 ID 和数量。 你会用 SyncList 还是自定义消息？如何设计？
  2. 代码找错：以下代码有什么问题？ 
    public SyncListString itemNames = new SyncListString();

void OnItemAdded(Operation op, int index, string item)
{
    Debug.Log($"新增: {item}");
}
  3. 推理题：如果服务器和客户端对同一个 enum 的定义不一致（服务器新增了值）， 会发生什么？如何避免？
  4. Mirror 96 变化题：旧代码使用了 public class MyMessage : MessageBase。 在 Mirror 96 中应该怎么修改？有什么好处？
参考答案：
1) 用 SyncList<ItemSlot>，其中 ItemSlot 是结构体 { int itemId; int count; }。SyncList 会自动同步增删改， 通过 OnSet 事件更新 UI。比自定义消息更简单——不需要手动处理序列化和注册。

2) 两个错误：① SyncListString 在 Mirror 96 中已移除， 应改为 SyncList<string>； ② Operation 枚举和 Callback 属性已被事件回调取代， 应使用 itemNames.OnAdd += (index, item) => { ... }。

3) 客户端可能将未知枚举值解析为默认值（0），导致行为异常。 避免方法：枚举只追加不修改；或在消息中加入版本号字段进行兼容性检查。

4) 应改为 public struct MyMessage : INetworkMessage。 好处：值类型避免 GC 压力；Weaver 自动生成序列化代码，无需手写 Serialize / Deserialize。
