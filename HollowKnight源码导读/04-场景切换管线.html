第 4 章　场景切换管线

场景切换是《空洞骑士》运行时最复杂的一条管线，它把异步 IO、相机淡入淡出、主角移动、对象池清理、垃圾回收全部编排进一条协程。理解它之后，全书其他子系统的调用时机几乎都能挂到这条管线的某个阶段上。

4.1 两个层次：机制类 SceneLoad 与编排类 GameManager

管线代码分两层，先把边界划清：

层次类职责
机制层SceneLoad（普通 C# 类，不是 MonoBehaviour）封装一次 additive 异步加载的八个阶段，暴露阶段事件；由外部传入的 runner 协程驱动
编排层GameManager.BeginSceneTransitionRoutine创建 SceneLoad、订阅它的事件、控制相机和主角、决定两个门控何时打开
触发层TransitionPoint（门口）等检测主角碰撞，构造 SceneLoadInfo 参数对象，调用 BeginSceneTransition

4.2 SceneLoad 的八阶段

SceneLoad 定义了八个阶段枚举，每个阶段记录起止时间（用于性能分析），并在关键节点触发事件：

#阶段做什么事件
0FetchBlocked空转等待，直到 IsFetchAllowed 打开—
1FetchLoadSceneAsync（Additive，禁止激活），等到 progress 达到 0.9FetchComplete
2ActivationBlocked空转等待，直到 IsActivationAllowed 打开—
3ActivationallowSceneActivation=true，等待场景真正激活WillActivate / ActivationComplete
4UnloadUnusedAssets按需执行 Resources.UnloadUnusedAssets—
5GarbageCollect按需执行 GCManager.Collect—
6StartCall等一帧，触发 StartCalledStartCalled
7LoadBoss按需加载 Boss 附加场景BossLoaded

核心机制：两个门控布尔

Fetch 阶段的加载循环长这样：

while (!IsFetchAllowed)
{
    yield return null;
}
AsyncOperation loadOperation = SceneManager.LoadSceneAsync(targetSceneName, LoadSceneMode.Additive);
loadOperation.allowSceneActivation = false;
while (loadOperation.progress < 0.9f)
{
    yield return null;
}

为什么 progress 停在 0.9？

Unity 的异步加载在 allowSceneActivation=false 时，进度最多到 0.9 并停住——剩下 0.1 是"激活场景"。这给了编排层一个精确的同步点：场景资源已经在后台加载完，但何时切换由 GameManager 决定。两个门控（Fetch 控制何时开始加载、Activation 控制何时允许激活）把"加载速度"和"演出节奏"彻底解耦。

4.3 编排层：事件订阅与门控配合

GameManager 在协程里创建 SceneLoad 后，通过订阅四个事件把自己的逻辑插进管线，而不是修改 SceneLoad 本身：

sceneLoad.WillActivate += delegate
{
    if (DestroyPersonalPools != null) DestroyPersonalPools();  // 清理场景对象池
    entryDelay = info.EntryDelay;
};
sceneLoad.ActivationComplete += delegate
{
    SceneManager.UnloadScene(lastSceneName);                   // 卸载旧场景
    RefreshTilemapInfo(info.SceneName);
    sceneLoad.IsUnloadAssetsRequired = /* 卸载策略 */;
    sceneLoad.IsGarbageCollectRequired = /* GC 策略 */;
};
sceneLoad.Complete += delegate
{
    SetupSceneRefs(refreshTilemapInfo: false);
    BeginScene();                                             // 新场景正式开始
    gameMap.GetComponent().LevelReady();
};
sceneLoad.Finish += delegate
{
    sceneLoad = null;
    isLoading = false;
    info.NotifyFinished();
    OnFinishedSceneTransition?.Invoke();
};

门控何时打开：等相机淡出

协程末尾有一段等待循环，把"激活新场景"和"相机淡出完成"对齐：

sceneLoad.IsFetchAllowed = !info.forceWaitFetch &&
    (Platform.Current.FetchScenesBeforeFade || info.PreventCameraFadeOut);
sceneLoad.IsActivationAllowed = false;
sceneLoad.Begin();

float cameraFadeTimer = 0.5f;
while (true)
{
    bool keepWaiting = false;
    cameraFadeTimer -= Time.unscaledDeltaTime;
    if (info.WaitForSceneTransitionCameraFade && cameraFadeTimer > 0f)
        keepWaiting = true;
    if (!info.IsReadyToActivate())
        keepWaiting = true;
    if (!keepWaiting) break;
    yield return null;
}
sceneLoad.IsFetchAllowed = true;
sceneLoad.IsActivationAllowed = true;   // 屏幕全黑后才放行激活

注意这里用的是 Time.unscaledDeltaTime——切换期间可能已经修改了 timeScale，等待逻辑必须不受时间缩放影响。

4.4 触发层：TransitionPoint 门口

门口是场景里的 Trigger Collider，主角走进来触发 OnTriggerEnter2D。它的 TryDoTransition 做了三件事：

1
资格校验：碰撞对象必须是 9 号层（主角）、gameState 必须是 PLAYING，门不能是需要交互的 isADoor。
2
方向处理：根据 GatePosition（从物体名里的 left/right/top/bot 解析）和主角朝向，决定是先把主角推出碰撞区还是直接切换。
3
切换音频快照并构造参数：过渡四个 AudioMixerSnapshot，然后构造 SceneLoadInfo 调用 BeginSceneTransition。
gm.BeginSceneTransition(new GameManager.SceneLoadInfo
{
    SceneName = targetScene,
    EntryGateName = entryPoint,
    HeroLeaveDirection = GetGatePosition(),
    EntryDelay = entryDelay,
    WaitForSceneTransitionCameraFade = true,
    PreventCameraFadeOut = (customFadeFSM != null),
    Visualization = sceneLoadVisualization,
    AlwaysUnloadUnusedAssets = alwaysUnloadUnusedAssets
});

命名约定即配置：门口的位置不是单独字段，而是 GetGatePosition() 从物体名字里找 "left/right/top/bot" 字符串解析的。这意味着门口物体一旦改名，切换逻辑就会报错返回 unknown。这是读这份代码时必须适应的"约定大于配置"风格。

4.6 两个值得学习的工程细节

细节一：所有事件回调都包 try-catch

SceneLoad 触发每个事件时都这样写：

try { this.FetchComplete(); }
catch (Exception exception)
{
    Debug.LogError("Exception in responders to SceneLoad.FetchComplete. Attempting to continue load regardless.");
    Debug.LogException(exception);
}

场景切换期间任何外部订阅者抛异常，都只记录、不中断加载。否则一个物件的 bug 会让玩家永久卡在黑屏。这是把"加载必须完成"作为最高优先级的防御性设计。

细节二：非关键 GC 的条件跳过

每次切换都做完整 GC 会造成卡顿，ActivationComplete 里有一套节流逻辑：加载耗时短、且连续切换次数没超阈值时，允许跳过这次非关键 GC，由 sceneLoadsWithoutGarbageCollect 计数，到上限强制回收。这是在内存占用和帧率之间做的量化权衡，阈值由 Platform 层按平台性能提供。
