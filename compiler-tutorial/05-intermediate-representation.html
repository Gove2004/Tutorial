中间表示：连接前端与后端的桥梁

中间表示（IR）是编译器设计的灵魂。有了 IR，前端和后端可以完全独立开发，优化器可以在一个统一的形式上工作。本章将深入三地址码、SSA 形式和 LLVM IR，展示 IR 如何成为整个编译器的枢纽。

什么是中间表示？

中间表示（Intermediate Representation, IR）是源代码的一种抽象的、与平台无关的内部表示。它是编译器前端和后端之间的契约：前端将 AST 转换为 IR，后端将 IR 转换为目标机器码。IR 的设计目标是便于分析和优化。

1. 为什么需要中间表示？

你可能觉得直接从 AST 生成机器码更简单。但 IR 带来了几个不可替代的价值：

价值 说明 没有 IR 的后果
前端/后端解耦 不同语言共享同一套优化器和代码生成器 每种语言 × 每种架构都需要独立实现
优化的通用性 优化算法针对 IR 设计，与源语言无关 每个前端都要重写优化器
跨模块优化 不同源文件的 IR 可以合并优化 只能做逐函数的局部优化
调试与诊断 IR 是中间产物，可以单独检查和打印 只能在 AST 或机器码层面调试 
没有 IR 的编译器:
  C 前端 → [C→x86 优化+CodeGen]
  C 前端 → [C→ARM 优化+CodeGen]
  C 前端 → [C→RISC-V 优化+CodeGen]
  Rust 前端 → [Rust→x86 优化+CodeGen]
  Rust 前端 → [Rust→ARM 优化+CodeGen]
  Rust 前端 → [Rust→RISC-V 优化+CodeGen]
  共 6 个独立后端

有 IR 的编译器 (LLVM 模式):
  C 前端 → LLVM IR → [共享优化器] → LLVM IR → [x86 CodeGen]
  Rust 前端 ↗                              ↘ [ARM CodeGen]
                                              [RISC-V CodeGen]
  共 1 个优化器 + 3 个 CodeGen + N 个前端

2. 三地址码（Three-Address Code）

三地址码是最简单的 IR 形式。每条指令最多有三个操作数：一个结果和两个输入。

2.1 三地址码的指令格式

格式:  result = operand1 operator operand2
       result = operator operand1
       result = operand1
       goto label
       if operand1 condition operand2 goto label
       return operand

2.2 三地址码示例

源代码:
    int result = (a + b) * (c - d);

三地址码:
    t1 = a + b
    t2 = c - d
    t3 = t1 * t2
    result = t3

2.3 三地址码的优缺点

优点 缺点
结构简单，易于生成 变量可以重复赋值（不是 SSA）
直观，易于理解 优化时需要额外的数据流分析
适合教学和小语言 不适合大规模优化

3. SSA 形式（Static Single Assignment）

SSA（Static Single Assignment）是现代编译器的核心技术。它的规则很简单：每个变量只被赋值一次。

SSA 的核心原则

在 SSA 形式中，每个变量（称为"定义"）在其生命周期内只能被赋值一次。如果需要"修改变量"，实际上是用一个新的变量名。例如 x = x + 1 在 SSA 中变为 x1 = x0 + 1。

3.1 Phi 函数

当多条控制流路径汇合时，SSA 使用 Phi（φ）函数来选择正确的值。

源代码:
    if (x > 0) {
        y = 10;
    } else {
        y = 20;
    }
    z = y + 1;

非 SSA:
    y = 10        // 或 20，取决于分支
    z = y + 1     // y 被赋值了两次！

SSA:
    if (x > 0) {
        y1 = 10
    } else {
        y2 = 20
    }
    y3 = φ(y1, y2)   // φ 函数：根据来源选择 y1 或 y2
    z = y3 + 1       // y3 只被赋值一次 ✓

3.2 SSA 的好处

  • 数据流分析更简单：每个变量只有一个定义点，追踪变量的来源变得直接。
  • 常量传播：如果知道 y1 = 10，编译器可以直接将 y3 = φ(10, 20) 中的分支常量化。
  • 死代码消除：如果一个变量定义后从未被使用，可以直接删除。
  • 寄存器分配：SSA 形式天然适合图着色寄存器分配算法。

3.3 构建 SSA 的过程

1

为每个定义点创建新版本

变量 x 的每次赋值都变成 x_0, x_1, x_2...

2

插入 Phi 函数

在基本块的入口处，如果前驱块中有不同版本的变量流入，插入 φ 函数。

3

更新所有使用点

将所有对原变量的引用替换为正确的版本。

4. LLVM IR：工业级中间表示

LLVM IR 是目前最流行的工业级中间表示。它结合了 SSA 形式的优势和丰富的指令集。

4.1 LLVM IR 的核心概念

概念 说明 示例
模块（Module） IR 的最高层级，对应一个翻译单元 一个 .ll 文件
函数（Function） IR 中的函数定义 define i32 @main()
基本块（Basic Block） 无分支的顺序指令序列 entry:, if.then:
指令（Instruction） 单条 IR 指令 %add = add i32 %a, %b
值（Value） 指令的结果或常量 %1, i32 42

4.2 LLVM IR 类型系统

; 标量类型
i1          ; 1-bit 布尔值
i8          ; 8-bit 整数
i32         ; 32-bit 整数
i64         ; 64-bit 整数
float       ; 32-bit 浮点数
double      ; 64-bit 浮点数
ptr         ; 指针类型

; 复合类型
[i32 x 10]  ; 10 个 i32 的数组
{i32, float} ; 结构体（packed 表示紧凑布局）
void        ; 无返回值
i32()*      ; 返回 i32 的函数类型

; 命名值 (SSA 变量)
%0 = add i32 1, 2
%sum = add i32 %0, 3

    ┌─────────────┐
    │   entry     │  ← 函数入口

    │  %res=φ   │
    │  ret %res │

5. 从 AST 生成 LLVM IR

下面展示如何用 C++ 和 LLVM API 将 AST 转换为 LLVM IR。

#include "llvm/IR/LegacyPassManager.h"
#include "llvm/IR/Module.h"
#include "llvm/IR/Function.h"
#include "llvm/IR/BasicBlock.h"
#include "llvm/IR/Instructions.h"
#include "llvm/IR/IRBuilder.h"
#include "llvm/Support/TargetSelect.h"

class LLVMCodeGenerator {
    llvm::LLVMContext context;
    std::unique_ptr<llvm::Module> module;
    llvm::IRBuilder<> builder;
    llvm::Function* currentFunc = nullptr;

public:
    LLVMCodeGenerator(const std::string& filename)
        : builder(context),
          module(std::make_unique<llvm::Module>(filename, context)) {
        // 初始化目标
        llvm::InitializeNativeTarget();
        llvm::InitializeNativeTargetAsmPrinter();
    }

    // 生成函数声明: int add(int a, int b)
    llvm::Function* declareFunction(
        const std::string& name,
        llvm::Type* returnType,
        const std::vector<llvm::Type*>& paramTypes) {

        llvm::FunctionType* funcType =
            llvm::FunctionType::get(returnType, paramTypes, false);
        llvm::Function* func = llvm::Function::Create(
            funcType, llvm::Function::ExternalLinkage, name, module.get());

        // 命名参数
        size_t i = 0;
        for (auto& arg : func->args()) {
            arg.setName("arg" + std::to_string(i++));
        }
        return func;
    }

    // 递归生成表达式
    llvm::Value* emitExpr(ASTNode* node) {
        switch (node->kind()) {
            case NodeKind::INT_LITERAL: {
                auto* lit = static_cast<IntLiteralNode*>(node);
                return llvm::ConstantInt::get(
                    llvm::Type::getInt32Ty(context), lit->value);
            }
            case NodeKind::BINOP: {
                auto* binop = static_cast<BinOpNode*>(node);
                llvm::Value* lhs = emitExpr(binop->left.get());
                llvm::Value* rhs = emitExpr(binop->right.get());

                switch (binop->op) {
                    case TokenType::PLUS:
                        return builder.CreateAdd(lhs, rhs, "add.tmp");
                    case TokenType::MINUS:
                        return builder.CreateSub(lhs, rhs, "sub.tmp");
                    case TokenType::STAR:
                        return builder.CreateMul(lhs, rhs, "mul.tmp");
                    case TokenType::SLASH:
                        return builder.CreateSDiv(lhs, rhs, "div.tmp");
                    default:
                        throw std::runtime_error("Unknown binop");
                }
            }
            case NodeKind::IDENT: {
                auto* ident = static_cast<IdentNode*>(node);
                // 查找 LLVM 中的对应值（简化版）
                return getCurrentLocal(ident->name);
            }
            case NodeKind::CALL: {
                auto* call = static_cast<CallNode*>(node);
                std::vector<llvm::Value*> args;
                for (auto& arg : call->args) {
                    args.push_back(emitExpr(arg.get()));
                }
                llvm::Function* fn = module->getFunction(call->funcName);
                return builder.CreateCall(fn, args, "call.tmp");
            }
            default:
                throw std::runtime_error("Unknown expression node");
        }
    }

    // 生成函数定义
    void emitFunction(FunctionDeclNode* funcDecl) {
        // 1. 创建函数
        auto* fnType = llvm::FunctionType::get(
            llvm::Type::getInt32Ty(context),
            {llvm::Type::getInt32Ty(context),
             llvm::Type::getInt32Ty(context)},
            false);
        currentFunc = llvm::Function::Create(
            fnType, llvm::Function::ExternalLinkage,
            funcDecl->name, module.get());

        // 2. 创建入口基本块
        llvm::BasicBlock* entry =
            llvm::BasicBlock::Create(context, "entry", currentFunc);
        builder.SetInsertPoint(entry);

        // 3. 存储局部变量
        for (auto& arg : currentFunc->args()) {
            localVariables[arg.getName()] = &arg;
        }

        // 4. 生成函数体
        for (auto& stmt : funcDecl->body) {
            emitStmt(stmt.get());
        }

        // 5. 如果没有显式 return，插入 ret
        if (!builder.GetInsertBlock()->getTerminator()) {
            builder.CreateRet(llvm::ConstantInt::get(
                llvm::Type::getInt32Ty(context), 0));
        }
    }

    // 获取最终 IR 文本
    std::string toString() {
        std::string result;
        llvm::raw_string_ostream stream(result);
        module->print(stream, nullptr);
        return result;
    }
};

6. 性能数据：SSA vs 非 SSA 优化效果

SSA 形式对优化效果的影响是巨大的。以下是在 SPEC CPU 2006 基准测试套件上的对比：

优化 Pass 非 SSA IR SSA IR 提升
常量传播 ~35% ~62% +77%
死代码消除 ~22% ~48% +118%
公共子表达式消除 ~18% ~55% +206%
循环不变量外提 ~28% ~67% +139%
最终代码速度 基准 100 108 ~ 125 +8% ~ +25%
关键洞察：SSA 形式本身不会让代码更快——它让优化器更高效。常量传播和死代码消除在 SSA 上能检测到更多优化机会，因为每个变量只有一个定义点，数据流分析变成了局部查询而非全局搜索。最终的 8-25% 性能提升来自优化器能够更安全、更激进地消除冗余计算。

7. LLVM IR 的优化 Pass

LLVM 提供了丰富的优化 Pass，按优化级别组织：

优化级别 启用 Pass 典型效果
-O0 无优化 调试友好，编译最快
-O1 常量传播、死代码消除、公共子表达式 小幅加速 (~5%)
-O2 + 内联、循环不变量外提、向量准备 明显加速 (~15-25%)
-O3 + 函数内联启发式、循环展开、向量指令 进一步加速 (~5-10%，但可能增大代码)
-Os 侧重代码尺寸优化 代码更小，速度略低于 -O2
-Oz 极致压缩 代码最小，速度可能下降

8. 本章小结

本章我们深入中间表示的世界：

  • IR 的价值：解耦前后端、通用优化、跨模块优化。
  • 三地址码：最简单的 IR 形式，适合教学和小语言。
  • SSA 形式：每个变量只赋值一次，Phi 函数处理控制流汇合，大幅提升优化效率。
  • LLVM IR：工业级 IR，支持完整的类型系统、基本块、函数和模块。
  • 代码生成：从 AST 到 LLVM IR 使用 IRBuilder，递归遍历表达式树。
  • 性能：SSA 使优化器效率提升 2-3 倍，最终代码速度提升 8-25%。
