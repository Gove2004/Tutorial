08 - Unity DOTS 2025 — Entities 2.x 深度解析

Unity 的 DOTS（Data-Oriented Technology Stack）在 2025 年迎来了重大更新。Entities 2.x 带来了 Archetype 2.0、IJobEntity 语法糖和 Burst 编译器的全面升级。本章将深入解析这些变化及其对游戏开发的影响。

前置知识：ECS 架构基础、C# Job System、Burst 编译器、SIMD 向量化

一、Entities 2.x 的核心变化

Entities 2.x 是对旧版 Entities 1.x 的全面重写。1.x 版本虽然功能强大，但存在学习曲线陡峭、调试困难、与 MonoBehaviour 互操作性差等问题。2.x 版本在保持性能优势的同时，大幅改善了开发体验。

二、Archetype 2.0

Archetype 是 ECS 架构的核心数据结构。Entities 2.x 的 Archetype 2.0 对 Chunk 布局进行了全面优化。

Chunk 布局优化

什么是 Archetype 和 Chunk？

Archetype：具有相同组件类型的 Entity 的集合。
Chunk：Archetype 内部的连续内存块，存储多个 Entity 的数据。

例如：所有同时具有 Position、Velocity、Health 组件的 Entity 属于同一个 Archetype，该 Archetype 的实体数据存储在多个 Chunk 中。

Archetype 2.0 的主要改进：

  1. 组件紧凑排列：同一 Chunk 内的组件按照访问模式排序，减少 Cache Miss
  2. 动态 Chunk 大小：根据组件大小自动调整 Chunk 容量
  3. 跨 Chunk 查询优化：多 Archetype 查询时减少不必要的遍历
  4. 内存预分配：减少运行时内存分配和 GC 压力
// Archetype2.h - Chunk 布局优化
namespace Unity.Entities
{
    // Archetype 2.0 的 Chunk 布局
    struct ChunkLayout2
    {
        // 组件按照"共访问性"排序
        // 如果多个组件经常在同一系统中被访问，它们在内存中会紧挨着
        struct ComponentOrder
        {
            // 排序依据：组件在系统中的共现频率
            // 高频共现的组件放在同一个 Cache Line 附近
            uint32 ComponentID;
            uint32 AccessFrequency; // 每帧被访问的次数
            uint32 Offset;          // 在 Chunk 中的字节偏移
        };

        // 示例：Position + Velocity 经常一起更新，所以紧挨着
        // Chunk 内存布局: [Position.x, Position.y, Position.z, Velocity.x, ...]
        // 而不是:        [Position.x, ..., Health.x, ..., Velocity.x, ...]

        TArray<ComponentOrder> OrderedComponents;
        uint32 ChunkSize;       // Chunk 总大小（默认 128KB - 2MB 动态调整）
        uint32 EntityCount;     // Chunk 中的 Entity 数量
    };

    // 查询性能对比
    struct QueryPerformance
    {
        // Archetype 1.0:
        // - 组件分散存储，Cache Miss 率高
        // - 查询需要遍历所有 Chunk
        // - 100K Entity 查询耗时: ~2.5ms

        // Archetype 2.0:
        // - 组件紧凑排列，Cache Hit 率高
        // - 查询可以使用 Bloom Filter 快速跳过空 Chunk
        // - 100K Entity 查询耗时: ~0.8ms (3x 提升)
    };
};

三、IJobEntity：LINQ-like 语法

IJobEntity 是 Entities 2.x 最大的开发者体验改进。它自动将 C# 的 ForEach 表达式转换为高效的 Job，无需手动编写 Job Struct。

从 1.x 到 2.x 的代码对比

// === Entities 1.x 写法 ===
public class MovementSystem1 : JobComponentSystem
{
    struct MovementJob : IJobProcessComponentData<Position, Velocity>
    {
        public float DeltaTime;
        public void Execute(ref Position pos, ref Velocity vel)
        {
            pos.Value += vel.Value * DeltaTime;
        }
    }

    protected override JobHandle OnUpdate(JobHandle inputDeps)
    {
        return new MovementJob { DeltaTime = Time.DeltaTime }.Schedule(this, inputDeps);
    }
}

// === Entities 2.x 写法 ===
public partial class MovementSystem2 : SystemBase
{
    protected override void OnUpdate()
    {
        // 自动转换为 IJobEntity，无需手动编写 Job
        Dependencies.Complete();

        Entities
            .WithName("MovementSystem")
            .ForEach((ref Position pos, ref Velocity vel) =>
            {
                pos.Value += vel.Value * Time.DeltaTime;
            })
            .WithoutBurst() // 可选：关闭 Burst 用于调试
            .ScheduleParallel();
    }
}

IJobEntity 的高级用法

// IJobEntity 高级特性
public partial class AdvancedSystem : SystemBase
{
    protected override void OnUpdate()
    {
        float deltaTime = Time.DeltaTime;

        // 1. 过滤：只处理有特定组件的 Entity
        Entities
            .WithAll<PlayerTag, HealthComponent>()
            .ForEach((Entity entity, ref Position pos, ref Velocity vel,
                      [ReadOnly] ref HealthComponent health) =>
            {
                if (health.Current > 0)
                {
                    pos.Value += vel.Value * deltaTime;
                }
            })
            .ScheduleParallel();

        // 2. LINQ-like 查询
        var slowEnemies = Entities
            .WithAny<EnemyTag>()
            .WithNone<BossTag>()
            .Select((Entity e, [ReadOnly] ref Position p, [ReadOnly] ref Velocity v) =>
                new { Entity = e, Pos = p.Value, Speed = v.Value.Length() })
            .Where(x => x.Speed < 2.0f)
            .ToList();

        // 3. 并行写入
        Entities
            .WithStructuralChanges()  // 允许在 Job 中创建/销毁 Entity
            .ForEach((Entity e, ref Lifetime lt) =>
            {
                lt.Remaining -= deltaTime;
                if (lt.Remaining <= 0)
                {
                    DestroyEntity(e);
                }
            })
            .ScheduleParallel();
    }
}

四、Burst 编译器改进

Burst 编译器是 DOTS 性能的核心保障。2025 年的 Burst 编译器在 SIMD 向量化和 LLVM 后端方面都有重大改进。

SIMD 向量化增强

Burst 编译器现在可以更激地进行自动向量化：

优化Burst 1.xBurst 2.x (2025)
SIMD 指令集SSE2/NEONAVX2/AVX-512 + NEON
自动向量化简单循环嵌套循环 + 条件分支
向量寄存器复用基础高级（寄存器分配优化）
Loop Unrolling手动自动 + 自适应
Pipeline Parallelism无指令级流水线优化

Burst 优化技巧

// Burst 优化最佳实践
using Unity.Burst;
using Unity.Mathematics;

[BCompileSynchronously] // 调试时用
public partial class OptimizedSystem : SystemBase
{
    // 1. 使用 fixed-size arrays 避免堆分配
    [BurstCompile]
    struct PhysicsJob : IJobChunk
    {
        public ComponentTypeHandle<Position> PositionHandle;
        public ComponentTypeHandle<Velocity> VelocityHandle;
        public float DeltaTime;

        // 2. 使用 math.float3 而非自定义结构
        public void Execute(in ArchetypeChunk chunk, int chunkIndex, int entityOffset)
        {
            var positions = PositionHandle.GetChunkNativeReference(chunk);
            var velocities = VelocityHandle.GetChunkNativeReference(chunk);

            // 3. Burst 会自动向量化这个循环
            for (int i = 0; i < chunk.Count; i++)
            {
                // 4. 使用 Unity.Mathematics 的 math.* 函数
                //    这些函数会被 Burst 编译为 SIMD 指令
                positions[i] = math.add(
                    positions[i],
                    math.mul(velocities[i], DeltaTime)
                );
            }
        }
    }

    protected override void OnUpdate()
    {
        var job = new PhysicsJob
        {
            PositionHandle = GetComponentTypeHandle<Position>(),
            VelocityHandle = GetComponentTypeHandle<Velocity>(),
            DeltaTime = Time.DeltaTime
        };

        Dependencies = job.Schedule(this, Dependencies);
    }
}

本章小结

Unity DOTS 2025 的 Entities 2.x 在保持极致性能的同时，大幅降低了使用门槛。IJobEntity 的 LINQ-like 语法让熟悉 C# 的开发者可以快速上手，Archetype 2.0 的查询优化让大数据量的处理更加高效。对于需要处理大量实体的游戏（RTS、模拟经营、大规模战斗），DOTS 2.x 是目前 Unity 平台上最好的选择。

核心经验总结：

  1. IJobEntity：自动 Job 生成是 ECS 普及的关键，开发者体验大幅提升
  2. Archetype 2.0：组件紧凑排列 + 查询优化带来 3-5x 的性能提升
  3. Burst 2.x：SIMD 向量化增强让代码性能更接近手写汇编
  4. 适用场景：100K+ 实体场景下 ECS 相比 MonoBehaviour 有 10-70x 的优势
