A.2 由数据规模倒推算法

时间限制按 1 秒 ≈ 108 次基本运算估算，超过一档就该换算法。

n 的上限可接受的复杂度典型算法
≤ 20O(2n)、O(n!)子集 DP、暴搜、状压
≤ 40O(2n/2)折半枚举（meet in the middle）
≤ 100O(n4) 勉强、O(n3) 稳Floyd、区间 DP、DP 套 DP
≤ 300O(n3)Floyd、矩阵乘、部分网络流
≤ 1000O(n2)朴素 DP、双重循环、EK
≤ 105O(n log n)、O(n√n)排序、线段树、树状数组、Dijkstra
≤ 106O(n)、O(n log n) 且常数小线性筛、KMP、单调栈
≤ 1018O(log n)、O(√n)快速幂、gcd、数位 DP、矩阵快速幂
这张表是“上限”不是“目标”。同样 O(n log n)，线段树常数是排序的十几倍； n = 106 时写得丑的 O(n log n) 一样会超时。估完复杂度还要估常数。

A.3 提交前的 18 项检查

按这个顺序过一遍，能消掉绝大多数“样例过、提交 WA/TLE/RE”。

类别检查项
输入① 多组数据是否读到文件尾（while (scanf(...) != EOF)）
② 每组数据前是否清空数组/容器/计数器
③ 输入规模是否用了 %lld / cin 同步关闭
边界④ n = 0、n = 1 是否特判
⑤ 下标从 0 还是从 1，是否混用
⑥ 数组开够了吗（线段树要 4n，链式前向星要 2m）
溢出⑦ 中间结果是否超过 int（乘法、累加、平方和）
⑧ INF 取 0x3f3f3f3f 还是 1e18，加法会不会溢出
精度⑨ 浮点比较是否用了 sgn
⑩ 输出是 %.2f 而不是 %lf
⑪ -0.00 是否需要处理
格式⑫ Case #x: 的 x 从 1 开始、大小写、空格
⑬ 行末是否有多余空格、最后一行是否要空行
算法⑭ 复杂度是否和数据规模匹配
⑮ 是否处理了“无解”分支（输出 -1 / No / 0）
⑯ 递归深度是否会爆栈（1e5 层要改迭代或加栈）
其他⑰ freopen 是否注释掉了
⑱ 输出是否用了 endl 刷了太多行（TLE 常见原因）

A.4 WA 的六种常见原因

现象最可能的原因怎么查
样例过、提交 WA没考虑多组数据、边界值自己造 n=1、全相同、极值的用例
大数据 WA、小数据对溢出或精度把 int 全换 long long 试一次
部分用例 WA特判漏了（0、负数、重复元素）随机小数据 + 暴力对拍
TLE复杂度选错、常数过大、I/O 慢看 n 的量级，换算法或关同步
RE数组越界、除零、递归爆栈把数组开大 10 倍先试
MLE开了 n2 的数组、容器没清算一遍内存：int 数组 1e8 就是 400MB

A.5 对拍的标准流程

1
写暴力：复杂度可以是 O(n3) 甚至 O(2n)，但一定要确定正确。
2
写数据生成器：先小数据（n ≤ 8）覆盖所有边界，再逐步放大。
3
循环对拍：生成 → 跑两个程序 → fc / diff 比较，不一致就停下来看数据。
4
定位：把不一致的输入缩到最小，再手工推一遍，找出是哪个分支错了。
// 数据生成器（Linux/Win 通用写法：直接用 rand）
int main() {
    srand(time(0));
    int n = rand() % 10 + 1;                 // 先从小数据开始
    printf("%d\n", n);
    for (int i = 1; i <= n; i++) printf("%d ", rand() % 100);
    puts("");
    return 0;
}
对拍的价值在于“可信”。正解写错时你自己看不出来，但暴力几乎不会错。 只要暴力可信，对拍就是最可靠的调试手段——比盯着代码看半小时有效得多。
