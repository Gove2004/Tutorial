实战：从零构建 Lisp 解释器

前面的章节我们分别学习了编译器的各个组件：词法分析、语法分析、语义分析、IR、优化、代码生成和运行时系统。现在，让我们把这些知识整合到一个完整的实践中——从零构建一个 Lisp 解释器。Lisp 是编程语言设计的"果蝇"：它足够简单，可以用几千行代码实现；又足够强大，可以表达任何计算。

为什么选择 Lisp？

Lisp 的核心语法只有一种构造：S-表达式（Symbolic Expression）。列表、代码、数据都用同一种结构表示（ homoiconicity ）。这使得解释器的实现非常简洁，同时保留了完整的图灵完备性。John McCarthy 在 1958 年发明了 Lisp，当时的实现只有 50 行代码——尽管现代 Lisp 解释器要大得多，但核心架构仍然保持着惊人的简洁。

1. Lisp 语言设计

1.1 S-表达式与语法

Lisp 的所有程序都是 S-表达式。S-表达式有两种基本形式：原子（atom）和列表（list）。

原子:  42, "hello", x, +, nil
列表:  (+ 1 2 3)
       (defun factorial (n)
         (if (= n 0)
             1
             (* n (factorial (- n 1)))))

S-表达式 = 原子 | (S-表达式*)
即: 每个列表是零个或多个 S-表达式的有序集合

Lisp 的语法糖：

语法 展开为 说明
(quote x) 'x 阻止求值，返回字面量
(car x) (car x) 取列表首元素
(cdr x) (cdr x) 取列表尾部
(cons a b) (cons a b) 构造列表
(lambda (x) (+ x 1)) #'(lambda (x) (+ x 1)) 匿名函数
(setf x 42) (setf x 42) 变量赋值

1.2 动态类型系统

Lisp 是动态类型的：类型检查在运行时进行，而不是编译时。每个值自带类型标签：

// Lisp 值的统一表示 (Tagged Union)
enum class Type {
    NIL, BOOLEAN, INTEGER, FLOAT, STRING,
    SYMBOL, LIST, FUNCTION, CLOSURE,
    BUILTIN_FUNC, CHAR, VECTOR
};

struct LispValue {
    Type type;
    union {
        bool boolean_val;
        int64_t integer_val;
        double float_val;
        std::string* string_val;
        Symbol* symbol_val;
        ConsCell* list_val;
        Closure* closure_val;
        BuiltinFunc* builtin_val;
    };

    // 构造函数
    static LispValue Nil() { return LispValue{Type::NIL}; }
    static LispValue Integer(int64_t v) {
        return LispValue{Type::INTEGER, {.integer_val = v}};
    }
    static LispValue Bool(bool v) {
        return LispValue{Type::BOOLEAN, {.boolean_val = v}};
    }
};
💡 实现技巧：Tagged Union 是最朴素的值表示方式，但每次读写都需要类型检查。生产级 Lisp 实现（如 SBCL）使用标签指针（tagged pointers）技术——利用 x86-64 地址的低几位作为类型标签，避免额外的类型字段。这可以让内存占用减少 30%，访问速度提升 2 倍。

2. AST 解释器：Eval/Apply 循环

Lisp 解释器的核心是 Eval/Apply 循环：evaluate 函数对表达式求值，apply 函数对函数调用求值。这两个函数互相递归，构成了语言语义的数学模型。

// 环境：变量名 → 值的映射
struct Environment {
    std::unordered_map<std::string, LispValue> bindings;
    std::shared_ptr<Environment> enclosing;

    Environment(std::shared_ptr<Environment> enc = nullptr)
        : enclosing(enc) {}

    LispValue lookup(const std::string& name) {
        auto it = bindings.find(name);
        if (it != bindings.end()) return it->second;
        if (enclosing) return enclosing->lookup(name);
        throw std::runtime_error("Undefined variable: " + name);
    }

    void define(const std::string& name, LispValue value) {
        bindings[name] = value;
    }
};

// 解释器核心: Eval/Apply 循环
class Interpreter {
    Environment& env;

    // eval: 对表达式求值
    LispValue eval(const Expr& expr) {
        switch (expr.kind) {
            case ExprKind::SELF_EVALUATING:  // 数字、字符串、布尔值
                return expr.value;

            case ExprKind::SYMBOL:  // 变量引用
                return env.lookup(expr.symbol_name);

            case ExprKind::QUOTE:  // (quote x) → x
                return eval(cadr(expr));

            case ExprKind::IF: {  // (if cond then else)
                LispValue cond = eval(cadr(expr));
                if (!isFalse(cond)) {
                    return eval(caddr(expr));
                } else if (expr.size() > 3) {
                    return eval(cadddr(expr));
                }
                return LispValue::Nil();
            }

            case ExprKind::SETQ: {  // (setf x v)
                auto sym = cadr(expr);
                LispValue val = eval(caddr(expr));
                env.define(sym.symbol_name, val);
                return val;
            }

            case ExprKind::DEFINE: {  // (defun f (x) body)
                auto def = cadr(expr);
                std::string name = def.car->symbol_name;
                auto params = def.cdr->list_val->elements;
                auto body = def.cdr->cdr->list_val->elements;
                auto fn = makeClosure(params, body, env);
                env.define(name, fn);
                return fn;
            }

            case ExprKind::LAMBDA: {  // (lambda (x) body)
                auto params = expr.cdr->car->list_val->elements;
                auto body = expr.cdr->cdr->list_val->elements;
                return makeClosure(params, body, env);
            }

            case ExprKind::APPLY: {  // 函数调用: (f a1 a2 ...)
                LispValue fn = eval(expr.car);
                std::vector<LispValue> args;
                for (auto& arg : expr.cdr->list_val->elements) {
                    args.push_back(eval(arg)); // 参数先求值
                }
                return apply(fn, args);
            }

            default:
                throw std::runtime_error("Unknown expression kind");
        }
    }

    // apply: 对函数求值
    LispValue apply(LispValue fn, const std::vector<LispValue>& args) {
        switch (fn.type) {
            case Type::BUILTIN_FUNC:
                return fn.builtin_val->impl(args, fn.builtin_val->env);

            case Type::CLOSURE: {
                auto& closure = *fn.closure_val;
                // 创建新环境: 参数绑定到实参
                Environment new_env(closure.env);
                for (size_t i = 0; i < closure.params.size(); i++) {
                    new_env.define(closure.params[i].symbol_name, args[i]);
                }
                // 依次求值函数体
                LispValue result = LispValue::Nil();
                for (auto& body_expr : closure.body) {
                    result = eval(body_expr);
                }
                return result;
            }

            default:
                throw std::runtime_error("Not a function");
        }
    }

    LispValue makeClosure(
        const std::vector<Expr>& params,
        const std::vector<Expr>& body,
        Environment& captured_env) {
        return LispValue{Type::CLOSURE, {new Closure{params, body, captured_env}}};
    }

public:
    Interpreter(Environment& e) : env(e) {}

    LispValue run(const std::string& source) {
        auto parsed = parse(source);  // 词法 + 语法分析
        return eval(parsed);          // 求值
    }
};

2.1 Eval/Apply 的执行流程

解释 (eval/apply) 循环:

用户输入: (+ (* 2 3) 4)

Step 1: Read → Parse → AST
    (APPLY
      (APPLY +
        (APPLY * (INTEGER 2) (INTEGER 3))
        (INTEGER 4))
      [])

Step 2: Eval (APPLY + ...)
  → Eval (+) → Lookup "+" → BuiltinFunc(add)
  → Eval ((* 2 3)) → Apply(*, [2, 3]) → Integer(6)
  → Eval (4) → Integer(4)
  → Apply(add, [Integer(6), Integer(4)]) → Integer(10)

Step 3: Print → "10"

完整流程:
  Read → Parse → Eval → Apply → Eval → Apply → ... → Result → Print
  ↑                                                                    │
  └────────────────────── REPL Loop ───────────────────────────────────┘

3. 宏系统

宏是 Lisp 最强大的特性之一：它允许你在编译期转换代码。宏接受源代码作为输入，输出转换后的源代码。

3.1 Quasiquote（准引号）

Quasiquote 让你可以写出"模板"形式的代码，其中某些部分可以求值：

(quasiquote (list ,x ,(+ 1 2) ,@(list 'a 'b)))
= (list x 3 a b)

语法糖:
  `(list ,x ,(+ 1 2))   →   (quasiquote (list ,x ,(+ 1 2)))
  ``(list ,x)           →   (quasiquote (quasiquote (list ,x)))

嵌套反引号:
  ``(a ,(+ 1 2) ,,(+ 3 4))
  = (quasiquote (a 3 ,( + 3 4)))   ; 外层 , 保留
  = (quasiquote (a 3 (+ 3 4)))     ; 内层 , 展开为 (+ 3 4)

3.2 Syntax-Rules 宏展开

Syntax-Rules 是 Scheme 提供的模式匹配宏系统：

// 宏展开器
class MacroExpander {
    // 内置宏: when, unless, do, let, cond
    std::map<std::string, MacroRule> macros;

    void expand_macros(Expr& expr) {
        if (expr.is_list()) {
            auto name = expr.car->symbol_name;
            if (macros.count(name)) {
                // 模式匹配 + 替换
                auto rule = macros[name];
                expr = rule.transform(expr.cdr);
            }
            // 递归展开嵌套表达式
            for (auto& child : expr.list_val->elements) {
                expand_macros(child);
            }
        }
    }
};

// 示例: (when condition body...)
// 等价于: (if condition (begin body...) #f)
MacroRule when_macro = {
    .pattern = "(when (? cond) . body)",
    .transform = [](const std::vector<Expr>& args) {
        return Expr::apply(Symbol{"if"}, {
            args[0],  // condition
            Expr::apply(Symbol{"begin"},
                std::vector<Expr>(args.begin()+1, args.end()))
        });
    }
};

// 示例: (let ((x 1) (y 2)) (+ x y))
// 等价于: ((lambda (x y) (+ x y)) 1 2)
MacroRule let_macro = {
    .pattern = "(let ((? bindings)) . body)",
    .transform = [](const std::vector<Expr>& args) {
        auto bindings = args[0].list_val->elements;
        auto body = std::vector<Expr>(args.begin()+1, args.end());

        std::vector<Expr> vars, vals;
        for (auto& bind : bindings) {
            vars.push_back(bind.car->copy());
            vals.push_back(bind.cdr->copy());
        }

        return Expr::apply(
            Expr::apply(Symbol{"lambda"}, vars),
            body
        );
    }
};
关键洞察：宏在 eval 之前运行。这意味着宏可以改变代码的结构——添加新的控制流、引入新的语法、甚至生成全新的代码。这就是为什么 Lisp 宏被称为"可编程语言"：你不仅可以写程序，还可以写语言的语法。

4. 闭包实现：环境模型

闭包是函数式编程的核心概念。闭包 = 函数 + 它捕获的环境。当函数被创建时，它会"记住"创建时的环境变量。

// 闭包: 函数 + 词法环境
struct Closure {
    std::vector<Expr> params;    // 形式参数
    std::vector<Expr> body;      // 函数体
    Environment env;             // 捕获的词法环境

    // 词法作用域 vs 动态作用域:
    // 词法作用域: 变量在定义时的环境中查找
    // 动态作用域: 变量在调用时的环境中查找

    // 词法作用域示例:
    // (let ((x 10))
    //   (let ((f (lambda () x)))  ; f 捕获 x=10
    //     (let ((x 20))
    //       (f))))               ; → 10 (不是 20!)
    //
    // 因为 f 在 x=10 的环境中创建，所以 f() 看到的是 x=10

4.1 环境模型详解

词法作用域的执行:

(let ((x 10))                  ; 环境 E1: {x: 10}
  (let ((f (lambda () x)))     ; 环境 E2: {f: }
                              ;   f 捕获 E1
    (let ((x 20))              ; 环境 E3: {x: 20}
                              ;   嵌套在 E2 之上
      (f))))                   ; 调用 f()

f() 的查找过程:
  1. f 的环境是 E1 (捕获时)
  2. 在 E1 中查找 x → 找到, x = 10
  3. 返回 10

如果是动态作用域:
  1. f 在调用时的环境中查找 x
  2. 当前环境是 E3 → x = 20
  3. 返回 20

Lisp/Scheme/JavaScript/Python 使用词法作用域
Bash/AWK 使用动态作用域

5. REPL：Read-Eval-Print Loop

REPL 是 Lisp 交互开发的核心。它不断循环：读取用户输入、解析为 AST、求值、打印结果。

// 完整 REPL 实现
class REPL {
    Interpreter interpreter;
    Environment global_env;
    std::ifstream* input_file;

public:
    REPL() : interpreter(global_env) {
        setup_builtins();  // 注册 +, -, *, if, defun 等
    }

    void setup_builtins() {
        // 内置函数注册
        global_env.define("+", BuiltinFunc{[](auto& args, auto&) {
            int64_t sum = 0;
            for (auto& a : args) sum += a.integer_val;
            return LispValue::Integer(sum);
        }});

        global_env.define("-", BuiltinFunc{[](auto& args, auto&) {
            if (args.size() == 1) return LispValue::Integer(-args[0].integer_val);
            int64_t result = args[0].integer_val;
            for (size_t i = 1; i < args.size(); i++)
                result -= args[i].integer_val;
            return LispValue::Integer(result);
        }});

        global_env.define("*", BuiltinFunc{[](auto& args, auto&) {
            int64_t prod = 1;
            for (auto& a : args) prod *= a.integer_val;
            return LispValue::Integer(prod);
        }});

        global_env.define("if", BuiltinFunc{[](auto& args, auto&) {
            if (args.size() < 3) throw std::runtime_error("if needs 3 args");
            return isTruthy(args[0]) ? args[1] : args[2];
        }});

        global_env.define("defun", BuiltinFunc{[](auto& args, auto&) {
            if (args.size() < 2) throw std::runtime_error("defun needs name and body");
            global_env.define(args[0].symbol_name, args[1]);
            return args[1];
        }});

        global_env.define("print", BuiltinFunc{[](auto& args, auto&) {
            for (auto& a : args) std::cout << stringify(a) << " ";
            std::cout << std::endl;
            return LispValue::Nil();
        }});
    }

    void run() {
        std::string line;
        std::string buffer;
        int paren_depth = 0;

        std::cout << "Lisp REPL v1.0 (Ctrl-D to exit)" << std::endl;

        while (true) {
            if (paren_depth == 0) {
                std::cout << "> ";
            } else {
                std::cout << "  ... ";
            }

            if (!std::getline(std::cin, line)) break;  // EOF

            for (char c : line) {
                if (c == '(') paren_depth++;
                else if (c == ')') paren_depth--;
                buffer += c;
            }

            if (paren_depth <= 0) {
                try {
                    auto ast = parse(buffer);
                    expand_macros(ast);  // 宏展开
                    auto result = interpreter.eval(ast);
                    std::cout << stringify(result) << std::endl;
                } catch (const std::exception& e) {
                    std::cerr << "Error: " << e.what() << std::endl;
                }
                buffer.clear();
                paren_depth = 0;
            }
        }
    }
};

7. 性能数据：解释器 vs JIT

纯解释执行的速度远慢于编译执行。以下是同一程序在不同执行模式下的性能对比：

程序 纯解释 缓存解释 JIT 编译 C 原生
Fib(30) 2.8s 0.8s 0.005s 0.003s
Factorial(10000) 1.5s 0.4s 0.002s 0.001s
Map 1M 元素 8.2s 3.1s 0.05s 0.02s
QuickSort 100K 5.6s 1.8s 0.03s 0.015s

可以看到，纯解释比 JIT 慢 100-1000 倍。但解释器有 JIT 无法比拟的优势：灵活性和交互性。这也是为什么下一章我们会讨论 JIT 编译——结合两者的优点。

8. 本章小结

本章我们从零构建了一个 Lisp 解释器：

  • S-表达式：Lisp 的唯一语法构造，列表即代码，代码即数据。
  • Eval/Apply 循环：解释器的核心架构。eval 求值表达式，apply 求值函数调用，两者互相递归。
  • 宏系统：Quasiquote 提供代码模板，Syntax-Rules 提供模式匹配。宏在 eval 之前运行，可以任意转换代码结构。
  • 闭包与环境：词法作用域意味着闭包捕获创建时的环境，而不是调用时的环境。
  • REPL：Read-Eval-Print 循环是交互式开发的核心，支持多行输入和宏展开。
  • 性能：纯解释比 JIT 慢 100-1000 倍，但提供了无与伦比的灵活性。
