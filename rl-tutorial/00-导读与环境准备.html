第 0 章 · 导读与环境准备

在写任何算法之前，我们先弄清楚一件最重要的事：强化学习到底在解决什么样的问题，它和你可能听过的"机器学习"有什么本质不同。这决定了你后面看一切代码的视角。

0.1 用一个生活场景理解强化学习

想象你在训练一只小狗：你不会（也无法）给它准备一份"在每种情境下标准答案是什么"的教科书。你能做的是——让它自由行动，做对了给零食（奖励），做错了不给、甚至轻微惩罚。小狗并不知道"为什么"，但它会逐渐发现："坐下"这个动作之后常常跟着零食，于是它越来越倾向于坐下。

强化学习（Reinforcement Learning，RL）就是把这个过程形式化和自动化。一个智能体（agent）通过不断与环境（environment）交互、试错，根据获得的奖励（reward）调整自己的行为，最终学会一套能拿到最多长期奖励的策略（policy）。

同一个框架出现在非常多地方：游戏 AI（AlphaGo、电竞 AI）、机器人学走路与抓取、自动驾驶决策、推荐系统与广告竞价、大模型的人类偏好对齐（RLHF）等。它们的共性是——没有人事先告诉你每一步的正确答案，你只能在行动之后得到一个"结果好不好"的分数。

0.2 强化学习与其他机器学习的根本区别

监督学习强化学习
学习信号每个样本都有"正确答案"标签（输入→标准答案）只有一个标量奖励，且常常延迟（赢了才知道这盘打得好）
数据来源通常是事先收集好的、静态的数据集数据是智能体自己"玩"出来的，行为决定了它能看到什么数据
样本关系默认样本之间相互独立前后状态高度相关，当前动作改变未来
核心矛盾拟合与泛化探索（尝试新动作）与利用（重复已知好动作）
目标对新输入做出正确预测最大化长期累计奖励，而非即时奖励
三个必须记住的独特困难
  • 信用分配（credit assignment）：一局棋赢了，是第 30 步的妙手还是第 5 步的布局起了决定作用？奖励只在终点出现，要把功劳"回传"给前面的动作。
  • 探索与利用：一直重复现在最好的动作可能错过更优解；盲目探索又可能一直输。
  • 数据是自己造的：学得不好→行为差→看到的经验差→更难学好，容易形成恶性循环（也可能正反馈地变好）。

0.3 强化学习的最小循环：先有个感性认识

无论多复杂的 RL 系统，核心都是同一个循环。我们先用纯 Python 标准库写一个最小版本：一个一维"走格子"世界，位置 0~4，目标是走到 4；智能体现在还很笨——只会随机选"左/右"。重点是让你看清 reset → 循环(step) → 结束 的骨架。

import random

class OneDWorld:
    """一维走格子：位置 0~4，目标位置 4。"""
    def __init__(self):
        self.target = 4

    def reset(self):
        """开局：把智能体放回起点，返回初始观测。"""
        self.pos = 0
        return self.pos

    def step(self, action):
        """执行动作：0=向左，1=向右；返回 (新观测, 奖励, 是否结束)。"""
        self.pos += 1 if action == 1 else -1
        self.pos = min(max(self.pos, 0), 4)          # 不能走出边界
        done = (self.pos == self.target)
        reward = 5 if done else -1                   # 到达 +5，每走一步 -1
        return self.pos, reward, done

env = OneDWorld()
for episode in range(3):
    obs = env.reset()
    total_reward, done, steps = 0, False, 0
    while not done:
        action = random.randint(0, 1)                # 暂时：随机动作
        obs, reward, done = env.step(action)
        total_reward += reward
        steps += 1
    print(f"第{episode+1}局：用了{steps}步，总奖励{total_reward}")

运行后你会看到随机智能体时好时坏，总奖励波动很大。这套教程的全部内容，本质上就是把"随机选动作"逐步替换成"根据经验聪明地选动作"。请先记住三个接口：reset() 开始新一局、step(action) 执行动作并返回新状态与奖励、用 done 判断一局结束。

0.4 环境准备（前半程零安装）

1

安装 Python 3

第 0–5 章只需要 Python 标准库。在终端运行 python --version 能看到版本号即可（本教程编写环境为 Python 3）。

2

准备一个编辑器

3

终端中进入文件所在目录，执行 python 文件名.py；也可在编辑器里直接运行。

关于深度学习部分：第 6 章起会用到 NumPy 与 PyTorch。现在不必安装，到那一章时按附录指引操作即可；如果你的 Python 版本很新，附录还说明了为什么建议另建一个稍旧版本的环境，并提供了浏览器里免安装运行（Colab / Kaggle）的方案。

0.5 这套教程的路线图

章节是按"思想如何一步步被需要、被发明"来组织的，而不是算法罗列：

  1. 先建立 智能体—环境交互与探索利用的直觉（第 1 章）
  2. 把问题形式化为 MDP，定义回报（第 2 章）
  3. 引入价值函数与贝尔曼方程，得到"未来值多少分"的递归表达（第 3 章）
  4. 环境已知用动态规划，环境未知先用蒙特卡洛（第 4 章）
  5. 结合两者优点得到时序差分与 Q-learning，做出第一个完整案例（第 5 章）
  6. 状态太多装不下表格时，用神经网络做函数逼近 → DQN（第 6 章）
  7. 换一条主线：直接优化策略，策略梯度 → Actor-Critic → GAE（第 7 章）
  8. 得到工业界最常用的 PPO，并了解连续动作控制（第 8 章）
  9. 补齐让训练真正可用的工程实践（第 9 章）
  10. 毕业项目：端到端独立做出一个案例（第 10 章）

练习与思考

1

运行 0.3 的代码 10 次，观察总奖励的波动；尝试把每步惩罚从 -1 改成 -0.1，思考这会如何改变"理想行为"。

2

用自己的话回答：为什么"到达终点 +5"是延迟奖励？随机智能体为什么无法稳定地拿到高分？

3

思考题：如果把目标改成"每走一步都给 +1"，智能体会学到什么？这说明奖励定义实际上是在向智能体表达"什么叫做好"。

本章小结

  • 强化学习研究的是：智能体通过与环境交互、依据延迟的标量奖励，学会最大化长期累计奖励的策略。
  • 它与监督学习最大的不同：没有标准答案、数据靠自己探索、要平衡探索与利用。
  • 最小骨架是 reset() 与 step(action)→(观测,奖励,done) 的循环。
