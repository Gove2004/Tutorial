T1 报数游戏：约瑟夫环

题目描述

A 级 · 17noi #1717 原题 第一届区域赛 100 分（推定） 时间 1s / 内存 256MB

有编号从 1 到 N 的 N 个人组成一圈报数，报到 M 的人出局， 下一位再从 1 开始；如此持续，直到剩下一个为止，报告此人的编号 X。

输入 N, M，求出 X。

输入描述

第一行：两个整数 N, M，表示开始人数 N 和报数到 M。

输出描述

一个整数 X，表示剩下的最后一个数。

样例

输入：
5 2

输出：
3

数据范围：0 < N, M < 2000。

先自己想一想（建议 10 分钟）
  • n = 5、m = 2 时，出局顺序是什么？最后剩下谁？
  • 如果 n 和 m 都到 109，你的做法还成立吗？

样例手推

5 个人围成一圈，报数到 2 的人出局。每一轮从「上一轮出局者的下一位」开始重新数 1：

轮次当前圈子从谁开始报数出局
11 2 3 4 511→1，2→22
21 3 4 533→1，4→24
31 3 555→1，1→21
43 533→1，5→25
—3——剩下 3

最后剩下 3，与样例一致。

第一个坑：把「下一位从 1 开始」理解成「编号重置」

题面的意思是每一轮报数重新从 1 数，而不是把剩下的人重新编号成 1、2、3。 两种理解得到的答案不同：前者是 3，后者会得到 1。等价的说法是： 从当前位置往后数 M 个人（包括当前这个人），数到的人出局，下一位接着作为新的起点。

做法一：数组模拟

最直白的做法是用一个循环数组，记录当前位置，每次往后跳 M 步，删掉一个人。 当 N, M < 2000 时，总操作量约 4×106，完全能过。 

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;

    vector<int> a(n);
    for (int i = 0; i < n; ++i) a[i] = i + 1;

    int pos = 0;                 // 当前报 1 的人的下标
    while (a.size() > 1) {
        // 从 pos 开始数 m 个人，数到的人出局
        int idx = (pos + m - 1) % a.size();
        a.erase(a.begin() + idx);
        // 下一个人接替 idx 的位置
        pos = idx % a.size();
    }
    cout << a[0] << '\n';
    return 0;
}

这段代码能过题，但 vector::erase 是 O(n)，总复杂度 O(n²)，n 一大就废。 而且它有一个隐蔽问题：当 a.size() 变成 1 后，idx % a.size() 虽然安全，但循环已经退出，不用管。

做法二：线性递推

设 f(i) 表示「i 个人围成一圈、报数到 m 出局」时最后剩下的那个人的0-indexed 编号。 关键观察是：删掉第一个人之后，剩下的 i−1 个人仍然是同样结构的子问题，只是编号整体左移了 m 位。

递推式

f(1) = 0 f(i) = (f(i−1) + m) mod i

最终答案 = f(n) + 1（转回 1-indexed）。

为什么是加上 m 而不是 m−1？因为删掉的那个人占了一个位置，剩下的人的编号整体前移，把子问题的解映射回原编号时，偏移量正好是 m。

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;

    int f = 0;                       // f(1) = 0
    for (int i = 2; i <= n; ++i) {
        f = (f + m) % i;
    }
    cout << f + 1 << '\n';          // 转成 1-indexed
    return 0;
}

复杂度 O(n)、空间 O(1)。即使 n 到 107 也能在一秒内跑完。注意 m 可以大于 i， (f + m) % i 自动处理，不需要额外取模。

两份代码的对拍

递推式很容易记错一位（写成 (f + m - 1) % i 是另一个问题的答案）。赛场上最稳的办法是写个暴力对拍： 

// 用 list 模拟，O(n^2)，只用于小数据对拍
int brute(int n, int m) {
    list<int> p;
    for (int i = 1; i <= n; ++i) p.push_back(i);
    auto it = p.begin();
    while (p.size() > 1) {
        for (int k = 1; k < m; ++k) {
            ++it;
            if (it == p.end()) it = p.begin();
        }
        auto del = it;
        ++it;
        if (it == p.end()) it = p.begin();
        p.erase(del);
    }
    return p.front();
}

本地验证结果：n、m 从 1 到 29 全部枚举，递推与模拟完全一致；n = 5、m = 2 时答案为 3，与样例相符。

如果 m 也很大

当 m 远大于 i 时，每一轮可能「空转」很多圈。可以做批量取模：当 m ≥ i 时， 把 m 先对 i 取模再递推？不行——递推的每一步 i 不同，不能提前取模。

但有一个常用优化：如果 m 很大而 n 很小，直接模拟反而更快；如果两者都大，就需要 「跳步」技巧（把连续多轮不跨越一圈的删除合并），这属于约瑟夫环的进阶内容，区域赛的数据范围用不到。

易错点清单

  • 把「下一位从 1 开始」理解成「编号重置」，导致样例对不上。
  • 递推写成 (f + m - 1) % i，答案整体偏移一位。
  • 忘记转 1-indexed，n = 1 时输出 0。
  • 用 vector::erase 模拟却开了 106 的数据，TLE 而不是 WA。
  • m 未开 long long：本题 m < 2000 没事，但变形题里 m 可能到 109。

延伸练习

1

求第 k 个出局者

给定 n、m、k，输出第 k 个出局的人的编号。提示：递推只能求最后剩下的人；求第 k 个出局者需要正向模拟或「倒推 + 记录」。

2

报数到 m 的人「留下」

把规则反过来：报到 m 的人留下，其他人出局。此时等价于一个步长为 m 的约瑟夫环变体，试着推出新的递推式。

3

n = 109、m = 2

此时有闭式解（最高位相关）。先写 O(n) 递推打表找规律，再验证公式。

本章小结

  • 签到题的价值不是「难」，而是「快且一次过」。
  • 约瑟夫环的 O(n) 递推是必须背下来的模板：f = (f + m) % i，答案 f + 1。
  • 任何递推都要用小数据模拟对拍，尤其是「偏移量」这种容易差一位的地方。
