04　编写第一个 System：行为属于系统，不属于对象

烘焙出来的实体有了数据，但还没有任何行为。这一章写第一个 System，让第三章的 Cube 真正转起来，并把一套熟悉的 MonoBehaviour 逻辑完整重构为 ECS 写法。

4.1 ISystem：现代 ECS 的系统基类

当前推荐的系统形式是实现 ISystem 的非托管 partial struct：

using Unity.Burst;
using Unity.Entities;
using Unity.Transforms;

public partial struct RotationSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        float deltaTime = SystemAPI.Time.DeltaTime;

        foreach (var (transform, speed) in
            SystemAPI.Query<RefRW<LocalTransform>, RefRO<RotationSpeed>>())
        {
            transform.ValueRW = transform.ValueRO.RotateY(
                speed.ValueRO.RadiansPerSecond * deltaTime);
        }
    }
}

这段代码有几个必须理解的硬性约定：

  • partial 不是可选项。Entities 的源生成器（source generator）会在编译期为查询和 Job 生成配套代码，必须声明 partial 才能让生成的部分与你的代码合并。
  • 它是 struct 而非 class，运行在非托管世界，整个系统可以被 Burst 编译、不产生 GC。
  • OnUpdate 接收 ref SystemState，系统自身的状态和所有上下文 API 都从这个引用获取。

4.2 系统的生命周期

ISystem 的方法都有默认实现，你只重写需要的：

方法调用时机与用途
OnCreate(ref SystemState)系统首次被创建时一次，用于初始化字段、缓存查询、配置更新条件。
OnUpdate(ref SystemState)每帧（实际按所属系统组的调度）执行，核心逻辑所在。
OnDestroy(ref SystemState)系统销毁时一次，用于释放 NativeContainer 等非托管资源。

系统里可以声明实例字段保存状态（如缓存的 NativeArray、配置参数），但字段同样必须是非托管类型或 NativeContainer，并在 OnDestroy 里释放，否则会泄漏原生内存——这类泄漏 GC 不会帮你回收。

4.3 SystemAPI.Query：声明你要哪些数据

SystemAPI.Query<T1, T2, ...>() 是主线程遍历实体的标准入口。泛型参数描述每个匹配实体要取出的组件，引擎自动筛出拥有这些组件的全部实体，逐个 Chunk 遍历。

RefRO 与 RefRW：读写意图显式化

  • RefRO<T>：只读访问，用 .ValueRO 取值。只读参数让 Job 安全系统知道这段逻辑不会修改该组件，从而允许更宽松的并行调度。
  • RefRW<T>：读写访问，用 .ValueRW 取值（也可读 .ValueRO）。
易错点：只读组件写成 RefRW 虽然能跑，但会收紧并行依赖、阻止其他只读 Job 同时执行，并可能触发安全系统报错。默认用 RefRO，只有确实要修改时才用 RefRW。

查询过滤：WithAll / WithNone / WithAny

泛型参数里的组件会被取出；只用于过滤、不需要取值的组件用链式方法：

// 处理“活着且被标记、但没有眩晕标签”的实体
foreach (var (transform, speed) in
    SystemAPI.Query<RefRW<LocalTransform>, RefRO<MovementSpeed>>()
        .WithAll<AliveTag>()
        .WithNone<StunnedTag>())
{
    // ...
}
  • WithAll<T>()：实体必须拥有 T；
  • WithNone<T>()：实体必须不含 T；
  • WithAny<TA, TB>()：至少拥有其中一个。

需要拿到实体本身（比如记录下来交给 ECB）时，把 Entity 放进查询参数：

foreach (var (entity, health) in
    SystemAPI.Query<Entity, RefRO<Health>>())
{
    // entity 即当前实体
}

变化过滤：只处理发生改变的数据

SystemAPI.Query<RefRO<InputState>>()
    .WithChangeFilter<InputState>();

WithChangeFilter 让循环只处理该组件自上一帧以来被写入过的实体，适合输入、配置变化等场景，避免对未变数据重复计算。

4.4 时间从哪来

忘掉 Time.deltaTime，ECS 里通过 SystemAPI.Time 获取：

  • SystemAPI.Time.DeltaTime：当前帧的时间步长（float）；
  • SystemAPI.Time.ElapsedTime：累计经过时间（double）；

在 Burst 编译的系统里直接使用这些值即可，它们由引擎在调度时注入。

4.5 ISystem 与 SystemBase 怎么选

你会在旧资料里看到继承 SystemBase 的 class 写法。两者对比如下：

ISystem（推荐）SystemBase（旧/托管）
形式unmanaged structmanaged class
Burst 编译 OnUpdate支持不支持直接 Burst（需把逻辑放进 Job）
GC 开销无有托管开销
适用新代码默认选择必须访问托管对象、或维护旧系统时

新写的系统一律用 ISystem。本教程后续全部基于它。

4.6 完整重构：从 MonoBehaviour 到 ECS

拿一个真实的移动逻辑做重构。原始 OOP 写法：

public class EnemyMover : MonoBehaviour
{
    public float Speed = 3f;
    public Transform Target;

    void Update()
    {
        Vector3 dir = (Target.position - transform.position).normalized;
        transform.position += dir * Speed * Time.deltaTime;
    }
}

拆成 ECS 需要四个部分。运行时组件：

using Unity.Entities;
using Unity.Mathematics;

public struct MovementSpeed : IComponentData
{
    public float Value;
}

// 目标用实体引用表达，而非 Transform
public struct MoveTarget : IComponentData
{
    public Entity Entity;
}

Authoring 与 Baker（目标物体在烘焙时转成实体引用）：

using Unity.Entities;
using UnityEngine;

public class EnemyMoverAuthoring : MonoBehaviour
{
    public float Speed = 3f;
    public GameObject Target;
}

class EnemyMoverBaker : Baker<EnemyMoverAuthoring>
{
    public override void Bake(EnemyMoverAuthoring authoring)
    {
        var entity = GetEntity(authoring, TransformUsageFlags.Dynamic);
        AddComponent(entity, new MovementSpeed { Value = authoring.Speed });
        AddComponent(entity, new MoveTarget
        {
            Entity = GetEntity(authoring.Target, TransformUsageFlags.Dynamic)
        });
    }
}

移动系统。目标的位置通过 SystemAPI.GetComponent<LocalTransform> 查询：

using Unity.Burst;
using Unity.Entities;
using Unity.Mathematics;
using Unity.Transforms;

public partial struct EnemyMoveSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        float dt = SystemAPI.Time.DeltaTime;

        foreach (var (transform, speed, target) in
            SystemAPI.Query<RefRW<LocalTransform>,
                          RefRO<MovementSpeed>,
                          RefRO<MoveTarget>>())
        {
            var targetTransform =
                SystemAPI.GetComponent<LocalTransform>(target.ValueRO.Entity);

            float3 direction = math.normalize(
                targetTransform.Position - transform.ValueRO.Position);

            transform.ValueRW.Position +=
                direction * speed.ValueRO.Value * dt;
        }
    }
}
注意这里的思维变化：OOP 里 Target 是一个对象引用，直接读它的 position；ECS 里目标是另一个实体，必须通过查询显式取出它的 LocalTransform。数据不会“自己找上门”，每次跨实体访问都要显式声明。这种写法在第六章会用 ComponentLookup 优化，避免在循环内重复查询。

4.7 让系统在没有数据时停止更新

默认系统每帧都会执行 OnUpdate，即使查询结果为空。可以在 OnCreate 里配置更新条件：

[BurstCompile]
public void OnCreate(ref SystemState state)
{
    // 仅当至少一个实体拥有 RotationSpeed 时才更新
    state.RequireForUpdate<RotationSpeed>();
}

没有匹配实体时系统自动跳过，避免空转，这在事件型、阶段性系统里很有用。

4.8 常见报错与排查

编译错误：类型未声明为 partial

给 System struct 加上 partial 修饰符。源生成器需要分部类才能合并生成代码。

查询循环里一个实体都没有

依次检查：① 实体是否真的同时拥有查询里的全部组件（在 Entity Inspector 核对）；② WithNone 是否误排除了目标；③ 组件是否在正确的 World；④ 结构变更是否还没回放。

安全系统报错：访问冲突 / 读写冲突

检查 RefRO/RefRW 是否与实际读写一致；确认没有在主线程遍历的同时调度了会修改同一组件的 Job。第五章讲 Job 依赖后会更清楚。

思考与练习

  1. 在 4.6 的 EnemyMoveSystem 基础上，增加一个 StunnedTag，让带标签的实体跳过移动（用 WithNone 实现）。
  2. 把旋转系统改成同时沿 Y 轴上下浮动（提示：用 ElapsedTime 和 math.sin 修改 Position）。
  3. 给一个系统加 RequireForUpdate，在场景中没有匹配实体时用 Profiler 确认它不再执行。
  4. 解释为什么 RefRO 应作为默认选择，它对并行调度有什么帮助。

本章小结

  • ISystem 是 partial、非托管 struct，可 Burst 编译 OnUpdate；生命周期方法按需重写。
  • SystemAPI.Query 是主线程实体遍历入口，RefRO/RefRW 显式表达读写意图，默认用 RefRO。
  • WithAll/WithNone/WithAny 做过滤，WithChangeFilter 只处理变化数据，Entity 可作为查询参数取出。
  • 时间通过 SystemAPI.Time 获取；RequireForUpdate 让系统在无数据时休眠。
  • 跨实体访问必须显式查询组件，这是与 OOP 引用式访问的重要区别。
