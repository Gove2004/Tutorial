第 6 章 基础算法思想

算法思想可以分成四大类：暴力、分治、减治、贪心，再加上动态规划。前三种在这一章，第四种在第 7 章。 这一章的价值不在记住定义，而在建立一种判断：这道题能不能贪？贪错了会怎样？怎么证明？

学完本章，你应该能做到

  • 用“交换论证”说明一个贪心策略为什么正确，并构造反例驳倒错误策略；
  • 手算 Huffman 编码的构造过程，解释前缀码与压缩比；
  • 用归并排序在 O(n log n) 内统计逆序对；
  • 写出快速排序的划分过程，并说清它最坏退化成 O(n2) 的条件。

6.1 贪心法：每一步都选当前最优

贪心把整个问题拆成多个步骤，每一步都选当前看起来最好的方案，并且不回头。 “走一步看一步”“目光短浅”是它的字面描述，也是它最大的风险——局部最优不一定等于全局最优。

6.1.1 硬币问题：什么时候贪心是对的

有 1 元、2 元、5 元三种面值，数量不限，要支付 M 元，求最少用多少枚硬币。 直觉做法是从大往小尽量用：M = 11 时用 5+5+1，三枚。

这个贪心在人民币体系下是对的，因为每个面值都是前一个的整数倍关系（1、2、5 的构造保证了“大面值总能被小面值等价替换且数量不增加”）。 但如果面值是 1、5、11，要凑 15 元：

策略方案枚数
贪心（先拿最大）11 + 1 + 1 + 1 + 15
最优5 + 5 + 53
贪心的第一条纪律：先找反例。在写下贪心策略之后，用 5 分钟构造小数据。 如果构造不出来，再尝试证明；如果构造出来了，立刻换思路（这题就该用 DP，见第 7 章的硬币问题）。

6.1.2 两个可靠的贪心模型

① 区间调度（活动选择）。有 n 个活动，每个有开始和结束时间，同一时刻只能做一个，求最多能参加几个。 策略是按结束时间升序排序，能参加就参加。按开始时间或按时长排序都会出错。

② 作业分配（多机调度）。n 个作业，处理时间分别为 t1…tn，m 台机器，求最短完工时间。

  • 若 n ≤ m，答案就是最长的那个作业时间 max(ti)——每台机器各做一个，瓶颈是最长的那个；
  • 若 n > m，把作业按处理时间从大到小排序，依次分配给当前最空闲的机器。 这个策略叫 LPT（Longest Processing Time first），是这类调度问题的经典近似解，在竞赛里也是标准写法。
// 作业分配：n 个作业，m 台机器
sort(t + 1, t + n + 1, greater<int>());        // 从大到小
priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆存机器负载
for (int i = 1; i <= m; i++) pq.push(0);
for (int i = 1; i <= n; i++) {
    int load = pq.top(); pq.pop();
    pq.push(load + t[i]);                       // 分给当前最闲的机器
}
int ans = 0;
while (!pq.empty()) { ans = max(ans, pq.top()); pq.pop(); }

6.1.3 Huffman 编码：贪心的经典证明

把一段字符串存进计算机，每个字符都要编成二进制数。最简单的方案是等长编码：5 个字符各用 3 位。 但字符出现频次不同，出现多的用短码、出现少的用长码，总长度会明显下降。

字符ABCDE
频次3961519
等长编码（3 位）000001010011100
变长编码11001111101100

等长编码的总长度是 3×(3+9+6+15+19) = 156；变长编码是 3×4 + 9×3 + 6×4 + 15×2 + 19×1 = 112。 压缩比 156/112 ≈ 1.39，省下约 28% 的空间。

但变长编码有一个硬要求：必须能唯一解码。上表第二行是正确的前缀码—— 任何一个码都不是另一个码的前缀，所以 11001111001101 只能解出 ABDEC。 如果把编码改成 A=100, B=10, C=11, D=1, E=0，读到 100 时无法判断是 A 还是 B+E，解码就失败了。

Huffman 的构造规则

把每个字符看成一个带权（频次）的叶子，反复取权值最小的两个合并成一个新节点，新节点权值为二者之和， 直到只剩一个节点。从根到叶的路径（左 0 右 1）就是各字符的编码。

它得到的是“前缀最优编码”：在所有权值给定的前缀码中，加权路径长度最小。

// Huffman：用优先队列合并最小两堆
struct Node { int w; bool operator<(const Node& b) const { return w > b.w; } };

priority_queue<Node> pq;
for (int i = 0; i < n; i++) pq.push({freq[i]});

long long total = 0;                 // 带权路径长度（合并代价之和）
while (pq.size() > 1) {
    Node a = pq.top(); pq.pop();
    Node b = pq.top(); pq.pop();
    total += a.w + b.w;              // 合并产生的新节点被下面所有叶子经过一次
    pq.push({a.w + b.w});
}
为什么“每次合并最小的两个”一定最优？ 因为权值最小的字符应该在最深处（编码最长），而合并两个最小权值恰好让它们成为兄弟、位于最深的一层。 交换论证可以把这个直觉变成严格证明：任何最优树里，权值最小的两个叶子一定可以调整为同一层的最深兄弟。

6.1.4 模拟退火：当贪心走不动时

有些问题（比如求函数全局最优、TSP 近似解）贪心会卡在局部最优。模拟退火的思路是： 以一定概率接受“变差”的解，概率随温度下降而降低，从而有机会跳出局部最优。 

double SA() {
    double T = 1000, T_min = 1e-8, delta = 0.98;
    double x = rand_pos(), best = calc(x);
    while (T > T_min) {
        double nx = neighbor(x);
        double nv = calc(nx);
        if (nv > best || exp((nv - best) / T) > (double)rand() / RAND_MAX)
            { x = nx; best = max(best, nv); }   // 以概率接受更差的解
        T *= delta;
    }
    return best;
}

竞赛里模拟退火属于“实在没思路时的最后一招”：参数（初温、降温系数、迭代次数）需要调， 而且不保证正确。能用确定算法做出就别用它。

6.2 分治法

分治把一个大问题分解为多个类型相同的子问题，分别求解后合并。 典型代表是归并排序和快速排序。

6.2.1 归并排序与逆序对

归并排序把序列对半分，递归排序左右两半，再线性合并。T(n) = 2T(n/2) + O(n)，解得 O(n log n)。

它的一个“副产品”非常好用：合并时，如果右半边的 a[j] 比左半边的 a[i] 小， 说明 a[i…mid] 这 mid−i+1 个数都比它大，于是这一轮就贡献了 mid−i+1 个逆序对。 HDU 4911 就是靠这一行统计逆序对。 

#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const int MAXN = 100005;
ll a[MAXN], b[MAXN], cnt;

void Merge(ll l, ll mid, ll r) {
    ll i = l, j = mid + 1, t = 0;
    while (i <= mid && j <= r) {
        if (a[i] > a[j]) {
            b[t++] = a[j++];
            cnt += mid - i + 1;          // 左半边剩下的都比 a[j] 大
        } else {
            b[t++] = a[i++];
        }
    }
    while (i <= mid) b[t++] = a[i++];
    while (j <= r)   b[t++] = a[j++];
    for (i = 0; i < t; i++) a[l + i] = b[i];
}

void Mergesort(ll l, ll r) {
    if (l < r) {
        ll mid = (l + r) / 2;
        Mergesort(l, mid);
        Mergesort(mid + 1, r);
        Merge(l, mid, r);
    }
}

int main() {
    ll n, k;
    while (scanf("%lld%lld", &n, &k) != EOF) {
        cnt = 0;
        for (ll i = 0; i < n; i++) scanf("%lld", &a[i]);
        Mergesort(0, n - 1);
        if (cnt <= k) printf("0\n");
        else          printf("%lld\n", cnt - k);   // 每次相邻交换最多消除 1 个逆序对
    }
    return 0;
}

逆序对也可以用树状数组做（离散化后按值插入，查后缀和），复杂度同为 O(n log n)，常数更小但要多写离散化。 竞赛里建议两种都掌握：归并版代码短，树状数组版能顺带统计其他东西。

6.2.2 快速排序与它的最坏情况

快排的划分思路：选一个基准 pivot，把序列分成“左边都比它小、右边都比它大”两部分，再递归处理两边。 平均 O(n log n)，但最坏是 O(n2)——当每次划分都极不均衡时（例如已有序序列 + 取首元素为基准）。 

void quick_sort(int a[], int l, int r) {
    if (l >= r) return;
    int i = l, j = r, pivot = a[l];
    while (i < j) {
        while (i < j && a[j] >= pivot) j--;   // 右边找比基准小的
        if (i < j) a[i++] = a[j];
        while (i < j && a[i] <= pivot) i++;    // 左边找比基准大的
        if (i < j) a[j--] = a[i];
    }
    a[i] = pivot;
    quick_sort(a, l, i - 1);
    quick_sort(a, i + 1, r);
}
这也是为什么竞赛里直接用 std::sort：它用内省排序（introsort）， 在快排递归过深时切换到堆排，保证最坏 O(n log n)。自己写快排如果没有随机化基准，遇到“有序数据 + 恶意构造” 就是 TLE 或 RE（递归爆栈）。

6.3 减治法

减治与分治的区别在于：分治把问题分成多个子问题，减治只保留一个子问题。 二分查找就是最典型的减治——每次砍掉一半，只在一个半边继续找，复杂度 O(log n)。 

// 减治的代表：二分查找
int lower_bound_manual(int a[], int n, int x) {   // 第一个 >= x 的位置
    int l = 0, r = n - 1, ans = n;
    while (l <= r) {
        int mid = (l + r) >> 1;
        if (a[mid] >= x) { ans = mid; r = mid - 1; }  // 记录答案，继续往左
        else l = mid + 1;
    }
    return ans;
}

二分不只用于查找，更常用于“答案具有单调性”的题：把“求最小可行值”变成“判断某个值是否可行”， 二分答案 + 判定函数，复杂度 O(log V × check)。
